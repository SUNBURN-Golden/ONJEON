# Audit 3: 로컬 원본 보관소 경로 이탈 차단

노드: `audit3-local-store-path-traversal`. 기준: `0026667dfe971aef4fd8077b4b9489aa79efdb8c` + 이 노드 변경.

연결: BLUEPRINT A1·A2, Q7, L1, I6의 원본·출처 기반, V1·M2의 불변 보관 도구. [09 제품 목적 대응표](../proposals/설계검토_결과/09_제품목적_대응표.md)의 P02·P03·P14에 필요한 보존·근거 관리의 보안 회귀 수정이다. I6 전체나 해당 제품 행의 완료를 선언하지 않는다.

## 수정

- `tools/source_archive.py`의 `LocalStore`는 생성 시 루트를 절대 경로로 고정한다. `put_new`, `get`, `exists`, `list`가 같은 검사를 거친다.
- 키는 상대 경로여야 하며 빈 구성 요소·`.`·`..`·절대 경로·Windows 드라이브/역슬래시·NUL을 거부한다. 잘못된 키를 정규화해 다른 객체와 합치지 않는다. 빈 접두어와 끝의 `/` 하나는 목록 조회에만 허용한다.
- 기존 심볼릭 링크를 해석한 경로가 루트 밖이면 읽기·쓰기 전에 `UnsafeStoreKey`로 거부한다. 전체 목록 조회도 외부 디렉터리·파일·끊어진 심볼릭 링크를 거부해 복사 원본에 섞지 않는다.
- 쓰기의 임시 파일은 배타적으로 생성한 무작위 이름을 쓴다. 기존의 예측 가능한 `.partial` 심볼릭 링크를 따라 외부 파일을 덮어쓰지 않는다. 최종 저장은 기존 `os.link`의 원자적 생성과 충돌 거부를 유지한다.
- CLI는 경로 거부 시 종료 코드 1과 `unsafe store key`를 출력한다. 예산 작업이 있으면 `unsafe_store_key`로 정산한다.
- 함께 지적된 `--extra` 덮어쓰기는 기준 코드에 이미 방어가 있다. `validate_observation_extra`가 JSON 객체만 허용하고 `source_id`, `url`, `observed_at`, `sha256`, `bytes`, `content_type`, `object_key`를 같은 값이어도 거부한다. CLI는 저장소 열기·입력 읽기·원본 쓰기 전에 검증한다. 기존 단위·CLI 시험을 다시 실행해 확인했다.

## 검증과 한계

[실행 증거와 재현 명령](../../../tools/evidence/audit3-local-store-path-traversal/README.md)에 수정 전·후 회귀와 프로젝트 시험 결과를 기록한다. 임시 디렉터리의 합성 바이트와 모의 버킷 키로 확인했으며 실제 S3/R2 접근·배포·비용 지출은 없다.

정상 중첩 키·한글 파일명·재실행·충돌 보존·목록 조회가 동작한다. 버킷에서 받은 `../`·절대 키의 `copy`가 루트 밖을 쓰지 못하고, 로컬 원본의 외부 심볼릭 링크도 CLI에서 실패한다. `--extra`의 7개 예약 필드 거부와 정상 메타데이터 보존도 통과해야 한다.

이 검사는 키와 기존 파일시스템 경로에 대한 검사다. 로컬 루트를 다른 프로세스가 악의적으로 검사와 I/O 사이에 교체하는 공격을 격리하는 파일시스템 샌드박스는 아니다. 신뢰하는 로컬 작업 디렉터리에서 사용하는 도구이며, 원격 버킷 키는 신뢰하지 않는다.

실제 R2 관측 대조(D-04 뒤), 전 상품 확보, 정정·릴리스 화면, 화면부터 원문까지의 추적 및 T-OP-08은 이 수정으로 완료되지 않는다. 09의 P01~P19 출시 증거 상태와 기존 접근 관문을 유지한다.
