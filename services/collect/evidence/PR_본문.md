## 변경 내용

1. HTML 전체 문자열에서 `href`를 찾던 처리를 태그·속성·인용부·주석·텍스트 요소 문맥을 구분하는 파서로 바꿨다. 실제 `a`·`area` 시작 태그의 `href`만 후보로 받는다. 주석·스크립트 문자열·스타일·textarea·template·SVG·MathML 내용·속성 안의 태그 모양 문자열은 목록 항목이 아니다. 같은 문맥 검사를 빈 목록·총건수 증거에도 적용한다. KNIA의 스크립트 템플릿만 있는 응답은 `ParseFailed`이며 `SinglePage` 성공으로 세지 않는다. 대소문자·엔티티·인용부 안의 `>`와 실제 비인용 링크는 보존한다.
2. 라이프플래닛 `ProductCandidate`에 상품 코드, 관측 판매기간 토큰, 구조화된 행 메타데이터, 응답 페이지 해시와 역할별 문서 참조를 함께 저장한다. 문서 계획에도 같은 후보를 기록해 문서 먼저 열거한 경우에도 관계를 보존한다. 두 과거 판매행의 서로 다른 약관과 공유 요약서·사업방법서 관계를 저장소에서 다시 읽어 검증한다. 후보 해시는 확정 판매본 ID가 아니며, 날짜나 판을 파일명에서 추론하지 않는다. 문서 참조는 후속 확보 단계에서 URL을 검증할 대상이다.
3. 기관 진행표의 `scope_progress`에 축·판매상태·채널·기간·문서 역할별 최신 상태와 모든 gap 사유를 보존한다. `unknown_denominators`도 역할당 단일 사유 대신 범위별 사유 목록을 제공한다. 축 요약은 모든 범위를 보고 계산하므로 다른 문서 역할·채널의 성공이 robots 보류나 차단을 덮지 않는다. 정확히 같은 범위·역할을 재시도해 성공한 경우에만 그 범위의 미확인을 해제한다. 문서 역할이 없는/알 수 없는 입력은 진행표 변경 전에 거부한다.
4. 어댑터 버전을 0.3.0으로 올렸다. robots 확인 불가 보류, 200 로그인 HTML 차단, 공제 제외와 사유 보존, 원본+추출+판 연결 모두 있어야 확보라는 규칙은 계속 적용한다. 미확보 사유는 확보 분자에 넣지 않는다.

공유 스키마·가격 계산·소비자 화면·규칙 결과·개인정보 경로 변경은 없다. 숫자로 표시할 수 없는 확보율을 0으로 채우지 않는다.

## 실제 검증과 한계

- 재실행 명령: `python3 -B services/collect/tests/verify.py`. 최종 실행은 의존 경계 검사만 exit 1이며 나머지 12개 검사는 exit 0이다. 결과·명령별 로그는 `verification.json`, `verification-00.log`~`verification-12.log`에 기록한다. 다른 `verification-fix*` 파일은 과거 회차 기록이다.
- 어댑터 시험 61개(라이브러리 회귀 17 + 통합 44). 새 회귀시험 5개는 실제 협회 계획의 가짜 링크 거부, HTML 속성·스크립트 경계, 가짜 빈 목록 증거 거부, 저장된 과거 판매행·공유 문서 관계, 범위·역할별 보류·차단 사유 보존을 확인한다. 필수 ID `acquisition-reason-not-counted`는 `adapters::acquisition_reason_not_counted`로 실행했다.
- 전체 workspace 시험, fmt, clippy, build, Python 상호운용·도구 시험, 누출 검사·자체시험, 스켈레톤 정적 비노출 검사·자체시험, `git diff --check`를 실행했다. 실제 종료 코드의 정본은 `verification.json`이다. 스켈레톤 검사는 실행 중 서비스의 HTTP 경로 검증이 아니다.
- 의존 경계는 **병합 차단 유지**: `python3 -B -I tools/ci/check_deps.py`의 ontology 의존·import 위반 3건은 `packages/ontology/Cargo.toml`, `packages/ontology/tests/common/mod.rs`, `packages/ontology/tests/fixture_origin/main.rs`에 있다. 이 파일·검사기·규칙은 입력 SHA와 동일하다(`dependency-boundary.json`). 이 노드 허용 경로 밖이므로 감독자가 해당 경로 권한이 있는 과제에서 수정한 뒤 원래 전체 검사를 통과시켜야 한다. 검사 범위를 줄이거나 예외를 추가하지 않았다.
- 네트워크 열거를 수행하지 않았다. 응답은 모두 합성 `fixture_only` transport이며 공시 원문 발췌가 없다. 라이프플래닛 구조는 저장소 조사 근거에 따른 구현으로 현재 실서버 검증 완료를 뜻하지 않는다. 실제 수집은 기존 D-04·O17 관문을 따른다.
- HTML 파서는 정적 목록의 보수적인 지원 범위에 한정한다. 완전한 HTML5 DOM 복구를 주장하지 않으며, 깨진 마크업·종료되지 않은 요소·지원하지 않는 script escape 문맥은 파싱 실패로 남긴다. 동적 JavaScript를 실행하지 않는다.
- 라이프플래닛 외 보험사 구체 목록 파서와 특약·별표·가격 열거는 미지원이다. 좁은 계획의 성공은 전체 기관 분모 미확인을 해제하지 않는다. 확정 ExpectedDocument·판매본 모델 구축, 실제 문서 확보, /coverage 화면과 제품 출시 완료를 주장하지 않는다.

## 작성·리뷰·대상 고정

- 작성에 참여한 모델 역할: 구현 및 자체 검증. 실행 경로: CLI → 현재 T-DT-04 worktree → Rust cargo / Python unittest. 모델 식별자 원문은 기록하지 않는다.
- 입력·제공 리뷰 대상 SHA: `0422e539e49265d1815bbe7dca02d6e24b35c3c2`. 제공 리뷰 역할 `st_re_review`의 판정은 BLOCK이다.
- 실제 시험 대상: 위 SHA와 미커밋 수정본. 수정 소스 바이트는 `verification.json`의 파일별 SHA-256으로 고정한다. 입력 SHA를 수정 완료 커밋으로 주장하지 않는다.
- 커밋·푸시·GitHub 호출을 하지 않았다. 감독자가 최종 커밋을 만든 뒤 최종 SHA에 검증과 독립 리뷰를 다시 고정해야 한다.
- 수정본 독립 리뷰는 미실시다. 작성 계열과 다른 리뷰어의 최종 SHA 고정 리뷰가 필요하다. 자체 검증은 독립 리뷰를 대신하지 않는다.
- 수정은 `services/collect/**` 안에 한정한다. 레지스트리 CSV와 금지 경로는 수정하지 않는다.
