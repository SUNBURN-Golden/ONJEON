# 세 흐름 시각 시안 원본 사본

상태: **토의 자료. 미확정.** 2026-10-11(18차: 브라우저 시안과 실행 검증)

- **가상 계약·가상 사건으로 만든 화면 예시다.** 실제 개인 자료가 아니다. 숫자는 가상 계약과 약관 조항으로 손으로 계산한 예시이며, 계산 엔진과 연결되지 않았다.
- 원본은 Design 캔버스 시안(https://claude.ai/artifact/DuB8aN9HtPJY5ECetSCTKu, 비공개)이다. 이 폴더는 그 파일의 사본이다.
- **검토 기준본은 [세흐름_시안.html](세흐름_시안.html)이다.** 전용 캔버스 없이 브라우저에서 바로 열린다(웹 글꼴만 인터넷에서 받는다). 세 화면이 한 쪽에 나란히 있고, 화면 사이 이동은 같은 쪽 안에서 된다.
- `.dc.html` 세 개와 `canvas.json`은 캔버스 5판의 사본이다. 독립 실행되지 않는다(`support.js`는 캔버스가 제공). 브라우저 시안보다 이전 판이며, 미구현 버튼의 화면 표시가 없다.
- 색과 구성은 [화면 조작 설계서](../../../design/화면_조작_설계서.md) §3.1의 시안 실측 토큰을 따른다(배경 #F6F4EE, 글자 #1A1411·#66554A, 테라코타 #AE583F·#A14529, 구분선 #E3DED5, 세그먼트 #EDE8E1·#E8D9CD).

## 어디까지 눌러 볼 수 있나

브라우저 시안에서는 연결 안 된 버튼에 **점선 테두리와 "미구현" 표시**가 화면에 붙는다(뒤로 버튼은 점선과 "뒤로 (미구현)" 라벨).

| 화면 | 동작함 | 연결 안 됨(누르면 아무 일 없음) |
|---|---|---|
| A 이런 일이 생기면? | 일반 암 / 제자리암 등 / 갑상선암 전환, "실제로 진단받았어요"(→C), "내 보험 보기"(→B) | 뒤로, "예시 조건 바꾸기", "적용 조건 보기", "자세히" |
| B 내 보험 | "아직 모르는 것" 펼치기·접기, "이런 일이 생기면?"(→A), "이 일이 생겼어요"(→C) | "계약 변경·서류 추가", 특별조건 "보기", "유지 중이에요"·"해지·실효된 적 있어요" |
| C 이 일이 생겼어요 | "받은 적 없어요"·"받은 적 있어요", 받은 진단금 고르기·해제, "처음으로", "고치기"(답변), "보험별 내역"·"계산에 쓴 정보" 펼치기 | 뒤로, "고치기"(계산에 쓴 정보 안), "자세히", "보험금 청구 준비", "납입면제 요청 안내" |



## C의 "받은 진단금 빼기"에 대해
- 받은 진단금을 고르면 그 보장을 빼고 합계를 다시 보인다. 이것은 이 사례의 세 특약(암진단Ⅱ, 암진단Ⅱ(갱신형), 보험료납입면제대상)이 약관상 최초 1회만 지급되는 규칙을 화면에서 보여 주는 예시다. 일반 계산 규칙이 아니다.
- "받은 적 있어요"를 누르고 아직 아무것도 고르지 않았으면, 금액 대신 "어떤 진단금을 받았는지 확인 중이에요"를 보인다.

## 실행 검증 (2026-10-11)
- 방법: Playwright 1.56 + Chromium(헤드리스)으로 `세흐름_시안.html`을 열어 버튼을 실제로 누르고, 화면 문구·금액·표시 여부를 확인했다. 캡처는 기기 배율 2배.
- 스크립트: [검증/run.js](검증/run.js) · 결과: [검증/결과.txt](검증/결과.txt)(41항목, 실패 0)
- 확인한 순서: 받은 적 있음 → "확인 중"(금액 숨김) → 암진단 선택 2,100만 원 → 갱신형 추가 선택 100만 원 → 둘 다 해제 → 다시 "확인 중" → 처음으로 → 5,100만 원과 처음 문구. 받은 적 없음 → 답변 기준 문구 → 고치기 → 질문으로.
- 그 밖에 확인한 것: 미구현 버튼은 화면마다 모두 표시되고 눌러도 상태·주소가 바뀌지 않음, 화면 사이 이동, 390px 폭에서 가로 스크롤 없음, 콘솔 오류 없음, 웹 글꼴 적용.
- 이 검증은 화면 동작 검증이다. 숫자가 맞는지는 계산 엔진으로 검증하지 않았다(숫자는 예시).
