## 2. "확인됨"으로 기록하는 증거 기준

자기 보고("나는 X 모델입니다")는 증거가 아니다. 아래 (a) 하나 이상 + (b)를 갖춰야 "확인됨"이다.

| (a) 실행 경로·모델 증거 | (b) 공통 |
|---|---|
| 설정 파일의 모델 필드(경로·해시) / API 응답 헤더·메타데이터의 모델 필드(해시, 역할 이름 표기) / 제공자 청구·사용량 기록의 해당 행 / 실행기 로그의 모델 필드 | 버전 출력, 인증 상태 출력(마스킹), 최소 호출 1회의 응답·지연·비용, 확인 시각, 호스트 해시 |

기록 형식(`vm_check/<날짜>/summary.json`): `{runner, role_name, installed, version, auth, model_evidence[], model_matches_role, min_call{ok, latency_ms, cost_units}, exit_code_profile{confirmed: bool, source}, checked_at, host_hash}`. `model_matches_role=false`면 가동에서 제외한다(운영 규칙 8).

## 6. 실제 실행기 검증(T-OP-09, VM, 가동 전): 같은 규칙·같은 시험을 실제 CLI·작업 트리·원격에서

T-OP-00과 분리된 과제다. 실제 빌더 CLI 프로세스, 실제 git worktree, 실제(시험용) 원격 저장소와 보호 브랜치, 데몬의 단기 푸시 자격을 쓴다. **T-OP-00과 같은 전이·검증 코어**(daemon_rules `execution_core`)를 쓰고 어댑터만 다르다. **가동이 아니다**: 과제는 `T-MOCK-*`뿐이고 제품 코드 브랜치에 쓰지 않으며 병합하지 않는다.

| # | 시험 | 방법 | 통과 기준 |
|---|---|---|---|
| R1 | 늦은 결과: 만료된 임대의 푸시 | 임대 A를 TTL 만료시키고(하트비트 중단) A의 CLI가 그 뒤 푸시 시도 | 보호 브랜치·회수된 자격으로 원격 거부 + 데몬 R-11 기록. 원격 브랜치 SHA 불변 |
| R2 | 늦은 결과: 만료된 임대의 결과 봉투 | A가 만료 뒤 결과 봉투 제출 | lease_id·토큰 불일치로 거부(late_envelope_rejected, R-11 기록). 현재 임대의 상태 전이 없음. 인계 순서(보존→중단→폐기→발급)가 실제 로그에서 그 순서 |
| R3 | 교체 전후 동시 쓰기 | A 전환 중 B 시작. A·B가 같은 파일을 각자 작업 트리에서 수정 | A 트리는 읽기 전용 보존, A 프로세스 그룹 종료 로그, 원격에는 B(새 토큰)의 푸시만. 두 프로세스가 동시에 쓰기 자격을 가진 시각 구간이 없음(자격 발급·회수 로그로) |
| R4 | 중단·재개 | 데몬 프로세스를 강제 종료(의도 레코드 뒤) → 재시작 | 외부 상태 조회 복원 또는 R-08. WIP 커밋 보존 |
| R5 | 중복 실행 | 데몬 두 인스턴스 동시 기동 | 잠금으로 한 인스턴스만 임대. 같은 세대·같은 멱등 키 봉투 1건 |
| R6 | 전환 신호 실제 채널 | 제공자 호출을 가로채는 시험 프록시가 429/5xx를 돌려줌 | 그 CLI의 상태 채널에서 신호가 데몬에 도달하는지. 도달하지 않으면 그 CLI는 `runner_exit_code`·`provider_http_response` 전환을 쓸 수 없다고 기록 |
| R7 | 종료 코드 확인표 | §1b 표를 실제 재현으로 채움 | 확인된 값만 `runner_profile`에 기록. 미확인은 미확인 |
| R8 | 반송 재개·결정 관문 | M10·M20을 실제 상태 저장소로 반복 | 같음 |
| R9 | 강제 종료 기한 | 중단 지시 뒤 하트비트를 계속 보내는 실제 CLI 프로세스 | grace_s 뒤 프로세스 그룹 종료·자격 회수. 그 뒤 푸시·봉투 거부 |
| R10 | 예산 집행 범위 | CLI 내부 제공자 호출을 프록시로 계량할 수 있는지 | 계량 가능한 CLI만 호출 수 제한 가능. 아니면 '사후 정산만'으로 기록 |
| R11 | 정지 확인 뒤 보존(S02, 실제 실행기 필요) | stop을 무시하고 루프로 쓰는 실제 CLI 프로세스 | 강제 종료 또는 쓰기 금지 격리가 실제로 쓰기를 막고, quiescence 조건이 실제 파일 시스템에서 판정되며, 데몬 보존 자격의 WIP 커밋 트리 해시 == quiescent 해시. 빌더 토큰 보존 커밋 0건 |
| R12 | 중복 전달 noop(S03, 실제 실행기 필요) | 실제 전달 경로의 재전송 | 두 번째 봉투 noop, 상태 저장소 불변 |
| R13 | 재시도 새 키(S03, 실제 실행기 필요) | 실제 재임대·인계·복귀 | lease_generation 변경, 새 세대 첫 봉투 수락, 이전 세대 키 거부 |
| R14 | 보존 manifest(T02, 실제 실행기 필요) | 실제 작업 트리의 삭제·미추적·권한·링크·제외 경로 | git write-tree OID == 보존 커밋 tree OID. 제외 파일이 커밋에 없음 |
| R15 | 보존 실패 정리(T03, 실제 실행기 필요) | 실제 index.lock·제한 마운트·네트워크 차단·권한 거부·보호 브랜치 거부 | 한도 안 재시도 뒤 handoff_blocked, 자격 저장소에서 빌더 자격·preserve_credential 회수 확인, 작업 트리 쓰기 금지, 새 임대 0. recovery_decision 뒤 푸시만 재시도 |
| R16 | 인계 도중 데몬 재시작(T03, 실제 실행기 필요) | 각 단계에서 실제 프로세스 강제 종료·재시작 | phase·preservation_state부터 재개 또는 handoff_blocked. preserve_credential 재발급 1회 |
| R17 | 봉투 식별(T04, 실제 실행기) | 실제 어댑터의 signal 둘 + 재전송 | 구분 처리 |
| R18 | 발급 원자성(T04, 실제 실행기 필요) | 발급 트랜잭션 도중 프로세스 종료 | 세대·임대·outbox 모두 있거나 모두 없음, 재시작 뒤 정확히 한 번 수락 |

T-OP-09 결과 기록 뒤에만 04 §8의 장치에 실제 실행기 검증 결과를 적을 수 있다. 그 전까지 허용되는 표기는 "명세됨" 또는 "모의 검증 대상(T-OP-00)"뿐이며, 어느 장치에도 "검증됨"을 쓰지 않는다.
