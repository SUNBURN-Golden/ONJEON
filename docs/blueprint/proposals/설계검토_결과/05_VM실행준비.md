# 05. VM 실행 준비 (검토용 묶음)

작성 2026-10-12 | 검토 대상 SHA 4549fd0 | 지위: **설계 담당 판단(감리 대상). 채택된 정본이 아니다.**

**실제 가동은 하지 않는다.** 이 문서는 사용자(또는 사용자가 지정한 VM 운영자)가 Grokbot 데몬을 올리기 전에 무엇을 어떻게 확인하고, 어떤 증거가 있어야 "확인됨"으로 적을 수 있는지, 그리고 가동 전에 규칙을 모의 작업으로 검증하는 방법을 정한다. CLI 설치는 이 세션에서 하지 않았다.

## 1. CLI별 확인 절차 (VM에서 사용자 계정으로 실행)

모든 명령의 출력은 `vm_check/<날짜>/<cli>/` 아래에 파일로 저장한다. 비밀값이 섞인 출력은 저장 전에 마스킹하고, 마스킹했다는 표시를 남긴다.

| 실행 경로 | 설치·버전 | 인증 상태 | 모델 지정 확인 | 최소 호출 | 주의 |
|---|---|---|---|---|---|
| claude CLI(Sonnet, Fable) | `claude --version` | CLI의 인증 상태 명령 또는 설정 파일의 계정 필드(값은 마스킹) | 설정 파일·환경 변수에 **지정된 모델 식별자**가 있는지. 역할표의 모델과 설정값의 대응을 표로 남긴다. 식별자 원문은 결과물에 적지 않고 설정 파일 경로와 해시만 적는다 | 고정 프롬프트 1회(예: "숫자 1을 출력")로 응답·지연·비용 기록 | API 기본 주소가 Anthropic인지 확인(GLM 경로와 구분) |
| Cursor CLI(Grok 4.7) | `cursor-agent --version` | CLI 로그인 상태 명령 | 설정에 Grok 4.7이 선택되어 있는지 | 같음 | 미설치면 `runner_missing` |
| grokbuild CLI(Grok 4.7) | `grokbuild --version` | 같음 | 같음 | 같음 | Cursor의 Grok과 같은 계열로 센다(운영 규칙 2) |
| Devin CLI(SWE2) | `devin --version` | 같음 | SWE2 지정 | 같음 | — |
| Claude Code(GLM 5.3) | `claude --version`(같은 바이너리) | 별도 프로필 | **API 기본 주소가 GLM 호환 주소**이고 모델이 GLM 5.3으로 지정된 별도 설정 프로필. Anthropic 주소 프로필과 섞이지 않게 환경 변수 분리 | 같음 | 이 세션에서는 주소가 Anthropic이라 GLM으로 연결되지 않았다 |
| GPT Astra(설계·감리 백업) | 사용할 CLI 또는 API 경로를 **사용자가 정한다**(미정) | 그 경로의 인증 상태 | GPT Astra 지정 | 같음 | 경로 자체가 미정이므로 확인 불가로 둔다 |

## 2. "확인됨"으로 기록하는 증거 기준

자기 보고("나는 X 모델입니다")는 증거가 아니다(인계 자료 §7). 아래 중 **(a) 하나 이상 + (b)** 를 갖춰야 "확인됨"이다.

| (a) 실행 경로·모델 증거(하나 이상) | (b) 공통 |
|---|---|
| 설정 파일의 모델 필드(경로·해시 기록) | 버전 명령 출력 파일 |
| API 응답 헤더·메타데이터의 모델 필드(원문은 해시, 역할 이름으로 표기) | 인증 상태 명령 출력(마스킹) |
| 제공자 청구·사용량 기록의 해당 모델 행(날짜·호출 수) | 최소 호출 1회의 응답·지연·비용 |
| 실행기 로그의 모델 필드 | 확인 시각·VM 식별(호스트 이름 해시) |

기록 형식(`vm_check/<날짜>/summary.json`): `{runner, role_name, installed: bool, version, auth: confirmed|unconfirmed|failed, model_evidence: [config|header|billing|log], model_matches_role: bool, min_call: {ok, latency_ms, cost_units}, checked_at, host_hash}`. `model_matches_role=false`면 그 경로는 가동에서 제외한다(운영 규칙 8: 몰래 대체 금지).

## 3. 호출·비용·재시도 한도 초안

수치는 모두 **[사용자 결정 필요]**다. 아래는 보수적 기본값이며 모의 작업(§5)에서 먼저 쓴다.

| 한도 | 보수 기본값 | 적용 단위 | 소진 시 |
|---|---|---|---|
| 과제당 빌더 호출 수 `max_calls` | 40 | 지시 봉투 1건 | 결과 봉투 `wip_preserved` + R-07 |
| 과제당 벽시계 시간 `max_wall_s` | 7200 | 같음 | 같음 |
| 과제당 비용 단위 `max_cost_units` | 제공자 과금 단위로 환산한 값. 기본값 없음 → **[사용자 결정 필요]** | 같음 | 같음 |
| 재시도 `max_retries` | 동일 명령 2회(합계 3회) | 호출 1건 | 전환 신호 판정으로 |
| 일일 데몬 총 호출 | 300 | 데몬 전체 | 새 임대 금지 |
| 월 총 비용 상한 | **[사용자 결정 필요]** | 데몬 전체 | 새 임대 금지 + 사용자 통지 |
| 리뷰 호출 | 과제당 1회 + 재리뷰(변경분) 2회 | PR | `merge_wait(reviewer_unavailable)`가 아니라 **R-07**(예산) |
| 감리 호출 | 즉시 감리 PR당 1회, 정기 감리 묶음당 1회 | — | `merge_wait(auditor_unavailable)` |

비용은 원장처럼 **행동 전 기록**한다(ADR-0017의 예약·정산 방식을 데몬 상태 저장소에 적용). 제공자 청구와의 대조는 월 1회 사람이 한다. 데몬은 청구를 막지 못한다(알림 ≠ 차단).

## 4. 비밀값 취급

| 규칙 | 구현 |
|---|---|
| 데몬은 R2 토큰·DB 자격 증명·AI 검수 제공자 키를 갖지 않는다 | 데몬 실행 계정의 환경에 해당 변수 없음. 시작 시 금지 변수 존재 검사 → 있으면 기동 거부 |
| 빌더 CLI 인증은 각 CLI의 자체 저장소에만 | 데몬 설정 파일에 키 필드 없음(스키마로 금지) |
| 봉투·로그에 비밀값 패턴 금지 | 전송·저장 전 패턴 검사(토큰 접두어, 긴 base64, `cfut_` 등). 검출 시 R-10 즉시 중단 |
| 대화에 노출된 R2 토큰·`cfut_` 토큰 | 사용자가 폐기한다. 데몬·빌더는 재사용·출력하지 않는다. 폐기 전까지 R2 쓰기 과제(T-OP-04)는 `blocked` |
| 모델 식별자 원문 | 결과물·봉투에는 역할 이름과 설정 해시만 |

## 5. 모의 작업(dry-run)으로 규칙을 검증하는 방법

가동 전에 **모의 빌더**(셸 스크립트)로 상태 기계·전환·리뷰 배정·감리 트리거·중단 복구·중복 방지를 검증한다. 실제 모델·실제 저장소를 쓰지 않는다. 모의 과제는 `tasks.json`의 형식을 따르되 `id`가 `T-MOCK-`로 시작하고 `allowed_paths`가 `mock/**`뿐이다.

| # | 모의 시나리오 | 모의 빌더 동작 | 기대 결과(기계 검사) |
|---|---|---|---|
| M1 | 정상 흐름 | 결과 봉투 `pr_opened`, CI 성공 신호, 모의 리뷰어(다른 계열) 승인 | `queued → leased → building → pr_open → review_pending → review_in_progress → review_approved → merge_wait(ready)`. 병합 API 호출 0건 |
| M2 | 사용량 제한 전환 | 1차 빌더가 stderr `rate limit exceeded`, 종료 코드 비정상 | `building → handoff → leased(2순위)`. WIP 커밋 SHA와 인계 기록 존재. `authors_families`에 2순위 계열 추가 |
| M3 | 시험 실패는 전환 아님 | 결과 봉투 `failed_tests` | 같은 빌더에 재임대. 전환 없음. 3회 연속이면 R-06 반송 |
| M4 | 리뷰어 없음 | 모든 리뷰 후보가 작성 계열 | `merge_wait(reviewer_unavailable)`. 데몬이 리뷰를 대신하지 않음 |
| M5 | 코드 변경 후 재리뷰 | 승인 뒤 head SHA 변경 | `review_approved → review_pending`. 옛 리뷰 결과 무효(R-04 기록) |
| M6 | 즉시 감리 판정 | 변경 경로에 `packages/schemas/x.json` | `review_approved → audit_pending`. 모의 감리 pass → `merge_wait(ready)` |
| M7 | 정기 감리 카운터 | 구현 PR 10개 merged 관측(그중 docs-only 2개 섞음) | 구현 PR만 세어 10번째에서 `audit_queued` 묶음 생성. docs-only는 세지 않음 |
| M8 | 허용 경로 밖 수정 | `touched_paths`에 `docs/BLUEPRINT.md` | R-01 반송. 전이 없음 |
| M9 | 판단 요청 | 결과 봉투 `verdict_requested` | R-02 반송 |
| M10 | 미결 결정 | `prereq_decisions: ["D-02"]`, 결정 기록 없음 | `blocked`. 결정 기록 추가 후 `queued` |
| M11 | 재시작 복원 | 의도 레코드만 남기고 데몬 강제 종료 → 재시작 | 외부 상태 조회로 결과 복원 또는 R-08. WIP 커밋 보존 |
| M12 | 중복 실행 방지 | 같은 과제를 두 데몬 인스턴스가 동시에 임대 시도 | 잠금으로 하나만 임대. 같은 멱등 키 봉투 1건만 전송. 같은 task_id 열린 PR 있으면 새 PR 없음 |
| M13 | 충돌 경로 직렬화 | `conflict_paths` 겹치는 두 과제 | 동시 임대 없음 |
| M14 | 비밀값 검출 | 결과 봉투 로그에 `cfut_` 패턴 | R-10 즉시 중단 |
| M15 | 모든 빌더 불가 | 5개 빌더 모두 `runner_missing` | `paused_no_builder`. 작업 보존. 대체 없음 |
| M16 | 병합 금지 검사 | 데몬 코드 정적 검사 | 병합 API·자동 병합 설정 호출 함수 0건 |

실행 방법(초안): `python3 -I tools/daemon/dry_run.py --rules daemon_rules.json --tasks mock_tasks.json --scenario M1..M16 --report vm_check/<날짜>/dry_run.json`. 보고서는 시나리오별 실제 전이 열과 기대 전이 열을 나란히 두고, 하나라도 다르면 종료 코드 1이다. 이 도구는 아직 없다. 가동 전 준비 과제 T-OP-00(tasks.json)으로 만든다.

## 7. 이 문서가 보증하지 않는 것

- 어떤 CLI가 VM에 있는지. 확인은 사용자 계정으로 VM에서 해야 한다.
- 제공자 한도·가격. 청구 기록으로만 확인한다.
- 모의 작업 통과가 실제 모델의 작성 품질을 보증하는 것. 모의 작업은 **데몬 규칙**만 검증한다.
