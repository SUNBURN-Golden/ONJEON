# Audit 3 — 데몬 정적 검사 우회와 빈 CLI 수정

대상: `audit3-daemon-static-check-bypasses`, T-OP-00 개발 도구. 기준 커밋은 `285b9edf1dd60b80b9a7414a46d94d46ab83ecab`이며 이 기록은 그 위의 미커밋 변경을 설명한다.

기존 검사는 호출 노드의 일부 함수명만 확인해 builtins 매핑, 리터럴 `getattr`, `os` 함수 가져오기 별칭, 일부 프로세스 실행 API와 네이티브 실행 모듈을 놓쳤다. 문자열 `while True` 검색은 `while 1:`을 놓치고 주석·문자열도 탐지했다. 또 모든 `static_checks.py`를 제외했고 파일을 직접 실행해도 검사 함수가 호출되지 않았다.

[검사기](../../../tools/daemon/static_checks.py)는 다음을 검사한다.

- `__builtins__` 이름·속성·매핑 키와 금지 멤버의 리터럴 `getattr` 조회.
- `from os import system as s`·와일드카드 가져오기, `exec`·`spawn` 함수군·`posix_spawn`·`fork` 등의 함수 참조·별칭, `ctypes`·`_ctypes`·`posix`·`nt` 가져오기. 상대 가져오기에서도 금지 모듈을 확인한다.
- AST에서 리터럴 조건이 참인 `while` 문. 주석·문자열 속 `while True`는 실행문으로 취급하지 않는다. 기존 스케줄러 패턴 검사는 유지한다.
- 검사기 자신의 정확한 경로만 자체 제외한다. 다른 위치의 같은 파일명은 검사하며, T-OP-09 `runner_verify/`의 별도 검사 경계는 유지한다.

CLI는 기본 입력을 스크립트 위치에서 찾고 전체 13개 검사를 실행한다. 정상 0·위반 1·읽기/JSON/소스 구문 등 완료 오류 2로 종료하며 위반이나 오류를 출력한다. 테스트는 다른 작업 디렉터리에서 격리 Python으로 실행하고, 복사한 데몬 소스에 위반을 심어 코드 실행 없이 탐지하는지 확인한다.

[회귀 시험](../../../tools/tests/test_daemon_static_checks.py)은 16개다. 수정 전에는 하위 사례 포함 실패 124건·오류 17건, 수정 후에는 모두 통과했다. 오류에는 기존 루프 검사에 검사 경로 인자가 없던 경우가 포함된다. 정상 대조로 `re.compile`, JSON·데이터 문자열, 일반 객체 `getattr`, 입력 의존 루프와 거짓 리터럴 루프를 허용하는지도 확인한다. [증거 안내와 전체 실행 결과](../../../tools/evidence/audit3-daemon-static-check-bypasses/README.md)에 수정 전후 로그·전체 시험·현재 소스 해시를 연결했다.

추가 `tools/ci/tests` 실행에서 의존성 검사 시험 2개가 기존 온톨로지→규칙 엔진 의존성 3건으로 실패했다. 관련 규칙·소스 네 파일이 HEAD와 바이트 단위로 같음을 별도 기록했다. 이 노드에서 해당 의존성 정책이나 온톨로지 코드는 바꾸지 않았다.

이 검사는 계산된 속성명·일반 데이터 흐름·입력 의존 무한 루프까지 차단하는 Python 샌드박스가 아니다. T-OP-00의 정적 소스 관문 보강이며 운영 가동·실데이터 접근을 승인하지 않는다. BLUEPRINT §11과 09 §5에 따라 데몬 개발 도구의 시험은 첫 출시 완성품의 일부가 아니고, P01~P19 완료 증거를 대신하지 않는다.
