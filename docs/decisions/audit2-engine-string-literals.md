# Decision: 명시적 문자열 리터럴 `str`

결정: 2026-10-28. 가역적인 DSL 확장. Audit 2 finding은 구현·회귀 시험으로 해결했다.

**결정과 구현:** M2 실제 라벨 컴파일 전에 `{"str":"..."}`을 추가한다. `rule-0.1`·`rule-0.2` 모두 `Expr::Lit(Value::Str)`와 정적 타입 `string`으로 로드한다. JSON 문자열만 받고 입력 이름 조회·요율 파싱·공백 제거·유니코드 정규화를 하지 않는다. 새 컴파일 출력은 `{"eq":[{"input":"event"},{"str":"surgery"}]}`처럼 입력과 상수를 명시한다. 구현은 [rule.rs](../../packages/rules-engine/src/rule.rs), DSL 계약은 [엔진 README](../../packages/rules-engine/README.md)의 문자열 리터럴 절이다.

**이유:** 기존 일반 문자열은 선언된 입력 이름을 먼저 찾고, 없으면 요율로 파싱한다. 따라서 미선언 `"surgery"`는 로드 오류이고, 선언된 `"surgery"`는 입력 참조다. 이 해석은 기존 규칙의 호환성을 위해 유지한다. 명시적 생성자는 상수를 입력 선언에서 독립시키며, 기존 평가기의 문자열 비교·모름 전파를 그대로 사용한다. 미선언 문자열을 자동으로 상수 처리하는 대안은 입력명 오타를 숨기므로 기각했다. 상수를 추가 입력으로 전달하거나 M2 이후로 미루는 대안도 고정 조건을 외부 입력에 의존시키므로 기각했다.

**회귀 검증:** [string_literals.rs](../../packages/rules-engine/tests/string_literals.rs)의 시험 8개가 두 DSL 버전에서 다음을 검증한다.

- `eq`·`ne`의 일치/불일치와 양쪽 피연산자 위치, 재평가 직렬화 재현성.
- 입력명 충돌(문자열·숫자형 이름·다른 입력 타입, 해당 입력 누락/null/다른 값), 숫자형 문자열·한글·빈 문자열·이스케이프 보존. 공백·숫자 표기·유니코드 형식을 정규화하지 않음.
- 입력 누락/null은 `Unknown`, 조건부 금액과 해당 입력 blocker를 유지하며 같은 스냅샷 해시·결과를 냄.
- 비문자열 인자·추가 키·타입 불일치·순서 비교·잘못된 최상위 타입을 오류 경로와 함께 로드에서 거부. 미선택 가지도 검사.
- `if`·논리 연산 합성 및 기존 일반 문자열의 입력명 우선·요율 해석과 미선언 이름 거부 유지.

새 시험을 먼저 실행했을 때 기존 파서는 7개 실패(`str` 미지원), 기존 해석 시험 1개 통과였다([수정 전 로그](../../tools/evidence/audit2-engine-string-literals/before.log)). 구현 후 8개 모두 통과했다. 어휘 정본은 1.8.0으로 올려 `rule_operator.str`만 추가하고 생성 문서·JSON Schema·Rust/TypeScript/Dart enum을 재생성했다. 어휘 시험은 연산자 28개와 버전별 로드 수용을 대조한다.

**호환성과 실행 증거:** [검증 색인](../../tools/evidence/audit2-engine-string-literals/README.md)에 명령·종료 코드·로그가 있다. `ONJ_REQUIRE_RULE_02=1 cargo test --all --locked`는 Rust 시험 466개 통과, 기존 fixture 재생성 시험 1개 ignored다. 엔진은 단위·통합 201개와 문서 시험 3개가 모두 통과했다. 기존 골든 결과·trace·입력 스냅샷 해시·합성 및 실제 규칙 7개의 내용 해시는 고정값 그대로 통과했고 공유/로컬 fixture를 수정하지 않았다. 전체 도구 Python 시험도 1,161개 실행, 환경 의존 6개 skip으로 통과했다. `cargo fmt`, `cargo clippy`, 어휘·생성물 최신성·설계도 수치·검증 자료 자체 시험도 통과했다. 생성된 Rust는 빌드했지만 TypeScript·Dart 컴파일러가 없어 두 언어 빌드는 건너뛰었다. 이전 기록의 세 언어 빌드 결과를 이번 트리의 증거로 재사용하지 않는다.

**호환 한계와 재검토:** 이전 엔진은 `str`을 거부한다. 같은 DSL 버전 이름이라고 이전 엔진이 새 규칙을 읽을 수 있는 것은 아니므로 지원 엔진을 먼저 배포해야 한다. 구버전 엔진과 신규 규칙을 혼용해야 한다면 배포 전에 DSL 버전 또는 기능 호환성 관문을 재검토한다. 실제 라벨에 코드 집합 판정이 필요하면 BLUEPRINT에 따라 입력 단계 책임으로 별도 검토한다. 이 수정은 M2의 실제 데이터→라벨 컴파일·근거 추적 완료나 제품 목적 대응표 P04·P14의 완료 증거를 대신하지 않는다.
