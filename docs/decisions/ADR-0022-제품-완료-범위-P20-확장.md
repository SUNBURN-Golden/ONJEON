# ADR-0022 제품 완료 범위의 P20 확장

상태: 채택(가역 설계 결정, 새로운 사용자 직접 결정 아님; 병합·가동·출시 승인은 별도) | 날짜: 2026-11-25

## 배경과 근거

Audit 8 finding은 [09_제품목적_대응표](../blueprint/proposals/설계검토_결과/09_제품목적_대응표.md)가 인용한 시험을 소유한 과제를 일부 행에서 빠뜨렸고, R01·R19·R20·R22·R23과 동의·삭제·누출 시험 작업(T-PS-03·T-PS-04)이 어떤 P행에도 속하지 않는다고 지적했다. 1·2차 수정에서 P02·P03·P08·P16·P18의 담당 과제를 보완하고 개인정보 보호·복구 행 P20을 추가했으며, 도구는 행 분모를 P01~P20으로 읽도록 바꿨다.

그러나 [ADR-0019](ADR-0019-제품-완료와-작업-계약-한정-채택.md) §25가 완료 범위 변경에는 새 ADR → BLUEPRINT §7·§9·§13 → 결정 원장·두 계약 동기화를 요구하는데, 이 범위 변경을 기록한 결정 문서가 없었다. [ADR-0020](ADR-0020-작업-단계와-V1-관문-정합화.md)과 결정 원장도 여전히 P01~P19를 완료 범위로 적었고, 출시 증거 안내문은 19행을 분모로 설명했다. [BLUEPRINT §13](../BLUEPRINT.md#13-실행-계약과-요구사항-추적-adr-00120019)의 "완료 범위·증거 기준 변경은 새 ADR" 절차를 이 ADR로 이행한다.

## 결정

1. 09의 완료 범위를 P01~P20으로 확장한다. P20은 09 §4a의 개인정보 보호·복구 행이며, 목적별 동의·철회, 선택 가족력 건너뛰기·삭제, 내 자료 삭제·내보내기, 백업 복원 뒤 삭제 표시 재적용과 안전한 롤백을 실제 출시 경로 증거로 판정한다.
2. P20의 구현·완료 증거 담당 과제는 T-CT-05, T-CT-06, T-PS-03, T-PS-04, T-AP-09, T-MB-04, T-AP-06, T-OP-05다. P20은 08 요구추적표의 R19·R20·R22·R23을 연결한다. R01(정보 열람을 상담과 분리)은 P18의 비로그인 탐색 경로가 담당하고, T-PS-03·T-PS-04의 동의·삭제·복원·누출 시험은 P20이 담당한다.
3. 인용 시험을 소유한 과제를 09에 함께 적는다: P02는 T-DT-04·T-AP-04, P03은 T-WB-01, P08·P16은 T-MB-04, P18은 비로그인 경로와 개인 영역 전환 전 미전송 시험을 맡는 T-AP-01·T-AP-02·T-MB-01·T-MB-03을 포함한다.
4. T-OP-08의 `purpose-rows-all-closed`는 P01~P20 전 행의 등록부 증거(`docs/release-readiness/evidence/`)를 요구한다. 승인된 범위 근거 없는 행 전체 제외는 계속 허용하지 않는다. P20의 DNA 항목은 BLUEPRINT §7.1의 부분 동결을 따르며 행 전체 제외가 아니다.
5. 이 ADR은 ADR-0019·ADR-0020·BP-D-20의 완료 행 수 문구만 P01~P20으로 대체한다. 두 계약의 한정 채택, 상위 계약 우선, 단계·관문 대응, V1 비대체, rule-0.2 한정 예외 등 나머지 결정은 그대로 유지한다.
6. [BLUEPRINT §7](../BLUEPRINT.md#7-확정-방향), §9.5, §13, [결정 원장](../blueprint/DECISIONS.md) BP-D-23, 09, `tasks.json`, `tools/release_readiness/check.py`, `tools/ci/check_product_purpose.py`를 같은 변경에서 20행 기준으로 맞춘다. `docs/release-readiness/evidence/README.md`의 19행 문구는 이 변경의 허용 경로 밖이므로 여기서 수정하지 않으며, 해당 안내문 소유자가 P01~P20으로 동기화할 때까지 남은 후속 항목으로 둔다.

## 결과와 한계

- 완료 분모가 19행에서 20행으로 늘어난다. 실제 증거가 없는 P20은 open이며, 이 ADR은 출시 완료나 개인정보 처리 승인을 선언하지 않는다.
- 문서·도구 정합성 통과는 실제 동의·삭제·복원·누출·롤백 실행 증거를 대신하지 않는다. D-17 조건 전 개인 영역 시험에는 합성 자료만 쓴다.
- 범위 축소·후속 표시를 하려면 승인된 범위 근거가 필요하며, 매니페스트는 분모를 줄일 수 없다.

## 검증

- `tools/tests/test_audit8_completion_scope.py`가 09·`tasks.json`·판정기·진척 도구의 20행 분모, ADR·원장의 P20 표기, CI 안내문의 시험 ID 수를 대조하고 19행 문구로 되돌린 회귀를 거부한다. 허용 경로 밖인 출시 증거 안내문은 이 시험이 편집 대상으로 삼지 않는다.
- `python3 -I tools/ci/check_product_purpose.py`, `python3 -I tools/release_readiness/check.py --json`(미완료이므로 예상 종료 1), `python3 -I tools/blueprint_status.py`를 실행해 정적 정합성을 확인한다. 실행 결과는 [Audit 8 증거](../../tools/evidence/audit8-p-row-task-links/README.md)에 남긴다.

## 대안과 재검토

- P01~P19를 유지하고 개인정보·복구 작업을 기존 행에 암묵적으로 두는 안: 동의·삭제·복원·누출 작업의 소유와 완료 증거가 추적되지 않으므로 기각.
- P20을 승인된 행 전체 제외로 두는 안: 승인된 범위 근거가 없고 09 §4a가 요구를 명시하므로 기각.
- 새 사용자 결정으로 표현하는 안: 이 변경은 기존 정본의 요구(R19·R20·R22·R23)를 완료 범위에 연결하는 가역적 설계 정리이므로 기각. 사용자가 범위를 바꾸면 새 ADR로 재검토한다.
