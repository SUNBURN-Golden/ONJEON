# ADR-0019 제품 완료와 작업 계약의 한정 채택

상태: 채택(이 변경에 적용하는 설계 기준, 병합·가동 승인은 별도) | 날짜: 2026-10-29

## 배경과 근거

2026-10-13 사용자 진행 지시로 09와 tasks.json은 이미 실행·완료 기준이었다([DEC-BUNDLE-STATUS](DEC-BUNDLE-STATUS.md)). 그러나 `proposals/` 경로와 정본 미채택 문구, BLUEPRINT 문서 위계의 누락 때문에 구현 기준과 권위가 충돌했다. [Audit 3 결정](audit3-adopt-09-and-tasks-as-canon.md)의 한정 채택을 이 ADR과 BLUEPRINT §0.1·§7·§9·§11·§13에 반영한다. 이번 정리는 가역적 설계 결정이며 새로운 사용자 직접 결정으로 표현하지 않는다.

## 결정

BLUEPRINT 하위 계약으로 다음 두 파일의 역할만 정본에 한정 채택한다. 기존 경로는 링크와 데몬 입력 호환성을 위해 유지한다. `proposals/`라는 경로만으로 이 두 계약을 미채택으로 해석하지 않는다.

| 계약 | 채택 범위 |
|---|---|
| [09_제품목적_대응표](../blueprint/proposals/설계검토_결과/09_제품목적_대응표.md) | 제품 목적 P01~P19 → 구현 작업 → 실제 데이터·화면 시험·출시 완료 증거의 기준. 제품 완료 판정에서 개별 작업 완료보다 우선한다 |
| [tasks.json](../blueprint/proposals/설계검토_결과/tasks.json) | 데몬의 작업 소스: 과제 ID·입력·허용 경로·선행 작업·결정 관문·개별 `done_criteria`·`required_test_ids`·`tests` 등 작업 실행·수락 계약. 시험 전용 mock_tasks.json은 제품 작업 소스가 아니다 |

사용자의 명시적 최신 결정과 불변 원칙, BLUEPRINT 및 상위 계약을 우선한다. 09의 최상위 완료 기준이라는 말은 이 위계를 뒤집지 않는다. tasks.json의 모든 과제 또는 합성 시험이 끝났다는 사실만으로 출시를 완료 처리하지 않는다. T-OP-08의 `purpose-rows-all-closed`는 근거 있는 축소·후속을 제외한 P01~P19 전 행의 등록부 증거(`docs/release-readiness/evidence/`)를 요구한다. 제품 완료와 개발 도구의 검증은 별개이며 §9의 마일스톤 관문도 유지한다.

## 제외 범위와 변경 절차

- 제안 묶음 전체, 01~08, U-01~U-04·onto-0.2 객체·A-01·판단 기준 영역을 일괄 채택하지 않는다. 09·tasks.json에서 이들을 참조하는 것은 정본 승격이 아니다. 상위 계약과 충돌하는 제안의 반영은 D-21 경로(새 ADR)와 작성 계열 밖 독립 리뷰를 따른다.
- `daemon_rules.json`은 기존 실행 기준을 유지하되 이번 정본 채택 대상에서 제외한다. 데몬 가동·자동 병합·실데이터 접근·지출·배포를 승인하지 않는다. 결정 기록과 실제 관문 해제는 구분한다.
- `common_done_criteria`는 검토용으로 남는다. `_common_done_criteria_status=non_binding_until_adopted`를 유지하며 공통 PR 기준은 BLUEPRINT §10과 현행 PR 템플릿이다. 개별 작업의 시험 의무는 유지한다.
- 완료 범위·증거 기준 또는 상위 설계 결정을 바꾸는 변경은 새 ADR → BLUEPRINT §7·§9·§13 및 결정 원장·두 계약의 동기화 순서로 반영한다. 단순 작업 정리는 기존 관문과 PR 리뷰 아래 수행한다. 이번 ADR은 DEC-BUNDLE-STATUS의 정본 미채택 판단 중 두 계약의 역할에 해당하는 부분만 대체한다.

## 검증

`tools/tests/test_pr_policy.py`가 채택 범위·문서 위계·상태·링크·공통 PR 기준 제외를 대조한다. 제품 목적 연결은 `tools/ci/check_product_purpose.py`와 그 회귀 시험, 작업 구조는 `검증/spec_check.py`, ADR 색인·날짜는 `tools/blueprint_status.py`로 검증한다. 실행 결과와 한계는 [Audit 3 증거](../blueprint/audits/2026-10-29_adopt_09_and_tasks.md)에 기록한다. 문서 정합성 통과는 제품 완료 증거가 아니다.
