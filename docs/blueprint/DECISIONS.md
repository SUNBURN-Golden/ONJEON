## 2. 충돌 해소표

| 과거 문구·혼동 | 적용할 기준 | 조치 |
|---|---|---|
| README의 ADR-0009가 최신이라는 문구 | 공개 가격·선택 화면은 ADR-0010, 실행 계약 보완은 ADR-0012 | README 진입점과 우선순위 교체 |
| 제2부가 항상 제3부보다 우선 | 최신 사용자 결정·원칙·통합 기준·지정 상세 계약 | 과거 문서 머리에 적용 기준 표시 |
| ADR-0006 두 번 포획 추정 | 조회 manifest·분모 대조·미탐색 공개, 추정으로 완전성 입증 금지 | ADR에 부분 대체 명시 |
| 모델 일치 또는 3/n이 실제 정확도 | 알려진 정답 평가와 실제 문서 불일치 별도 | AI 합의만으로 정확도 보증 금지 |
| 설명→계산→비교의 단일 선형 등급 | 설명/조건 비교/가격 비교/계산별 capability | 이번 설계 기준, 스키마에서 명시 |
| 가족력도 상담과 함께 제외 | 가족력 선택 입력은 첫 출시, 가족 초대는 후속 제안 | 범위 표에 분리 |
| 공개 가격이 없다는 이유로 예산 삭제 | 예산 입력 유지, 확보한 동일 조건 가격만 필터 | 현재 화면·가격 계약 적용 |
| 크롤링 불가와 미공개 동일시 | unqueried/blocked/failed/not_found/not_disclosed 분리 | 미공개는 근거가 있을 때만 |
| 코드 전체 미구현이라는 오래된 설명 | 규칙 엔진 부분 구현, 앱·수집·API 미구현 | 과거 마스터플랜 상태 정정 |
| 1900~2199년, 범위 비교 미지원 | 현재 엔진 지원 범위, 제품의 영구 제한 아님 | 미지원은 capability 차단, 확장은 설계·테스트와 함께 |

ADR-0008·0009 및 평가서는 결정 이력으로 보존한다. 과거 문구가 남아 있더라도 현재 규칙처럼 구현하지 않는다.

미정 항목 때문에 전체 작업을 멈추지 않는다. 표의 차단 범위에만 적용한다. 미정 사항을 해결하면 근거·결정·영향 요구 ID·기존 문서 변경을 이 원장에 기록한다. 위 표는 법적 결론이나 외부 서비스 조건을 확정한 것이 아니다.
