# Audit 4 — 데몬 정적 검사의 AST 허용 목록

대상: `audit4-daemon-static-check-bypass`, T-OP-00 개발 도구. 이 기록은 현재 작업 트리의 변경과 로컬 실행 증거를 설명한다.

Audit 4가 지적한 별칭 가져오기, `os.execve`·`posix_spawn`, `getattr(__builtins__, ...)`, `while 1:`은 Audit 3에서 AST 탐지와 회귀 시험이 이미 추가됐다. 그러나 모듈 가져오기는 여전히 금지 목록이어서 `pickle`·`marshal`·`webbrowser` 같은 미검토 모듈과 미등록 API를 기본 허용했다. 이번 수정은 그 관문을 허용 목록으로 전환한다.

[정적 검사기](../../../tools/daemon/static_checks.py)의 `ALLOWED_IMPORTS`에 외부 모듈·하위 모듈과 멤버를, `ALLOWED_LOCAL_MODULES`에 검사 대상 데몬 모듈을 명시했다. 미등록 가져오기, 와일드카드, 패키지 밖 상대 가져오기와 외부 모듈의 미등록 멤버를 거부한다. `import`·`from ... import`의 별칭과 단순 변수 대입으로 전달된 모듈 별칭에도 적용한다. 모듈 대상 `getattr`는 허용 멤버의 리터럴 조회만 허용하며, 일반 포트/데이터의 동적 조회와 `re.compile`은 유지한다. 별칭은 범위·재대입·선언 순서에 걸쳐 보수적으로 누적한다.

기존 동적 코드·프로세스 함수 참조 검사와 참 리터럴 `while` 검사는 유지한다. 다른 위치의 `static_checks.py`도 검사하고, 정확한 검사기 자신과 T-OP-09 `runner_verify/`의 기존 별도 경계만 제외한다. CLI는 검사 대상 소스를 실행하지 않으며 정상 0·위반 1·검사 완료 오류 2를 유지한다.

[회귀 시험](../../../tools/tests/test_daemon_static_checks.py) 19개는 원래 지적된 모든 사례, 미등록 모듈·하위 모듈·멤버, 상대 경로·와일드카드, 모듈/조회 함수 별칭과 정상 사용을 확인한다. 같은 새 시험을 변경 전 코드에 실행하면 하위 사례 포함 35건이 실패했고 변경 후 모두 통과했다. 복사한 데몬의 CLI에도 위반을 주입해 실제 종료 코드와 위반 위치를 확인한다.

[실행 증거와 재현 명령](../../../tools/evidence/audit4-daemon-static-check-bypass/README.md)에 전체 Python·Rust 시험과 데몬 모의 시나리오, 정적·문서 검사 결과를 기록한다. 공용 데몬 보고서의 소스 내용 해시도 갱신했다.

검사기는 Python 샌드박스가 아니다. 컨테이너·함수 반환·모듈 간 전달을 포함한 일반 데이터 흐름, 일반 객체의 계산된 속성명, 입력 의존 무한 루프를 증명하지 않는다. 새 허용 항목은 코드 검토가 필요하다. BLUEPRINT §9.5·§11과 09 §5에 따라 이 노드는 개발 도구 보강이며 P01~P19의 실제 수집·트윈·화면·출시 완료 증거를 대신하지 않는다. 실데이터 접근·데몬 가동·출시 관문을 변경하지 않는다.
