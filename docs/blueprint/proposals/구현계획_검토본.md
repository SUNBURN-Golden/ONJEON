> 이 계획의 목표는 **첫 출시 범위의 완성품**이다(진행 지시·사용자). 단계는 내부 구축·검증 순서다. 어느 단계도 공개 MVP, 베타, 납품 단위가 아니다. 정본의 단일 출시(ADR-0007)와 마일스톤 M1~M6(BLUEPRINT §9)을 따르고, PR #2의 작업 그래프(N00~N13)와 대응시켰다. 날짜는 약속하지 않는다. 관문을 통과해야 다음으로 넘어간다(BLUEPRINT §9.2).

## 1. 완성품의 정의

완성품은 설계 통합안 §2.1~§2.8의 모든 기능이 **실제로 연결되어** 동작하는 상태다. "연결됨"의 기준은 다음과 같다.

| 구간 | 연결됐다고 보는 조건 |
|---|---|
| 화면 ← API | 화면의 모든 숫자·사실 문장이 API 응답(release_id, input_hash 포함)에서 온다. 화면 쪽 계산이나 하드코딩 값이 없다 |
| API ← 지식 | 응답이 공개된 지식 릴리스에서 온다. 그 릴리스는 원문 해시까지 근거 사슬이 이어진다(I6) |
| API ← 엔진 | 지급액·판정은 규칙 엔진의 EvaluationResult에서만 온다. 결과에 규칙 판·내용 해시·근거가 붙는다 |
| API ← 개인 영역 | 개인 계약·가정·동의는 비공개 저장소에서 오고, 공개 영역·로그로 새지 않는다(I11·I12) |
| 지식 ← 데이터 | 릴리스의 필드는 실제 수집 원문에서 추출되고 AI 검수 정책을 통과했다. 합성 픽스처가 아니다 |
| 운영 | 일일 수집·검수·릴리스·롤백·삭제·오류 대응이 실제 실행 기록을 남기며 돈다 |

**완성으로 보고하지 않는 것**(진행 지시·사용자, 정본 REQUIREMENTS "완료 보고 규칙"):
- 시안의 숫자, 화면 예시 모드, HTML 시안
- 누르면 "시안이라 연결되지 않았어요"가 뜨는 버튼, 기본 off가 아닌 미구현 경로
- 합성 픽스처나 임시 데이터로만 동작하는 기능
- CI·자동 UI 검사 통과. 이 둘은 그 검사에 들어간 코드만 확인한다
- 미확보 사유만 기록된 상품(ADR-0018 §5)
- AI 모델끼리 일치한 것. 이것은 실제 정확도가 아니다(ADR-0006)
- 구현자의 읽기 점검. 이것은 사용자 이해 검증이 아니다

## 2. 다섯 평가 축

다섯 축을 따로 평가하고 따로 보고한다. 한 축이 다른 축을 대신하지 않는다. ADR-0018의 네 축(추적 체계, 실제 확보, 검증 기능 범위, 최신성)은 축 2와 축 3 안에 그대로 들어간다.

| 축 | 묻는 것 | 측정과 증거 | 통과 기준 | 이 축으로 대신할 수 없는 것 |
|---|---|---|---|---|
| **1 기능 완성** | 출시 범위의 모든 기능이 실제 연결 상태로 동작하는가 | 기능별 E2E 시나리오(§5)를 실제 릴리스·실제 API·개인 영역에서 실행한 기록. 공통 화면 상태 7종이 화면마다 있는지. 스켈레톤 비노출 시험 | 출시 범위 기능 전부 통과. 미통과 기능이 있으면 출시를 미룰지 그 기능을 끌지 사용자가 정한다(ADR-0007) | 데이터가 충분한지, 계산이 맞는지 |
| **2 실제 데이터 확보** | 포함 범위의 분모를 추적하고 실제로 얼마나 확보했나 | (a) 추적 체계: 분모 전 판매본의 능력별 상태와 미확보 사유. (b) 층별 실제 확보율: 목록 조회 → 원문 → 조항 → 참조 → 가격 조건, 보험사·상품군·문서 형식별. (c) 최신성: 마지막 시도·성공·내용 확인·검수·배포 시각 | (a)는 포함 범위 전 기관에서 완비되어야 한다. (b)·(c)는 수치 기준이 D-19로 미정이다. 미정인 동안 "충분하다"고 판정하지 않고 실측치를 공개한다 | 계산 정확도. 확보했다고 계산 가능한 것은 아니다 |
| **3 계산 검증** | 켜진 기능(설명·조건 비교·가격 비교·계산)이 각각 근거와 검수를 통과했나 | capability별 승인 범위. 엔진 골든·경계·변이·건전성·재현성 시험. 공시 예시 재현. 그림자 비교. 표본 재추출 불일치율. W1~W6 연산의 합성·변이 시험 | 승인된 범위의 C0 검사 전부 통과, 설명 안 되는 금액 변화 0건(배포 차단). 승인되지 않은 담보는 "아직 계산하지 않아요"로 표시된다. 출시 게이트에 "전 담보 계산 가능"은 없다(ADR-0007 §4) | 실제 지급 결과와의 일치. 보험사 지급 사례 대조는 이 축에 없다 |
| **4 사용자 이해** | 소비자가 보장·제한·가격 조건·차이를 맞게 이해하나 | 사전에 고정한 과제(D-16)로 실제 참가자를 시험한다. 5초·30초 기준, 잘못 이해한 비율, 원문 도달 두 탭 이내, 예산과 보험료 구별, 공개 조건과 개인 조건 구별. 가상 계약만 쓴다 | 수락 수치는 D-16에서 사전 고정한다. 정하지 않은 채 "이해됨"으로 보고하지 않는다 | 자동 UI 검사, 구현자 읽기 점검, 시안 검토 |
| **5 운영 준비** | 매일 돌고, 틀렸을 때 멈추고 고치고 되돌릴 수 있나 | 일일 확인 달성률 실측, 장애 주입 시 최신성 경고와 마지막 검증 데이터 유지, 서킷 브레이커 발동 연습, 롤백(manifest 교체) 연습, 삭제 후 되살아남 없음 시험, 누출 시험, 비용 상한 동작, 런북 실행 기록, 4주 리허설 중요 오류 0건 | 리허설 기준(제3부 §54.1 P4). 임계값은 D-19 | 문서만 있는 런북, 수동 1회 실행 |

### 4.1 S1 상품 선정

## 5. 기능별 완료 기준

각 행의 E2E는 **실제 릴리스·실제 API·실제 개인 영역**에서 실행한다. "완료로 세지 않는 것"은 1절 목록에 더해 행마다 붙는 것이다.

| 기능 | 완료 증거(E2E) | 완료로 세지 않는 것 |
|---|---|---|
| 세 진입점·계정 | 익명 → 탐색 → 계정 전환 시 로컬 데이터 선택 이관, 민감정보는 전환 전 서버 미전송 | 진입 화면만 있음 |
| 홈 | 가입내역 상태 네 가지마다 다른 화면, 미제출을 0원·무보험으로 표시하지 않음 | 합성 계약으로만 표시 |
| 담보 상세 | 무엇을 보장 → 언제 못 받나 → 한도·갱신 → 가격 → 만약에 → 원문까지 실제 담보로. 결과를 뒤집는 제외가 첫 층에 보임(R07) | 원문 없는 설명 |
| 같은 담보 비교 | 같은 비교축의 실제 담보 둘 이상, 정의 차이 칩, 확인 필요 상품이 같은 목록에 남음, 가격은 같은 조건에서만 비교 | 이름이 같은 담보의 병합 |
| 만약에 | 사용자 가정 입력 → 엔진 결과 → 미확인·적용 조건 → 근거. 감액·면책 경계일 시험 포함 | 화면 쪽 계산 |
| 내 설계·두 안 비교 | 예산 필터가 같은 비교 기준 안에서만 동작, 가격 미확인 n개 고정 노출, 줄어드는 것이 같은 비중으로 표시, 초안 저장 시 릴리스·기준일·가정 저장 | 예산이 보장금액을 바꿈, 절감액 계산 |

| PDF 가져오기 | 실제 형식의 PDF(텍스트·스캔), 비밀번호 PDF, 계약 여러 개, 버전 불명확 → 개인 계산 보류 | 사용자 확인 없는 추출값 사용 |

| 오류 신고 | 접수 ID → 지식 쪽 검수 대기 → 영향 상태 표시. 자동 전달은 공개 근거 ID뿐 | 개인 문서 자동 첨부 |
