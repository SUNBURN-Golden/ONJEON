## 변경 내용

- Docker 부재는 기본 실패다. 제어 가능한 IPv4·IPv6 서버의 연결 성공을 격리 시험 전후로 확인한다. 같은 프로브가 네트워크 활성 변이를 실패로 판정해야 격리 성공을 인정한다. 거절·시간 초과는 통과가 아니다.
- digest로 고정한 Ubuntu 24.04에서 실제 Poppler 24.02.0으로 unittest·pytest, 지문, 인용·좌표, 재추출 ID 시험을 실행한다. 추출 시험의 버전 위장은 제거했다. 시험용 이미지 단계만 pytest를 설치한다.
- 인용은 별도 좌표 crop의 layout 출력이며 내부 공백을 보존한다. bbox 단어와 crop이 다르면 실패한다. 검증기는 전체 결과 대조 뒤 각 crop을 다시 읽어 반복되는 재구성 오류도 잡는다.
- 제3조의2 같은 삽입 조항을 보존하고, 본문의 조항 참조를 printed 제목으로 오인하지 않는다. 이 변경의 기본 추출 판은 docproc-text@1.1이다. 구획 식별자와 fp-0.1 규칙은 유지한다.
- Compose의 services.docproc 아래 구조를 파싱해 권한·격리 설정을 검사한다. PDF 바이트 전체를 중복해서 읽지 않는다.
- 기본 Docker 소켓이 없는 실행 환경에서 시험 하네스가 설치된 dockerd와 root/비대화식 sudo로 작업 트리 안의 임시 데몬을 시작한다. 시험 후 자기 데몬과 데이터 마운트·상태를 정리하며, 다음 실행도 별도 환경변수 없이 재현할 수 있다. 명시한 endpoint·context와 기존 시스템 소켓은 교체하지 않는다. 데몬 선택·시작 실패·정상/실패 후 정리·데이터 마운트 정리를 회귀 시험한다.
- 변경은 services/docproc/**뿐이다. 화면·가격·규칙·개인정보·출시 기능의 변화는 없다. 원문·자격 정보·실제 상품 데이터는 넣지 않았다.

## 검증과 한계

- 대상 checkout SHA: 4a355d813afb606cf2185dcbb0b908010c31c532. 이 수정은 해당 SHA 위의 미커밋 작업 트리다. 검증 대상 파일은 evidence/source-sha256.txt로 고정하고 명령·종료 코드·전체 로그는 evidence/validation.txt 및 연결된 로그에 기록한다. 현재 checkout 자체가 수정 내용을 포함한다고 주장하지 않는다.
- 작성 참여 역할·실행 경로: 감독 프로세스가 연 터미널 CLI의 단일 작성 에이전트가 구현·시험·자체 점검을 수행했다. 작업 트리 /workspace/onjeon-run/wt/T-DT-02. 모델 식별자 원문은 기록하지 않는다. 커밋·푸시·GitHub 호출 없음.
- 독립 리뷰: 제공된 두 차단 리뷰를 수정 근거로 사용했다. 수정 후의 서로 다른 작성 계열 독립 리뷰는 감독 프로세스가 커밋 후 최종 대상 SHA에 고정해야 한다. 자체 점검을 독립 승인으로 세지 않는다.
- 필수 시험: `cd services/docproc && python3 -m pytest -q`, `DOCPROC_SANDBOX_REQUIRE_LIVE=1 bash services/docproc/test_sandbox.sh`. 별도로 unittest, 직접 컨테이너 시험, cargo test --workspace, 누출·스켈레톤 검사도 실행한다. 실제 결과는 검증 로그가 기준이다.
- native 24.02 컨테이너 시험은 합성 PDF만 검증한다. 호스트 25.03은 추출 시험을 명시적으로 건너뛰며 수락 증거가 아니다. 컨테이너에서는 DOCPROC_REQUIRE_PINNED=1로 버전 불일치·추출 건너뛰기를 허용하지 않는다.
- 이번 실패는 이전 임시 데몬의 종료 후 기본 소켓이 없는데 시험이 외부 DOCKER_HOST 설정에 의존했던 것이다. 하네스가 이 수명 주기를 소유하도록 수정했다. 설치된 legacy 방화벽 실행 파일은 임시 전용 shim으로 선택하고 전역 설정은 바꾸지 않는다. 데몬은 기본 bridge 없이 실행하고 이미지 빌드 단계만 host 네트워크로 패키지를 받는다. 제품 Compose의 network_mode:none에서 실제 추출·인용 검증과 제어 endpoint IPv4/IPv6 격리를 검사한다. 도구 설치는 자동화하지 않으며 전제 조건이 없으면 시험은 실패한다.
- PDF에는 보편적인 바이트 단위 원문 공백 표현이 없다. 인용의 정확성은 좌표 crop의 Poppler layout 출력에 대한 일치다(quote_basis=poppler-layout-region). 외곽 여백·줄/쪽 끝 문자는 제외한다. 표·각주·계층·OCR 복원은 미지원이며 구조의 빈 값은 미분류를 뜻한다. 실제 원문 정확도·사용자 검증·출시 승인을 주장하지 않는다.
- CI 연결은 수정 금지 경로 .github/workflows/**가 필요하므로 이 과제에서 바꾸지 않았다. 로컬 필수 live 실행의 증거를 첨부한다.
