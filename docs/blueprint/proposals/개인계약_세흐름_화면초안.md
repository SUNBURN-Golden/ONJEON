# 같은 계약, 세 흐름의 화면 초안 (데이터 모델 묶음 2)

상태: **토의 자료. 미확정.** 2026-10-11(15차 토의) | 바탕: [개인 계약 모델 토의 초안](개인계약_모델_토의초안.md)

> **표기:** **토의상 제안(사용자)** = 사용자가 토의에서 제시했으나 "이 방향으로 확정해서 반영하라"는 지시가 없는 사항. **검토 의견(구현자)** = 구현자의 초안·의견. **진행 지시(사용자)** = 토의 순서·방식에 대한 지시이며 설계 결정이 아니다. 이 문서에 확정된 설계 결정은 없다.

**진행 지시(사용자).** 상태값을 더 늘리지 않는다. 같은 계약을 세 흐름으로 각각 3~4화면씩 그려 본다. 이 화면들로 두 가지를 확인한다.
1. 실제 지급액으로 오인하지 않으면서도 첫눈에 상황과 금액을 이해할 수 있는가
2. 그러려면 어떤 내부 정보가 필요한가

**세 흐름(토의상 제안·사용자).** 같은 데이터와 엔진을 쓰지만, 사용자가 기대하는 답의 성격이 달라 화면 문구와 질문 깊이가 다르다.

| 흐름 | 사용자의 물음 | 답의 성격 |
|---|---|---|
| A. 가상 탐색 | "이 상황이라면?" | 사용자가 고른 가정에 따른 금액 |
| B. 내 계약 확인 | "내 보험에서는?" | 확인된 계약 자료와 부족한 정보에 따른 결과 |
| C. 실제 사건 확인 | "이 일이 생겼어요" | 사건 자료를 더하고 필요한 조건만 좁혀 확인한 결과 |

**계약.**
- [개인 계약 모델 초안](개인계약_모델_토의초안.md) §1의 가정한 시나리오를 쓴다(굿앤굿1540(Hi2607), 2026-08-20 가입, 건강고지Ⅰ(8년), 담보 7개, 갑상선 부담보 5년).
- 문서 안에서는 이 계약을 사용자의 실제 계약처럼 다룬다. 실제 개인 자료나 실제 가입 성립의 증거가 아니다.
- 화면 문구와 금액은 검토 의견(구현자)의 예시다.

---

## A. 가상 탐색: "이 상황이라면?"

질문은 고르는 것뿐이다. 서류를 요구하지 않는다. 모든 금액 앞에 "~라면"이 붙는다.

### A1. 진입

```text
┌────────────────────────────────────┐
│ 내 보험 › 굿앤굿1540                  │
│                                    │
│ 이런 일이 생기면 얼마일까?              │
│ 미리 알아보는 계산이에요.               │
│                                    │
│ [암 진단] [뇌졸중·뇌출혈] [심근경색]      │
│ [다쳤을 때] [수술·입원]                 │
└────────────────────────────────────┘
```

내부:
- 계약 사실은 증권에서 읽은 값이다(출처: 원문 추출, 사용자 확인됨, 기준 시점: 증권 발행일).
- 시나리오 묶음을 새로 연다. 이 묶음 안의 값은 모두 "가정"이다.

### A2. 경우 고르기

```text
┌────────────────────────────────────┐
│ 암 진단 · 어떤 경우를 볼까요?            │
│                                    │
│ ● 일반 암(위암·폐암 등)                │
│ ○ 갑상선암                           │
│ ○ 제자리암·경계성종양·피부암             │
│                                    │
│ 이 경우로 볼게요                       │
│ · 가입 후 90일이 지나서 · 처음 진단       │
│   [다른 경우로 바꾸기]                  │
│                                    │
│            [계산하기]                 │
└────────────────────────────────────┘
```

내부:
- "가입 90일 이후", "처음 진단"은 사용자가 고른 가상 시나리오의 기본 선택이다. 허용되는 가정이다(14차 토의상 제안).
- 화면에 보이고 바꿀 수 있다. 이 가정이 C 흐름의 실제 사실로 넘어가지 않는다.

### A3. 결과

```text
┌────────────────────────────────────┐
│ 일반 암으로, 가입 90일 뒤 처음 진단받는다면  │
│                                    │
│        5,000만원                     │
│   + 보험료납입면제 특약 100만원           │
│   + 이후 보험료 납입면제                 │
│                                    │
│ 암진단 3,000만 · 암진단(갱신형) 2,000만   │
│                                    │
│ 미리 본 계산이에요. 실제로 일이 생기면       │
│ 진단 자료와 보험회사 심사로 정해져요.        │
│                                    │
│ [다른 경우 보기]  [실제로 진단받았어요 →C]  │
└────────────────────────────────────┘
```

내부:
- 엔진이 표현할 수 있는 규칙을 평가한다: 보장개시 90일, 지급 사건 "암(유사암 제외)", 최초 1회, 감액 없음, 납입면제 사유.
- 시나리오의 가정은 결과의 "가정"으로 붙는다.
- 계약 전 알릴의무, 진단 확정 방법처럼 시나리오가 정하지 않는 것은 결과에 "확인하지 않음"으로 남는다. 화면에서는 "실제로 일이 생기면 … 심사로 정해져요" 한 줄이 그 의미를 진다.

### A4. 경우 비교

```text
┌────────────────────────────────────┐
│ 암 진단, 경우별로 보면 (처음 진단이라면)    │
│                                    │
│ 일반 암 · 90일 뒤       5,000만원 + 면제 │
│ 제자리암·경계성종양 등       600만원      │
│ 갑상선암               특별조건 있음 ⓘ   │
│ 가입 90일 안 진단         암진단 0원 ⓘ    │
│                                    │
│ ⓘ 갑상선: 이 계약에 갑상선 부담보(5년)가    │
│   있어 기간 안이면 지급액 계산을 보류해요.   │
│ ⓘ 90일 안: 암진단 특약들이 무효가 되고      │
│   그 특약 보험료를 돌려받아요.            │
└────────────────────────────────────┘
```

내부:
- 갑상선 행에 특별조건이 금액 자리 가까이 나온다. 실제 계약 사실(특별조건)이 가정한 경우와 만나는 지점이다.
- 90일 안 행은 약관 2-5 제5조(보장개시일 전 진단 시 특약 무효, 보험료 반환)를 엔진이 평가한 결과다.
- 분기는 내부에서 모두 유지하고, 화면에는 이해하기 쉬운 네 갈래만 보인다.

## B. 내 계약 확인: "내 보험에서는?"

계약이 무엇을 보장하는지와, 아직 모르는 것을 보인다. 사건이 없으므로 "받는 금액"이 아니라 "보장 내용(가입금액)"이다.

### B1. 계약 요약

```text
┌────────────────────────────────────┐
│ 굿앤굿1540 (현대해상)                  │
│ 2026.8.20 가입 · 100세 만기 · 20년 납입 │
│                                    │
│ 암 진단        3,000만 + 2,000만(갱신형) │
│ 유사암 진단        600만               │
│ 뇌혈관질환 진단   1,000만               │
│ 허혈심장질환 진단 1,000만               │
│ 상해 사망·후유장해   1억               │
│ 보험료 납입면제    있음                 │
│                                    │
│ 특별조건 1건 · 갑상선(5년)  [보기]        │
│ 증권 기준이에요. 바뀐 게 있으면             │
│ [계약 변경·서류 추가]                    │
└────────────────────────────────────┘
```

내부:
- 담보 행에서 특약으로, 특약에서 적용 본문 판으로 연결한다(공개 지식 연결 판단).
- "증권 기준"은 계약 사실의 기준 시점(증권 발행일)을 화면에 옮긴 것이다.
- [계약 변경·서류 추가]는 내 보험에서 늘 찾을 수 있는 입구다(15차 토의상 제안). 필수 절차가 아니다.

### B2. 보장 상세: 암

```text
┌────────────────────────────────────┐
│ 암으로 진단받으면                       │
│                                    │
│ 일반 암   3,000만 + 2,000만(갱신형)      │
│ 유사암      600만 (갑상선·제자리암 등)     │
│                                    │
│ · 2026.11.18부터 보장 (가입 후 90일)     │
│ · 같은 진단금은 한 번만                  │
│ · 갱신형 2,000만은 2046.8월에 갱신,       │
│   그때 보험료를 다시 계산해요(오를 수 있음)  │
│ · 갑상선은 특별조건이 있어요 [보기]         │
│                                    │
│ [이런 일이 생기면? →A]                  │
└────────────────────────────────────┘
```

내부:
- 보장개시일, 갱신일, 최초 1회는 엔진이 계약일과 약관 규칙으로 계산한다.
- 갱신 때 약관 판이 바뀔 수 있는 조건(이 상품의 6-10 ⑧, 사업방법서 §8다1)은 상세 [보기]의 뒤쪽 층에 둔다.

### B3. 아직 모르는 것

```text
┌────────────────────────────────────┐
│ 이 계약에서 아직 모르는 것                │
│                                    │
│ 지금도 유지 중인지                       │
│   [유지 중이에요] [해지·실효된 적 있어요]    │
│   → 사고·진단 금액을 볼 때 필요해요        │
│                                    │
│ 증권 뒤에 바뀐 것(특약 해지·감액·조건 추가) │
│   서류가 없으면 증권 기준으로 보여 드려요    │
│   [계약 변경·서류 추가]                  │
│                                    │
│ 지금 답하지 않아도 돼요.                  │
└────────────────────────────────────┘
```

내부:
- 현재 상태를 받을 수 있다(15차 토의상 제안). 답은 사용자 입력이고, 기준 시점은 답한 날이다.
- [유지 중이에요]와 함께 "가입 후 해지·실효된 적 없음"을 받으면 가입일부터 답한 날까지가 확인 구간이 된다. C 흐름에서 그 구간 안의 사건일이면 다시 묻지 않는다.

### B4. 계약 중 바뀔 수 있는 것

```text
┌────────────────────────────────────┐
│ 앞으로 이 계약에서 바뀔 수 있는 것          │
│                                    │
│ 2046.8월  갱신형 특약 갱신(보험료 재계산)   │
│ 2046.8월  보험료 납입 완료                │
│                                    │
│ 보험료를 낮추는 무사고 계약전환은           │
│ 이 계약에서는 신청할 수 없어요.             │
│ 특별조건(갑상선)이 붙은 계약이라서요 [근거]  │
└────────────────────────────────────┘
```

내부:
- 무사고 계약전환(약관 6-9, 사업방법서 §21)은 이 계약의 공개 규칙이다. 건강고지Ⅰ(8년)의 신청기한은 가입 1년 뒤부터 5년이 지나기 전까지다.
- 그런데 6-9 제2조①은 "특정 신체부위·질병 보장제한부 인수제도 또는 특별조건부(할증보험료법)제도가 적용된 계약은 계약전환 신청이 불가"라고 정한다. 이 계약에는 갑상선 부담보가 있으므로 엔진은 신청 불가로 평가한다.
- 특별조건 하나가 지급 계산 밖의 규칙(계약전환)에도 걸린다. 특별조건을 금액 화면에서만 다루면 이 연결이 빠진다.
- 이 평가는 증권 기준이다. 부담보가 끝났거나 바뀌었다는 서류가 들어오면 다시 평가한다. 새 상품의 가입 가능성 판단과는 다른 흐름이다.

## C. 실제 사건 확인: "이 일이 생겼어요"

사건 자료를 더하고 필요한 조건만 좁힌다. 사용자가 코드를 해석하지 않게, 결과지에서 읽은 사실을 확인받는다. 사진 없이 가는 길도 둔다.

### C1. 무슨 일이 있었나요

```text
┌────────────────────────────────────┐
│ 어떤 일이 있었나요?                      │
│ [암 진단] ← 선택                       │
│                                    │
│ 결과지나 진단서가 있으면 올려 주세요.       │
│ 필요한 부분만 읽어 드릴게요.               │
│                                    │
│   [사진 올리기]    [사진 없이 계속]        │
└────────────────────────────────────┘
```

내부: 사건 자료(제출 문서)와 상황을 새로 연다. A 흐름의 가정은 가져오지 않는다.

### C2. 읽은 내용 확인 (사진을 올린 경우)

```text
┌────────────────────────────────────┐
│ 결과지에서 이렇게 읽었어요                 │
│                                    │
│ 진단명   위 선암 (예시)                   │
│ 결과보고일 2027.1.5                     │
│ 질병코드  결과지에 없음                    │
│                                    │
│ 맞나요?   [맞아요]  [고칠게요]             │
│                                    │
│ 진단서에 질병코드가 있으면 함께 올려 주세요. │
│ [진단서 추가]  [나중에]                   │
└────────────────────────────────────┘
```

내부:
- 진단명·결과보고일·코드는 원문 추출이고, 사용자 확인을 받는다.
- 코드가 없으면 그 값은 미확인이다. 진단명으로 분류를 추정해 확정하지 않는다.
- 사건일 계약 상태: B3에서 "가입 후 해지·실효 없이 유지"를 이미 답했고 사건일이 그 구간 안이면 묻지 않는다. 아니면 이 화면에 한 줄 더 묻는다. "진단받은 날 이 계약이 유지되고 있었나요? 해지·실효 상태였다면 보장되지 않아요."

**사진 없이 계속한 경우:** "진단받은 부위"(위)와 "결과가 나온 날"만 묻는다. 진단명은 "의사에게 들은 말로 적어 주세요(모르면 비워 두세요)"로 받는다.

### C3. 결과

**코드까지 확인된 경우** (진단서에서 C16.x를 읽고 사용자가 확인)

```text
┌────────────────────────────────────┐
│ 확인한 진단 기준, 처음 받는 진단금이라면     │
│                                    │
│        5,000만원                     │
│   + 보험료납입면제 특약 100만원           │
│   + 이후 보험료 납입면제 (신청 필요)        │
│                                    │
│ 이 금액이 달라질 수 있는 것               │
│ · 이전에 받은 진단금  [받은 적 있어요]       │
│ · 보험회사의 진단 확정 심사                │
│ · 계약 전 알릴의무 관련 사실(확인 안 함)     │
│                                    │
│ 약관에 따라 계산한 금액이며 지급 결정이       │
│ 아니에요. [계산 근거]                    │
└────────────────────────────────────┘
```

**결과지만 있거나 사진 없이 온 경우**

```text
┌────────────────────────────────────┐
│ 위암 진단 · 처음 받는 진단금이라면          │
│                                    │
│ 진단 내용을 확인하면 적용되는 담보를         │
│ 좁힐 수 있어요.                         │
│                                    │
│ 일반 암으로 확인되면   5,000만원 + 면제     │
│ 제자리암 등으로 확인되면   600만원          │
│                                    │
│ [진단서의 진단명·코드 부분 올리기]          │
│ [이 정도면 됐어요]                       │
│                                    │
│ 이 금액이 달라질 수 있는 것  [보기]         │
└────────────────────────────────────┘
```

내부:
- 코드가 확인돼도 엔진은 코드 하나로 지급을 확정하지 않는다. 분류 규칙(예: [별표2], C77~C80 원발부위 규칙)을 평가하고, 나머지 조건마다 결과를 돌려준다.
  - 평가할 수 있는 규칙(보장개시, 감액, 최초 1회 규칙, 부담보 부위 대조)은 평가한다.
  - 자료가 없는 조건(이전 지급 여부)은 "미확인"으로 돌려준다.
  - 외부 확인이 필요한 조건(진단 확정 요건, 알릴의무 관련 사실)은 "미확인"으로 돌려주고, 확인 주체(보험회사)를 붙인다.
- 금액을 바꿀 수 있는 미확인은 금액 바로 아래 "이 금액이 달라질 수 있는 것"에 둔다. 확인 주체가 회사라는 이유로 뒤쪽에 숨기지 않는다(15차 토의상 제안). 세 줄을 넘으면 접고 개수를 보인다.
- 두 번째 화면에서도 분기가 많다는 이유로 보류하지 않는다. 이해하기 쉬운 두 갈래부터 보이고 질문으로 좁힌다.

## 16차 토의: 시각 시안으로 확인 (토의상 제안·사용자, 미확정)

**시각 시안:** A 결과, B 계약 요약, C 결과를 같은 디자인으로 나란히 그렸다.
- 시안: https://claude.ai/artifact/DuB8aN9HtPJY5ECetSCTKu (비공개. 공유 메뉴에서 공유하기 전에는 다른 사람이 열 수 없다)
- 원본 사본: [시안_세흐름/](시안_세흐름/)

**확인할 것(진행 지시·사용자):** 몇 초 안에 세 가지가 보이는가. 무슨 상황인지, 이 숫자가 무엇인지, 다음에 무엇을 할 수 있는지.

### 세 질문에 대한 답
| 항목 | 토의상 제안(사용자) |
|---|---|
| A 가상 탐색 기본값 | 미리 채워서 바로 탐색하게 한다. "예시 조건"임을 표시하고 쉽게 바꿀 수 있게 한다. 실제 계약 사실로 저장하지 않는다 |
| B 아직 모르는 것 | 계약 요약 안에 짧게 넣는다. 별도 필수 화면으로 만들지 않는다. 선택한 상황의 결과에 필요한 순간 펼쳐 보인다 |
| C 결과 아래 조건 순서 | 금액·지급 여부에 미치는 영향부터 보인다. 영향이 비슷하면 사용자가 바로 확인할 수 있는 것을 먼저 보인다 |

### 고친 것
- **경계에 걸린 기본값을 쓰지 않는다.** "가입 90일 뒤" 같은 기간 표현 대신, 정확한 기준일과 사건일로 계산하고 그 조건을 짧게 보인다. 시안 A의 예시 조건은 "2027.3.15 진단 · 처음 받는 진단금"이다(보장개시 2026.11.18과 떨어진 날짜).
- **같은 경고를 매번 세 줄씩 붙이지 않는다.** 내부에서는 모두 관리하고, 화면은 세 층으로 나눈다.

| 층 | 무엇 | 어디에 |
|---|---|---|
| 현재 자료에서 확인된 제한 | 예: 갑상선 특별조건 | 금액 가까이에 바로 |
| 이번 계산을 바꾸는 구체적인 미확인 | 예: 이전 수령 여부 | 이유와 확인 행동을 함께 |
| 계산과 실제 지급 결정의 차이에 관한 일반 안내 | "약관에 따라 계산한 금액이에요. 실제 지급은 보험회사 심사로 정해져요." | 일관된 짧은 문구와 상세 보기 |

이전 수령 여부가 실제로 필요한 경우(시안 C):

> 처음 받는 진단금이라면
> ○○만 원
> 이전 수령 여부에 따라 달라질 수 있어요.
> [받은 적 없어요] [받은 적 있어요]

- 사용자가 직접 고른 가정에 따른 계산인지, 그 조건으로 분기한 결과인지가 명확해야 한다.
- 관련 제한이 여러 개면 숨기지 않고 카드나 펼침 구조로 읽기 쉽게 묶는다.

### 모델에 남길 것
- **기준 시점은 모델에 넣는다.** 계약 상태 구간도 "사용자 진술"인지 "문서로 확인한 사실"인지를 유지한다. 한 번 답했다고 검증된 계약 이력으로 바뀌지 않는다. 시안 C는 "계약 유지는 2027.2.1에 답하신 내용 기준"으로 출처를 보인다.
- **특별조건은 영향을 받는 기능·행동에도 연결한다.** 담보 금액에만 붙이지 않는다. 이 사례에서는 무사고 계약전환 신청 불가(약관 6-9 제2조①)가 근거다. 시안 B의 특별조건 카드가 "갑상선 관련 보장과, 보험료를 낮추는 계약전환 신청에 영향을 줘요"로 이를 보인다.

### 이 절 이전 내용 중 바뀐 것
- A2의 "가입 후 90일이 지나서" 기본 선택 → 정확한 날짜의 예시 조건
- C3의 "이 금액이 달라질 수 있는 것" 세 줄 상시 표시 → 위의 세 층
- B3 별도 화면 → 계약 요약 안의 "아직 모르는 것 2가지" 펼침

## 17차 토의: 시안 정정 (토의상 제안·사용자, 미확정)

검토는 저장소의 시안 소스를 기준으로 했다. 비공개 링크의 실제 화면을 직접 조작한 검토는 아니다. 고친 시안은 같은 링크(5판)와 [시안_세흐름/](시안_세흐름/)에 있다.

| 지적 | 고친 것 |
|---|---|
| 색 분위기가 회청색·파란 버튼으로 바뀌었다. 새 디자인 방향을 정한 것이 아니다 | 아이보리·차콜·테라코타로 돌아갔다([화면 조작 설계서](../../design/화면_조작_설계서.md) §3.1 실측 토큰). 카드를 줄이고 큰 제목·숫자·얇은 구분선·하단 테라코타 버튼으로 구성했다 |
| "모든 버튼이 동작한다"는 보고가 사본과 다르다. 일부 버튼에 처리 코드가 없고, 일부 링크는 목적지 없는 해시다. 사본에 `support.js`가 없어 독립 실행되지 않는다 | 보고가 틀렸다. 동작하는 것과 연결 안 된 것을 캔버스 메모와 [시안 README](시안_세흐름/README.md)에 표로 적었다. 목적지 없는 해시 링크는 버튼으로 바꿨다. 사본이 독립 실행되지 않는다는 점도 README에 적었다 |
| "받은 적 있음 → 해당 보장 0원"을 계산 규칙으로 일반화하면 안 된다. 고르기 전에도 기존 합계가 남아 재계산 결과처럼 읽힌다 | 고르기 전에는 금액 대신 "어떤 진단금을 받았는지 확인 중이에요"를 보인다. 고른 뒤에는 "고른 진단금을 뺀 예시 금액"과 "이 사례 기준의 화면 예시"를 함께 보인다. 질문은 "이 계약에서"로 범위를 밝힌다 |
| B·C에도 가상 계약 표시가 필요하다 | 세 화면 모두 상단에 "가상 계약으로 만든 화면 예시 · 숫자는 예시"를 붙였다. C는 "가상 계약·가상 사건"이다 |
| C의 사건 자료 카드가 금액보다 먼저 나온다 | 순서를 바꿨다. "위암 진단" → "처음 받는 진단금이라는 조건에서" → 금액 → 금액을 바꾸는 미확인(이 계약에서의 이전 수령) → [보험별 내역]. 진단명·코드·보고일·입력 출처는 "계산에 쓴 정보"로 접었다. 계약 유지 답변에는 "문서 확인 아님"을 붙였다 |

**방향(토의상 제안·사용자):** 지금은 조건 설명을 더할 때가 아니다. 기존 색 분위기를 되살리고, "상황 → 금액 → 필요한 질문"이 먼저 읽히게 다듬는다. 계산 기능이 연결되지 않은 시안의 숫자는 예시로 밝힌다.

## 18차: 실행 검증 (진행 지시·사용자)
- 새 기능이나 데이터 모델은 더하지 않았다. 현재 세 화면의 완성도만 확인했다.
- 전용 캔버스 없이 브라우저에서 열리는 시안 [세흐름_시안.html](시안_세흐름/세흐름_시안.html)을 만들었다.
- Chromium으로 렌더링하고 버튼을 눌러 41항목을 검사했다(실패 0). 기본 화면 세 장, 상태가 바뀐 C 두 장 등 캡처 9장을 남겼다([README](시안_세흐름/README.md)).
- 연결 안 된 버튼은 화면에서도 점선과 "미구현" 표시로 구분한다.
- 캡처를 보고 고친 것: A 예시 조건 줄의 어색한 줄바꿈, 뒤로 버튼 점선이 글자를 덮는 것, C 질문 문장 끝 글자만 따로 넘어가는 줄바꿈, "확인 중" 문장의 줄바꿈 위치, 펼침 화살표가 돌아가는 도중 캡처되는 것, "자세히" 점선이 앞 글자에 붙는 것.

캡처 검토 결과 C 기본 화면이 원하는 방향에 가장 가깝다("위암 진단 → 조건부 금액 → 필요한 질문"). 색감과 숫자 크기는 유지한다. 새 기능이나 설명은 늘리지 않는다.

## 20차: 버튼 처리 원칙과 이해 점검 (토의상 제안·사용자, 미확정)
- "보험금 청구 준비"는 정상 테라코타 주 버튼으로 둔다. 비활성 모양은 "내 조건에서는 청구할 수 없나?"라는 오해를 부른다.
- 두 가지를 구분한다.
  - 제품상 할 수 없는 행동: 비활성 처리하고 이유를 표시한다.
  - 시안에서만 연결하지 않은 행동: 실제 디자인을 유지하고 시안임을 안내한다.
- 간격·위치 수치는 목표가 아니다. 자동 검사는 겹침·잘림·상태 전환을 보고, 정보가 잘 읽히는지는 화면으로 판단한다.
- 세 화면의 잔수정은 여기서 멈춘다.

**이 시안으로 확인할 세 가지(진행 지시·사용자)**
1. 지금 보는 금액이 가정상 금액인지, 가입금액인지, 내 사건의 조건부 계산인지
2. 금액을 바꾸는 미확인 사항이 무엇인지
3. 다음에 무엇을 할 수 있는지

**구현자 읽기 점검(검토 의견·구현자).** 사용자 시험이 아니다. 화면 문구로 세 가지가 어디서 읽히는지 대조했다.

| | 1. 금액의 성격 | 2. 금액을 바꾸는 미확인 | 3. 다음 행동 |
|---|---|---|---|
| A | 금액 바로 위 "일반 암 진단이라면", 바로 아래 "예시 조건" 표시 → 가정상 금액 | 예시 조건 자체(진단일·처음 받는 진단금). 갑상선암은 특별조건 카드 | "실제로 진단받았어요", "내 보험 보기", 조건 "바꾸기" |
| B | 열 머리 "가입금액", 묶음 제목 "가입한 진단 보장" → 가입금액 | "아직 모르는 것 2가지"(접힘), 특별조건 카드 | "이런 일이 생기면?", "이 일이 생겼어요", "계약 변경·서류 추가" |
| C | 제목 "위암 진단" + "처음 받는 진단금이라는 조건에서" → 내 사건의 조건부 계산 | 금액 바로 아래 "이전 수령 여부에 따라 달라질 수 있어요" + 답 버튼 | 답 버튼, "보험금 청구 준비" |

**읽기 점검에서 남은 의문(검토 의견·구현자).** 고치지 않고 적어 둔다.
- 시안 표시 "숫자는 예시"와 A의 제품 문구 "예시 조건"이 같은 낱말을 쓴다. 실제 제품에서는 시안 표시가 사라지므로 시안 안에서만 생기는 겹침이다.
- A와 C의 금액 문장 구조가 비슷하다("~이라면" / "~조건에서"). 두 화면의 차이는 제목("이런 일이 생기면?" / "위암 진단")과 위치(가정 조건 / 사건 자료)가 맡는다. 실제로 구분되는지는 사람에게 보여 줘야 안다.
- 확인 방법 제안: 처음 보는 3~5명에게 화면을 몇 초 보여 주고 위 세 질문을 묻는다.
