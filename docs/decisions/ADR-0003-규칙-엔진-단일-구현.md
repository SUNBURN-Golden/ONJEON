# ADR-0003 규칙 엔진 단일 구현, 서버 계산

상태: 제안 (승인 대기) | 날짜: 2026-10-08 | 근거: 제3부 §47.3·§49, 제1부 §10·§34

## 맥락

앱에서 슬라이더를 움직이면 즉시 결과가 바뀌어야 한다는 요구가 있다. 클라이언트에 계산 로직을 복제하면 서버와 값이 달라질 수 있고, 금액 불일치는 불변 원칙 5·7을 위반한다.

## 결정

1. 규칙 평가는 `packages/rules-engine` 한 곳에서만 구현한다. 앱·웹은 계산하지 않고 결과와 trace를 표시한다.
2. 슬라이더 조작은 디바운스한 서버 호출로 처리하고, 응답 전까지 이전 결과를 '갱신 중'으로 표시한다. 오프라인에서는 마지막 결과와 기준 시각을 보여주며 새 계산을 하지 않는다.
3. 엔진은 정수·유리수 연산만 쓰고 부동소수점을 금지한다. 같은 입력 스냅샷·규칙 버전·엔진 버전은 같은 출력을 낸다(CI 검사).
4. 언어를 바꿔 재구현할 경우 골든·속성·변이 테스트(§49.7) 전체를 통과해야 하며 두 구현을 동시에 운영하지 않는다.

## 결과

- 응답 지연이 UX 위험이다. 예산 슬라이더는 사전 계산한 구간 결과 캐시(릴리스·프로필 단위)로 완화한다. P1에서 지연을 측정하고 목표(체감 즉시)를 정한다.
- 엔진 변경은 규칙·엔진 버전이 바뀌므로 그림자 비교 대상이다.

## 후속 검토

모바일이 Flutter이고 엔진이 Rust이므로 flutter_rust_bridge 같은 연결로 같은 크레이트를 기기에서 실행하는 선택지가 생겼다. 이 경우에도 구현은 하나다. 다만 전 상품의 규칙 번들을 기기에 두기는 크기 문제가 있어, 사용자 프로필에 관련된 규칙만 내려받는 방식을 P1 지연 측정 뒤에 검토한다. 그 전까지는 서버 계산이 기본이다.
