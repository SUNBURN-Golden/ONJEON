# R2 비용 제한

결정: ADR-0017(사용자 요청, 2026-10-09). 구현: `tools/r2_budget.py`, 정책 `budget_policy.json`, 작업 `jobs/*.json`. 시험: `tools/tests/test_r2_budget.py`.

## 1. 무엇이 막고 무엇이 막지 못하나

| 장치 | 성격 | 막는가 |
|---|---|---|
| 이 저장소의 도구(`source_archive.py`, `verify_sources.py`, `r2_budget.py`)의 한도 | 요청을 보내기 **전에** 검사하고 넘으면 중단 | 이 도구로 하는 모든 R2 요청을 막는다 |
| Cloudflare 예산 알림(Budget alert) | 예상 월 지출이 기준을 넘으면 이메일 | **막지 않는다.** 알림일 뿐 과금을 차단하지 않는다 |
| R2 자체 | 하드 지출 상한 없음 | 막지 않는다 |
| 토큰 범위·만료·폐기 | 토큰으로 할 수 있는 일을 줄임 | 이 도구를 거치지 않는 요청(토큰을 가진 다른 프로그램)은 이것만이 막는다 |

이 도구의 한도는 토큰을 가진 사람이 다른 프로그램으로 R2를 직접 호출하는 것을 막지 못한다. 그래서 토큰을 범위 제한·만료·폐기로 관리하는 것이 함께 필요하다(§4).

## 3. 동작

순서마다 앞 단계를 통과해야 다음 요청을 보낸다.

1. **작업 파일:** R2·AWS 접근에는 `--job infra/r2/jobs/initial-119.json[#upload|#verify|#status]`가 필요하다. 없으면 요청 없이 멈춘다.
2. **로컬 실행 통제(요청 없음):** 이 컴퓨터에서 예산 실행은 한 번에 하나(파일 잠금), 최근 1시간 시작 30회까지, 이번 달 마감을 한 번 본 컴퓨터는 그 달 동안 바로 거부한다. 상태 파일을 읽지 못해도 거부한다. 위치는 `$ONJEON_GATE_DIR` 또는 `~/.cache/onjeon`.
3. **마감 확인(HEAD 2회):** `closed/v1/<월>/_global.json`, `closed/v1/<월>/<작업>.json`이 있으면 멈춘다. 마감 뒤 다른 컴퓨터에서 시도하면 이 두 요청만 나간다. 이 두 요청은 원장에 남지 않는다.
4. **입장 기록(읽기 전 쓰기):** `admission/v1/<월>/<작업>/<실행>.json`을 `If-None-Match`로 먼저 쓴다. 예약 전까지 계량기는 입장 한도(위 표)를 적용하므로, 입장 기록 하나가 그 실행의 예약 전 비용 상한이 된다(원장·입장 목록 읽기, 예약 쓰기, 재시도 포함). 정산까지 가지 못한 실행의 입장은 입장 한도만큼 사용한 것으로 센다. 그래서 거부된 실행을 반복해도 매번 비용이 기록되고 한도에 들어간다.
5. **원장 검증:** `ledger/v1/<순번>.json`을 읽고 순번 연속, 해시 연결, 알려진 정책, genesis 해시를 확인한다. 읽지 못하거나 어긋나면 중단(입장은 이미 기록됨). 입장 목록은 LIST만 하고 내용은 읽지 않는다.
6. **입장 한도와 마감:** 이번 달 입장이 작업 20회 또는 전체 100회를 넘었거나, 마지막 입장 몫을 쓴 실행이 거부되면 마감 기록을 쓰고 멈춘다.
7. **예약:** 사용량(예약·정산·정산 안 된 입장) + 이번 실행 예약량 + **이번 달 남은 입장 몫**이 전체·작업 한도 안이면 예약을 쓴다. 남은 입장 몫을 비워 두므로 거부된 실행이 이어져도 한도를 넘지 않는다. 동시 실행이 같은 순번을 쓰면 한쪽은 412를 받고, 새로 생긴 기록만 읽어 다시 판단한다. 예약 전에는 보관소 요청을 보내지 않는다(계량기가 막는다).
8. **실행 중 계량:** 허용 연산(Get, Head, Put, ListObjectsV2)만, 작업 버킷과 통제 접두어만, 고정 목록의 키와 바이트만, Standard 저장 등급만. HTTP 시도마다(재시도 포함) Class A/B, Content-Length 기준 업로드 바이트, 본문을 읽기 전 내려받기 바이트, 재시도, 시간을 센다. 넘을 요청은 보내기 전에 멈춘다.
9. **정산:** 원장 꼬리(LIST 1회, GET 1회)를 읽고, 입장부터 잰 사용량에 **정산 쓰기 자체의 최악값**(시도 3회분의 Class A·바이트·재시도·시간 제한)을 더해 예약 이하로 기록한다. 정산된 실행은 이 값만, 정산되지 않은 실행은 입장과 예약 전체가 계속 쓰인 것으로 센다.
10. 다시 업로드하는 실행은 먼저 HEAD로 저장된 SHA-256을 비교한다. 같으면 바이트를 보내지 않는다.

남은 사용량 확인(이것도 입장·예약을 거친다):

```bash
python3 -I tools/r2_budget.py status --job infra/r2/jobs/initial-119.json
```

`init-pre-ledger`는 정책에 genesis가 고정된 뒤에는 요청 없이 거부한다.

## 4. 과금을 막기 위한 나머지 장치

| 항목 | 상태 |
|---|---|
| 저장 등급 Standard(Infrequent Access는 무료 사용량 제외, 최소 30일 과금, 조회 수수료) | 세 버킷 모두 기본 등급 Standard 확인(Cloudflare API, 2026-10-09). 도구가 다른 등급 업로드를 거부 |
| 멀티파트 업로드(미완료 조각이 저장량으로 남을 수 있음) | 도구가 멀티파트 연산을 거부. R2는 미완료 업로드를 기본 7일 뒤 중단 |
| 공개 접근(r2.dev, 사용자 도메인): 열리면 남이 읽기 요청을 만들어 Class B 사용량이 생김 | 세 버킷 모두 공개 개발 URL 비활성, 사용자 도메인 없음(검토자가 Cloudflare API로 확인, 2026-10-09). 다시 켜지 않는다 |
| 토큰 | 대화창으로 받은 토큰은 이번 작업 뒤 **폐기**. 이 토큰은 새로 만든 원장 버킷에도 접근됐으므로 두 버킷 한정이 아니다. 새 토큰은 버킷 지정(원본·파생·원장), Object Read & Write, 만료일 지정으로 만들고 환경 설정 Network secrets로만 넣는다. Admin 토큰은 쓰지 않는다 |
| 예산 알림 | 권장: Billing → Billable Usage → Set Budget Alert(예: 1달러). **알림일 뿐 과금 차단이 아니다** |
| GitHub 재검증 | 수동 실행만, 동시 실행 1개, 같은 원장으로 예약. 원장에 쓸 권한이 없으면 실행되지 않는다 |
| 다른 유료 제품 | 이 작업은 R2 외 Cloudflare 제품을 만들거나 켜지 않는다 |

## 5. 남는 한계

- 마감 확인 HEAD 2회는 원장에 남지 않는다. 마감 뒤 다른 컴퓨터에서 반복하면 시도마다 이 두 요청이 나간다(같은 컴퓨터에서는 0회). 이 도구 밖에서 토큰으로 직접 호출하는 것과 같은 성격이므로 토큰 관리로 막는다.
- 입장 기록 쓰기 자체가 네트워크 오류로 실패하면 그 시도(최대 3회)는 남지 않는다. 그 실행은 읽기 없이 멈춘다.
- 여러 컴퓨터에서 동시에 입장하면 입장 한도를 그 수만큼 넘을 수 있다. 넘은 입장도 모두 기록되어 사용량에 들어간다.
- 원장의 **마지막** 기록들을 지우면 감지하지 못한다(중간 삭제·변조·전체 삭제는 감지). 입장·마감 기록 삭제도 마찬가지다. 막으려면 원장 버킷에 기간 있는 버킷 잠금이 필요하다(O14와 함께 결정, 승인 전 적용 안 함).
- 원장 기록이 100건을 넘으면 입장 한도 안에서 원장을 다 읽을 수 없어 실행이 멈춘다. **대량 수집 전에** 원장 요약(체크포인트) 설계가 필요하다.
- 원장 이전 사용량(순번 1)은 측정값이 아니라 상한 추정이다.
- 한도는 Cloudflare의 실제 청구액이 아니다. 청구 기준(GB-월 평균, 단위 올림)과 차이가 있으며 실제 청구는 대시보드에서 확인한다.
- 이번 실행 통제는 S3 스텁 서버(요청 기록 비교)로 검증했다. R2 키를 지운 뒤라 실제 R2에서는 아직 돌리지 않았다.
