## 0. 작성 주체와 실행 경로

- 작성: 사용자가 2026-10-12에 지정한 **설계 담당(아키텍트·감리) 역할 Fable**로 호출된 하위 에이전트. 실행 경로는 이 클라우드 세션의 claude CLI(2.1.296) 하위 에이전트다. **자기 보고 모델명은 증명이 아니다.** 실행 기록에는 실행 경로의 설정값만 증거가 된다(인계 자료 §7).
- 독립 리뷰·감리 없음. 이 묶음을 정본에 반영하거나 병합하려면 **작성 계열(claude) 밖의 리뷰어**가 필요하다. 현재 확인된 경로가 없다(자동개발_설정안 §4). 그것은 **이 묶음의 병합만** 막는다. 사용자 검토와 다음 설계 작업은 막지 않는다.
- 금지 사항 준수: 정본·토의 자료를 고치지 않았다. 새 폴더 `docs/blueprint/proposals/설계검토_결과/` 안에만 파일을 만들었다. 커밋·푸시·CLI 설치·외부 수집·배포·가동·발송을 하지 않았다. 비밀값·모델 식별자 원문·원문 발췌를 넣지 않았다.

## 4. 핵심 판단 요약 — [설계 담당 결정(감리 대상)]

1. **구역은 정본 D15 다섯 개 그대로.** 보강: 설명 템플릿은 knowledge가 만들고 api는 렌더링만; `packages/ontology`는 knowledge 라이브러리(T-box JSON만 contracts); personal은 docproc 개인용 배포만 호출하고 R2 토큰을 갖지 않는다.
2. **주장(Assertion)과 FieldAssertion을 한 테이블로 통합.** 릴리스 = 주장 ID 집합. K1~K13을 한 집합에 검사한다.
3. **온톨로지 사례는 시험 전용으로 고정.** `origin=fixture`는 accepted가 될 수 없고(DB 제약), accepted는 ReviewDecision(계열 2개 이상) 없이 존재할 수 없고, 근거 문서 해시는 R2 관측 목록에 있어야 하며, 릴리스 빌더는 `fixture_only`를 거부한다. 손으로 상태를 바꾸는 지름길은 B3·B4·B7에서 막힌다. 정식 경로는 P1~P8.
4. **트윈 축을 S0~S1에 고정:** T-KN-01 → T-TW-01 → T-TW-03 → T-KN-07 → T-AP-03 → T-MB-02. 컴파일러는 AI 검수(D-02) 없이도 작성·시험하되, accepted 없이는 규칙·릴리스가 생기지 않는다.
5. **범위 관계는 공식 CodeSystem이 있을 때만 accepted.** 픽스처 우주(3자리 + 별표 세부)는 근사이며 서비스 판정에 쓰지 않는다.
6. **뷰모델에 `evidence_kind`·`applicability` 추가.** 큰 금액 자리는 `scenario:` + `terms`만. 24차의 ADR-0014 충돌이 구조로 막힌다.
7. **세 흐름(A·B·C)은 4탭 안에:** A·C는 만약에 탭의 진입 제목 둘(상품 트윈 / 개인 계약 트윈), B는 홈·계약 상세. 다섯 번째 탭 없음.
8. **데몬은 전령.** 전이표에 없는 조건은 전부 반송(R-01~R-10). 병합 API 호출 함수가 없다. 전환 신호는 HTTP 코드·정규식·종료 코드로만 판정하고 시험 실패는 전환 사유가 아니다.
9. **독립 리뷰어 부재는 병합만 막는다.** 계열표(Fable·Sonnet 같은 claude 계열)는 사용자 확인 전까지 더 엄격한 쪽을 쓴다.
10. **수치는 정하지 않았다.** 임대 TTL·동시 임대·예산·운영 임계값은 [사용자 결정 필요] 또는 보수 기본값으로 표시했다.
