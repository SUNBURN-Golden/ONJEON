**기준 릴리스 r26.** 담보-판 연결(in_edition) 주장 두 개를 새로 넣었다. 그래서 질문과 릴리스 시험의 기준을 `rel:case-r26`으로 옮겼다. r24·r25는 고정값을 그대로 두고, 정정 이력 재현에만 쓴다. r25에는 in_edition 주장이 없으므로, 지금의 입력 단계(case-0.2)로 r25를 계산하면 담보 연결이 없어 보류된다. 과거 결과를 재현하려면 릴리스와 함께 당시 입력 단계의 판(`input_stage`)도 고정해야 한다. 이 사례에서는 릴리스 기록에 판 이름만 적었고, 이전 입력 단계 코드를 따로 보존하지는 않았다(미검증).

**아직 검증하지 못한 것.** 보통약관 정의 조항 구획은 이 사례에서 수집하지 않아 판의 구성에 없다. 정의가 바뀌는 경우는 같은 장치(K16)로 다루도록 설계했지만, 실제 자료로 시험하지 않았다. 사업방법서처럼 약관 밖에서 적용 범위가 달라지는 경우는 판의 구성이 아니라 판매 구성-판 적용 관계(uses_edition)의 범위 문제다. 이 경우는 시험하지 않았다.

사례 릴리스 `rel:case-r24`·`rel:case-r25`는 onto-0.2 구조로 다시 고정했다. 포함한 내용의 의미(r24는 롯데 v1, r25는 롯데 v2)는 그대로다. 구획의 본문 지문은 세션 임시 영역의 원본에서 계산했다(지문 규칙 fp-0.1, 해시만 저장). 현대 지문은 원본 PDF 사본이 이 세션에 없어, 남아 있던 pdftotext 출력에서 계산했다.

## 1. 왜 온톨로지를 따로 설계하나

지금까지의 설계에는 지식의 **값**을 담는 그릇(FieldAssertion, PremiumObservation)과 **실행**하는 그릇(Rule, 엔진)이 있었다. 그러나 다음 질문에 답하는 층이 명시되어 있지 않았다.
- 이 값이 무엇에 대한 것인가. 담보·범주·조건 중 어느 것인가.
- 서로 어떤 관계인가.
- 어느 판·어느 시점에 적용되는가.
- 무엇이 근거인가.
- 무엇이 미확인이거나 충돌하는가.
- 언제 어떻게 바뀌었나.

그 결과 몇 가지 판단이 사람의 해석이나 화면 문구에 남아 있었다. 예를 들면 "이름이 같은 암 진단 담보를 같은 것으로 볼지", "요약서의 조건을 확인된 조건으로 볼지", "판매본이 어느 약관을 쓰는지"다.

온톨로지는 이 판단을 **검사할 수 있는 구조**로 옮긴다. 범용 추론기를 도입하는 것이 아니다. 허용하는 추론은 §4.2에 적은 몇 가지뿐이다.

## 2. 구성

| 층 | 무엇 | 판 관리 |
|---|---|---|
| T-box(정의) | 개념(클래스) 25개, 관계 25개, 주장 필드, 일관성 제약 16개 | 온톨로지 판(onto-x.y). 바꾸면 영향받는 A-box를 다시 검사하고 즉시 감리 |
| A-box(인스턴스) | 노드(담보 발생·범주·코드 집합·조건 등)와 **주장**. 주장은 근거·범위·시점·상태를 갖는다 | 주장마다 불변. 정정은 새 주장 |
| 릴리스 | 구성원 ID 목록(원본·구획·판·조항·노드·주장·충돌·공백 등) + 규칙 파일 해시 + 내용 해시 | 불변. 과거 결과는 그 릴리스로 재현(K15) |

상태 값은 어휘 정본(`packages/schemas/vocabulary.json` 1.2.0)의 `value_state`, `review_status`, `hold_reason`, `capability`, `relation_type`을 그대로 쓴다. 새 값(근거 역할, 범위 관계 값, 주장 필드)은 어휘 정본 절차로 추가해야 한다(§13).

| 상품 | 판매 구성(판매본), 상품 계열, 구성 요소, 담보 발생 | **증거로 묶은 내부 식별자**(자연 키 없음, 조사 H1·H5) / 탐색용 선택 주장 / 판매 구성 안의 종·형·심사 유형·특약 선택 / 약관 판 안의 보장 조항 하나 |
| 의미 | 질병 범주, 코드 집합, 사건 유형, 조건, 기산 시점, 공통 담보 개념 | **그 약관 판이 정의한 범주**(이름이 같아도 판마다 다름) / 코드 체계 + 개정차수 + 시행일 + 범위 + 판정 시점 / 통제 어휘 / 종류별 구조화 값 / 통제 어휘 / 비교 축(등가 아님) |
| 가격 | 가격 관측 | 출처 행 + 조건·구성·기준일 |
| 실행 | 실행 규칙 | rule_id + 판 + 내용 해시(엔진 소유) |
| 메타 | 주장, 충돌, 지식 공백, 확보 작업, 릴리스 | — |

이 설계의 핵심 결정은 다음 두 가지다(검토 의견·구현자).
- **질병 범주를 상품 판마다 따로 둔다.** "암", "일반암", "암(유사암 제외)"는 이름이 비슷해도 다른 노드다. 공통 담보 개념은 이 노드들을 비교 축에 놓을 뿐, 같다고 하지 않는다.
- **판매 구성과 약관 본문 판을 다대다 관계로 둔다.** 둘을 잇는 것도 근거가 있는 주장이다.
- **파일과 약관 판을 분리한다.** 한 파일에 약관 수백 개가 들고(통합약관), 한 판이 여러 파일에 있으며(개별 특약 파일, 재압축본), 재압축하면 해시가 바뀐다(토의 공개지식 모델 §1).

## 5. 적용 범위와 시점

**범위.** 모든 주장은 적용 범위를 갖는다.
- 약관 본문 판·판매 구성
- 계약 구분(최초계약 / 갱신계약 / 부활)
- 구성 요소 조건(종·형·심사 유형)
- 피보험자 조건(예: "보험나이 15세 이상만 해당")

예를 들어 하나 2-1의 감액 조건은 적용 대상이 "최초계약"이고, 갱신계약에는 적용되지 않는다. 범위가 빠진 감액 조건은 확인된 값(observed)이 될 수 없다(K7).

**시점(세 가지를 섞지 않는다).**
- `valid_from/valid_to`: 그 주장이 현실에서 적용되는 기간(판매 기간, 약관 적용 기간)
- `recorded_at`: 우리가 기록한 시각. 정정 이력과 릴리스 재현의 축이다
- `observed_at`: 출처에서 관측한 시각

판정 시점 규칙도 따로 둔다(`judged_as_of`). 사례의 두 약관은 모두 "진단 당시 시행 중인 한국표준질병사인분류"로 판정한다.

**시점이 바꾸는 결과(사례 Q10).** 같은 이름의 하나 상품이라도 가입일이 2026-03-15이면 적용 판매본은 2026-01-01~03-31판이다. 그 판의 약관(파일 45c3fe396a)은 수집하지 않았다. 그래서 2026-07-01판의 약관이 있어도 계산하지 않고 공백(gap:H_old)으로 남는다.

## 6. 근거

| 역할 | 무엇 | C0 주장에서 |
|---|---|---|
| basis | 약관 구획(보통약관·특약 약관·별표)의 조항으로, 그 구획이 accepted realizes로 본문 판에 이어진 것 | **필수**(ADR-0014 §1) |
| cross_check | 상품요약서, 사업방법서, 공시, 상품안내 표 | 교차 확인만. 단독으로는 accepted가 될 수 없음(K1) |
| observation | 공시 행, 회사 목록, 문서 구획(본문 지문) | 판매 구성과 판의 대응, 구획과 판의 대응 같은 구조 주장의 근거 |

근거는 조항 → 구획(본문 지문) → 원본 해시·PDF 쪽 → 판으로 가리킨다. 저장소가 public이고 원문 발췌의 재배포 조건이 미결정(O16·D-12)이다. 그래서 A-box에는 원문을 옮기지 않고 구현자 요약(note)만 둔다. 원문 대조는 세션 임시 영역의 원본으로 했다.

## 7. 미확인과 충돌

| 상황 | 표현 | 영향 |
|---|---|---|
| 근거를 찾지 못함 | `value_state=not_found`, `review_status=hold`, `hold_reason=reference_unresolved` | 그 주장에 기대는 capability 차단. 공백(KnowledgeGap) 생성 |
| 요약서만 있음 | 근거 역할 cross_check만, `review_status=hold` | 같음(사례: 롯데 일반암) |
| 출처끼리 다름 | `value_state=conflicting` + Conflict 노드 | 해소 전 영향 담보 simulate 차단(K11). 다수결 금지 |
| 판정 입력이 없음(예: 진단 코드 모름) | 엔진 입력 `null` | 엔진이 3값 논리로 "판단 불가"와 조건부 금액을 낸다(사례 Q5) |
| 계산할 수 없는 범위 관계 | `scope_relation=not_comparable`, 출처 주장은 hold | 비교 화면에서 "정의를 확인하지 못해 비교 불가"로 표시 |

**지식 공백과 확보 작업은 따로 둔다**(토의 24차). 롯데 사례의 상태는 다음과 같다.
- 확보 작업 task:L1_collect는 "보류"다(robots 확인 불가). task:L1_inquiry는 "초안 작성, 미발송"이다.
- 공백 gap:L1은 "일부 해소(요약서 기재)"에 머문다.

회신이 와도 질문에 답하지 않았으면 공백은 그대로다.

## 8. 정정 이력

주장은 고치지 않는다. 정정은 새 주장을 만들고 `supersedes`로 이전 판을 가리키며, `correction_reason`과 `recorded_at`을 남긴다.

**릴리스 고정(onto-0.2).** 릴리스는 구성원 ID 목록과 내용 해시를 고정한다. 정정 주장은 **다음 릴리스**에만 들어간다. 그래서 과거 결과를 그대로 재현할 수 있다.
- 자체 시험 I1: r25를 만든 뒤 "하나 판 연결을 보류로 정정"하는 주장을 추가했다. r25는 여전히 고정된 37개 주장을 읽고, Q1은 500만 원으로 같다. 그 정정을 포함한 릴리스 후보에서는 Q1이 계산 보류가 된다.
- I2 제자리 수정, I3 구성원 삭제, I4 규칙 파일 교체는 모두 K15 위반으로 잡힌다.

**실제 사례(검증 결과 §정정 이력 재현).**
- `rel:case-r24`(24차 시안 시점): 롯데 보장개시 조건 주장 v1은 요약서만을 근거로 `accepted`였다. 검사기는 이 릴리스에서 **K1 위반 1건**을 찾는다.
- `rel:case-r25`(25차 정정 뒤): v2가 v1을 대체한다. `hold`이고, 사유는 "오류 정정: C0 근거는 약관(ADR-0014)"이다. 위반은 0건이다.
- v1은 지워지지 않는다. r24로 계산했던 화면은 r24로 재현된다.

| K15 | 릴리스 구성원(주장·노드·조항·구획·판·공백·규칙 파일)이 없어지거나 제자리에서 바뀌면 위반이다. 릴리스는 목록에 있는 것만 읽는다 | I2·I3·I4·I6 → 잡음. I1·I5(새 주장·새 판 추가) → r25 결과·설명 불변 |
| K16 | 판의 구성과 근거 묶음을 나눈다. 근거 묶음이 구성 일부를 덮지 못하면 동일성 미확인(hold). 지문 차이(내용 차이 후보·정규화 규칙 차이)는 검수 결정으로만 같은 판 | 별표12 지문 변경 → 잡음. D4·D8·D9 → 잡음. D5·D6 → 위반 없음 |

자체 시험은 세 갈래다. 제약 K1~K14·K16은 **릴리스 후보**(지금 저장된 전부)에서 검사한다. 고정 릴리스 r24·r25는 K15까지 검사한다. 릴리스·문서 모델 시험 I1~I7·D1~D9·E1~E4·S01·S01b·T01·U01·P1은 모두 실행해서 결과를 비교하는 동작 검증이다. 금액 표시·비교 시험은 지급 대상·판단 불가 각각에 확정 금액·확정 0원·범위·가입금액 null·가입금액 누락을 적용하는 10개다. 엔진의 `exact`·`range`·`unknown` 태그와 범위 양 끝을 결과 비교에 보존하고, 설명에는 범위 또는 금액 미확정을 명시한다([Audit 4 증거](../../audits/2026-10-30_ontology_check_unknown_as_zero.md)). 다만 검사기 자체가 구현자 작성이고, 다른 계열의 검토를 받지 않았다.

### 10.3 이 검증이 증명하지 못하는 것

- **해석은 미검수다.** 사례 주장의 `accepted`는 "사례 검증용 가정 승인"이다. 다른 계열의 AI 검수(D-02)를 거치지 않았다.
- **코드 범위는 근사다.** 계산은 3자리 코드와 별표에 나온 세부 코드로 했다. KCD 전체 세부 코드를 대조하지 않았다.
- **원발부위 규칙은 판정하지 않았다.** C77~C80의 원발부위 기준과 전암 상태 제외는 입력 단계의 별도 판정으로 남겼다.
- **보험기간 끝은 가정이다.** 하나는 20년 만기를 가정했다. 현대는 가입 나이를 몰라 먼 날짜를 넣었다.
- **계약 효과는 표현하지 못했다.** 제5조의 무효·보험료 반환은 rule-0.1로 표현할 수 없다(G23).
- **구획 경계는 확인한 쪽만이다.** 특약·별표가 시작하고 끝나는 쪽을 확정하지 않았고, 구획과 판의 연결(realizes)도 사례 가정 승인이다. 약관 본문 판의 개정 표기·시행일은 본문에서 따로 확인하지 않았다.
- **범위가 작다.** 상품 세 개, 담보 세 개만 다뤘다. 실손·간병·여러 계약 관계는 다루지 않았다. 처리 성능도 재지 않았다.
