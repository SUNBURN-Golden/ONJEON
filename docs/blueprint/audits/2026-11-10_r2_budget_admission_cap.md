# Audit 5 — 월별 입장 마감과 원장 쓰기 상한

대상 노드: `audit5-r2-budget-admission-cap`.
제품 연결: P02·P03 / Q7 / L1 / M1의 원본 보관 비용 통제 기반.

기존 `Session.open()`은 정상 예약에 성공한 마지막 허용 입장에서 마감을
남기지 않았다. 다음 실행은 입장 기록을 하나 더 쓴 뒤 한도 초과로 거부됐다.
입장 LIST 직후 전체·작업 한도가 N에 도달했는지 확인하고 예약 전에 마감한다.
N번째 실행 자체는 계속 예약·정산할 수 있다. 전체 마감은 모든 작업을 막고,
작업 마감은 다른 작업의 남은 전체 입장 몫을 유지한다. 0회 한도는 요청 없이 거부한다.

마감 PUT 전에 로컬 마감을 저장한다. 원격 마감 쓰기가 실패하면 예약·보관소
접근 없이 중단하고 잠금을 해제하며, 같은 환경의 재입장을 막는다. 입장·마감
요청은 기존 계량기와 예산을 그대로 따른다. 정책·한도·정책 해시는 바꾸지 않았다.
여러 환경의 동시 입장을 원자적으로 제한하는 기능은 아니며, 마지막 입장 뒤
입장 LIST 실패나 원격 마감 실패와 새 환경 사용의 조합은 잔여 한계다.
기존 지정 환경 하나·동시 1개·수동 운영 범위를 유지한다(`infra/r2/BUDGET.md` §5·6).

원장 100건 결함은 이 작업의 시작 상태에 이미 `Ledger.append()` 쓰기 검사가
반영돼 있었다. 읽기 검사만으로 끝내지 않고 예약·정산 모두 쓰기 직전에
`count - base_seq >= max_ledger_records`를 검사한다. 기존 98/99/100건 HTTP 경계
시험을 재실행하고, 체크포인트 50 이후 정확히 100건을 쌓은 상태에서 일반·복구
세션의 예약·정산 쓰기가 모두 PUT 전에 거부되는 시험을 추가했다. 체크포인트로
요약한 과거 이력은 남으며 체크포인트 이후 상한은 계속 100이다.

검증:

- 정상 실행의 작업/전체/동시 한도 도달, N번째 정산 성공, N+1번째 입장 미생성,
  로컬 요청 0회·새 환경 마감 HEAD만 수행, 정산값과 서버 요청량 대조.
- 마지막 입장 뒤 원장 읽기 실패에도 마감이 먼저 존재함, 마감 PUT 실패의
  계량·잠금 해제·로컬 재입장 차단, 0회 한도, 다른 작업 및 다음 UTC 월 입장.
- 기존 거부 실행 마감·원장 상한·예약 전 체크포인트 복구 회귀.
- 메모리에서만 월 마감 `>=`를 `>`로 바꾸는 변이와 원장 append `>=`를 `>`로
  바꾸는 변이를 새 회귀 시험이 검출한다.

전체 Python 첫 실행은 비용 안내서 전체 해시를 고정한 O13 관문 회귀 1건에서
실패했다. 안내서의 실행 순서·월 마감·실패 한계 설명만 바뀌었음을 검토하고
`tools/tests/fixtures/o13_unchanged_gates.json`의 해당 문서 해시를 갱신했다.
다른 결정 관문·정책 파일의 해시는 유지하며 관문 시험 11건을 재검증했다.
