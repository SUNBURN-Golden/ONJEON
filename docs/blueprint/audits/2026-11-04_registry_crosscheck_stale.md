# Audit 4 — FSS 후속 교차검증 미수행 안내 정정

대상: `audit4-registry-crosscheck-stale`, `data/registry/README.md` 알려진 공백 1·10.
기록 대조일: 2026-11-04. 연결: Blueprint A1·Q7·L0·I17·V0/M3, 09 제품 목적 대응표 P01·P02.

## 판정과 변경

finding의 허용 해법 중 안내 정정을 적용했다. 기존의 “2026-10-11 이후” 재검증 지시는 이미 지난 시점의 계획이었고, 이후 실행 증거가 없었다. README에 후속 교차검증 미수행 상태와 기록 대조일을 명시했다. 공백 10의 “감독당국 목록이 복구되면” 문구도 공백 1의 증거 요건을 참조하도록 바꿨다.

현재 서비스 중단 여부는 조회하지 않았다. 2026-10-09의 중단 안내는 당시 관측으로만 설명한다. 기관 목록 대조와 상품·특약·판매본 분모 열거를 구분하고, 후자는 T-DT-04의 D-04·O19 실데이터 관문을 계속 따른다. 이 정정에는 새 외부 조회나 원문 보관 작업이 없다.

## 저장소에 있는 증거

- `data/registry/access_log.csv`: FSS·FISIS·파인 호스트의 접근은 2026-10-09에만 4건(307 이동 1건, 서비스 중단 안내 3건)이다.
- `data/registry/sources.csv`: 같은 호스트의 응답 해시 3건은 모두 서비스 중단 안내다. DART 업종 조회는 별도로 존재하지만 감독당국 허가 목록 대조를 증명하지 않는다.
- `data/registry/insurers.csv`: 보험사 53행의 `product_list_status`는 모두 `unqueried`다. 기존 CSV와 상태는 변경하지 않았다.

후속 교차검증에는 FISIS 보험회사 목록·파인 금융회사 조회의 시각·URL·응답 해시와 기관별 일치·누락·명칭 차이·미확인 사유가 필요하다. `two_or_more_sources`는 기존 협회 + KIDI/DART 근거를 뜻한다. 미수행 사유를 적거나 테스트가 통과한 것을 실제 확보·전수 대조로 계산하지 않는다.

## 회귀 검증과 완료 범위

`tools/tests/test_registry_crosscheck_note.py`의 4개 시험이 README의 상태·후속 증거 요건을 실제 CSV 관측과 대조한다. 현재 시험을 수정 전 README의 임시 복사본에 적용하면 과거 계획·누락된 상태 설명을 검출한다. 기존 레지스트리 시험도 함께 실행했다. 새 시험은 기존 CI의 `tools/tests` 전체 발견에 자동 포함된다.

명령·결과·로그는 [실행 증거](../../../tools/evidence/audit4-registry-crosscheck-stale/README.md)에 있다. 이 finding의 완료 범위는 오래된 안내의 정정과 그 회귀 검증이다. FSS 교차검증, 상품·문서 분모, 09 P01·P02 또는 첫 출시의 완료 증거는 아직 아니다.
