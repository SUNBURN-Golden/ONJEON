# 데이터 수집·분류·디지털 트윈 실행 계약

상태: 설계 보완안 | 2026-10-09 | 제2부 §23–37, 제3부 §57–61의 실행 기준

목표는 문서를 많이 모으는 데서 끝나지 않는다. 어떤 모집단에서 무엇을 놓쳤고, 어떤 근거로 어떤 조건을 실행하는지 재현할 수 있어야 한다. 아래는 구현 명세이며 실제 소스 접근성·수집률·정확도를 측정한 결과가 아니다.

## 1. 소스 등록과 분모

금융당국 데이터, 협회 비교공시, 보험사 공시실을 서로 보완하는 발견 경로로 다룬다. 어느 한 곳이 전체 약관·특약·판매 버전의 권위 있는 단일 목록이라고 가정하지 않는다.

`SourceRegistry`: source_id, 기관 ID, 채널, URL, 문서 종류, 검색·페이지 방식, 허용 수집 방식, 요청 제한, 어댑터 버전, 마지막 시도/성공, 다음 예정, 장애 사유.

`DiscoveryManifest`: 조사 회차, 회사×판매상태×채널×기간×문서종류, 요청 조건, 페이지 수, 결과 건수, 종료 증거, 발견 문서 ID, 미탐색·차단 구간. 목록이 0건이어도 성공한 빈 목록과 응답 오류를 구분한다. 이름 변경·합병 이력은 기관 별칭으로 보존한다.

`ExpectedDocument`: 상품 버전별 기대하는 약관·특약·사업방법서·요약서·별표, 기대 근거, 발견 상태, 확보 상태, 참조 미해결. 문서가 없다는 판단도 증거가 필요하다. 공제·우체국 후보는 별도 분모로 두고 범위 결정 전 일반 보험사 확보율에 섞지 않는다.

## 2. 스케줄과 실패 복구

- 모든 등록 소스의 일일 확인을 목표로 하되 마지막 시도와 성공을 분리한다. robots·인증·요청 제한을 우회하지 않는다. 차단은 실패 상태로 공개한다.
- ETag·Last-Modified는 재다운로드 최적화 단서다. 주기적 전체 바이트 검사로 잘못된 서버 메타데이터를 탐지한다. 동일 URL에 덮어쓴 문서도 해시로 새 발생본을 만든다.
- 큐 우선순위: 누락된 필수 근거와 진행 중 변경→신규·개정→일일 확인→과거 정합성. 별도 할당량을 두어 과거 상품이 영구적으로 밀리지 않게 한다.
- 호스트별 동시성·속도·백오프·재시도 상한을 설정하고 상한 이후 격리 큐로 보낸다. 무한 재시도 금지. 구조 변화·HTML 오류 페이지를 PDF 성공으로 저장하지 않는다.
- 다운로드는 임시 객체→길이·MIME·파싱·해시 검증→불변 원문 저장 순서다. 중복 작업은 `(source_id, content_hash, parser_version)`으로 멱등 처리하되 발견 URL·관측 이력은 각각 남긴다.
- 운영 지표는 발견→원문 확보, 확보→검증, 검증→공개를 별도로 p50/p95와 실패 수로 측정한다. 공급자 게시 시각을 모르면 변경 감지 지연을 확정값으로 보고하지 않는다. 수치 목표는 파일럿 결과로 정한다.

## 3. 문서 복원과 조항 단위

원본 바이트·수집 시각·요청 경로·해시를 보존한다. 텍스트 PDF는 위치 포함 추출, 스캔은 페이지 OCR, 혼합 문서는 페이지별 전략을 사용한다. 표의 행/열/병합 셀, 제목 계층, 각주, 반복 머리말, 별표 번호를 분리한다.

문장만 잘라 임베딩하지 않는다. `ClauseOccurrence`는 문서 버전·조항 경로·페이지·좌표·정확 인용·상위 제목·표 셀·각주·정의 참조를 가진다. OCR 숫자·부정어·경계어·단위 불확실성은 해당 필드를 hold로 전파한다. 페이지 수 불일치·별표 누락·끊긴 표·참조 미해결은 자동 승인 차단 사유다.

## 4. 라벨 사전과 필드 계약

| 축 | 주요 필드 | 주의점 |
|---|---|---|
| 식별 | insurer_id, product_id, product_version, rider_occurrence_id, channel | 이름 유사도로 버전 병합 금지 |
| 기간 | 판매 기간, 계약 적용일, 보장 개시, 개정 효력일 | 수집일·게시일과 분리, 모르면 null+사유 |
| 지급 사건 | 진단·수술·입원·장해·사망·간병, 정의 참조 | 질환명보다 약관 정의 우선 |
| 지급 방식 | 정액/실손, 금액 기준, 비율, 횟수·누적 한도 | 지급 방식이 다른 금액 무조건 합산 금지 |
| 제약 | 면책, 감액, 제외, 기산점, 포함 경계 | 부정어·이상/초과·날짜 단위 보존 |
| 관계 | 주계약 종속, 특약 배타, 동시가입, 공유 한도 | 그래프 간선에도 증거 |
| 생애주기 | 갱신, 종료, 소멸, 환급 구조 | 가격 표와 지급 규칙 혼합 금지 |
| 기능 자격 | search, explain, compare_conditions, compare_price, simulate | 각 기능은 독립. 담보 전체와 필드별 준비 상태 구분 |

모든 추출 필드는 `raw_value`, `normalized_value`, `unit`, `evidence_refs`, `scope`, `effective_from/to`, `observed_at`, `extractor_version`, `value_state`, `review_status`, `unknown_reason`을 가진다. null은 0·해당 없음·미기재·해석 실패와 다르다. 라벨 사전에는 정의·포함/제외 기준·양성/음성 예·상충 규칙·버전·변경 이력을 둔다. 질병 분류 코드 개정판을 명시하고 서로 다른 개정판은 검증된 매핑이 없으면 합치지 않는다.

## 5. AI와 코드의 역할

AI는 후보 필드·근거 위치·참조 관계·쉬운 설명을 제안한다. 코드는 스키마·타입·단위·인용 일치·참조 해결·날짜 경계·금액 보존·필수 필드·이용 등급을 검사한다. 작성 AI와 다른 계열 검증 AI가 페이지·표를 다시 보고 반례를 찾는다. 다수결·자기보고 확신 점수로 승인하지 않는다.

원문에 지시문이 있어도 데이터로만 처리한다. 추출 워커에는 개인 프로필·저장소 쓰기·외부 전송 권한을 주지 않는다. 자유 문장 요약은 계산 입력이 될 수 없다.

평가셋은 합성 정답, 공개 계산 예시, 경계값 변이, 시간 홀드아웃, 실제 문서 재추출 감사로 구분한다. 같은 상품 계열을 학습/평가에 나누어 넣어 누출시키지 않는다. 재추출 일치는 실제 정답의 증명이 아니며 3/n 오류율 상한으로 바꾸지 않는다. 각 평가가 측정하지 못하는 오류를 함께 기록한다.

## 6. 하나의 근거, 두 표현

검증된 필드와 참조 그래프에서 기계용 DSL과 사람용 문장 템플릿을 함께 만든다. 두 표현은 동일 `rule_version`·`evidence_refs`를 참조한다. 설명에 등장한 숫자·기간·예외가 구조화 필드와 다르면 릴리스를 막는다. 사람이 읽기 쉬운 설명에서도 결과를 뒤집는 제외·감액을 생략하지 않는다.

트윈은 실제 보험사의 인수 심사나 지급 결정을 복제했다는 뜻이 아니다. 확인된 약관 규칙과 계약 조건을 입력 가정 아래 실행하는 모델이다. 원문에 없는 인수 조건·실견적·의학적 발병 확률을 생성하지 않는다.

## 7. 변경 전파와 릴리스

`discovered → archived → parsed → labeled → validated → compiled → candidate → released`를 기록한다. 어느 단계든 `hold` 또는 `failed`로 격리할 수 있고 공개본은 불변이다.

1. 원문 차이를 바이트와 구조 단위로 확인한다. 레이아웃 변경과 의미 변경은 재추출·검증 후 구분한다.
2. 변경 조항의 정의·별표·각주·참조를 양방향으로 추적해 영향 폐쇄 집합을 만든다. 상품 특약이 공통 정의를 덮어쓰는 경우도 포함한다.
3. 범위가 확실하지 않으면 문서 전체·상품 버전 전체로 확대한다. 삭제된 조항·새 참조도 포함한다.
4. 후보 DSL과 이전 버전을 같은 입력으로 그림자 평가한다. 결과 차이마다 변경 근거를 연결한다. 원인 없는 차이는 배포 차단이다.
5. 릴리스 manifest에 원문 해시·스키마·사전·모델·프롬프트·추출기·엔진·규칙 버전을 고정한다. 의존 규칙을 원자적으로 교체하고 캐시 키에도 release_id를 넣는다.
6. 롤백은 이전 manifest로 수행하되 기존 문제가 있는 결과를 다시 유효하게 만들지 않는다. 심각한 원문 변경은 구버전 계산도 hold하고 영향 범위를 안내한다.

## 8. 구현 승인용 체크 사례

| 사례 | 통과 조건 |
|---|---|
| 목록 200 응답이 로그인 HTML | 확보 성공으로 세지 않음 |
| 같은 URL의 개정 PDF | 구원본 유지, 새 버전·영향 추적 |
| 본문 그대로, 별표 질환만 삭제 | 영향 담보 전부 재검증 |
| 공통 약관 + 상품별 예외 특약 | 상품별 실행 결과가 다름 |
| OCR 90일→900일 | 인용·이미지 대조 실패로 hold |
| 예외 누락, AI 전원 동일 답 | 알려진 변이 테스트 실패로 차단; 실제 공통 오류 잔존 인정 |
| 신규 상품 목록은 있으나 약관 없음 | 분모 포함, 원문 확보 미달 공개 |
| 가족력·DNA가 로그에 유입 | 경계 테스트 실패로 배포 차단 |

출시 게이트는 원문 추적성·필수 참조 해결·C0 승인·재현성·경계값 검사·미확인 표시·민감정보 경계·롤백을 각각 통과해야 한다. AI 점수 하나나 평균 확보율 하나로 대신하지 않는다. 전 상품을 조사 대상으로 삼는 것과 모든 담보를 계산 가능하다고 보증하는 것은 별개다.
