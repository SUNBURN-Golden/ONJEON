- 주 시각 기준은 `assets/selected-my-plan.png`(711×1536)다. 수치는 같은 구성의 원본 `assets/approved-warm-direction.png`(853×1843)에서 측정했고 390×844 dp로 환산했다(계수 0.457). 두 이미지의 비율은 같다.
- 시안과 다른 부분은 §2에 모두 적는다. 거기에 없는 변경은 허용하지 않는다.
- 시안의 금액·문구는 가상 예시다. 실제 데이터에서는 가격 근거와 기준일이 붙는다(§5).
- 측정 오차는 위치 ±2dp, 색 ±6 정도다. P0에서 디자인 도구로 원본과 대조해 토큰을 확정한다.
- 접근성은 목표가 아니다(제3부 §51.4). 시각 완성도와 조작감이 우선이다.

## 1. 기준 화면 구성 (고정)

위에서 아래로 다음 순서다.

1. 상단 바: 좌측 "온전" 로고 글자, 우측 잠금 아이콘
2. 헤드라인 "나에게 필요한 만큼"과 보조문
3. 월 예산 라벨, 큰 숫자("15만 원"), 슬라이더(5만 원~30만 원), 고지 캡션 한 줄
4. 구분선
5. 세그먼트 탭 `현재 유지 | 보완안`
6. 담보 목록: 진단 보장, 입원·수술, 생활비 대비, 무엇이 달라지나요?
7. 주요 행동 버튼 "두 안 비교하기"
8. 잠금 캡션
9. 하단 탭바: 홈, 만약에, 내 설계(선택), 내 정보

시안은 상태바 영역이 없는 콘텐츠 기준이다. 실제 기기에서는 안전 영역을 별도로 더한다. 15만 원과 5만~30만 원은 시각 예시이며 기본값이 아니다.

### 3.4 시안의 오차

시안의 슬라이더 썸 위치는 트랙의 약 44% 지점이다. 5~30만 범위에서 15만은 40%다. 구현은 값에 대해 선형으로 위치를 계산한다. 시안의 썸 위치는 따르지 않는다.

## 4. 조작 설계

### 4.1 월 예산 슬라이더

월 예산은 사용자의 지출 상한이다. 상품 가격이나 목표 보장금액이 아니며, 슬라이더가 보장금액을 임의로 바꾸지 않는다.

| 항목 | 규칙 |
|---|---|
| 범위 | 시안 값 5만~30만 원을 기본으로 한다. 직접 입력이 범위를 넘으면 5만 원 단위로 넓힌다. 상한은 100만 원. 상한 근처를 강조하거나 상한까지 쓰도록 유도하지 않는다 |
| 단계 | 1만 원. 값은 정수 "N만 원"으로만 표시한다 |
| 초기값 | 사용자가 입력한 월 예산. 입력이 없으면 큰 숫자 자리에 "월 예산 정하기"를 보이고 값을 강제하지 않는다. 현재 납입액이 확인되면 "현재 12만 원을 예산으로 가져올까요?"를 선택지로 묻는다. 자동으로 가져오지 않는다 |
| 드래그 | 1만 원 단계로 붙고 큰 숫자는 단계마다 갱신한다 |
| 촉각 | 1만 원마다 약한 틱, 5만 원 배수에서 강한 틱 |
| 현재 납입액 눈금(C2) | 썸이 눈금 ±0.5만 원 안에 들어오면 붙고 틱 한 번. 눈금 왼쪽은 "줄이기", 오른쪽은 "늘리기" 의미를 가진다 |
| 큰 숫자 탭 | 숫자 입력 시트(키패드)를 연다. 확인하면 슬라이더가 따라간다 |
| 손가락 놓기 | 확정 계산을 요청한다. 결과가 오는 동안 이전 결과를 유지한다 |

슬라이더가 하는 일은 상태에 따라 다르다(CONSUMER_FLOW_SPEC §3).

| 상태 | 슬라이더를 움직이면 | 화면에서 말하지 않는 것 |
|---|---|---|
| 같은 비교 기준의 공개 가격이 있음 | 해당 조건으로 가격이 확인된 후보를 예산별로 필터링. 제외 후보의 사유 갱신 | 내 확정 보험료, 인수 가능, 전 시장 최저가 |
| 유효한 개인 견적이 있음(후속) | 견적 유효기간·구성을 고정해 비교 | 가입 확정, 갱신 보험료 |
| 공개 가격이 없거나 조건이 다름 | 예산만 저장하고 조건 비교를 계속. 가격 미확인 후보를 별도 노출 | 가격 추측, 미확인 후보를 예산 초과로 숨기기 |

### 4.2 결과 갱신

- 드래그 중에는 서버가 미리 계산한 구간 결과(릴리스·프로필·1만 원 단위 격자)를 쓴다. 계산 구현은 서버의 규칙 엔진 하나뿐이다(ADR-0003).
- 최신 입력 해시의 결과만 화면에 적용한다. 늦게 도착한 과거 응답은 버린다.
- 드래그 중에는 목록을 재정렬하지 않는다. 행이 손가락 아래서 갑자기 움직이지 않게 하며, 손을 뗀 뒤 250ms 동안 재정렬한다.
- 조작 피드백 목표는 150~250ms다. 숫자 카운트업 220ms(ease-out), 상태 라벨 교차 페이드 150ms를 쓴다. 계산 시간은 별도로 측정한다.
- 응답이 300ms를 넘으면 가격 줄에 "다시 비교 중"을 보이고 이전 가격을 유지한다.
- 응답이 실패하면 마지막 결과를 유지하고 캡션에 "마지막으로 확인한 결과예요"를 보인다.

### 4.3 세그먼트 탭 `현재 유지 | 보완안`

| | 현재 유지 | 보완안 |
|---|---|---|
| 의미 | 등록 계약을 바꾸지 않은 기준안. 최적이라는 판정이 아니다 | 사용자가 담보를 추가·제외·변경해 보는 초안. 자동 가입 추천도 해지 실행도 아니다 |
| 선택 | 기본 선택 | 초안이 있으면 보완안으로 열린다 |
| 슬라이더 | 예산(지출 상한)과 현재 납입액의 관계만 보여준다 | 예산 안에서 같은 비교 기준의 가격이 확인된 후보를 필터링한다 |
| 행 상태 | 유지 / 조건 확인 | 유지 / 추가 검토 / 조건 확인 |
| 가격 | 내 계약 납입액이 있으면 표시 | 가격 보조줄(C3) |

- 두 탭은 같은 크기이고 위계가 같다. 전환은 알약이 200ms로 미끄러진다.
- 가입내역이 없으면 현재 유지 탭은 "현재 계약을 아직 확인하지 않았어요"와 선택 업로드를 보인다. 보장을 0으로 간주하지 않으며 관심 담보 비교는 계속된다.
- 예산 안에서 확인된 후보가 없으면 "예산 안에서 가격이 확인된 후보가 없어요 · 가격 미확인 n개 보기"를 보인다. 유지가 적절하다는 판정을 만들지 않는다.
- 같은 사용자가 예산을 올려도 반드시 더 가입하는 결과가 되지 않는다. 보완안에는 "추가 없음" 상태가 정상이다.

### 4.4 담보 목록

- 행 구조: 아이콘 원 + 제목/부제 + 상태 라벨(+ 가격 보조줄) + 쉐브론.
- 부제는 한 줄이며 "보장 요약 · 가장 중요한 제한"이다. 시안의 "암, 뇌, 심장 등 주요 질병" 형식을 따르고, 해당 버전 원문이 있을 때만 제한을 붙인다. 예시(합성 픽스처): "암 진단금 · 첫 1년 50%". 주요 제외를 원문 링크 뒤로 숨기지 않는다.
- 행은 담보 그룹이다. 진단 보장, 입원·수술, 생활비 대비가 기본이며 그 밖의 그룹은 사용자의 관심 담보 순으로 정렬한다. 근거 없는 충족률이나 공백 크기로 정렬하지 않는다.
- 마지막 행은 항상 "무엇이 달라지나요?"이며 상태 라벨 대신 쉐브론만 있다.
- 행 탭은 담보 상세 시트(§4.5)를 연다. 눌림 연출은 배경이 80ms 동안 약간 어두워진다.
- 상태 라벨은 사용자 초안 상태 `plan_action`이다(§6).

### 4.5 담보 상세 시트

행을 탭하면 아래에서 올라오는 시트(화면 높이 85%, 끌어서 닫기)가 열린다. 순서는 CONSUMER_FLOW_SPEC §5의 담보 상세와 같다.

1. 머리: 담보 그룹명과 데이터 상태 칩(§6)
2. 무엇을 보장하나 → 언제 못 받나 → 한도·갱신
3. 지금 | 보완안 두 열 비교(받을 수 있는 조건과, 가격이 확인된 경우 가격)
4. 추가되는 것 / 줄어드는 것 / 그대로인 것 / 비용과 미확인(§7)
5. 같은 담보 비교: 상품 목록(§8)
6. 하단: 원문 보기(해당 조항 페이지 이미지와 하이라이트)

### 4.6 "무엇이 달라지나요?" 행

탭하면 전체 차이 화면(§7.3)이 전체 시트로 열린다. 이름 그대로 추가되는 것과 제외·불이익을 함께 보여준다.

### 4.7 "두 안 비교하기" 버튼

탭하면 비교 화면(§7.4)으로 이동한다. 비교 가능한 필드는 비교하고 부족한 가격은 별도로 표시한다. 가입내역이 없어도 관심 담보 기준의 비교는 가능하다.

### 4.8 하단 탭 이동

탭을 오가도 슬라이더 값, 선택한 탭, 보완안 초안은 유지한다. 앱을 다시 열면 마지막 값을 쓰되 데이터 릴리스가 바뀌었으면 캡션에 "데이터가 갱신됐어요"를 한 번 보인다.

## 5. 가격 표시 규칙

가격 근거 코드는 PREMIUM_DATA_CONTRACT와 제3부 §47.1을 따른다. 이 코드들은 신뢰 순위가 아니라 서로 다른 근거다.

### 5.1 가격 근거와 라벨

| 근거 | 화면 라벨 | 칩 모양 | 쓰임 |
|---|---|---|---|
| `illustrative` | "공시 예시 · 40세 남 · 기준일 10-01" | 채움 칩 | 같은 비교 기준끼리 비교 |
| `table_derived` | "요율표 재현 · 조건" | 채움 칩 + 표 아이콘 | 검증된 범위만. 개인 인수 견적이 아님 |
| `contract_observed` | "내 계약 납입액 · 납입 시점" | 채움 칩 + 문서 아이콘 | 현재 유지 기준선 |
| `quoted` | "내 견적 · 만료 10-12" | 채움 칩 + 사람 아이콘 | 후속(스켈레톤). 첫 출시에서는 표시하지 않음 |
| 가격 미확인 | "가격 미확인 · 사유" | 점선 칩 | 목록에 남기고 별도 노출 |

- 공개 가격과 개인 견적·내 계약 납입액은 서로 다른 칩 모양과 아이콘이다. 색만으로 구분하지 않는다.
- 공개 가격은 개인 견적이 아니다. 캡션(C1)과 비교 화면에 "견적 아님"을 상시 표시한다.
- 가격에는 항상 조건·구성·가격 근거·기준일이 붙는다. 탭하면 조건 시트가 열린다.
- 기준일과 확인일은 구분한다. 기준일은 소스가 밝힌 적용일이고 확인일은 우리가 마지막으로 확인한 날이다.

### 5.2 비교 기준

- 예산 필터와 가격 정렬은 하나의 **비교 기준**(연령·성별·가입금액·기간·특약 구성 등 공시 조건 집합) 안에서만 한다. 캡션이 그 기준을 말한다.
- 비교 기준이 내 실제 조건과 다르면 조건 시트에 "내 조건 아님"을 표시한다. 예시 보험료를 사용자 나이에 선형 보간하거나 가입금액에 비례시키지 않는다. 구간 추정 값을 만들지 않는다.
- 월납과 연납을 환산해 월납처럼 보이지 않는다. 연납÷12는 "월평균(연납÷12)"으로 따로 표시한다.
- 다른 조건·버전·묶음의 가격을 합산하지 않는다. 가입 가능한 묶음·주계약·특약 종속·최저 가입금액을 검증하지 못하면 조합 총액은 미확인이다.
- 원래 계약과 후보의 가격 기준이 다르면 절감액을 계산하지 않는다.
- 갱신형의 첫해 가격을 평생 고정 비용으로 표시하지 않는다.
- 개인별 편차가 큰 상품군(예: 자동차)은 "개인별로 크게 달라요" 표시를 단다.

### 5.3 가격 미확인

- 가격 미확인 상품은 목록에서 빠지지 않는다. 같은 목록 안에서 점선 칩으로 표시한다.
- 사유는 짧은 문구로 나눈다: 찾지 못함, 공개되지 않음, 읽지 못함, 근거 충돌, 검토 중, 조건이 달라 적용 불가, 오래됨.
- 가격 정렬에서는 확인된 가격 뒤에 두되 목록 위에 "가격 미확인 n개"를 고정 표시한다. 미확인 상품을 "비싸서 제외된 상품"으로 오인하게 하지 않는다.
- 합계에서 제외하고 건수를 표시한다. 0원으로 합산하지 않는다.

### 5.4 예산과 후보 분류

| 분류 | 조건 | 표시 |
|---|---|---|
| 예산 안 | 같은 비교 기준의 확인된 가격이 예산 이하 | 일반 목록 |
| 예산 초과 | 확인된 가격이 예산 초과 | 별도 접힘 목록, 사유 "예산 초과" |
| 가격 미확인 | 가격을 확인하지 못함 | 별도 노출, 예산 초과로 취급하지 않음 |

## 6. 상태 어휘

행에 보이는 상태와 데이터 검증 상태는 서로 다른 축이다. 섞지 않는다(제3부 §44.3).

### 6.1 행 라벨: `plan_action`과 `row_label` (시안의 세 라벨)

저장하는 것은 사용자의 초안 행동 `plan_action`이다. 행에 보이는 라벨 `row_label`은 서버가 파생한다. 정본은 `docs/blueprint/VOCABULARY.md`다.

| 저장값 | 화면 문구 | 뜻 | 글자색 | 아이콘 |
|---|---|---|---|---|
| `plan_action=keep` | 유지 | 이번 초안에서 변경하지 않음 | `status-keep` | 체크 |
| `plan_action=add` | 추가 검토 | 사용자가 고른 추가 후보 | `status-add` | 더하기 |
| `plan_action=remove` | 제외 검토 | 사용자가 고른 제외 후보 | `status-add` | 빼기 |
| `plan_action=modify` | 변경 검토 | 사용자가 고른 금액·구성 변경 후보 | `status-add` | 화살표 |
| `row_label=needs_condition` | 조건 확인 | 이 행에 미해결 항목(`input_missing`, `data_missing`, `hold`)이 있음. 저장하지 않고 파생 | `status-add` | 물음표 |

- 기본은 `keep`이다. 미해결 항목이 있으면 `needs_condition`이 plan_action 문구보다 우선해 보인다.
- AI가 가족력이나 공백 추정으로 plan_action을 정하지 않는다. 사용자가 고른 것만 저장한다.
- 시안의 세 라벨(유지, 추가 검토, 조건 확인)은 글자 크기와 위치를 그대로 쓴다. 상태는 색 외에 글자와 아이콘으로도 전달한다.

### 6.2 화면 데이터 상태 `display_status`

`confirmed` 조건 확인됨, `input_missing` 입력 필요, `data_missing` 자료 필요, `under_review` 확인 중, `hold` 판단 보류, `not_applicable` 해당 없음. 서버가 `value_state`·`review_status`·사용자 입력에서 파생하며 담보 상세 시트의 머리 칩과 필드 단위 표시에 쓴다. 담보 전체가 확인된 것처럼 확대하지 않는다. "조건 비교 가능"·"가정 계산 가능"은 상태가 아니라 기능 자격(`capability`)이다.

### 6.3 가격 상태

가격 미확인과 그 사유(§5.3). 행의 두 번째 줄 칩(C6)으로 표시한다.

## 7. 보장과 불이익의 동시 비교

보완안은 얻는 것만 보여주면 안 된다. 사라지는 보장, 새로 시작하는 면책, 감액, 제외도 같은 비중으로 보여준다.

### 7.1 차이 항목 모델

화면은 네 묶음으로 보여준다: 추가되는 것 / 줄어드는 것 / 그대로인 것 / 비용과 미확인.

| 유형 | 묶음 | 예 |
|---|---|---|
| `gain_coverage` | 추가되는 것 | 새로 생기는 보장 |
| `gain_amount` | 추가되는 것 | 금액 증가 |
| `lose_coverage` | 줄어드는 것 | 사라지는 보장(교체로 기존 특약이 없어짐) |
| `lose_amount` | 줄어드는 것 | 금액 감소 |
| `new_waiting` | 줄어드는 것 | 면책기간이 새로 시작 또는 재시작 |
| `new_reduction` | 줄어드는 것 | 감액기간·감액률 적용 |
| `new_exclusion` | 줄어드는 것 | 새로 붙는 제외 조건 |
| `term_change` | 줄어드는 것 | 보장 종료 시점이 앞당겨짐 |
| `limit_change` | 줄어드는 것 | 한도·횟수 변화 |
| `surrender_loss` | 줄어드는 것 | 기존 계약 해지 시 환급금 손실 |
| `unchanged` | 그대로인 것 | 변하지 않는 보장과 조건 |
| `renewal_change` | 비용과 미확인 | 갱신형 전환, 갱신 시 보험료 변동 가능 |
| `price_basis_diff` | 비용과 미확인 | 두 안의 가격 기준이 달라 절감액을 계산할 수 없음 |
| `underwriting_unknown` | 비용과 미확인 | 인수 심사에 따라 달라질 수 있음 |
| `unknown` | 비용과 미확인 | 원문·가격을 확인하지 못함 |

모든 차이 항목은 근거(릴리스, 조항, 페이지)와 이용 등급을 가진다. 근거가 없는 항목은 만들지 않는다.

### 7.2 표시 규칙

1. 네 묶음은 같은 글자 크기와 같은 시각 비중으로 둔다. 줄어드는 것이 추가되는 것보다 작게 보이면 안 된다.
2. 추가 가입에도 불이익이 붙는다. 새 담보의 면책·감액·제외는 `new_waiting`, `new_reduction`, `new_exclusion`으로 반드시 보여준다. 새 담보의 이득만 보이고 새 불이익이 안 보이는 상태를 허용하지 않는다.
3. 지급에 영향을 주는 항목은 개수와 상관없이 첫 층에 보인다(불변 원칙 9). 항목이 많으면 영향이 큰 순으로 정렬하고 나머지는 "더 보기"로 접되 접힌 개수를 표시한다.
4. 줄어드는 것이 0건이어도 "불이익 없음"이라고 쓰지 않는다. "확인된 불이익 없음 · 미확인 n건 제외"로 쓴다.
5. 보완안 유형을 표시한다: 추가형(기존 유지 + 신규), 교체형(기존 해지 + 신규), 축소형(일부 해지). 교체형에는 보장 공백, 면책 재시작, 인수 불확실, 해지 손실을 반영한다(v0.3 §11). 보완안은 해지·가입 실행이 아니다.
6. 비용 변화는 같은 비교 기준의 확인된 가격이 있을 때만 한 줄로 쓴다. 기준이 다르면 `price_basis_diff`로 두고 절감액을 만들지 않는다.

### 7.3 전체 차이 화면 ("무엇이 달라지나요?")

```text
무엇이 달라지나요?                          [보완안: 추가형]
비용  +월 2.1만 (후보 A, 공시 조건 40세 남, 10-01)    미확인 1건 제외

추가되는 것            줄어드는 것                그대로인 것        비용과 미확인
+ 암 진단비 3,000만     ! 면책 90일 새로 시작       = 입원 일당        ? 인수 심사 결과
+ 입원 일당 5만          ! 감액 1년(50%)           = 수술비          ? 갱신 시 보험료 변동
                      ! 제외: 일부 소액암           (가상 예시)       ? 가격 미확인 1건
```

좁은 화면에서는 네 묶음이 세로로 쌓인다. 순서는 추가되는 것, 줄어드는 것, 그대로인 것, 비용과 미확인이다. 항목을 탭하면 원문 근거 시트가 열린다.

### 7.4 두 안 비교 화면 ("두 안 비교하기")

| | 현재 유지 | 보완안 |
|---|---|---|
| 비용 | 내 계약 납입액(있을 때) | 같은 비교 기준의 확인된 가격(있을 때) |
| 받을 수 있는 조건 | 담보별 한 줄 | 담보별 한 줄(차이 강조) |
| 추가되는 것 | - | 목록 |
| 줄어드는 것 | - | 목록 |
| 그대로인 것 | 목록 | 목록 |
| 비용과 미확인 | 목록 | 목록 |

- 상단에 두 안의 가장 큰 얻는 것 하나와 가장 큰 줄어드는 것 하나를 큰 글자로 요약한다. 30초 안에 말할 수 있어야 한다(v0.3 §17).
- 하단 행동은 "초안 저장"과 "원안으로 돌아가기"다(CONSUMER_FLOW_SPEC §5). 저장하면 그 시점의 릴리스, 가격 기준일, 가정이 함께 저장된다(결과 재현).

## 8. 담보 비교와 상품 행

담보 상세 시트와 비교 화면의 상품 행은 보장, 가격, 불이익을 한 줄에서 함께 보여준다.

```text
[보험사]  상품명 · 구성(주계약 + 특약 2)       ← 한눈에 구분되는 첫 줄
보장 3,000만 · 진단 후 지급                    ← 보장 요약
월 3.2만  [공시 예시 · 40세 남 · 10-01]       ← 가격 + 근거 + 기준일
! 면책 90일  ! 감액 1년  ! 갱신형               ← 불이익 칩(영향 큰 순)
```

- 가격 미확인 상품도 같은 형식으로 나오며 가격 줄이 점선 칩 "가격 미확인 · 사유"다.
- 같은 담보명이어도 질병 정의가 다르면 "정의 차이" 칩을 단다(§59.6).
- 정렬 기본은 사용자의 관심 담보 순서다. 가격 정렬은 같은 비교 기준의 확인된 가격만 대상으로 하며 미확인은 뒤에 두되 "가격 미확인 n개" 구간 머리글이 고정된다. 가격만 같다고 동등한 상품으로 취급하지 않는다.
- 광고비·수수료는 정렬에 영향을 주지 않는다(불변 원칙 1). 이 화면에 광고 영역은 없다.

## 9. 화면 상태 카탈로그 (시안이 필요한 것)

내 설계 탭의 기준 화면 1장(데이터 있음)에 아래 상태를 모두 시안으로 만든다.

| 상태 | 시안이 달라지는 부분 |

| 기준(데이터 있음, 보완안 선택) | 시안과 같음 + C1~C4 |
| 현재 유지 선택 | 담보 상태, 가격 보조줄 없음 |
| 가입내역 없음 | 슬라이더 눈금 없음, 현재 유지 탭이 업로드 안내 |

## 11. 뷰모델 (화면 ← API)

화면은 이 구조만 받아 그린다. 계산은 모두 서버에서 한다. 참조 키는 CONSUMER_FLOW_SPEC §6과 같다.

```json
{
  "view": "my_design",
  "plan_id": "...", "input_hash": "...", "release_id": "r123",
  "data_as_of": "2026-10-01",
  "budget": {"value_man": 15, "set_by_user": true, "min_man": 5, "max_man": 30, "step_man": 1,
             "current_paid": {"man": 12, "basis": "contract_observed", "as_of": "..."}},
  "tab": "current",
  "comparison_basis_id": "cb_40m_standard",
  "price_caption": {"text": "공시 조건으로 비교 중", "conditions_ref": "cb_40m_standard"},
  "groups": [
    {"id": "diagnosis", "title": "진단 보장", "subtitle": "암, 뇌, 심장 등 주요 질병",
     "plan_action": "add", "row_label": "from_plan_action",
     "price_line": {"basis": "illustrative", "man": [2.1, 3.0], "candidates": 3,
                    "as_of": "2026-10-01", "unpriced": 0},
     "coverage_occurrence_ids": ["..."], "premium_observation_ids": ["..."],
     "unresolved_items": []}
  ],
  "data_missing_count": 3,
  "unpriced_count": 1,
  "diff_available": true,
  "synthetic": false
}
```

- `plan_action`, 가격 `basis`, 데이터 상태는 `packages/schemas`의 enum이다. 문자열 상수를 화면에 흩어 두지 않는다.
- 가격 줄이 후보 범위(`man`의 두 값)를 가질 때 두 값은 서로 다른 후보 상품의 확인된 가격이다. 한 상품의 보간 값이 아니다.
- 가격이 없으면 `price_line.state`가 미확인 사유다.

## 12. 수락 기준

1. 기준 화면 일치: 390×844 기준 상태 "기준(데이터 있음)"을 시안 이미지와 겹쳐 비교한다. 요소 위치 오차 ±2dp 이내, 색 오차 ΔE 3 이내(C1~C7은 별도 승인 영역).
2. 조작: 슬라이더 1만 원 단계, 눈금 붙음, 틱, 큰 숫자 탭 입력, 탭 전환 애니메이션이 사양대로 동작한다. 과거 응답이 최신 입력의 결과를 덮지 않는다. 드래그 중 행이 이동하지 않는다.
3. 가격: 공시 예시·내 계약 납입액이 칩 모양으로 구분된다. 가격 미확인 상품이 목록에서 빠지지 않고 "비싸서 제외"로 오인되지 않는다. 미확인이 0원으로 합산되지 않는다. 서로 다른 조건의 가격이 합산되지 않는다.
4. 불이익: 신규 가입 담보에 면책·감액·제외가 보인다. 교체형에서 사라지는 보장과 해지 손실이 보인다. "불이익 없음"이 단독으로 나타나지 않는다.
5. 예산을 올려도 반드시 더 가입하는 결과가 되지 않는다.
6. 이해 시험: 가상 계약으로 8~12명이 5초 안에 예산과 보험료를 구별하고, 30초 안에 두 안의 줄어드는 것과 추가되는 것을 각각 하나씩 설명한다. 공개 조건과 개인 조건의 차이를 스스로 찾는다. 잘못 이해한 비율을 기록한다.
7. 성능: 드래그 중 결과 갱신의 체감 지연을 P1에서 측정해 목표를 정한다.

## 13. 열린 항목

- 서체 확정과 정확한 글자 크기(P0 디자인 도구 대조).
- C2~C4, C7 승인. 보조문 문구(시안 "예산을 움직여 보장을 비교하세요." 대 명세 "예산 안에서 보장과 조건을 비교하세요.").
- 상태 색 `status-add`의 최종값. 시안의 밝은 주황빨강과 UX_UI_REFERENCE의 `accent` 시작값 #C67557의 관계.
- 기본 선택 탭: 시안은 보완안이 선택된 모습이고 명세는 현재 유지를 기본으로 한다. 이 설계서는 명세를 따른다.
- 홈·만약에·내 정보 탭 시안은 같은 시각 토큰으로 후속 제작한다.
