## 4. 검증하지 않은 것

- R03~R05는 명세 수정이다. spec_check의 기계 검사로 명세끼리 서로 맞는지(작업 의존, 전이 목적지, 임대 가드, 봉투 필드, 정본 예외 문구)만 확인했다. 다음 것은 코드가 없어 실행해 보지 못했다: 모의 코어(T-OP-00), 실제 실행기(T-OP-09), 통합 시험(T-CT-07), 봉투 검증기. "이전 임대의 늦은 결과가 상태를 바꾸지 않는다"와 "이전 CLI의 쓰기가 차단된다"는 실행으로 증명되지 않았다.
- R06②③(조항 ID 형식, 이유 종류별 근거)은 계약 문서와 작업 명세만 바꿨다. 서비스 구현은 없다.
- 온톨로지 시험은 사례 세 상품 범위의 Python 검증기다. 약관 해석은 검수하지 않았다(사례 가정 승인).
- 지금의 입력 단계(case-0.2)로 r25를 계산하면 담보 연결 주장이 없어 보류된다. 과거 재현에는 당시 입력 단계 판이 필요하다. 릴리스에는 판 이름만 적었고, 이전 입력 단계 코드는 따로 보존하지 않았다.
- 판단 기준 관리, 부분 보류, 이유 근거가 제품 의미로 적절한지는 사람이 검토해야 한다.
- 설계 담당과 구현자는 둘 다 claude 계열이다. 검사기도 구현자가 썼으므로 검토 대상이다.
