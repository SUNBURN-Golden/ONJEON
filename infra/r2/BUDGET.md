# R2 비용 제한

결정: ADR-0017(사용자 요청, 2026-10-09). 구현: `tools/r2_budget.py`, 정책 `budget_policy.json`, 작업 `jobs/*.json`. 시험: `tools/tests/test_r2_budget.py`.

## 1. 무엇이 막고 무엇이 막지 못하나

| 장치 | 성격 | 막는가 |
|---|---|---|
| 이 저장소의 도구(`source_archive.py`, `verify_sources.py`, `r2_budget.py`)의 한도 | 요청을 보내기 **전에** 검사하고 넘으면 중단 | 이 도구로 하는 모든 R2 요청을 막는다 |
| Cloudflare 예산 알림(Budget alert) | 예상 월 지출이 기준을 넘으면 이메일 | **막지 않는다.** 알림일 뿐 과금을 차단하지 않는다 |
| R2 자체 | 하드 지출 상한 없음 | 막지 않는다 |
| 토큰 범위·만료·폐기 | 토큰으로 할 수 있는 일을 줄임 | 이 도구를 거치지 않는 요청(토큰을 가진 다른 프로그램)은 이것만이 막는다 |

이 도구의 한도는 토큰을 가진 사람이 다른 프로그램으로 R2를 직접 호출하는 것을 막지 못한다. 그래서 토큰을 범위 제한·만료·폐기로 관리하는 것이 함께 필요하다(§4).

## 3. 동작

1. 실행은 작업 파일을 지정해야 R2에 접근한다(`--job infra/r2/jobs/initial-119.json[#upload|#verify]`). 없으면 아무 요청도 보내지 않고 멈춘다.
2. 실행 전에 원장(`onjeon-budget-ledger` 버킷 `ledger/v1/<순번>.json`)을 모두 읽고 검증한다: 순번 연속, 앞 기록 해시 연결, 알려진 정책 해시, 첫 기록이 정책에 고정한 genesis 해시. 하나라도 어긋나거나 읽지 못하면 **중단**(종료 코드 4).
3. 전체·작업 한도에 이번 실행분이 들어가면 예약 기록을 `If-None-Match`로 새로 쓴다. 동시 실행이 같은 순번을 쓰려 하면 한쪽은 412를 받고 다시 읽어 다시 판단한다. 예약 전에는 보관소 요청을 보내지 않는다.
4. 실행 중 모든 요청은 계량기를 거친다: 허용 연산(Get, Head, Put, ListObjectsV2)만, 작업 버킷만, 고정 목록의 키만, Put은 고정 해시와 같은 바이트만, Standard 저장 등급만. HTTP 시도마다 Class A/B를 세고(재시도 포함), 업로드는 Content-Length로, 내려받기는 본문을 읽기 전에 크기로 센다. 한도를 넘을 요청은 보내기 전에 멈춘다. 실행 시간은 요청 시점과 별도 타이머 둘로 막는다.
5. 끝나면 정산 기록(측정값, 예약 이하로 제한)을 남긴다. 정산된 실행은 측정값만, 정산되지 않은 실행(중단·충돌)은 예약 전체가 계속 쓰인 것으로 센다. 그래서 재실행·병렬 실행으로 한도를 넘을 수 없다.
6. 다시 업로드하는 실행은 먼저 HEAD로 저장된 SHA-256을 비교한다. 같으면 바이트를 보내지 않는다.

남은 사용량 확인(이것도 예약을 거친다):

```bash
python3 -I tools/r2_budget.py status --job infra/r2/jobs/initial-119.json
```

## 4. 과금을 막기 위한 나머지 장치와 사용자 확인 항목

| 항목 | 상태 |
|---|---|
| 저장 등급 Standard(Infrequent Access는 무료 사용량 제외, 최소 30일 과금, 조회 수수료) | 세 버킷 모두 기본 등급 Standard 확인(Cloudflare API, 2026-10-09). 도구가 다른 등급 업로드를 거부 |
| 멀티파트 업로드(미완료 조각이 저장량으로 남을 수 있음) | 도구가 멀티파트 연산을 거부. R2는 미완료 업로드를 기본 7일 뒤 중단 |
| 공개 접근(r2.dev, 사용자 도메인): 열리면 남이 읽기 요청을 만들어 Class B 사용량이 생김 | **사용자 확인 필요.** 연결된 도구로는 설정을 조회할 수 없다. 세 버킷의 Settings에서 Public Development URL이 Disabled, Custom Domains가 비어 있는지 확인 |
| 토큰 | 대화창으로 받은 토큰은 이번 작업 뒤 **폐기**. 이 토큰은 새로 만든 원장 버킷에도 접근됐으므로 두 버킷 한정이 아니다. 새 토큰은 버킷 지정(원본·파생·원장), Object Read & Write, 만료일 지정으로 만들고 환경 설정 Network secrets로만 넣는다. Admin 토큰은 쓰지 않는다 |
| 예산 알림 | 권장: Billing → Billable Usage → Set Budget Alert(예: 1달러). **알림일 뿐 과금 차단이 아니다** |
| GitHub 재검증 | 수동 실행만, 동시 실행 1개, 같은 원장으로 예약. 원장에 쓸 권한이 없으면 실행되지 않는다 |
| 다른 유료 제품 | 이 작업은 R2 외 Cloudflare 제품을 만들거나 켜지 않는다 |

## 5. 남는 한계

- 원장의 **마지막** 기록들을 지우면 감지하지 못한다(중간 삭제·변조·전체 삭제는 감지). 막으려면 원장 버킷 `ledger/`에 기간 있는 버킷 잠금이 필요하다(O14와 함께 결정, 승인 전 적용 안 함).
- 원장을 읽는 비용이 기록 수에 비례한다. 기록이 많아지면(정책 상한 500) 실행이 예약 단계에서 멈춘다. **대량 수집 전에** 원장 요약(체크포인트) 설계가 필요하다.
- 원장 이전 사용량(순번 1)은 측정값이 아니라 상한 추정이다.
- 한도는 Cloudflare의 실제 청구액이 아니다. 청구 기준(GB-월 평균, 단위 올림)과 차이가 있으며 실제 청구는 대시보드에서 확인한다.
