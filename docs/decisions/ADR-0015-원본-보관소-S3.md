# ADR-0015 원본 보관소: AWS S3 비공개 버킷(서울 리전), 보관본 재현과 출처 변경 감지의 분리

상태: 확정(사용자 결정, 2026-10-09). 보관소 제공자는 ADR-0016으로 R2로 바뀜(1번 항목과 S3 고유 설정만 대체, 나머지 규칙 유지) | 근거: 결정 원장 O13 → D14, `infra/s3/`, `docs/data/DATA_PIPELINE_CONTRACT.md` §3.1

## 맥락

V1 설계 검증 원본 14건이 세션 임시 디렉터리에만 있었다. 출처 문서가 바뀌거나 세션이 끝나면 재현할 수 없다. 리뷰는 CI의 내부 일관성 검사를 원본 검증처럼 보고한 점과, 동적 HTML의 본문 해시를 바이트 일치처럼 다룬 점을 지적했다.

## 결정 (사용자)

1. AWS S3 비공개 버킷, ap-northeast-2(서울)를 원본 보관소로 쓴다.
2. 공시 PDF·HTML·보험료표 원본과, OCR·추출 결과는 다른 버킷이다.
3. 원본은 SHA-256 기반 경로에 둔다. 바뀐 문서는 새 원본으로 추가한다. 같은 URL의 과거 원본을 덮어쓰지 않는다.
4. 버전 관리, 공개 접근 차단, 저장 시 암호화를 적용한다. 수집 작업에는 삭제 권한을 주지 않는다.
5. Object Lock은 보존 기간과 해제 권한 정책을 문서화하고 승인한 뒤 적용한다. 임의의 무기한 잠금은 두지 않는다.
6. 개인 계약·건강·가족력·DNA 자료는 공시 원본 저장소에 넣지 않는다.
7. 원본 보존과 외부 재배포는 별도 결정이다. 이번 범위는 비공개 내부 보존이다.
8. 두 검사를 분리한다. 보관본 재현 검사는 당시 보존한 원본으로 해시·페이지·인용·추출 결과를 다시 확인한다. 현재 출처 변경 감지는 원 URL의 현재 문서를 받아 새 버전인지 본다. 현재 문서가 바뀌었다고 과거 원본을 교체하거나 과거 검증을 실패로 바꾸지 않는다. 변경 문서는 별도 검수 후 새 데이터 릴리스에 반영한다.
9. 동적 HTML의 본문 해시는 보조 지표다. 정규화 규칙과 버전을 기록하고, 의미 있는 변경이 정규화로 사라지지 않는지 시험한다. 본문 해시 일치를 바이트 일치로 보고하지 않는다.

## 구현 (구현자)

- 버킷 정의: `infra/s3/source-archive.cfn.yaml`(조건부 쓰기 아닌 PutObject 거부, 수집 주체 삭제·정책·버전·수명주기 변경 거부, TLS 강제, 리전 고정, Object Lock 미설정).
- 보관 도구: `tools/source_archive.py`(같은 배치로 S3와 로컬 디렉터리. 삭제 명령 없음).
- 검사: `tools/verify_sources.py reproduce` / `detect`. 상태 어휘 `archive_reproduction`, `source_change`(vocabulary 1.3.0).
- 본문 해시: `tools/html_content_hash.py` 규칙 `html-visible-text-v1`, 시험 `tools/tests/test_html_content_hash.py`.

## 결과

- 2026-10-09 이 세션에는 유효한 AWS 자격 증명이 없어(환경 변수가 자리표시자, AWS가 `InvalidAccessKeyId`로 거부) S3에 올리지 못했다. 원본 14건은 같은 배치의 로컬 보관소로 보존하고, 다시 읽어 14/14 바이트 일치를 확인한 뒤 사용자에게 비공개 묶음으로 전달했다. 같은 코드 경로를 S3 에뮬레이터에서 시험했다. 실제 S3 보존과 다운로드 대조는 자격 증명 설정 후 수행한다(`infra/s3/README.md` §2·§3).
- 저장소가 공개 상태라 Git LFS·GitHub 아티팩트는 임시 보관소로 쓰지 않았다(비공개 내부 보존 범위를 넘는다).
