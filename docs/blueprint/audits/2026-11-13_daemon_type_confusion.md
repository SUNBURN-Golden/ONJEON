# Audit 6 — 데몬 봉투 식별자 자료형 혼동

2026-11-13 · 노드 `audit6-daemon-type-confusion`.
범위: BLUEPRINT §11의 T-OP-00·T-OP-09 개발 도구 보강.
[09 §5](../proposals/설계검토_결과/09_제품목적_대응표.md)의 출시 완성품 제외 항목이며,
P01~P19의 실제 데이터·트윈·소비자 화면 완료 증거를 대체하지 않는다.

## 결함과 수정

`gate_evaluator.Ctx._compare`는 Python의 `==`를 그대로 사용해 `true`·`1.0`을 정수 `1`과
동일하게 취급했다. `envelope_validator.dedup_key`는 같은 값을 `str()`로 변환해 각각
`True`·`1.0`·`1`이라는 서로 다른 키를 만들었다. 따라서 같은 임대·봉투 ID로 하트비트·결과·
push 요청을 다시 수락하거나 실행할 수 있었다. 숫자 봉투 ID와 문자열 봉투 ID의 키가 겹치는 문제도 있었다.

- `==`·`!=`는 정확한 자료형을 비교하고 목록·사전 값에도 재귀 적용한다. 수신기 임대 비교도 같은 술어를 쓴다.
- 수신 봉투와 쓰기 요청의 기존 `required_present` 단계에서 필수 식별자의 자료형을 함께 검사한다.
  `lease_generation`·`fencing_token`·필수 `attempt`는 정확한 `int`, 필수 `task_id`·`lease_id`·
  `envelope_id`는 공백 아닌 `str`이다. 잘못된 값은 R-13 `required_missing`으로 기록하고
  상태·임대·처리 키·원격 쓰기를 바꾸지 않는다. 수정한 봉투를 재전송할 수 있다.
- 중복 키는 검증된 자료형으로만 만든다. 정상 키 형식과 규칙의 `idempotency_key_fields` 순서를 유지하므로
  기존 저장 상태의 중복 방지 기록을 그대로 조회한다. 잘못된 키 입력에는 키를 만들지 않는다.
- 기존 `fenced_write`의 push·PR 갱신 공용 signal 키를 유지한다. 동일 과제·세대의 `envelope_id`가 같으면 sha·PR 번호·
  사건 종류를 바꿔도 같은 처리 키다. 커밋 전 키 예약과 발송 전 임대 재검사는 계속 적용된다.

## 회귀와 증거

[`EnvelopeIdentityTypes`·`FencedWriteIdentityTypes`](../../../tools/tests/test_daemon_dry_run.py)는
bool·float·문자열·컨테이너·빈 식별자 거부, 정상·변형 입력의 양쪽 순서, 수신기 실행 차단,
수정 재전송, 문자열 ID의 독립성, 정상 키 호환을 검사한다. 하트비트·첫 하트비트·결과·전환 신호·
위반 보고와 push·PR 갱신 입구를 모두 포함한다. 쓰기 중복 시험은 메모리 및 파일 저장소를 다시 열어
내용·사건 종류가 달라진 같은 ID가 한 번만 실행되고 다른 ID는 별도 실행됨을 확인한다.
기존 동시 재전달·롤백·발송 전 임대 교체·만료·오류 후 재전달 시험도 함께 실행한다.
기존 오래된 토큰 회귀 2개의 문자열 `"stale"` 입력은 오래된 정수로 바꿔 R-11 검사 목적을 유지한다.
문자열 토큰은 신규 회귀에서 R-13으로 거부됨을 확인한다.

수정 전 실패, 수정 후 통과, 전체 프로젝트 시험과 재현 명령은
[증거 안내](../../../tools/evidence/audit6-daemon-type-confusion/README.md)에 기록한다.

정본 규칙과 의사결정·비용·실데이터·출시 관문은 변경하지 않았다. 이 변경은 상주 데몬 가동 승인이나
원격 전달의 exactly-once 보장을 추가하지 않는다. 커밋 후 미발송 intent 자동 복구는 기존 구현 범위 밖이다.
