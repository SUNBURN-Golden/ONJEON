**Decision:** Do not make a structured start cond a precondition for stage 4: stage 4 is already running, and only four tasks have a non-empty decision_gates.start in tasks.json: T-OP-03 (D-02), T-OP-04 (D-04), T-OP-07 (D-03) and T-UX-01 (D-16). Enforce the gate in code now anyway, and keep the grokbot procedure as a second layer. Changes: (1) daemon_rules.json blocked→queued (prereqs_satisfied) gets a cond alongside the prereq check: {field: task.decision_gates.start, op: subset_of, value: task_state.decisions_recorded} (a path in `value` is resolved, per _cond_note). A null or non-list start is unevaluable and keeps the task blocked; it never moves it to queued. (2) The mock core (tools/daemon/core transition_engine/gate_evaluator) evaluates that cond. subset_of already exists and backs the real_data derive in envelope_validator.build_instruction. (3) Tests in tools/tests/test_daemon_dry_run.py: start-gate-blocks (start=[D-X], D-X not recorded, prereqs_satisfied → stays blocked, reason lists D-X); start-gate-opens (record D-X → queued); start-gate-empty (start=[] → queued, regression for T-CT-01 and similar); start-gate-null (start missing → stays blocked); the existing d02-mock-start-allowed (M10a) and decision-gate-merge-only tests still pass. (4) Docs: DEC-D-02 §8 changes from 'start gate is not enforced in code; grokbot procedure is the only block' to 'the mock core enforces decision_gates.start; the procedure still blocks real dispatch until access is confirmed, because supervisor deps only check that the DEC-D-02 record exists'. Update the _cond_note, spec_gaps.py core_reads, and the README/handoff text to match. Commit the test log under tools/evidence/audit1-start-gates-enforcement/. (5) Operator follow-up outside the repo: supervisor program.json T-OP-03 depends on the DEC-D-02 node, which only shows the decision was written. It should also depend on the node that records confirmed non-Claude access (the Audit 5 node on the D-02 model family), or the supervisor should read decisions_recorded.

**Why:** The gap is real but small, and closing it is cheap. The evaluator already has subset_of, the real_data derive already uses the same shape, and this node's allowed_paths include tools/** and docs/**. Encoding the gate makes the rules file match its own statement that the core reads only cond, and the tests turn 'T-OP-03 cannot start without D-02' into something tested. Making it a stage-4 precondition is moot: stage 4 is already running and only four tasks have a start gate (T-OP-03 is also blocked by unfinished deps T-KN-06 and T-OP-09). The procedure stays because the mock core is a development tool (09 대응표: not part of the release) and does not dispatch work. The supervisor does, and its DEC-D-02 dep is satisfied by the decision record, not by confirmed non-Claude access or D-02 registration. Not critical: this is a reversible change to development tooling with no money, credentials or production path. It makes the system stricter.

**Options:** ['A: Accept the procedural control only and record it (rejected: the finding stays open, the mock core contradicts its own rule that the natural-language when is human-only, and the block rests on memory with no test)', 'B: Make a structured start cond a precondition for stage 4 and stop product dispatch until it lands (rejected: stage 4 is already running, the 59 tasks with start=[] gain nothing, and T-OP-03 and T-OP-04 are also blocked by unfinished supervisor deps)', 'C: Add the structured cond, mock-core enforcement and tests now, keep the procedure as a second layer, and flag the supervisor dep gap to the operator (chosen)', 'D: Enforce the start gate inside envelope_validator at lease time (rejected: by then the task is already queued and blocked→queued is the wrong transition; envelope validation already covers real_data, and a task should not hold a lease while its start gate is unmet)']

**Revisit if:** The supervisor starts reading tasks.json decision_gates or decisions_recorded directly, or the T-OP-03 dep is switched to the access-confirmation node (then DEC-D-02 §8 can drop the procedural layer); T-OP-09's real runner replaces the mock core as the dispatcher (carry the cond and tests over); a task gains a non-empty decision_gates.start beyond T-OP-03, T-OP-04, T-OP-07 and T-UX-01; D-02 is split into a separate access-confirmation gate, or D-04 is redefined (audit1-d04-gate-redefinition), which changes what the start lists contain; or the merge gate's merge_wait(decision_pending) turns out to lack a structured cond as well (apply the same fix).
