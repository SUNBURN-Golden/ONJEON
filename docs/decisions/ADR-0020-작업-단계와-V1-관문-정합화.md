# ADR-0020 작업 단계와 V1 관문 정합화

상태: 채택(가역 설계 결정, 새로운 사용자 직접 결정 아님; 병합·가동·출시 승인은 별도) | 날짜: 2026-11-18

## 배경과 근거

Audit 7의 채택 누락 전제는 현재 정본과 다르다. ADR-0019가 이미 `tasks.json`과 `09_제품목적_대응표.md`를 한정 채택했고 BLUEPRINT §0.1에도 둘 다 있다. 그러나 구현계획 §4의 S0~S5와 BLUEPRINT의 M0~M6 대응, T-OP-02와 미통과 V1의 관계, ADR-0014 결정 6의 선행 구현 금지와 이미 존재하는 rule-0.2 코드 사이의 충돌은 남아 있었다.

이번 변경은 이 ADR을 저장하고 BLUEPRINT §7·§9·§11·§13, ADR-0014의 후속 주석, 결정 원장, 두 계약을 함께 갱신한다. 이전 Audit 7 기록의 읽기 전용·미저장 설명은 실제 작업 트리와 맞지 않아 정정했다. 변경 후 회귀 검사와 프로젝트 시험은 [Audit 7 증거](../../tools/evidence/audit7-adopt-task-bundle-adr/README.md)에 남긴다. 이 문서 정합성 finding을 해결하며, 제품 관문 통과를 선언하지 않는다.

## 결정 1. 두 계약의 한정 채택 유지

[ADR-0019](ADR-0019-제품-완료와-작업-계약-한정-채택.md)를 유지한다. [tasks.json](../blueprint/proposals/설계검토_결과/tasks.json)은 데몬 작업 소스·개별 수락 계약이고 [09_제품목적_대응표](../blueprint/proposals/설계검토_결과/09_제품목적_대응표.md)는 제품 완료 증거 계약이다. BLUEPRINT 및 상위 계약을 우선한다. 묶음 전체·01~08·온톨로지 제안·common_done_criteria를 채택하지 않는다.

## 결정 2. S–M 대응

구현계획 §4의 정본 대응을 아래처럼 구체화한다. M0는 이미 있는 엔진 기반이며 S0의 새 완료 목표가 아니다. S2의 M4·M6는 준비 기여, S4의 M3·M4는 통합 기여다. 다대다 작업 대응이므로 단계 완료가 마일스톤 통과를 뜻하지 않는다. V0·V1은 별도 선행 관문이며 생략되지 않는다.

| 단계 | 마일스톤 대응 | 범위 |
|---|---|---|
| S0 | M0·M1 | 기존 엔진 재사용·공통 계약과 데이터 척추 기반 |
| S1 | M2 | 실제 상품 하나 관통 검증, M2 최소 구성 |
| S2 | M2·M4·M6 | 구조 다양성 관통·가격 기반·상품군 연산 준비 |
| S3 | M3·M4 | 분모·수집 확장과 가격 수집 |
| S4 | M3·M4·M5·M6 | 공개 웹 연결·비교·계약 트윈·상품군 확장 통합 |
| S5 | M6 | 출시 리허설·최종 검증 |

## 결정 3. T-OP-02는 V1을 대체하지 않는다

V1의 전체 14/14 파생 재현·실제 이종 계열 검수·화면 S1·S6 해결은 독립적으로 충족해야 한다. 여기서 화면 S1·S6는 V1 화면 검증 항목이며 작업 단계 S1 또는 새 작업 단계 S6를 뜻하지 않는다. T-OP-02의 실제 데이터 관통 증거는 각 V1 조건을 충족하는 범위에서만 재사용한다. 모의 경로만으로 S1·M2를 통과시키지 않는다. 실제 상품 하나 관통도 다양한 V1 표본 전체의 증거를 자동으로 대체하지 않는다. V1은 여전히 관문 미통과다.

## 결정 4. 조기 rule-0.2의 한정 예외

`packages/rules-engine/src/rule.rs`·`eval.rs`에 존재하는 rule-0.2 구현은 되돌리지 않는다. T-TW-02의 로컬 엔진·픽스처 검증에 한해 조기 구현을 허용한다(`fixture_only`). ADR-0014 결정 6의 "미리 넣지 않는다"와 BLUEPRINT §9.1·§9.3의 순서에 대한 명시적 한정 예외다. 다른 기능의 선행 구현이나 V1·M1~M6 관문 면제까지 확대하지 않는다.

서비스 상품군 적용은 M5·M6에서 실제 사례와 검수·릴리스 증거를 갖춘 뒤 허용한다. 연산 의미론·서비스 적재·출시 관문(해당하는 DEC-O12의 연산별 S6 포함)을 유지한다. 예외는 서비스 사용 승인이나 엔진의 자동 차단 기능이 아니다. 현재 로컬 엔진은 rule-0.2를 평가할 수 있으며, 서비스 연결 시 별도 적재·릴리스 검증이 필요하다. 코드 존재·합성 시험 통과만으로 제품 완료를 선언하지 않는다.

첫 출시 완료는 09의 P01~P20 실제 데이터·화면·출시 증거와 T-OP-08의 `purpose-rows-all-closed`로 판정한다(완료 범위 확장은 [ADR-0022](ADR-0022-제품-완료-범위-P20-확장.md)). 실제 서비스 활성화·외부 제공자·운영 환경·지출을 이번 결정으로 승인하지 않는다.

## 대안과 재검토

- 묶음 전체 채택 및 T-OP-02로 V1 대체: 증거 기준을 약화하므로 기각.
- 조기 rule-0.2 전면 철회: 검증용 구현과 회귀 시험은 보존하고 서비스 적용을 제한하는 편이 타당하여 기각.
- ADR-0019만으로 종료: 단계·관문·선행 구현의 충돌이 남으므로 기각.

단계 배치·완료 기준이 바뀌거나 조기 연산이 서비스에 유입되거나 실제 사례가 연산 의미와 충돌하면 새 ADR로 재검토한다. 문서·회귀 증거의 동기화는 이번 변경에 포함하며 제품의 V1·출시 완료 증거는 별도다.
