# ADR-0016 원본 보관소 제공자: Cloudflare R2

상태: 확정(사용자 결정, 2026-10-09) | 바꾸는 결정: D14의 보관소 제공자(AWS S3 → R2) | 근거: 결정 원장 D16, `infra/r2/README.md`

## 결정 (사용자)

원본·파생 보관소를 Cloudflare R2로 한다. 원본 버킷 `onjeon-raw-sources`, 파생 버킷 `onjeon-derived-sources`. 기존 AWS 전용 설정은 R2 호환 여부에 맞게 고친다.

## 그대로 유지하는 D14 규칙

원본·파생 버킷 분리, SHA-256 경로, 같은 URL의 바뀐 문서는 새 원본으로 추가, 덮어쓰기 금지, 비공개, 저장 시 암호화, 개인 계약·건강·가족력·DNA 자료 금지, 보존과 재배포는 별개, 보관본 재현 검사와 현재 출처 변경 감지의 분리, 무기한 잠금 금지와 승인 전 잠금 금지.

## R2에서 달라지는 점 (구현자 확인, R2 문서 2026-10-09)

| D14 항목 | R2 | 처리 |
|---|---|---|
| 서울 리전 | 서울 없음. 위치 힌트 `apac`는 최선 노력이고 보장이 아님 | 지킬 수 없음. 이 결정으로 D14의 리전 조건을 대체한다 |
| 버전 관리 | 미지원 | 덮어쓰기·삭제를 되돌릴 수 없다. 버킷 잠금(O14)과 별도 사본으로 보완 |
| 버킷 정책으로 무조건 쓰기·삭제 거부 | 버킷 정책 미지원. Object 읽기·쓰기 토큰에서 삭제만 빼는 선택지가 문서에 없음 | 도구가 모든 쓰기를 `If-None-Match: *`로 하고 삭제 명령이 없다. 저장소 단의 강제는 버킷 잠금(O14) 승인 뒤에만 생긴다 |
| SSE-S3 헤더 | 미지원(모든 객체 자동 암호화) | R2에서는 헤더를 보내지 않는다 |
| Object Lock(O14) | 미지원. 버킷 잠금(접두어별 기간·날짜·무기한)으로 대신 | O14의 대상이 버킷 잠금 규칙으로 바뀐다. 승인 전 적용하지 않음 |

## 구현

- `tools/source_archive.py`: 엔드포인트(`--endpoint-url` 또는 `ONJEON_S3_ENDPOINT`)가 `*.r2.cloudflarestorage.com`이면 R2(https만, region `auto`, `R2_ACCESS_KEY_ID`·`R2_SECRET_ACCESS_KEY`만 사용, SSE 헤더 없음). 412는 기존 키로 처리해 바이트를 비교한다. 새 명령 `listing`(키별 SHA-256 목록), `verify-copy`(모든 키를 다시 받아 원본 또는 고정 목록과 바이트 해시 대조).
- 키·해시 목록 고정: `docs/blueprint/validation/source_checks/archive_listing_raw.json`(58키), `archive_listing_derived_v2.json`(61키). 전달 묶음이 없어도 R2 내용을 대조할 수 있다.
- `.github/workflows/sources.yml` reproduce: OIDC 대신 읽기 전용 R2 토큰(Secrets), 목록 대조 후 재현 검사.
- 시험: `tools/tests/test_store_provider.py`.

## 결과

(갱신) 2026-10-09 R2에 원본 58키·파생 v2 61키를 보존하고 다시 받아 전부 바이트 일치를 확인했다. 412 거부와 저장 SHA-256도 실제 R2에서 확인했다(`infra/r2/README.md` §6).

(처음 기록) 2026-10-09 이 환경에 R2 자격 증명이 없어(`AWS_*`는 14자 자리표시자, `R2_*` 없음) 실제 업로드·대조는 하지 않았다. R2 엔드포인트는 응답했고 키 길이 오류로 거부했다. 같은 코드로 S3 에뮬레이터에서 원본 58키·파생 61키 업로드, 재실행 덮어쓰기 없음, 목록 대조 전부 일치를 확인했다. 에뮬레이터는 R2가 아니다.
