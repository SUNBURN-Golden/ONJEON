## 2. 상태 기계

### 2.1 상태

| 상태 | 뜻 |
|---|---|
| `blocked` | 선행 과제 미병합 또는 `prereq_decisions` 미결(사유에 ID) |
| `queued` | 실행 가능 |
| `leased` | 빌더에게 임대(lease_id, TTL). 쓰기 전 |
| `building` | 빌더가 브랜치에 쓰는 중. 하트비트 필요 |
| `handoff` | 전환 신호 감지. 쓰기 중단·보존 중 |
| `paused_no_builder` | 모든 빌더 불가. 작업 보존 후 대기 |
| `pr_open` → `ci_failed` / `review_pending` | PR 열림 → CI 결과 |
| `review_in_progress` → `changes_requested` / `review_approved` | 리뷰(대상 SHA 고정) |
| `audit_pending` | 즉시 감리 대상, 병합 전 감리 대기 |
| `merge_wait` | 사람 병합 대기. 사유: `ready` / `reviewer_unavailable` / `auditor_unavailable` / `decision_pending` |
| `merged` → `audit_queued` → `done` | 사람이 병합 → 정기 감리 묶음 → 감리 통과 |
| `returned` | 데몬이 판단할 수 없어 담당자에게 반송(return_code 필수) |
| `cancelled` | 담당자 취소 |

### 2.2 전이 (전부 daemon_rules.json `transitions`에 있음. 조건은 기계 판정만)

핵심 전이와 조건:

| from → to | 조건 | 수행자 |
|---|---|---|
| blocked → queued | 모든 `prereq_tasks`가 merged **and** 모든 `prereq_decisions`가 결정 기록에 있음 | daemon |
| queued → leased | 빌더 가용 **and** `conflict_paths` 겹치는 임대 없음 **and** 잠금 획득 | daemon |
| building → handoff | 허용 전환 신호 감지(§3) | daemon |
| building → returned | `touched_paths`가 허용 경로 밖(R-01) / `verdict_requested`(R-02) / 하트비트 2회 누락 | daemon |
| handoff → leased / paused_no_builder | 보존 완료(WIP 커밋 푸시 + 인계 기록) **and** 다음 빌더 있음 / 없음 | daemon |
| pr_open → ci_failed → building | CI 실패 → **같은 작성자** 재임대(운영 규칙 1: 전환 금지) | daemon |
| review_pending → review_in_progress / merge_wait | 작성 계열 밖 리뷰어 있음 / 없음(`reviewer_unavailable`) | daemon |
| review_approved → review_pending | `pr.head_sha ≠ review.sha`(코드가 바뀜 → 변경분 재리뷰, 운영 규칙 4) | daemon |
| review_approved → audit_pending / merge_wait | 즉시 감리 판정(§5) 참 / 거짓 | daemon |
| audit_pending → merge_wait / changes_requested | 감리 pass(SHA 일치) / 지적 | auditor |
| merge_wait → merged | `pr.merged == true` **관측**(데몬은 병합하지 않음) | human |
| merged → audit_queued | 구현 PR이면 `merged_impl_counter += 1` | daemon |
| * → returned | 표에 없는 모든 조건 | daemon |

## 3. 빌더 순서와 전환 조건

전환은 **사용량 제한·서비스 가용성** 문제일 때만 한다(운영 규칙 1). 데몬은 다음 신호만 전환 사유로 인정한다. 모두 기계 검출이다.

| 신호 | 검출 기준 | 전환 |
|---|---|---|
| `usage_limit` | HTTP 429, 또는 stderr가 `/(usage|rate) ?limit|quota|exceeded your/i`에 맞음, 또는 실행기가 문서화한 한도 종료 코드 | 예 |
| `auth_failure` | HTTP 401/403, 또는 `/not (logged|signed) in|unauthorized|invalid (api )?key|expired token/i` | 예(인증은 사람이 고쳐야 하므로 다음 빌더로) |
| `service_unavailable` | HTTP ≥ 500, 연결 거부·재설정, 출력 없는 타임아웃 3회 연속 | 예 |
| `runner_missing` | `command not found`, 버전 확인 실패 | 예 |
| 시험 실패, CI 실패, 리뷰·감리 지적, 품질 불만, 느린 진행 | — | **아니오.** 같은 작성자가 고친다 |

전환 절차(자동개발_설정안 §3.2 그대로): 쓰기 중단 확인 → WIP 커밋 푸시(`wip_commit_sha`) → 인계 기록(시험 로그 위치, 남은 작업) → 다음 빌더가 같은 브랜치·같은 SHA에서 시작 → `authors_families`에 새 계열 추가. 마지막 빌더까지 실패하면 `paused_no_builder`. 몰래 대체 없음.

## 4. 독립 리뷰 배정

```text
candidates = builders 순서
for c in candidates:
    if c.family in pr.authors_families: continue   # 작성 참여 계열 제외(운영 규칙 2)
    if c.available: assign(c); break
else: state = merge_wait(reviewer_unavailable)      # 데몬은 리뷰를 대신하지 않는다(운영 규칙 4)
```

- 리뷰 결과는 `sha`를 가진다. `pr.head_sha`와 다르면 무효(R-04) → 변경분 재리뷰.
- 계열표: claude{Fable, Sonnet}, gpt{GPT Astra}, grok{Cursor CLI, grokbuild CLI}, swe{Devin CLI}, glm{Claude Code(GLM 5.3)}. **Fable·Sonnet을 같은 계열로 보는 해석은 사용자 확인 대상**이다(자동개발_설정안 §3.3). 확인 전까지 데몬은 더 엄격한 이 표를 쓴다. 그 결과 **이 환경에서 확인된 경로(claude 계열)만으로는 Sonnet 작성 PR의 리뷰어가 없다** → 모든 PR이 `merge_wait(reviewer_unavailable)`에 머문다. 이것은 병합만 막고 작성·시험·설계는 막지 않는다.

## 6. 봉투 형식

### 6.1 지시 봉투(데몬 → 빌더)

필수: `envelope_id, task_id, attempt, lease_id, builder, runner, branch, base_sha, allowed_paths, forbidden_paths, inputs, tests, done_criteria, deadline_heartbeat_s, budget{max_calls, max_cost_units, max_wall_s, max_retries}, reply_to`. 본문 끝에 빌더 규칙 5줄: 허용 경로 밖 금지, 정본·토의 자료 금지, 비밀값 출력 금지, 판단 필요 시 `verdict_requested`로 반송, 병합·자동 병합 설정 금지.

### 6.2 결과 봉투(빌더 → 데몬)

필수: `envelope_id, task_id, attempt, lease_id, builder, runner, status ∈ {pr_opened, wip_preserved, switch_signal, verdict_requested, failed_tests, completed_no_change}, branch, head_sha, touched_paths, tests_run, test_log_ref, signals_seen, cost_units, calls, wall_s`. 선택: `pr_number, verdict_question, handoff_record`.

데몬 검증: 필수 필드 존재 → `touched_paths ⊆ allowed_paths` → 비밀값 패턴 없음 → 상태별 전이. 하나라도 실패하면 반송(§7).

### 6.3 리뷰·감리 결과

`review_result{pr_number, sha, reviewer, reviewer_family, runner, verdict, findings_ref}`, `audit_result{batch_id|pr_number, sha, auditor, verdict, report_ref}`. `sha` 불일치는 무효.

## 10. 이 명세가 PR #2 AIOPS 인계안과 다른 점

중앙 AIOPS를 재가동하지 않는다. 데몬은 판단 주체가 아니라 전령이다. 자동 병합 권한이 없다. 역할·전환 정책은 U-04가 정했고 이 문서는 그것을 기계 규칙으로 옮겼을 뿐이다.
