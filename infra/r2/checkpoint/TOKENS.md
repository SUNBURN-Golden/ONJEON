# 토큰 재발급 절차 (D-04)

상태: **절차서. 재발급·폐기를 하지 않았다.** 소유자는 대화에 노출된 R2 토큰을 폐기하지 않기로 결정했다(`docs/decisions/DEC-D-04.md`). 그 결정은 노출된 토큰의 재사용을 승인하지 않으며 T-OP-04의 시작 관문(D-04)을 열지 않는다. (갱신) 준태님이 2026-10-16 19:45 KST에 환경의 기존 자격을 이번 T-OP-04 검증에 한해 쓰도록 명시 승인했고, 그 범위에서만 접근했다. 그 자격은 계정 전체 범위로 확인되어 아래 요건을 충족하지 않는다(`token-scope-no-admin` fail).

비밀값은 이 문서·Git·로그·대화에 쓰지 않는다. 계정 엔드포인트(계정 ID 포함)도 쓰지 않는다.

## 재발급이 필요할 때 (소유자가 한다)

1. Cloudflare 대시보드 → R2 → Manage API tokens.
2. 토큰마다 **버킷을 지정하고 만료일을 둔다.** Admin 권한 토큰은 만들지 않는다(버킷 설정·잠금 변경·삭제가 가능해진다).

| 토큰 | 권한 | 버킷 | 쓰는 곳 |
|---|---|---|---|
| 수집 | Object Read & Write | `onjeon-raw-sources`, `onjeon-derived-sources` | 지정 실행 환경 하나 |
| 원장 | Object Read & Write | `onjeon-budget-ledger` | 같은 환경(`R2_LEDGER_*`) |
| 검증 | Object Read only | `onjeon-raw-sources`, `onjeon-derived-sources` | 재검증 |

3. 값은 환경의 Network secrets에만 넣는다(세션 시작 때 적용). 대화창에 붙여 넣지 않는다.
4. 노출됐던 토큰은 새 토큰으로 `VERIFICATION.md`의 A·B를 마친 뒤 폐기한다(폐기를 먼저 하면 검증 전에 접근을 잃는다). 폐기 여부는 소유자의 결정이다.
5. 기록: 토큰 ID(비밀 아님)·버킷 범위·만료일·발급일을 `real_r2_record.json`의 `token_scope_record`에 적는다. 키 값은 적지 않는다.

## 만료와 회전

- 만료일은 필수다. 기본은 짧게 두고(값은 소유자가 정한다), 만료 전에 같은 절차로 교체한다.
- 의심되는 노출이 있거나 원장·청구 이상이 보이면(DEC-D-04 재검토 조건) 즉시 폐기한다.

## 이 저장소가 하는 확인

- 도구는 R2 엔드포인트에서 `R2_*` 변수만 읽고(원장은 `R2_LEDGER_*`), 삭제 명령이 없고, 허용 연산이 Get·Head·Put·List뿐이다.
- 토큰의 실제 범위(다른 버킷 접근, 삭제 가능 여부)는 도구가 확인하지 못한다. `VERIFICATION.md` C가 새 토큰으로 범위 밖 요청이 거부되는지 확인한다.
