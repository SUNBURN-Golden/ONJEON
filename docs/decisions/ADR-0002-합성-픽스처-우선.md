# ADR-0002 합성 픽스처 우선, 두 트랙 병렬

상태: 제안 (승인 대기) | 날짜: 2026-10-08 | 근거: 제3부 §43

## 맥락

실제 공시 수집·검수·정답셋은 오래 걸린다(§39). 앱·엔진·관제를 그 뒤에 시작하면 UX 검증이 늦어진다.

## 결정

1. 데이터 트랙(실제 공시)과 제품 트랙(합성 픽스처)을 병렬로 진행한다.
2. 합성 상품 3개·담보 10개·계약 5건·시나리오 30개를 `packages/fixtures`에 둔다. 모든 합성 데이터에 `synthetic_not_a_real_product`를 표시한다.
3. 앱과 엔진은 픽스처와 실데이터를 같은 릴리스 API로 읽는다. 교체 시 화면·엔진 코드 변경이 없어야 한다.
4. 합성 데이터는 실제 공시 정답셋(§32)을 대체하지 않으며 정답셋 평가에 섞지 않는다.

## 결과

- 사용성 시험(5초·30초)을 P1에 시작할 수 있다.
- 픽스처 화면이 실제 상품처럼 보이지 않도록 앱 내 '화면 예시' 고지를 유지한다.
- 교체 시 코드 변경이 필요했다면 API 계약이 픽스처에 종속된 것이므로 결함으로 기록한다.
