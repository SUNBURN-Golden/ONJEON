## 이번 수정

- 허용 경로 안에 시험 전용 별도 Cargo 진입점을 추가했다. 실제 `defaults`
  소스를 컴파일하고 `onjeon-criteria`의 공용 타입·검증기를 사용한다.
  제품 파일을 임시로 바꾸고 되돌리는 시험은 하지 않는다.
- 후보 납품 시험이 실제 저장소 경로의 디렉터리·판 존재를 요구하도록 바꿨다.
  기존에는 미존재 경로도 빈 저장소로 처리되어 통과했다.
- 제품 공개 API를 직접 가져오는 통합 시험 표적을 추가했다. 미연결을 성공으로
  보고하지 않는다. 루트 workspace에 시험이 연결되었다고 주장하지 않는다.
- 반복된 과거 시험 로그·상태 이력을 최신 실제 출력으로 교체했다.

공식 공공 통계 페이지는 확인했으나 직접 다운로드가 실패하여 RawAsset
바이트 해시는 확보하지 못했다(공식 링크·조건은 `../README.md`).
해시·통계·개인 필요액을 만들어 넣지 않았다. 빈 후보를 데이터 납품으로
간주하지 않는다. 출력 디렉터리만 만들면 기존 conformance 시험의
비존재 단정이 실패하므로 계약 문서만 넣어 납품한 것으로 표시하지 않았다.

이 문제는 금전·법률·비밀·운영 또는 비가역 결정 요청이 아니다.
