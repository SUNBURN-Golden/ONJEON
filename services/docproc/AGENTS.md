# docproc execution contract

Run from the repository root:

- `DOCPROC_SANDBOX_REQUIRE_LIVE=1 bash services/docproc/test_sandbox.sh`
- `cd services/docproc && python3 -m pytest -q`
- `python3 -B -m unittest discover -s services/docproc/tests -v`
- `python3 -B services/docproc/tests/container_network.py`
- `python3 -I tools/ci/check_leak.py`
- `python3 -I tools/ci/check_skeleton.py`
- `cargo test --workspace`

The sandbox command requires Docker Compose and a working daemon; missing Docker fails by default. When the default system socket is absent, the harness can start an owned temporary daemon using an installed dockerd and root or noninteractive sudo privileges. Its socket, data, executable shims and logs live in an ignored services/docproc/.d-*/ directory. No manual DOCKER_HOST export or persistent daemon is needed. A caller-selected DOCKER_HOST/DOCKER_CONTEXT, nondefault active context, existing system socket, or unavailable prerequisites fail rather than being silently replaced. An already working daemon is reused. The harness stops only its own daemon, unmounts its data bind mount and removes its temporary state after container/network cleanup, including acceptance failure. A shutdown/cleanup failure fails the command. It does not install packages or change global daemon configuration or firewall alternatives. For the owned daemon, installed legacy firewall executables are selected through private shims when available, and vfs storage avoids a nested overlay dependency. Linux daemon privileges and kernel support are required; this fallback is for a disposable local test environment.

`DOCPROC_SANDBOX_STATIC_ONLY=1` explicitly runs only the host checks and prints LIVE: SKIPPED, which is not acceptance evidence. It cannot be combined with DOCPROC_SANDBOX_REQUIRE_LIVE=1. The mandatory live harness builds both image targets, runs unittest and pytest with native Poppler 24.02 and DOCPROC_REQUIRE_PINNED=1 (no extraction skips), and exercises the production CLI. The host extraction class explicitly skips unsupported Poppler; its identity is never relabeled. Pure normalization, heading, configuration, daemon lifecycle and probe regression tests still run on the host. An unsupported version in the mandatory container suite fails.

Extraction requires Poppler 24.02.x, matching ontology fp-0.1. Ubuntu 24.04 is pinned by digest and its Poppler version is asserted during build. The runtime uses only the Python standard library; pytest is installed in the test stage only. The test stage inherits the production extraction code, libraries and nonroot user. Tests and evidence are excluded from the final runtime image.

Build/run: set DOCPROC_INPUT_DIR to a directory containing a PDF and segment specification, then run `docker compose -f services/docproc/compose.yaml run --build --rm docproc /input/document.pdf --segments /input/segments.json`. JSON goes to stdout, never to a tracked file. For fixtures add `--origin fixture`. Verify saved JSON using `--verify /input/result.json` instead of `--segments`. The mounted input directory/files must be readable by uid 65532.

Segment input is a nonempty JSON array of objects with integer page_from/page_to (physical, inclusive, 1-based), doc_role (보통약관, 특약 약관, 별표, 요약서, 공시 목록, 안내 쪽), seg_rule_ver (slug of the upstream boundary rule), and optional boundary (confirmed/unconfirmed; default unconfirmed). Overlaps and nonexistent pages fail. Classification and boundary decisions come from the caller. Table/heading/footnote/reference reconstruction is not implemented: empty arrays/null mean unclassified, not confirmed absent. Every occurrence stays hold/extraction_uncertain. Textless pages fail for a separate OCR strategy. No semantic mapping or approval is performed.

Occurrences are physical layout lines with word boxes and a top-left PDF-point bounding box [xmin,ymin,xmax,ymax]. The quote is the exact UTF-8 text returned by a separate `pdftotext -layout -r 72 -x -y -W -H -nopgbrk` crop, excluding outer layout padding and line/page terminators. Internal crop spacing is preserved; quote_basis=poppler-layout-region records this representation. PDF streams have no universal byte-exact textual spacing, and Poppler can split widely spaced content into separate lines. Crop word content must agree with bbox words; ambiguous reconstruction fails. verify checks the entire re-extraction and independently reads every coordinate crop again, rejecting even repeated quote reconstruction mistakes. Default extraction edition is docproc-text@1.1 because quote/path behavior changed. Korean inserted articles include 의<number>; printed headings must end or be followed by a parenthesized title. Cross-reference prose receives an inferred location path. No claim of complete article hierarchy.

Fingerprints separately use per-page -layout output concatenation, NFC, whitespace removal, UTF-8 SHA-256. Synthetic PDFs are generated in temporary directories with origin=fixture; no original document excerpts are stored. Native 24.02 synthetic evidence does not establish real insurance-document accuracy.

Network isolation is provided by compose network_mode:none. The local database/archive stack is not attached: docproc receives only a read-only input mount, with no credentials. The live harness validates parsed services.docproc settings, starts a controlled dual-stack TCP endpoint on a temporary internal Docker bridge, proves IPv4/IPv6 reachability before and after isolation, and verifies that enabling networking causes the same isolation probe to fail. Only ENETUNREACH/EHOSTUNREACH are accepted as isolation; refusal, timeout and other errors fail. No public endpoint is contacted by runtime probes. Building images requires package/registry access and the harness explicitly uses host networking for build steps only; this allows the owned daemon to run without a default bridge. The production CLI runs the freshly built image through Compose using its expected project image tag. Temporary fixture containers, images and networks are cleaned up.
