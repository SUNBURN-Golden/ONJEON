# Audit 6 — §12·결정 원장의 상태 동기화

기록일: 2026-11-16. 노드: `audit6-blueprint-s12-decisions-sync`.

감리 지적은 결정 기록이 있는 항목을 BLUEPRINT §12와 DECISIONS가 계속
열린 결정으로 나열한다는 것이다. Audit 5의 §12.1·§12.2 분리는 이미
반영돼 있었다. 잔여 문제는 [결정 원장 §3](../DECISIONS.md#3-결정-상태와-남은-차단-조건)의
제목이 해결·기록된 항목까지 미정으로 묶고, O 항목별 상태가 명시되지
않은 점과 §12.2에 기록 없는 O03·O06·O11·O18이 빠져 있던 점이다.

원장 §3을 ‘결정 상태와 남은 차단 조건’으로 바꾸고, 기존 링크를 위한
앵커를 유지했다. O01~O19의 기존 ID·질문·책임·시점·차단 범위를 보존하고
결정 상태 열을 추가했다. 상태는 기록이 정한 범위에만 적용한다.

| 분류 | O 항목 | 근거·잔여 조건 |
|---|---|---|
| 해결(기록 범위) | O01·O04·O12·O13·O16 | ADR-0018, DEC-O04·O12·D-04·D-12. 대상 범위·가격 규칙·의미론·기존 토큰 사용·앱 표시는 해결. 구현·S6·O14/O17·새 발췌와 재배포 등은 별도 |
| 기록(조건 잔여) | O02·O05·O07·O08·O09·O10·O14·O17 | 소스별 조건·첫 출시 기본값 비활성·사용자 시험·개인정보·외부 검토·잠금·수집 기본값 기록이 있다. 구체 값·실제 시험·확인·적용 승인·새 결정은 원문에 따라 잔여 |
| 미정 | O03·O06·O11·O15·O18·O19 | 해당 질문의 DEC·ADR 기록 없음. §12.2에 모두 연결하고 기존 차단 범위를 유지 |

[BLUEPRINT §12](../../BLUEPRINT.md#12-열린-결정)에 O01·O04의 해결 범위를
명시적 행으로 추가하고, 기록 없는 네 항목을 §12.2에 복원했다. DEC가
있는 13개 O 항목은 §12.1과, 기록 없는 6개는 §12.2와 대조한다. §12의
D-02·D-03 등 실행 결정 요약과 §3.1의 전체 DEC 색인도 계속 유지한다.

이 수정은 새로운 사용자 확정·법적 판단·비용 결정·접근·실행·출시 승인을
만들지 않는다. `decisions_recorded`나 작업 관문은 변경하지 않는다.
특히 O05 기본값 도입, D-03 운영 환경, O14 잠금 적용, O17 대량 자동
수집, O16 새 공개 발췌 등 기록 밖의 잔여 결정은 계속 필요하다.

회귀 시험은 [test_audit6_blueprint_decisions_sync.py](../../../tools/tests/test_audit6_blueprint_decisions_sync.py)다.
전체 O ID의 상태·근거 링크·§12 분류를 함께 검사하며, 기록된 항목을
미정으로 되돌리기·§12.1에서 §12.2로 옮기기·기록 없는 질문을 삭제하기의
변이를 각각 거부한다. 실행 결과는 [검증 증거](../../../tools/evidence/audit6-blueprint-s12-decisions-sync/README.md)에 기록한다.

집중 시험 100건(신규 7건 포함), Python 전체 1,663건(실패·오류 0,
조건부 건너뜀 6), Rust 532건(기존 무시 1), 온톨로지 실행기 4건을
검증했다. 결정 색인·수치 검사와 `git diff --check`도 통과했다.
원장 19개 행의 기존 다섯 열과 `tasks.json`·`daemon_rules.json`의 관문은
수정 전과 일치한다. 실제 접근·수집·배포는 실행하지 않았다.

이 문서는 문서 정합성 finding의 완료 증거다. [09 제품 목적 대응표](../proposals/설계검토_결과/09_제품목적_대응표.md)의
P01~P19 실제 수집·검수·상품/계약 트윈·소비자 화면·사용자 시험·첫 출시
완료 증거를 대신하지 않는다.
