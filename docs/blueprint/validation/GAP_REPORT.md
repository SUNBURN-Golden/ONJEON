## 1. 네 가지 질문의 답

### 1.1 면책(대기기간·제외)

표현됨: 기산일 포함 여부("그 날을 포함하여 90일이 되는 날의 다음날"), 부활 시 기산일 교체, 원인별 면책 해제(재해면 계약일부터), 고의 사고와 심신상실 예외, 코드 범위 제외. 엔진의 `date_add`·`if`·3값 논리로 경계일 사례가 모두 맞았다(`kyobo-cancer-main-dx` k01·k02·k05·k06).

모자람:
- 면책 기간 단위가 다르다. 2026년 상품은 90일, 1995년 상품은 3개월이다. 둘을 같은 값으로 정규화하면 지급 판정이 바뀐다(2026-06-01 계약, 08-31 진단에서 결과가 갈림. 테스트 `waiting_period_units_are_not_interchangeable`). 단위를 그대로 저장한다(G13).
- 면책 예외가 다른 급부로 지급을 넘긴다. 종신보험의 2년 후 자살은 지급 거절이 아니라 질병사망보험금, 심신상실 자해 사망은 재해분류표에서 빠지는데도 재해사망보험금이다. 결과가 "지급/불지급" 두 값이 아니다(G10). 지금은 서로 배타인 규칙 두 개와 `routes_to` 간선으로 표현했고, 108개 조합에서 둘이 동시에 지급되지 않음을 테스트로 확인했다.
- 질병 코드 판정은 DSL 밖이다. 약관은 "진단 시점의 KCD로 판단, 이후 개정으로 다시 판단하지 않음"을 규정한다. 코드 체계·개정차수·판정 시점 없이는 같은 코드라도 결과가 달라진다(G08).
- 계약 무효(보장개시 전 장기요양상태 → 무효·보험료 반환)는 지급 결과가 아니라 계약 효과다. Payout이 담지 못한다(G23).

### 1.2 감액

표현됨: 기간 감액(1년 미만 50%), 기산일이 갱신 후에도 최초계약인 경우, 계약해당일 전일까지라는 경계 정의. 원인별 감액(1년 미만이라도 재해면 100%)은 조건으로 표현할 수 있다.

모자람:
- 2월 29일 계약의 계약해당일, 해당일이 없는 달의 "3개월이 지난 날", "2년이 지난 후" 당일 포함 여부를 약관이 적지 않았다. 엔진은 말일 고정(clamp)으로 계산하지만 원문 근거가 없는 가정이다(G13).
- 금액이 예시로만 적혀 있다("1,000만원 기준 200만원"). 비율로 바꾸는 것은 해석이므로 `derived`로 저장했다(G06).
- 반올림 규칙이 원문에 없으면 엔진은 범위를 낸다(k13). 의도대로다.

### 1.3 특약 종속·갱신

표현됨: 부가(`attached_to`), 의무부가(`mandatory_with`), 주계약 소멸 시 소멸과 예외(`terminates_with` + 조건), 최종 갱신 종료일 상한(`renewal_bounded_by`), 급여·비급여 배타(`excludes`), 외부 공시값 참조(`parameter_from`). 모두 근거 조항이 붙은 간선으로 넣었다.

모자람:
- 같은 개념의 기준이 회사마다 다르다. 교보는 최종 갱신을 주계약 종료일(날짜)로, KB는 기본계약 종료나이(나이)로 정한다. 조문 번호도 표준약관과 상품이 다르다(제5조 → 제6조, 제37조 → 제41조). 번호·이름으로 의미를 매핑하면 안 된다(G22).
- 갱신을 넘는 상태가 규칙 입력이 된다(갱신 전 계약에서 지급된 같은 소액암은 재지급 안 함). 지급 이력 누적이 필요하다(G05).
- 같은 이름의 채널 변형(교보통합암보험 / [D])이 공시에 따로 있다. 약관 대조 전에는 병합하지 않는다(G26).

### 1.4 가격 조건

표현됨: 금액·납입주기·조건·구성·기준일·관측일·가격 근거·비교 기준. 요약서의 남/여 주계약·특약 보험료가 협회 공시와 같은 값임을 교차 확인했다. 원문이 직접 공시한 "주계약 + 특약" 묶음 금액은 `source_bundle`로 저장했다(임의 합산 아님).

모자람:
- 조건이 표 밖에 있다. 성별은 소제목("1. 남자")에, 월보험료는 소제목 괄호("남자(21,100원)")에, 협회 목록의 나이·만기는 다른 문서(작성기준 팝업)에 있다(G16).
- 협회 목록 금액은 요약서의 100세만기 예시와 같은데 협회 작성기준은 80세만기다. 어느 조건의 값인지 판별할 수 없어 `condition_mismatch`로 보류했다. 작성기준 표에는 오기로 보이는 값(간병 보험기간 "90년", 납입기간 "20세")도 있다(G16).
- 가격 차원이 상품군마다 다르다. 운전자보험은 상해급수·운전형태·플랜형·이율 시나리오·천원 미만 절사가 조건이다(G17).
- 운전자보험 예시는 8개 담보 묶음 금액뿐이고, 묶음의 벌금 특약은 인코딩한 벌금 특약과 다른 종류다. 묶음 가격을 특약 가격으로 쓰면 안 된다(G18).
- 나이×성별×납입기간 보험료 격자는 어느 표본에도 없었다. 상품마다 40세 한 점이다. 대부분의 사용자에게 공개 가격은 "내 조건 아님"이 된다(G19).

## 5. rule-0.2 후보 (구현은 M2 이후, 실제 표본이 요구하는 순서)

모든 연산은 허용 목록에 들어가고, 부동소수점을 쓰지 않으며, 반올림을 명시하고, 미확인을 0으로 바꾸지 않는다.

1. `multiply_count(money, int)` → money. 횟수·일수는 0 이상 정수. (G01)
2. `subtract_floor0(money, money)` → money, 음수면 0. (G02)
3. `pro_rata(money, part, whole, {rounding, unit})` → money. `whole=0`이면 오류가 아니라 unknown. (G03)
4. `divide_count(money, int, {rounding, unit})` → money. 균등 배분과 1일 평균. (G03)
5. `anniversary_band(date_from, date_at, [[years, value]...])` → 구간 값. 구간은 경계 포함 규칙을 명시. (G14)
6. 목록 입력 타입과 `max_over`. 같은 시점 사건 목록에서 동치류별 최고값. (G04)
7. EvaluationResult `contract_effect`: none / void_refund_premium / terminated_pay_reserve. (G23)

코드 집합 판정(G08), 시간 단위 판정(G09), 누적 사용량(G05), 외부 파라미터 조회(G07)는 DSL에 넣지 않는다. 각각 사전·입력 단계·계약 트윈·ParameterTable이 판정하고, 규칙은 판정 결과와 그 근거 참조를 입력으로 받는다. 규칙의 `inputs_from_outside_dsl`에 그 입력을 모두 적는다.

## 6. 이 검증이 증명하지 못하는 것

- 표본은 2개 회사(교보생명, KB손해보험)와 공시 2곳이다. 다른 회사의 문서 형식을 대표하지 않는다. 전체 대상 추적은 `data/registry/`가 한다.
- 인코딩은 같은 계열 AI 한 번의 해석이다. 다른 계열 검증(ADR-0006)을 거치지 않았다. 해석이 틀렸을 수 있다.
- 원문 대조는 추출 텍스트와의 대조다. 표의 행·열 대응은 좌표로 확인하지 않았다(그래서 해당 값은 hold).
- 규칙 사례의 기대값은 약관 문장에서 만든 것이고 보험사 실제 지급 사례가 아니다. 약관에 실린 계산 예시(변호사비 예시 1·2)만 공개 계산 예시다.
- 가격은 상품당 한 점이라 가격 비교 기능의 실제 유용성은 아직 검증하지 못했다.
