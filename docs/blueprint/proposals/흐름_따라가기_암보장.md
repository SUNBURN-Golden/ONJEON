# 소비자 행동 하나로 책임 구조 따라가기: "이미 보험이 있는데 암 보장을 더 알아보고 싶다"

상태: **토의 자료. 미확정.** 2026-10-10 | 바탕: [소비자 기능과 전체 구조 토의 자료](소비자_기능_필요정보.md) §3.7의 책임 구조(사용자 제안)

- 목적은 책임 구조(수집·문서 복원, 지식·검수, 계산 엔진, 필요성·비교 판단, 서비스 조합, 화면·대화, 그리고 별도 경계인 개인정보 영역)에 행동 하나를 흘려 보고, **빈틈과 중복 책임**을 찾는 것이다. 필드 형식은 정하지 않는다.
- 등장하는 사람과 계약은 **가상**이다. 상품명은 조사에서 실제로 본 이름을 썼다. 가입금액 같은 계약 사실은 "증권에서 읽었다고 가정한 값"이다. 약관의 면책·감액 같은 조건은 이 문서에서 값을 지어내지 않고 "약관에서 확인"으로만 적는다.

## 0. 가상 사용자

- 40대. 보험 몇 개를 가지고 있다. 그중 하나는 증권에 "(무)현대해상굿앤굿1540종합보험(Hi2607)"으로 적혀 있다고 가정한다.
- 처음 한 말: "보험은 몇 개 있는데, 암 보장을 더 알아보고 싶어요."

## 1. 흐름

각 단계마다 **누가 무엇을 읽고, 무엇을 판단하고, 무엇이 부족하면 묻고, 무엇을 넘기는지** 적었다.

### 1단계. 의도 이해

| 영역 | 하는 일 |
|---|---|
| 화면·대화(AI) | 말을 해석한다: 관심 위험은 암, 하려는 일은 알아보기(추가 가입이 정해진 것은 아님), 기존 계약이 있음. 해석을 **사용자의 의도로** 되묻는다: "지금 가진 보험으로 암에 얼마나 대비되는지 보고, 더 필요한지 알아보려는 거죠?" |
| 넘기는 것 | 확인된 의도(관심 위험: 암 / 목표: 현재 대비 확인 → 필요 시 비교)를 서비스 조합에 |

AI는 이 단계에서 "암보험이 필요하다"고 말하지 않는다. 필요한지는 4단계의 판단이다.

### 2단계. 기존 계약 확보

| 영역 | 하는 일 |
|---|---|
| 서비스 조합 | 이 질문의 결론에 기존 계약이 **결과를 바꾸는 조건**이라는 것을 안다(기존 암 보장에 따라 결론이 달라짐). 그래서 계약 자료를 요청하는 다음 행동을 만든다 |
| 화면·대화 | "가지고 계신 보험 증권을 올려 주시면 지금 암 보장을 먼저 확인할게요. 나중에 하셔도 돼요." 올리지 않으면 기존 보장을 **미확인**으로 두고 진행한다 |
| 개인정보 영역 | 올린 PDF를 보관한다. 다른 영역에는 필요한 사실만 내준다 |
| 문서 복원(개인 문서) | 증권 PDF에서 회사, 상품명, 가입일, 담보·특약, 가입금액을 읽는다 → **빈틈 G2** |
| 화면·대화 | 읽은 사실을 사용자에게 확인받는다(사용자의 사실): "현대해상 굿앤굿1540종합보험(Hi2607), 가입일 ○○, 암진단II(유사암제외) 1,000만 원, 유사암진단Ⅱ 200만 원이 맞나요?" (금액은 가정) |

### 3단계. 계약을 판매 구성과 약관에 잇기

| 영역 | 하는 일 |
|---|---|
| 지식·검수 | 상품명·가입일로 판매 구성 후보를 낸다. 이 이름은 조사에서 손보협회에 공시행 둘("건강고지Ⅰ", "일반심사")로, 회사 목록에 같은 이름 두 행으로 나왔다. 후보가 둘이고 관계는 미확인이다 |
| 누가 연결을 확정하나 | 사용자의 계약을 특정 판매 구성과 그 가입일의 약관 판에 잇는 일의 주인이 책임 구조 표에 없다 → **빈틈 G1** |
| 부족하면 묻기 | 사용자의 **사실**을 묻는다: "증권에 '건강고지'나 '일반심사' 같은 표시가 있나요?" 증권에 없으면 두 후보를 모두 두고 미확인으로 간다. 어느 쪽인지를 사용자에게 고르게 하지 않는다(해석 책임을 넘기지 않음) |
| 지식·검수 | 판매 구성이 정해지면 가입일 기준의 약관 판과 그 뒤 덧씌워지는 변경(갱신, 표준약관 소급 등)을 근거와 함께 낸다. 약관 판이 그 기간에 바뀌었을 수 있으면 그렇다고 낸다 |

### 4단계. 지금 계약으로 암에 얼마나 대비되나

| 영역 | 하는 일 |
|---|---|
| 지식·검수 | 해당 약관 판에서 암 관련 담보(암진단, 유사암진단 등)의 정의·면책·감액·횟수·한도를 낸다 |
| 계산 엔진 | 대표 사건 몇 개를 이 계약에 적용한다: 일반암 진단, 유사암 진단, 같은 사건을 가입일과 가까운 시점에 진단받은 경우 등. 결과는 금액과 3값 판정(확인됨·안 됨·미확인), 빠진 입력 |
| 판매 구성 미확인일 때 | 두 후보 각각으로 계산한다. **(5차에서 정정)** ~~결과가 같으면 미확인이어도 결론에 영향이 없다~~ → 결과가 같을 때는 "현재 확인한 두 후보에서는, 이 사건과 입력에 대한 계산 결과가 같습니다. 계약 연결은 아직 미확인입니다"라고만 말한다. 두 후보가 가능한 경우를 모두 포함하는지, 개인별 특별조건이 없는지 확인하지 않았다면 확정 지급액처럼 보이지 않는다. 특정 사건에서 결과가 같다고 두 계약이 같은 것도 아니다 |
| 넘기는 것 | 기준선: "지금 계약으로 일반암 진단 시 ○원, 유사암 ○원, 이 조건에서는 0원 또는 감액" + 각 조건의 근거 |

### 5단계. 더 필요한가(필요성 판단)

| 영역 | 하는 일 |
|---|---|
| 필요성·비교 판단 | 4단계 기준선, 사용자 상황, 판단 기준을 읽는다. 사용자 상황은 아직 거의 없다 |
| 판단 기준 | "암 진단 시 어떤 비용·소득 공백을 우선 고려하나"의 기준과 참고 통계(치료비 수준, 치료로 쉬는 기간 등)가 필요하다. **이번 조사는 이 자료를 다루지 않았다.** 그리고 이 기준을 누가 관리하는지가 책임 구조 표에서 빠졌다 → **빈틈 G3** |
| 부족하면 묻기 | 판단 기능이 "이 답에 따라 결론이 달라지는 입력"을 낸다. 예: 치료로 일을 쉬면 생활비를 얼마나 버틸 수 있는지, 부양가족이 있는지. 대화 AI는 그중 하나를 골라 쉽게 묻는다. 답하지 않으면 미확인으로 두고 결론을 조건부로 낸다 |
| 넘기는 것 | 선택지: 현재 유지 / 추가 검토(어떤 보장을 왜: 예를 들어 진단비 증액, 유사암 범위, 치료비형) / 보류. 각각의 이유와 득실, 미확인. "지금은 추가 가입이 필요하지 않을 수 있어요"도 정상 결론이다 |

### 6단계. 추가 검토를 고르면: 비교

| 영역 | 하는 일 |
|---|---|
| 화면·대화(AI) | 사용자의 선호를 해석해 **의도로** 되묻는다: "매달 보험료가 적은 쪽보다 보장 범위가 넓은 쪽이 중요하신 거죠?" 확인된 선호가 "사용자가 중요하게 보는 조건"이 된다 |
| 지식·검수 | 지금 판매 중인 암 관련 판매 구성, 비교 항목의 대응(대응이 확인된 것과 아닌 것), 공시 가격과 그 조건을 낸다 |
| 계산 엔진 | 사용자가 원하면 같은 사건(예: 유사암 진단)을 후보 상품들에 명시한 가정으로 적용한다. 정확성 기준은 4단계와 같다. 다른 것은 입력이 가정이라는 점이다 |
| 기존 계약과 합쳐 보기 | 추가 가입은 기존 계약과 **함께** 작동한다. 정액형은 약관이 따로 정하지 않는 한 계약마다 받고, 실손형은 여러 계약이 비례로 나눠 지급한다(실손 표준약관 제37조 "다수보험의 처리": "각 계약의 비례분담액을 지급합니다", 시행세칙 별표 15). 그래서 "기존 + 후보"를 한꺼번에 계산해야 득실이 맞다. 여러 계약을 함께 계산하는 일이 계산 엔진의 책임인지 명시되지 않았다 → **빈틈 G4** |
| 필요성·비교 판단 | 후보와 득실을 구성한다. 정렬은 사용자가 고른 조건으로만 한다 |
| 넘기는 것 | 후보별 조건 차이, 같은 사건 결과(기존 + 후보), 가격과 그 조건, 대응 미확인 항목 |

### 7단계. 서비스 조합

| 구성 | 이 사례에서 담기는 것 |
|---|---|
| 기준선 | 지금 계약으로 본 암 대비(4단계). 판매 구성 미확인이면 그 사실 |
| 후보·선택 | 현재 유지 / 추가 검토(후보 상품들) / 보류 |
| 이유와 차이 | 어떤 입력·선호 때문에 이 후보가 나왔나. 선택하면 무엇이 달라지나 |
| 근거 | 약관 사실, 공시 사실(가격·판매 상태), 사용자 입력, 판단 기준(판), 계산 결과를 구분 |
| 조건(네 가지) | 적용을 막는 조건, 결과를 바꾸는 조건, 사용자가 중요하게 보는 조건(6단계에서 확인된 선호에서만), 추가 설명. **개수 제한 없음** |
| 범위 | 비교 범위(어느 회사·상품까지), 상품별 확인 상태(조건·가격·계산), 빠진 후보와 이유. 예: 생보사 상품은 협회 비교공시를 수집하지 않아 가격을 확인하지 못함 |
| 불확실성 | 판매 구성 미확인(건강고지Ⅰ/일반심사), 답하지 않은 입력, 그 기간 약관 미확인 등. 확인하면 어떤 결론이 바뀌는지 |
| 다음 행동 | 증권 표시 확인, 질문에 답하기, 비교 조건 바꾸기, 사건 바꿔 보기, 근거 열기 |
| 판 참조 | 지식 릴리스, 판단 기준의 판, 규칙의 판 |

### 8단계. 화면·대화

첫 화면은 짧게, 그러나 적용을 막는 조건과 결과를 바꾸는 조건은 개수와 관계없이 빠뜨리지 않는다. 예시(값은 가정, 문구는 토의용):

> 지금 보험으로 암 진단을 받으면 약 ○원을 받을 수 있어요.
> 다만 가입 후 일정 기간 안의 진단, 유사암은 금액이 달라져요. [조건 보기]
> 이 결과는 계약 종류 하나가 확인되지 않은 상태예요. 증권에 표시가 있는지 봐 주세요. [확인하기]
> 더 알아보기: 현재 유지 · 보장 추가 검토 · 나중에

"사용자가 중요하게 보는 조건"은 사용자가 선호를 밝힌 뒤에만 앞으로 나온다.

## 2. 드러난 빈틈

| 번호 | 빈틈 | 왜 문제인가 | 토의할 선택지(정하지 않음) |
|---|---|---|---|
| G1 | **개인 계약 연결의 주인이 없다.** 사용자의 계약을 판매 구성과 가입일의 약관 판(덧씌움 포함)에 잇는 일 | 사건 계산·필요성 판단·비교(기존 + 후보) 모두 이 결과를 쓴다. 주인이 없으면 기능마다 따로 하게 되고 서로 다른 답이 나온다 | (가) 지식·검수가 후보와 규칙을 내고, 연결 확정은 개인정보 경계 안의 별도 단계가 한다 (나) 계산 엔진 앞단에 둔다 (다) 필요성·비교 판단이 각자 한다 |
| G2 | **개인 문서 복원의 위치.** 수집·문서 복원은 공개 자료를 다룬다. 사용자의 증권 PDF도 같은 기술로 읽어야 한다 | 같은 추출기를 쓰되, 개인 문서와 그 결과가 공개 영역에 섞이면 안 된다(공개 지식 영역에 개인 식별자 없음, ADR-0018) | 기술은 공유하고 실행·저장은 개인정보 경계 안에서 한다는 규칙 |
| G3 | **판단 기준의 주인.** 2차 구조에는 "판단 기준" 영역이 따로 있었는데 4차 책임 표에는 없다 | 판단 기준은 판과 근거가 있는 지식이고, 약관 지식과 다른 종류다. 누가 만들고 검수하고 판을 올리는지 정해야 한다. 참고 통계 자료도 아직 없다 | (가) 지식·검수가 함께 관리하되 종류를 구분 (나) 별도 영역 (다) 필요성·비교 판단 안에 둠 |
| G4 | **여러 계약을 함께 계산하는 책임.** 기존 + 후보, 실손의 비례 분담, 정액의 중복 지급 | 하나씩 계산해서 더하면 실손에서 틀린다(표준약관 제37조). 기존 V1 검증에서 규칙 엔진 v0.1은 실손의 비례분담을 "표현 불가"로 기록했다(`docs/blueprint/validation/GAP_REPORT.md` 표 2행, G03) | 계산 엔진의 책임으로 명시. 여러 계약 입력과 나눗셈 표현이 필요 |
| G5 | **조건 네 가지 분류를 누가 붙이나.** 적용을 막는·결과를 바꾸는 조건은 지식과 계산에서, 사용자가 중요하게 보는 조건은 사용자 선호에서, 추가 설명은 지식에서 나온다 | 출처가 셋으로 나뉜다. 한 곳에서 일괄로 붙이면 세 번째가 "모두에게 중요"로 바뀔 위험이 있다 | 분류는 각 출처가 붙이고 서비스 조합은 모으기만 한다 |

## 3. 겹칠 수 있는 책임

| 번호 | 겹침 | 경계 후보 |
|---|---|---|
| O1 | 필요성·비교 판단과 서비스 조합이 둘 다 "구성"한다 | 판단은 후보와 득실을 정한다. 서비스 조합은 새 판단(후보 걸러내기, 순서 바꾸기)을 더하지 않고, 모으고 일관성(근거·범위·판 참조가 빠지지 않았는지)만 검사한다 |
| O2 | 질문을 고르는 일: 판단 기능은 "결론을 바꾸는 입력"을 알고, 대화 AI는 무엇을 먼저 물을지 고른다 | 판단 기능은 후보 질문 목록과 각 질문이 바꾸는 결론을 낸다. AI는 그 안에서 순서와 말을 고른다. 목록 밖 질문으로 결론을 바꾸지 않는다 |
| O3 | 미확인이 지식(확인 상태), 계산(3값), 판단(결론이 바뀌는지), 조합(불확실성)에 모두 나온다 | 같은 어휘로 끝까지 전달한다(기존 상태 어휘의 `value_state`·`tri` 등). 영역마다 새 이름을 만들지 않는다 |
| O4 | "빠진 후보와 이유": 지식은 자료 확보 상태를, 판단은 걸러낸 이유를 안다 | 두 영역이 각자의 이유를 내고 서비스 조합이 합친다 |

## 4. 이 흐름에서 다시 확인된 원칙

- 사용자에게는 사실과 의도만 확인받는다(2·3·6단계). 해석·분류는 지식과 규칙이 한다.
- AI는 질문을 고르고, 의도를 해석하고, 설명을 구성한다. 지급액·가격·적용 조건을 만들지 않는다.
- 조사에서 가설이었던 관계(건강고지Ⅰ/일반심사와 회사 목록 두 행의 대응)는 화면에서도 미확인이다.
- **(5차에서 정정)** 판매 구성이 미확인이면, 후보들의 계산 결과가 같더라도 "확인한 후보 안에서 이 사건·입력에 대한 결과가 같다"까지만 말하고 연결 미확인을 함께 보인다(4단계).

## 5. 5차 토의 뒤: 새 책임 구조로 다시 본 빈틈 (구현자 정리, 합의 전)

책임 구조는 [소비자 기능과 전체 구조 토의 자료](소비자_기능_필요정보.md) §3.8(사용자 제시)에 있다. 각 빈틈이 어디로 가는지:

| 빈틈 | 맡는 영역 | 남는 확인 |
|---|---|---|
| G1 개인 계약 연결 | 비공개 개인 영역(공통 지식이 후보와 연결 근거 제공) | 아래 ①② |
| G2 개인 문서 복원 | 비공개 개인 영역(추출 기술은 재사용, 저장·권한 분리) | 추출 워커가 개인 영역에서 돌 때도 기존 원칙(추출 워커에 저장소 쓰기·외부 전송 권한 없음, DATA_PIPELINE_CONTRACT §5)을 따른다 |
| G3 판단 기준의 주인 | 판단 기준 관리 | 참고 자료가 공개 자료라면 그 수집·보존은 공개 자료 기반의 일이다(아래 ④) |
| G4 여러 계약 계산 | 공통 계산 엔진 | 지원하지 않는 관계는 "관계 미지원"으로 돌려준다(합산하지 않음) |
| G5 조건 분류 | 지식(제한 조건)·엔진(이번 사건의 영향)·개인 영역(선호)이 각자 붙이고 보존 | 한 조건에 여러 성격이 함께 붙을 수 있다 |
| O1 판단과 조합의 경계 | 서비스 조합의 책임을 넓힘(호출, 릴리스 혼합 검사, 오류·미확인 전달) | 순위·지급 조건을 바꾸지 않는다 |

**이 구조에서 확인하면 좋을 점(승인 요청이 아니라 다음 단계의 확인 항목):**

1. **개인 계약 표현에도 판이 필요하다.** 사용자가 사실을 고치거나 새 증권을 올리면, 또는 공통 지식의 새 릴리스로 연결 근거가 바뀌면, 개인 계약 표현의 판이 바뀐다. 서비스 조합이 "섞이지 않았는지" 확인할 대상은 지식 릴리스, 판단 기준의 판, 규칙의 판, 그리고 **개인 계약 표현의 판**이다.
2. **의존 방향은 한쪽이다.** 개인 영역은 공통 지식을 읽지만, 공통 지식은 개인 영역을 읽지 않는다(공개 지식 영역에 개인 식별자 없음, ADR-0018. 개인 계약에서 발견한 누락 상품 자동 전달 없음, O18). 그래서 공통 지식의 판단이 바뀌면(예: [데이터 모델 토의 보완안](데이터모델_토의_보완안.md)의 병합·분리), 개인 영역이 새 릴리스를 받아 **스스로** 자기 연결을 다시 점검해야 한다. 공통 지식이 "누구의 계약이 영향을 받는다"를 알 수 없기 때문이다.
3. **공통 계산 엔진은 개인 정보를 저장하지 않는다.** 개인 입력으로 실행한 결과는 개인 영역에만 남는다. 엔진은 같은 코드로 공개 상품 트윈(가정 입력)과 개인 계약 표현(실제 입력)을 모두 계산한다.
4. **공개 자료 기반(수집·문서 복원)의 자리.** 이번 책임 표에는 "공통 보험 지식"이 맨 아래에 있다. 공시 원문을 모으고 보존하는 수집·문서 복원은 그 아래에 그대로 있고, 판단 기준의 참고 자료가 공개 자료라면 같은 수집·보존 원칙(원본 보존, 출처·시각 기록)을 따르는 것이 일관된다.
5. **개인별 특별조건.** 부담보·할증 같은 인수 조건은 증권·청약서에만 있다. 그 뜻(어떤 담보를 어떻게 제한하나)은 공통 지식이, 값(이 사람에게 무엇이 붙었나)은 개인 영역이 갖는다. 4단계의 "특별조건이 없는지 확인하지 않았다면 확정 지급액처럼 보이지 않는다"가 이 연결에 기대고 있다.
