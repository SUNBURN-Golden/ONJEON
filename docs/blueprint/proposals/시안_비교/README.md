# 같은 상황으로 비교: 화면 시안 (21차, 토의 자료)

> 이 폴더는 **토의 자료**입니다. 설계 결정이 아니고, 구현 범위나 계약 문서에 반영하지 않았습니다.
> 표기: **진행 지시(사용자)** · **토의상 제안(사용자)** · **검토 의견(구현자)**

- `비교_시안.html`: 단독으로 여는 화면 시안(390px 한 화면).
- `검증/run.js`, `검증/결과.txt`: 자동 실행 검증과 그 결과.
- `캡처/`: 기본, 가입 후 2년, 현대해상 근거를 펼친 상태.

## 1. 이번 차수에 받은 지시와 제안

**진행 지시(사용자)**
- 세 화면(A·B·C)은 일단 확정하고 비교 화면으로 넘어간다. 사용자 시험은 나중에 하며, 이번 단계의 전제가 아니다.
- A와 C를 구분하는 일은 나중에 진입 제목('상황을 가정해 보기' / '내 사건 확인')으로 처리한다. 지금 세 화면을 다시 고치지 않는다.
- 차이가 분명한 상품을 3개쯤 고른다. 확인된 실제 자료만 쓰고, 모르는 것은 모른다고 표시한다. 보험료나 금액을 지어내지 않는다.
- 9개 보험사 126개는 우선 **"확보한 공시에서 찾은 비교 후보"**로만 본다. 서로 다른 상품인지, 같은 기준으로 비교할 수 있는지는 따로 확인해야 한다. 담보명에 '암 진단'이 들어 있다고 같은 보장으로 묶지 않는다.

**토의상 제안(사용자): 비교 화면 구성**
- 먼저 보여 줄 것: "같은 상황을 넣었을 때 무엇이 같고 무엇이 다른가".
- 맨 위: 상황과 공통 가정(진단 상황, 가입 후 경과 기간, 최초 진단 여부). 짧게, 바꿀 수 있게.
- 상품마다 같은 자리에: 계산한 금액, 또는 계산하지 못한 이유. 가입금액을 지급액처럼 보여 주지 않는다.
- 차이를 나란히: 지급 대상, 제외, 감액 기간, 갱신 여부.
- 보험료: 조건이 같을 때만 바로 비교한다. 다르면 공시마다 조건을 붙인다. '최저가' 표시와 가격순 정렬은 하지 않는다.
- 근거 조항과 전체 조건은 접는다. 결과를 바꾸는 조건은 금액 가까이에 둔다.
- 비교 화면에서 상황 → 금액 → 중요한 차이 → 근거 순서로 잘 읽히는지 확인한다.

**상품을 고른 이유:** 같은 "위암, 처음 받는 진단금"을 넣어도 결과가 세 가지로 갈립니다.
- 하나손보: 계산되지만 1년 안에는 50%가 됩니다.
- 현대해상: 약관으로 계산되고 감액이 없습니다.
- 롯데손보: "일반암"의 정의가 공시에 없어 계산을 보류합니다.

이 밖에도 비갱신과 갱신, 제외 범위의 차이(유방암·생식기암 제외 / 유사암 제외), 공시에 없는 항목이 실제로 있습니다.

**계산 방식:** 공시 예시 가입금액 1,000만 원에 공시 문구나 약관 조건을 손으로 적용했습니다. 계산 엔진은 연결하지 않았습니다.

**검토 의견(구현자): 시안이 정한 표시 방식**
- 하나손보의 50% 감액은 공시 문구로만 적용했습니다. 보장개시일과 '1년 미만'을 세는 기준일은 약관으로 확인하지 못했고, 화면과 접힌 근거에 미확인으로 적었습니다.
- 롯데손보는 금액 대신 "계산 보류"와 그 이유를 같은 자리에 두었습니다. "일반암에 든다면"이라는 조건부 금액은 이유 아래 작은 글씨로만 두었습니다.
- 롯데손보 공시는 보험료 조건이 "일반심사형"인데 담보명에는 "간편맞춤형Ⅱ"가 붙어 있습니다. 둘이 맞지 않는 점을 근거 안에 적었습니다.
- 현대해상의 "지급 횟수 최초 1회"(2-5 제1조)와 "1년 안 감액 없음"은 공시가 아니라 약관에서 가져왔습니다. 감액 없음은 약관 PDF 117쪽(상품안내 지급제한표)의 암진단Ⅱ(유사암제외) 행에서 "1년미만 보험금 감액여부"가 "-"인 것을 이미지로 확인하고 "없음"으로 읽은 것입니다. 같은 담보에 "(감액및면책기간미적용)" 판(2-246)이 따로 있는데, 이는 90일 면책을 없앤 판으로 보이지만 확인하지는 않았습니다. 표에는 출처를 따로 적지 않았고, 접힌 근거에만 적었습니다. 표 안에서 출처를 구분할지는 토의할 거리입니다.
- 보험료는 세 공시의 조건이 모두 달라 나란히 비교하지 않았습니다. 각 금액 아래 조건을 붙이고, 순서는 보험사 이름 가나다순이라고 밝혔습니다.
- 보험료 "(남)"은 공시 필드 `TP_M_BILL`을 남자 보험료로 읽은 것입니다(`TP_W_BILL`은 여자).

## 3. 126개 후보 수치에 대한 정정

**검토 의견(구현자):** 앞서 말한 "9개 보험사 126개"는 아래 방식으로 센 숫자입니다.
- PB*.json의 `list`에서, 담보명(`TP_PAY_NAME`)에 `암진단|암\s*진단`이 들어간 행만 골랐습니다.
- 그중 '유사암'과 '소액'이 들어간 담보는 뺐습니다.
- 이렇게 걸러진 행을 가진 공시행을 상품 하나로 세었습니다.

이 기준은 느슨해서, 다음과 같은 담보만 있는 상품도 같이 들어갔습니다.
- 유방암및생식기암, 갑상선암, 기타피부암, 제자리암, 대장점막내암
- 특정암, 고액치료비암, 전이암

같은 스크립트로 다시 세어 보니, 이렇게 부위나 특정암으로 한정된 담보만 있는 상품이 **53개**였습니다. 이를 빼면 **6개 보험사 73개**가 남습니다.

남은 73개도 같은 보장이라고 볼 수 없습니다. 이번 세 상품만 봐도 "일반암", "암(유방암·생식기암 제외)", "암(유사암 제외)"처럼 지급 대상의 정의가 다릅니다. 상품을 몇 개로 볼지도 아직 정하지 않았습니다. 예를 들어 심사 유형만 다른 공시행을 한 상품으로 볼지, 따로 볼지의 문제입니다. 그래서 126과 73은 모두 "확보한 공시에서 찾은 비교 후보"의 대략적인 크기일 뿐입니다.

## 4. 검증한 것과 하지 않은 것

**한 것.** `node 검증/run.js 비교_시안.html 캡처`로 실행했고 결과는 `검증/결과.txt`에 있습니다. 실패는 0건입니다. 확인한 내용은 다음과 같습니다.
- 위에서 아래로 놓인 순서: 상황 → 공통 가정 → 경과 기간 → 금액 → 차이 → 보험료 → 근거.
- 세 상품의 금액 또는 이유가 같은 자리(오른쪽 위)에 있는지.
- '최저가', '추천' 같은 문구가 없고, 보험료 순서가 상품 순서와 같은지.
- 경과 기간을 8개월과 2년으로 바꿀 때 금액, 50% 줄, 롯데 조건부 문구가 바뀌고 되돌아오는지.
- 근거를 펴고 접을 수 있는지.
- 시안 전용 버튼 2개(뒤로, 바꾸기)를 누르면 안내가 뜨고 상태는 바뀌지 않는지.
- 겹침이나 잘림이 없는지, 390px 화면에서 가로 스크롤이 없는지, 콘솔 오류가 없는지.

캡처를 눈으로 본 뒤에는 한국어 단어가 줄 중간에서 끊기는 문제(예: "약/관을")를 단어 단위 줄바꿈으로 고쳤습니다.

**하지 않은 것.**
- 사용자 시험은 하지 않았습니다. 사람들이 이 화면을 잘 이해하는지는 확인되지 않았습니다.
- 롯데손보와 하나손보의 약관은 확보하지 않았습니다.
- 공시 문구가 실제 판매 조건과 같은지는 확인하지 않았습니다.
