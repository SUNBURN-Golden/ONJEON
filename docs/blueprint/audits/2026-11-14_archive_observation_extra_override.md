# Audit 6 — 원본 관측의 핵심 필드 우선 병합

대상: `audit6-archive-observation-extra-override`, `tools/source_archive.py::put_observation`.
연결: Blueprint A1·Q7·L1·I6·M1, 09 제품 목적 대응표 P02·P03.

기준 코드에는 [Audit 2 예약 키 거부](2026-10-26_archive_extra_reserved_keys.md)가
이미 적용되어 있어 일반 CLI 입력으로 핵심 필드를 덮어쓸 수 없었다.
다만 레코드 구성은 여전히 핵심 필드 뒤에 `rec.update(extra)`를 실행했다.
이를 `{**extra, **core}`로 바꿔 예약 키 검증과 독립적으로 핵심 필드를 우선한다.
기존 CLI·함수의 예약 키 거부 계약은 유지한다.

관측은 JSON 바이트가 같아야 재실행 시 `already_present`가 된다.
병합 순서만 뒤집으면 정상 추가 정보가 JSON 앞에 와서 과거 레코드와 충돌하므로,
직렬화는 기존의 핵심 필드 → 추가 정보 순서를 유지한다. 직렬화하는 값은 모두
핵심 필드 우선 병합 결과에서 읽으며, 호출자의 `extra`는 변경하지 않는다.

`tools/tests/test_source_archive.py`에 두 회귀 시험을 추가했다.

- 예약 키 검증만 모의 우회하고 핵심 필드 7개를 각각 위조한다. 다른 실제 보관 객체의
  유효한 SHA-256·객체 키도 사용한다. 최종 레코드, 원본 바이트 연결, 해시와 추가 정보
  보존을 검사한다. 이는 병합 자체의 독립 방어 시험이며 일반 CLI에서 우회를 허용하지 않는다.
- 과거 순서로 직렬화한 관측을 먼저 저장하고 정상 메타데이터로 재실행한다.
  `already_present`와 기존 바이트 보존을 검사한다.

수정 전 새 시험은 7개 필드 사례 모두 실패했다. 수정 후 아카이브 시험 74개가 통과했다.
기존 시험은 예약 키의 같은 값 입력·비객체 입력 거부, 저장 전 CLI 거부,
정상 중첩 메타데이터·충돌·재실행·기존 보관 내용 보존을 계속 검증한다.
전체 실행 명령·결과·로그는 [증거 안내](../../../tools/evidence/audit6-archive-observation-extra-override/README.md)에 기록한다.

로컬 임시 보관소와 모의 서비스 기반 검증이며 실제 R2 요청이나 공시 수집을 수행하지 않았다.
P02·P03의 실제 확보율·관측 목록 대조·변경 재처리·트윈·소비자 화면·첫 출시 완료는
이 finding의 완료와 별도로 판정한다.
