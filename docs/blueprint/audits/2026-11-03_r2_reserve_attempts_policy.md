# Audit 4 — 입장 예산과 예약 시도 횟수 정합성

대상 노드: `audit4-r2-reserve-attempts-policy`.
제품 연결: A1·A2·A4 / Q7 / L1 / I1 / M1, 제품 목적 대응표 P02·P03의 원본 보관 비용 통제 기반.

일반 예약의 첫 시도는 입장 PUT, 입장 LIST, 체크포인트 LIST, 원장 LIST,
예약 PUT으로 Class A 5회를 쓴다. 412 경합 뒤에는 입장 LIST, 원장 LIST,
예약 PUT으로 3회를 추가한다. 입장 한도 8회에서 가능한 총 시도는 2회인데
정책은 5회를 허용했다. 두 번 경합하면 세 번째 시도를 준비하다가
`class_a would reach 9 > limit 8`로 중단해 실제 원인인 경합 소진을 가렸다.

`infra/r2/budget_policy.json`의 `reserve_attempts`를 5에서 2로 낮춘다.
입장·전체·작업 예산은 유지한다. 변경 직전 정책 SHA-256
`6d9e33cab2227c6d53e9838c6043b73911fc38802fe54895f6f13ce98325efc9`를
`previous_policy_sha256`에 추가해 기존 정책으로 쓴 원장을 계속 검증한다.
공통 시험 정책도 총 2회 시도로 맞춘다.

루프백 S3 스텁과 실제 botocore 요청으로 배포 정책의 요청·입장 한도를 사용해 검증한다.

- 첫 PUT 직전에 경쟁자의 유효한 원장 기록을 넣어 412를 발생시키고, 새 기록을
  읽은 두 번째 시도가 성공하는지 확인한다. 서버가 받은 Class A는 정확히 8회다.
- 두 번 모두 경쟁자가 먼저 기록하면 정확히 두 번의 412 뒤
  `could not reserve after 2 attempts (concurrent runs)`로 종료하는지 확인한다.
  입장 기록은 남고 예약·보관소 접근은 허용되지 않으며 로컬 잠금은 해제된다.
- 변경 직전 정책 해시로 쓴 기록을 새 정책의 허용 해시 목록으로 검증한다.

수정 전 두 경합 시험은 실패 1개·오류 1개로 위 Class A 오류를 재현했다.
수정 후 새 회귀 시험 3개·R2 시험 131개가 통과했고, 전체 Python은
1,329개 실행·1,323개 통과·기존 건너뜀 6개·실패/오류 0이다.
Rust 작업 공간은 478개 통과·기존 무시 1개, 별도 온톨로지 실행기는 3개 통과했다.
정책·제품 목적·설계·문서 정합성 검사도 통과했다.
명령과 수정 전후·전체 시험 결과는
[검증 증거](../../../tools/evidence/audit4-r2-reserve-attempts-policy/README.md)에 기록한다.

이 계산은 추가 HTTP 재시도·목록 페이지·체크포인트 쓰기가 없는 일반 예약 기준이다.
추가 비용이 생기면 기존 계량기가 입장 한도에서 먼저 차단할 수 있다.
로컬 도구 회귀 증거이며 실제 R2 접근·공시 확보율·관측 목록 대조·소비자 화면·
첫 출시 완료 증거를 대체하지 않는다.
