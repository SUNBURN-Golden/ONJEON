# 화면·조작 설계서 v0.1: 내 설계 탭

2026-10-08 | 제3부 §44의 하위 문서 | 기준 화면 `docs/design/내설계_기준화면.png`

## 0. 문서의 지위

- 첨부 화면(내 설계 탭)을 **주 기준으로 고정**한다. 월 예산 슬라이더, 현재 유지/보완안 탭, 담보 목록은 그대로 살린다.
- 시안과 다른 부분은 모두 §2 "시안 대비 추가·변경"에 적는다. 거기에 없는 변경은 허용하지 않는다.
- 시안의 금액·문구는 가상 예시다. 실제 데이터에서는 가격 라벨과 기준일이 붙는다(§5).
- 수치는 시안 이미지(853×1843 px)를 390×844 dp로 환산한 실측이다(환산 계수 0.457). 오차는 ±2dp이며 색은 안티앨리어싱 때문에 ±6 정도 오차가 있다. P0에서 디자인 도구로 원본 에셋과 대조해 토큰을 확정한다.
- 접근성은 목표가 아니다(제3부 §51.4). 시각 완성도와 조작감이 우선이다.
- 관련 문서: 제3부 §44, §59.6, §60 / `docs/masterplan/가격_수집_명세.md`

## 1. 기준 화면 구성 (고정)

위에서 아래로 다음 순서다.

1. 상단 바: 좌측 "온전" 로고 글자, 우측 잠금 아이콘
2. 헤드라인 "나에게 필요한 만큼"과 보조문 "예산을 움직여 보장을 비교하세요."
3. 월 예산 라벨, 큰 숫자("15만 원"), 슬라이더(5만 원~30만 원), 고지 캡션 한 줄
4. 구분선
5. 세그먼트 탭 `현재 유지 | 보완안`
6. 담보 목록: 진단 보장, 입원·수술, 생활비 대비, 무엇이 달라지나요?
7. 주요 행동 버튼 "두 안 비교하기"
8. 잠금 캡션 "건강 · DNA 분석은 본인 전용"
9. 하단 탭바: 홈, 만약에, 내 설계(선택), 내 정보

시안은 상태바 영역이 없는 콘텐츠 기준이다. 실제 기기에서는 상단·하단 안전 영역을 별도로 더한다.

### 3.4 시안의 오차

시안의 슬라이더 썸 위치는 트랙의 약 44% 지점이다. 5~30만 범위에서 15만은 40%다. 구현은 값에 대해 선형으로 위치를 계산한다. 시안의 썸 위치는 따르지 않는다.

## 4. 조작 설계

### 4.1 월 예산 슬라이더

| 항목 | 규칙 |
|---|---|
| 범위 | 기본 5만~30만 원. 현재 보험료나 입력한 예산이 범위 밖이면 5만 원 단위로 범위를 넓힌다. 상한은 100만 원 |
| 단계 | 1만 원. 값은 정수 "N만 원"으로만 표시한다 |
| 초기값 우선순위 | ① 처음부터 준비하기에서 입력한 월 예산 ② 가입내역에서 확인된 현재 월 보험료 ③ 범위 중앙값(예시값으로 표시) |
| 드래그 | 값이 손가락을 따라 연속으로 변하지 않고 1만 원 단계로 붙는다. 큰 숫자는 단계마다 갱신한다 |
| 촉각 | 1만 원마다 약한 틱, 5만 원 배수에서 강한 틱 |
| 현재 보험료 눈금(C2) | 썸이 눈금 ±0.5만 원 안에 들어오면 자석처럼 붙고 틱 한 번. 눈금 왼쪽 영역은 "줄이기", 오른쪽은 "늘리기"로 의미를 가진다 |
| 큰 숫자 탭 | 숫자 입력 시트(키패드)를 연다. 확인하면 슬라이더가 따라간다. 범위 밖 값은 범위를 넓힌다 |
| 손가락 놓기 | 확정 계산을 요청한다. 결과가 오는 동안 이전 결과를 유지한다 |

### 4.2 결과 갱신

- 드래그 중에는 서버가 미리 계산한 구간 결과(릴리스·프로필·1만 원 단위 격자)를 쓴다. 계산 구현은 서버의 규칙 엔진 하나뿐이다(ADR-0003).
- 결과가 바뀌는 연출은 숫자 카운트업 220ms(ease-out), 상태 라벨 교차 페이드 150ms, 목록 재정렬 250ms다.
- 응답이 300ms를 넘으면 캡션 위에 얇은 진행선을 보인다. 이전 결과는 지우지 않는다.
- 응답이 실패하면 마지막 결과를 유지하고 캡션에 "마지막으로 확인한 결과예요"를 보인다.

### 4.3 세그먼트 탭 `현재 유지 | 보완안`

| | 현재 유지 | 보완안 |
|---|---|---|
| 의미 | 내 현재 계약 그대로 | 예산 안에서 필요 담보를 채운 구성 |
| 슬라이더의 역할 | 현재 보험료와 예산의 차이(여유·초과)를 보여주는 기준선 | 후보 구성을 바꾸는 입력 |
| 담보 상태 | 유지, 조건 확인, 미확인, 축소 검토 | 추가 검토, 유지, 조건 확인, 가격 미확인 |
| 월 보험료 | 내 계약 보험료(가입내역 기준) | 현재 보험료 + 추가분 − 해지분(공개 가격 기준 범위) |
| 가격 변화 보조줄(C3) | 없음 | 있음 |

- 두 탭은 같은 크기다. 전환은 알약이 200ms로 미끄러진다.
- 기본 선택은 보완안이다(시안과 같음). 보완안 후보가 없으면 현재 유지를 기본으로 하고 "지금 예산에서는 유지가 적절해요"를 한 줄로 보여준다. 억지로 대안을 만들지 않는다(§11).
- 가입내역이 없으면 현재 유지 탭은 "가입내역을 올리면 보여요"만 나온다. 보장을 0으로 간주하지 않는다.

### 4.4 담보 목록

- 행 구조: 아이콘 원 + 제목/부제 + 상태 라벨(+ 가격 변화 보조줄) + 쉐브론.
- 행은 담보 그룹이다. 진단 보장, 입원·수술, 생활비 대비가 기본이며 간병, 사망 등은 사용자의 걱정 상황과 공백 크기에 따라 앞쪽에 온다. 정렬은 공백이 크고 지급에 영향이 큰 순이다.
- 마지막 행은 항상 "무엇이 달라지나요?"이며 상태 라벨 대신 쉐브론만 있다.
- 행 탭: 담보 상세 시트(§4.5). 눌림 연출은 배경이 0.06 어두워지는 80ms다.
- 상태 라벨은 `status` 값에서 온다(§6).

### 4.5 담보 상세 시트

행을 탭하면 아래에서 올라오는 시트(화면 높이 85%, 끌어서 닫기)가 열린다.

1. 머리: 담보 그룹명과 상태 칩
2. 두 열 비교: 지금 | 보완안. 각 열에 "받을 수 있는 금액"을 큰 숫자로, 아래에 월 보험료(라벨 포함)
3. 얻는 것 / 잃는 것 / 확인할 것(§7)
4. 담보 비교: 같은 담보를 제공하는 상품 목록(§8)
5. 하단: 원문 보기(해당 조항 페이지 이미지와 하이라이트)

### 4.6 "무엇이 달라지나요?" 행

탭하면 전체 차이 화면(§7)이 전체 시트로 열린다. 이름 그대로 추가되는 것과 제외·불이익을 함께 보여준다.

### 4.7 "두 안 비교하기" 버튼

탭하면 비교 화면(§7.4)으로 이동한다. 가입내역도 보완안도 없으면 버튼은 비활성이 아니라 "가입내역 없이 보기"를 안내하는 상태가 된다.

### 4.8 하단 탭 이동

탭을 오가도 슬라이더 값과 선택한 탭은 유지한다. 앱을 다시 열면 마지막 값을 쓰되 데이터 릴리스가 바뀌었으면 캡션에 "데이터가 갱신됐어요"를 한 번 보인다.

|---|---|---|---|
| 공개 가격 | "공개 가격 · 40세 남 기준 · 기준일 10-01" | 채움 칩 | 포함(범위로) |
| 내 계약 보험료 | "내 계약 · 가입내역 기준" | 채움 칩 + 문서 아이콘 | 포함 |
| 개인 견적 | "내 견적 · 만료 10-12" | 채움 칩 + 사람 아이콘 | 첫 출시에서는 없음(스켈레톤) |
| 추정 범위 | "공시 40·50세 사이 추정" | 외곽선 칩 | 포함(범위로) |
| 가격 미확인 | "가격 미확인 · 사유" | 점선 칩 | 합계에서 제외, 건수로 표시 |

- 공개 가격과 개인 견적은 서로 다른 칩 모양과 아이콘을 쓴다. 색만으로 구분하지 않는다.
- 공개 가격은 개인 견적이 아니다. 캡션과 비교 화면에 "견적 아님"을 상시 표시한다.
- 가격에는 항상 조건과 기준일이 붙는다. 탭하면 조건(나이·성별·가입금액·기간·특약 구성)을 보여준다.
- 기준일과 확인일은 구분한다. 기준일은 소스가 밝힌 가격 적용일이고 확인일은 우리가 마지막으로 확인한 날이다.

### 5.2 가격 범위

- 사용자 조건과 공시 조건이 정확히 같으면 단일 값이다.
- 사용자 나이가 공시 나이 사이에 있으면 두 값 사이를 `추정 범위`로 보인다. 선형 보간 값을 단일 값처럼 보이지 않는다.
- 가입금액이 다르면 비례 환산하지 않는다. 직접 적용이 안 되면 가까운 공시 조건을 라벨과 함께 보여주거나 가격 미확인으로 둔다.
- 개인별 편차가 큰 상품군(예: 자동차)은 "개인별로 크게 달라요" 표시를 단다.

### 5.3 가격 미확인

- 가격 미확인 상품은 목록에서 빠지지 않는다. 같은 목록 안에서 점선 칩으로 표시한다.
- 사유는 짧은 문구로 나눈다: 찾지 못함, 공개되지 않음, 읽지 못함, 근거 충돌, 검토 중, 조건이 달라 적용 불가, 오래됨.
- 가격 정렬에서는 확인된 가격 뒤에 두되, 목록 위에 "가격 미확인 n개"를 고정 표시해 존재를 알린다.
- 예산 합계에서 제외하고 "합계에 미포함 n건"을 보인다. 0원으로 합산하지 않는다.

### 5.4 예산 판정 문구

| 상황 | 문구 |
|---|---|
| 범위 상한이 예산 이하 | "예산 안이에요" |
| 하한은 안, 상한은 초과 | "예산에 걸쳐 있어요" |
| 하한도 초과 | "예산을 넘어요" |
| 미확인 포함 | 위 문구 뒤에 "· 가격 미확인 n건 제외" |

## 7. 보장과 불이익의 동시 비교

보완안은 얻는 것만 보여주면 안 된다. 사라지는 보장, 새로 시작하는 면책, 감액도 같은 비중으로 보여준다.

### 7.1 차이 항목 모델

| 유형 | 묶음 | 예 |
|---|---|---|
| `gain_coverage` | 얻는 것 | 새로 생기는 보장 |
| `gain_amount` | 얻는 것 | 금액 증가 |
| `lose_coverage` | 잃는 것 | 사라지는 보장(교체로 기존 특약이 없어짐) |
| `lose_amount` | 잃는 것 | 금액 감소 |
| `new_waiting` | 잃는 것 | 면책기간이 새로 시작 또는 재시작 |
| `new_reduction` | 잃는 것 | 감액기간·감액률 적용 |
| `new_exclusion` | 잃는 것 | 새로 붙는 제외 조건 |
| `surrender_loss` | 잃는 것 | 기존 계약 해지 시 환급금 손실 |
| `term_change` | 잃는 것 또는 확인할 것 | 보장 종료 시점이 앞당겨짐 |
| `limit_change` | 잃는 것 또는 확인할 것 | 한도·횟수 변화 |
| `renewal_change` | 확인할 것 | 갱신형 전환, 갱신 시 보험료 변동 가능 |
| `underwriting_unknown` | 확인할 것 | 인수 심사에 따라 달라질 수 있음 |
| `unknown` | 확인할 것 | 원문·가격을 확인하지 못함 |

모든 차이 항목은 근거(릴리스, 조항, 페이지)와 이용 등급을 가진다. 근거가 없는 항목은 만들지 않는다.

### 7.2 표시 규칙

1. 세 묶음 `얻는 것 | 잃는 것 | 확인할 것`을 같은 글자 크기와 같은 시각 비중으로 둔다. 잃는 것이 얻는 것보다 작게 보이면 안 된다.
2. 추가 가입에도 불이익이 붙는다. 새로 가입하는 담보의 면책·감액·제외는 `new_waiting`, `new_reduction`, `new_exclusion`으로 반드시 보여준다. 새 담보의 이득만 보이고 새 불이익은 안 보이는 상태를 허용하지 않는다.
3. 지급에 영향을 주는 항목은 개수와 상관없이 첫 층에 보인다(불변 원칙 9). 한 묶음의 항목이 많으면 영향이 큰 순으로 정렬하고 나머지는 "더 보기"로 접되, 접힌 개수를 표시한다.
4. 잃는 것이 0건이어도 "불이익 없음"이라고 쓰지 않는다. "확인된 불이익 없음 · 미확인 n건 제외"로 쓴다.
5. 보완안의 유형을 표시한다: 추가형(기존 유지 + 신규), 교체형(기존 해지 + 신규), 축소형(일부 해지). 교체형에는 보장 공백, 면책 재시작, 인수 불확실, 해지 손실을 반드시 계산에 반영한다(§11).
6. 월 보험료 변화는 차이 화면 맨 위에 한 줄로 둔다. 가격 라벨과 기준일, 미확인 제외 건수를 함께 쓴다.

### 7.3 전체 차이 화면 ("무엇이 달라지나요?")

```text
무엇이 달라지나요?                     [보완안: 추가형]
월 보험료  +2.1만 ~ +3.0만   공개 가격 · 기준일 10-01 · 미확인 1건 제외

얻는 것                 잃는 것                  확인할 것
+ 암 진단비 3,000만     ! 면책 90일 새로 시작      ? 인수 심사 결과
+ 입원 일당 5만         ! 감액 1년(50%)          ? 갱신 시 보험료 변동
                        ! 제외: 일부 소액암          ? 가격 미확인 1건
                        (가상 예시)
```

세 열은 좁은 화면에서 세 구역의 세로 배열로 바뀌며 순서는 얻는 것, 잃는 것, 확인할 것이다. 항목을 탭하면 원문 근거 시트가 열린다.

### 7.4 두 안 비교 화면 ("두 안 비교하기")

| | 현재 유지 | 보완안 |
|---|---|---|
| 월 보험료 | 12만 (내 계약) | 14.1만~15.0만 (공개 가격) |
| 받을 수 있는 금액 | 담보별 막대 | 담보별 막대(차이는 강조) |
| 얻는 것 | - | 목록 |
| 잃는 것 | - | 목록 |
| 확인할 것 | 목록 | 목록 |

- 상단에 두 안의 가장 큰 이득 하나와 가장 큰 불이익 하나를 큰 글자로 요약한다. 사용자가 30초 안에 말할 수 있어야 한다(v0.3 §17).
- 하단 행동은 "선택 보관" 하나다. 보관하면 그 시점의 릴리스, 가격 기준일, 가정이 함께 저장된다(결과 재현).

## 8. 담보 비교와 상품 행

담보 상세 시트와 비교 화면의 상품 행은 보장, 가격, 불이익을 한 줄에서 함께 보여준다.

```text
[보험사]  상품명 · 구성(주계약 + 특약 2)       ← 한눈에 구분되는 첫 줄
보장 3,000만 · 진단 후 지급                    ← 보장 요약
월 3.2만~4.1만  [공개 가격 · 40세 남 · 10-01]  ← 가격 + 라벨 + 기준일
! 면책 90일  ! 감액 1년  ! 갱신형               ← 불이익 칩(영향 큰 순)
```

- 가격 미확인 상품도 같은 형식으로 나오며 가격 줄이 점선 칩 "가격 미확인 · 사유"다.
- 같은 담보명이어도 질병 정의가 다르면 "정의 차이" 칩을 단다(§59.6).
- 정렬 기본은 내 필요에 맞는 정도다. 가격 정렬을 고르면 확인된 가격이 먼저이고 미확인은 뒤에 두되 "가격 미확인 n개" 구간 머리글이 고정된다.
- 광고비·수수료는 정렬에 영향을 주지 않는다(불변 원칙 1). 이 화면에 광고 영역은 없다.

## 9. 화면 상태 카탈로그 (시안이 필요한 것)

내 설계 탭의 기준 화면 1장(데이터 있음)에 아래 상태를 모두 시안으로 만든다.

| 상태 | 시안이 달라지는 부분 |
|---|---|
| 기준(데이터 있음, 보완안 선택) | 시안과 같음 + C1~C4 |

| 보험 없음 응답 | "본인 답변 기준" 표시 |

| 예산 초과 | 예산 판정 문구(§5.4) |
| 가격 미확인 포함 | 점선 칩, 합계 미포함 n건 |
| 가격 오래됨 | 캡션에 "가격 확인일이 오래됐어요" |
| 로딩 | 골격 화면 |
| 갱신 중 | 얇은 진행선 |
| 오류 | 마지막 결과 + 안내 |
| 데이터 갱신됨 | 캡션 한 번 |
| 예시 모드 | 시안 원문 "화면 예시 · 실제 견적 아님" |

## 11. 뷰모델 (화면 ← API)

화면은 이 구조만 받아 그린다. 계산은 모두 서버에서 한다.

```json
{
  "view": "my_design",
  "release_id": "r123",
  "data_as_of": "2026-10-01",
  "budget": {"value_man": 15, "min_man": 5, "max_man": 30, "step_man": 1,
             "current_premium": {"man_range": [12, 12], "kind": "contract"}},
  "tab": "supplement",
  "price_caption": {"kind": "public", "basis": "40세 남", "as_of": "2026-10-01"},
  "groups": [
    {"id": "diagnosis", "title": "진단 보장", "subtitle": "암, 뇌, 심장 등 주요 질병",
     "status": "review_add",
     "price_delta": {"man_range": [2.1, 3.0], "kind": "public", "unpriced": 0},
     "evidence_ref": "..."}
  ],
  "unverified_count": 3,
  "unpriced_count": 1,
  "diff_available": true,
  "synthetic": false
}
```

- `status`, `kind`는 `packages/schemas`의 enum이다. 문자열 상수를 화면에 흩어 두지 않는다.
- 가격 필드는 `{man_range, kind, as_of, basis, state}` 묶음이다. 값이 없으면 `state`가 미확인 사유다.

## 12. 수락 기준

1. 기준 화면 일치: 390×844 기준 상태 "기준(데이터 있음)"을 시안 이미지와 겹쳐 비교한다. 요소 위치 오차 ±2dp 이내, 색 오차 ΔE 3 이내(C1~C4는 별도 승인 영역).
2. 조작: 슬라이더 1만 원 단계, 눈금 자석, 틱, 큰 숫자 탭 입력, 탭 전환 애니메이션이 사양대로 동작한다.
3. 가격: 공개 가격과 내 계약 보험료가 칩 모양으로 구분된다. 가격 미확인 상품이 목록에서 빠지지 않는다. 미확인이 0원으로 합산되지 않는다.
4. 불이익: 신규 가입 담보에 면책·감액·제외가 보인다. 교체형에서 사라지는 보장과 해지 손실이 보인다. "불이익 없음"이 단독으로 나타나지 않는다.
5. 이해 시험: 가상 계약으로 8~12명이 5초 안에 화면 목적을 말하고, 30초 안에 두 안의 가장 큰 이득과 불이익을 말한다. 잘못 이해한 비율을 기록한다.
6. 성능: 드래그 중 결과 갱신 체감 지연을 P1에서 측정해 목표를 정한다.

## 13. 열린 항목

- 서체 확정과 정확한 글자 크기(P0 디자인 도구 대조).
- C2~C4 승인.
- 상태 색 `status-add`의 최종값. 시안의 밝은 주황빨강과 v0.3 테라코타의 관계.
- 홈·만약에·내 정보 탭의 시안은 같은 시각 토큰으로 후속 제작한다(제3부 §60.2의 보장 지도 포함).
