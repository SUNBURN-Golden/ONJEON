# ADR-0014 V1 실제 자료 검증 결과의 설계 반영

상태: 확정(구현자, ADR-0013 이행) | 날짜: 2026-10-09 | 근거: `docs/blueprint/validation/GAP_REPORT.md`, `SCREEN_BINDING.md`

## 맥락

ADR-0013에 따라 실제 공시 문서 14개 파일(정액 진단, 실손, 수술·입원, 간병, 사망, 운전자 비용, 특약 종속·갱신, 가격)을 지금의 데이터 구조와 규칙 DSL rule-0.1에 넣고, 같은 자료를 내 설계 화면에 연결했다. 면책·감액·특약 종속은 대부분 표현됐지만 실손·간병·수술 계산과 가격 조건에서 부족분 26개(G01~G26)가 나왔다.

## 결정

1. 실행 규칙의 C0 근거는 약관이다. 상품요약서는 교차 검증과 쉬운 문장에만 쓴다. 둘이 다르면 `conflicting` + hold다. 설명문은 약관의 예외를 모두 담아야 릴리스한다.
2. 기간 단위(일·달·연)는 원문 그대로 저장하고 서로 바꾸지 않는다. 기산일 포함 여부와 날짜 경계의 출처를 함께 저장한다. 원문에 없는 날짜 관례는 엔진 가정으로 표시한다.
3. 표준약관 값은 상한·선택값일 수 있다. FieldAssertion에 `value_kind`(fixed / upper_bound / contract_selected)를 둔다. 금액 형식은 `amount_form`으로 저장하고 예시 금액의 비율 환산은 `derived`다.
4. 코드 판정(KCD 등), 하루 미만 시간 판정, 청구를 넘는 누적 사용량, 약관 밖 공시값 조회는 DSL에 넣지 않는다. 각각 CodeSet, 입력 단계, 계약 트윈, ParameterTable이 맡고 규칙은 판정 결과를 근거 참조와 함께 입력으로 받는다.
5. 면책 예외가 다른 급부로 지급을 넘기는 경우는 서로 배타인 규칙 묶음과 `routes_to` 간선으로 표현하고, 배타성을 테스트로 강제한다.
6. rule-0.2 연산 후보(`multiply_count`, `subtract_floor0`, `pro_rata`, `divide_count`, `anniversary_band`, 목록 입력과 `max_over`, `contract_effect`)는 해당 상품군을 계산 범위에 넣는 마일스톤에서 실제 사례와 함께 추가한다. 미리 넣지 않는다.
7. 화면 숫자는 엔진 결과만 쓴다. 실제 표본 화면 인스턴스의 수치를 엔진으로 다시 계산하는 테스트를 둔다.
8. 상태 어휘를 1.2.0으로 올린다: `hold_reason.extraction_uncertain`, 축 `clause_path_basis`, `relation_type`, `amount_form`.

## 결과

- 계약 문서 갱신: DATA_PIPELINE_CONTRACT §3·§4·§6, PREMIUM_DATA_CONTRACT, 화면·조작 설계서 §4.5·§11·§13, 설계도 §5.1·§6·§9·§11.
- `tools/validation_check.py`와 `cargo test --test real_clauses`가 CI에서 검증 자료를 지킨다.
- 화면 쪽 열린 항목 2개(행 라벨 쏠림, 공개 가격 한 점 문제)는 P0 시안 검토와 M3 가격 격자 조사로 넘긴다.
- 실제 조항 규칙 8건은 `fixture_only`로 고정되며 서비스에 쓰지 않는다.
