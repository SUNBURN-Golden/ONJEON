# Decision: BLUEPRINT §9.2 and §10.6 require the V1 gate before M1, but `tasks.json` lets T-CT-* start with no V

Decided by Claude Sonnet 5.5 xhigh (ONJEON autoloop, 2026-11-10 20:51 KST); reversible.

**Decision:** The BLUEPRINT governs. BLUEPRINT §9.2 (V1 is a milestone gate) and §10 rule 6 ('마일스톤 관문을 건너뛰지 않는다') — reinforced by §9.5, ADR-0013 §5 ('M1은 V1의 관문을 통과한 뒤 시작한다') and BP-D-12 — require V1 to pass before M1/contracts work starts. tasks.json is only a subordinate task contract (ADR-0019 limited adoption; its own _status says '상위 계약을 우선한다'), so the empty prereq_tasks/decision_gates on T-CT-01..08 is a defect in the bundle, not authorization. Do not lease/start T-CT-* (the contracts tasks the finding identifies as M1; 03_작업명세 §4 maps the S0 stage to the M1 gate) until V1 is judged passed. Correct the bundle by encoding the V1 gate as a start prerequisite — a gate task or start decision covering every M1 task — and re-run spec_check, check_bootstrap and check_product_purpose so the machine graph matches the milestone order.

**Why:** The conflict is between a subordinate contract and its superior, not between peers. tasks.json line 2 states '상위 계약을 우선한다' and ADR-0019 adopts 09/tasks.json only as a BLUEPRINT sub-contract. BLUEPRINT §9.5 (line 329) is explicit: satisfying task prerequisites, decision gates, done_criteria, required_test_ids and tests does NOT omit the §9.2 milestone gates. §9.2 line 284 says each milestone must pass its gate before the next and a blocked gate is fixed, not skipped; §10 rule 6 repeats this. ADR-0013 §5 (line 20) and BP-D-12 (DECISIONS.md line 22) put V1 before M1. T-CT-01 and T-CT-02 have prereq_tasks: [] and all four decision_gates empty (tasks.json:1615-1621, 1715-1721), and 03_작업명세 §4 (line 70) places the S0 contracts work under the M1 gate, so the bundle mechanically permits a start the BLUEPRINT forbids. V1 is still unpassed: BLUEPRINT §9.2 (line 276) and §11 (line 359) record derived-output reproduction 8/14 plus open cross-family review and S1/S6; audit4-v1-gate-closure.md line 5 keeps 'V1 미통과와 M1 진입 차단'. Absence of a dependency in a subordinate file therefore cannot be read as a waiver.

**Options:** ['Adopt BLUEPRINT §9.2 + §10 rule 6 as governing: V1 is a hard milestone prerequisite and empty tasks.json dependencies cannot authorize M1 start. (chosen)', 'Adopt tasks.json as governing: T-CT-* may start because prereq_tasks and decision_gates are empty. (rejected: contradicts §9.5, §10.6 and ADR-0013 §5; would skip an unpassed gate)', 'Encode the gate mechanically in tasks.json: add a V1 gate as a start/prerequisite for every M1 (T-CT-*) task so the daemon graph enforces the same order. (accepted as the follow-up correction; does not change which rule governs)', 'Declare V1 passed or defer its remaining evidence to M2 to unblock M1. (rejected: audit4-v1-gate-closure keeps V1 unpassed)']

**Revisit if:** V1 is judged passed with the evidence audit4-v1-gate-closure.md requires (14/14 reproduction, real cross-family ReviewDecision, S1/S6 closed) and BLUEPRINT §9.2/§11 are updated; or an ADR/BLUEPRINT revision changes the §9.2 milestone ordering or the scope of the tasks.json adoption; or tasks.json is amended to carry the V1 gate for M1 tasks, in which case re-check whether the mechanical graph and the milestone rule still diverge.
