# ADR-0013 전체 대상 목록 우선, 표본은 구현자가 선정, M1 전 설계 확정

상태: 확정(사용자 결정) | 날짜: 2026-10-09 | 근거: `docs/BLUEPRINT.md` §9, `docs/blueprint/DECISIONS.md` D11·D12

## 맥락

설계도 v1.0은 M2의 대상 보험사·상품 선정을 사용자 결정으로 두고, 다음 단계를 바로 M1 구현으로 적었다. 사용자는 이를 바로잡았다.

1. 전 보험사·전 상품·전 특약 포괄은 확정이다. 보험사·상품 선정을 사용자 결정이나 작업 시작 조건으로 두지 않는다.
2. 전체 수집 대상 목록부터 만든다. 설계 검증용 표본은 구현자가 다양한 상품 구조와 문서 형식을 다루도록 직접 고른다.
3. 표본 검증을 서비스 범위 축소로 해석하지 않는다. 전체 대상의 수집·처리 여부와 미확보 사유를 추적한다.
4. M1 구현 전에 설계 세 가지를 마무리한다: 상태값 확정, 실제 약관으로 표현력 확인, 소비자 화면 연결.

## 결정

1. V0: 전체 수집 대상 목록(보험사 전부, 공시 진입점, 이 환경에서의 접근 결과, 미확보 사유)을 `data/registry/`에 증거와 함께 둔다. 하위 상품·특약은 열거하지 못한 상태를 그대로 기록해 추적한다.
2. V1-a: 상태 어휘 정본을 `packages/schemas/vocabulary.json`으로 확정하고 `tools/vocab_check.py`로 CI에서 강제한다.
3. V1-b: 구현자가 고른 실제 공개 문서(정액 진단, 실손, 수술·입원, 간병, 사망, 비용 담보, 특약 종속·갱신, 보험료표 등)를 FieldAssertion·규칙 DSL·PremiumObservation에 넣어 보고, 표현하지 못한 것을 부족분으로 기록해 설계에 반영한다. 합성 규칙 테스트 통과와는 별개의 확인이다.
4. V1-c: 같은 자료로 "무엇을 보장하나 / 언제 못 받나 / 왜 이 가격인가"가 선택한 화면에 어떻게 나타나는지 뷰모델과 화면 배치로 연결한다.
5. M1은 V1의 관문을 통과한 뒤 시작한다.

## 결과

- 설계도 §12에서 대상 선정 항목을 지웠다. 결정 원장 O01은 공제·우체국 포함 여부만 남는다.
- 표본 문서는 설계 검증 자료이며 서비스 데이터가 아니다. AI 해석이고 검수 정책을 거치지 않았음을 표시한다.
