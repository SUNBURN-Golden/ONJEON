# ADR-0001 기술 스택

상태: 제안 (승인 대기) | 날짜: 2026-10-08 | 근거: 제3부 §48

## 맥락

문서 처리·OCR·AI 추출이 데이터 트랙의 중심이고, 소비자 앱·공개 웹·관제 콘솔을 한 팀이 만든다. 클라우드 공급자는 미정이다.

## 결정(제안)

| 계층 | 선택 | 대안 |
|---|---|---|
| 모바일 | React Native(Expo) + TypeScript | Flutter |
| 웹(공개·체험판·관제) | Next.js + TypeScript | SvelteKit |
| API·워커 | Python(FastAPI) | NestJS |
| 규칙 엔진 | 의존성 없는 순수 Python 패키지 | Rust + 바인딩 |
| DB | PostgreSQL (+pgvector) | - |
| 객체 저장소 | S3 호환(로컬 MinIO) | - |
| 작업 큐 | PostgreSQL 기반. 복잡해지면 Temporal | Redis + Celery |
| 인프라 | Docker, Terraform. 클라우드 미확정 | - |

## 이유

- Python은 문서 변환·OCR·평가 도구가 가장 성숙하다.
- React Native와 Next.js는 TypeScript를 공유하여 상태 enum·API 클라이언트·체험판 코드를 재사용한다.
- PostgreSQL 하나로 시간 이중 모델(valid/recorded), JSONB 근거, 전문·벡터 검색을 초기에 처리한다.

## 결과와 위험

- Python과 TypeScript 두 언어를 운영한다. 공통 계약은 `packages/schemas`에서 생성한다.
- 규칙 엔진이 Python이면 대량 재계산 성능이 병목일 수 있다. P3 전에 측정하고, 필요하면 Rust 구현으로 교체하되 골든 테스트를 그대로 통과해야 한다(ADR-0003).

## 열린 질문

모바일 프레임워크와 백엔드 언어는 팀 역량에 따라 사용자가 확정한다. 확정 전 P0 일부(스키마·엔진·픽스처)는 스택과 무관하게 진행할 수 있다.
