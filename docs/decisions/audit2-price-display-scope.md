Decided by Claude Sonnet 5.5 xhigh (ONJEON autoloop, 2026-10-27 17:39 KST); reversible.

**Decision:** Neither side is wrong: they cover different things. For scope, the source of truth is ADR-0010 → BLUEPRINT §7.1 / DECISIONS D08 / README: public price collection, display and comparison are in the first release. For when price display can be switched on, the source of truth is the DECISIONS.md §3 gate rows (O04, O10/D-18), which 09 P02/P09 restate; those rows say the price column's public display waits on a decision and is not a scope cut. D-18 already has a delegated decision record (docs/decisions/DEC-D-18.md, 2026-10-15) that is listed in the BLUEPRINT §11 index, so the job is to reference it in the ledger, not decide it again. Fix: (1) add DEC-D-18 and DEC-O04 rows to DECISIONS.md §3.1, with DEC-D-18 tied to O10 and clearly separated from §1 D18 (R2 operations); (2) mark the O04 row resolved by DEC-O04 (delegated, reversible; lifts the T-KN-09 compare_price gate once the I7/I8/K13/bundle tests pass) and the O10 row as recorded by DEC-D-18, with the remaining condition that no external reviewer has been named yet; (3) add a BLUEPRINT §12 row 'name the D-18/O10 external reviewer | before external launch | no external reviewer yet, so the price column can't be shown to the public; storage, comparison eligibility and internal/rehearsal display are allowed'; (4) add one gate note to the BLUEPRINT §7.1 '첫 출시 데이터' row and to README:31 (in scope; public display after O10/D-18); (5) in 09 P02/P09 change the O04 note to 'resolved by DEC-O04' and keep the D-18 note as 'external reviewer must be named'; (6) add a test that checks every DEC-D-*/DEC-O* file has a §3.1 row and that the scope docs and 09 rows use the same gate wording, plus an audit evidence note under docs/blueprint/audits/. Do not edit DEC files and do not make any legal judgment.

**Why:** ADR-0010 and D08 decide what is in scope; DECISIONS.md §3 decides when gated features may be enabled; 09 points to those gates for completion evidence. 09 P02 itself separates in-scope storage and eligibility from display that waits on a decision, and DEC-O04 says public display of the price column waits only on D-18. So the conflict is only on the surface. The real defects are that ledger §3.1, the O04/O10 rows and BLUEPRINT §12 don't reference two recorded decisions, plus the D18/D-18 naming clash. Fixing those references settles the finding without shrinking scope or making a legal call. Every change is a reversible doc or test edit: no money, secrets, deployment or legal conclusion.
