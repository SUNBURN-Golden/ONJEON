## 0. 최상위 기준(사용자 원문 요지)

- 만드는 것은 **세 부분이 끝까지 연결된 완성품**이다: 철저한 데이터 수집·관리·레이블링 → 그것을 기반으로 한 수준 높은 디지털 트윈 → 소비자가 쉽게 이해하는 직관적 UX/UI.
- 목적은 보험 소비자와 공급자 사이의 **정보비대칭을 줄이는 것**이다. 소비자가 설계사의 설명을 검증하고, 불필요하거나 불리한 선택을 스스로 구별할 수 있어야 한다.
- 이 목적은 소개 문장이 아니라 **실제 작업과 완료 기준**에 연결된다(아래 표의 "구현 작업"·"완료 증거" 칸, tasks.json의 done_criteria·required_test_ids).
- **일부 상품 시연이나 자동 개발 데몬 완성을 첫 출시 완성품으로 바꾸지 않는다.** 데몬 과제(T-OP-00·T-OP-09)는 개발 도구이며 출시 완성품의 일부가 아니다. 최종 관문(T-OP-08)은 이 표의 모든 행(축소·후속 표시 제외)이 등록부 증거로 닫혀야 통과한다.
- 칸의 뜻: 완료 증거 = 실제 데이터·실제 화면 시험·출시 증거(`docs/release-readiness/evidence/`). 합성 픽스처 통과는 증거가 아니다. "축소·후속" 칸은 근거(사용자 결정 ID·정본)가 있을 때만 채운다. 근거 없는 축소는 없다.

- 모든 과제는 증거 작성 경로를 `tasks.json`의 `allowed_paths`·`produces`·`conflict_paths`에 등록한다. 제품 과제는 `docs/release-readiness/evidence/<과제 ID>/`에 완료 증거와 수락 실행 로그를 남긴다. T-OP-08의 감리 보고서와 수락 로그는 `docs/release-readiness/evidence/T-OP-08/`에 둔다. 개발 도구 과제 T-OP-00·T-OP-09는 `tools/evidence/<과제 ID>/`에 검증 기록을 남기며(§5), 이 기록은 최종 감리의 축 5 운영 기록에만 사용한다.
- T-OP-08은 제품 과제의 증거를 검토하고 공용 `docs/release-readiness/evidence/readiness.json`에 P행·기능별 증거 참조와 수락 실행 결과를 집계한다. 파일 참조는 증거 디렉터리 기준 상대 경로(예: `T-DT-04/denominator-report.md`)다. 과제 상태의 근거는 이 매니페스트가 아니라 통합 담당자가 기록하는 [과제 상태 원장](../../progress/tasks_state.json)이며, 판정기는 원장의 관측된 상태·병합 SHA·검토된 과제 증거 경로를 읽는다. 다른 과제의 증거나 공용 매니페스트를 수정하는 권한은 T-OP-08에게만 있으며, 일반 제품 과제와 개발 도구 과제는 다른 과제의 증거나 공용 증거 매니페스트를 쓰지 않는다. 두 파일의 참조는 증거 디렉터리 기준 상대 경로다. 경로 권한은 실제 데이터·개인정보·공개·출시 관문을 해제하지 않으며, 증거 파일 존재나 로컬 회귀 통과만으로 완료가 되지 않는다.

[ADR-0020](../../../decisions/ADR-0020-작업-단계와-V1-관문-정합화.md) 보완: S0~S5와 M0~M6는 BLUEPRINT §9.6의 다대다 작업 대응이다. T-OP-02는 V1을 대체하지 않는다. 전체 14/14 파생 재현·실제 이종 계열 검수·화면 S1·S6 해결은 별도다. T-TW-02 조기 rule-0.2는 로컬 엔진·픽스처 검증(`fixture_only`)에 한해 허용하며, 서비스 상품군 적용은 M5·M6의 실제 사례·검수·릴리스 증거 뒤다. 이 예외로 P08·P14 또는 T-OP-08을 완료 처리하지 않는다.

결정 상태 열은 구현 작업의 직접 관문과 축소·후속 칸의 결정 ID를 [결정 원장](../../DECISIONS.md#31-결정-게이트-기록-dec-)과 연결한다. 실제 완료 판정은 각 행의 완료 증거를 따른다. [Audit 8 검증 증거](../../../../tools/evidence/audit8-decision-status-sync/README.md).
