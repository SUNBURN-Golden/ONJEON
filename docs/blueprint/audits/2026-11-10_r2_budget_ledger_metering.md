# Audit 5 — 원장 GET 계측과 정책별 HTTP 시도 횟수

노드: `audit5-r2-budget-ledger-metering`. 대응: A1·A2, Q7, L1, M1, P02·P03.

`Session.open()`이 원장 클라이언트를 생성한 뒤에야 `start()`가 `ACTIVE`를
설정한다. 기존 Audit 2·4의 `st.meter = self.meter` 연결로 GET 본문 계측은
이미 복구돼 있었지만, 생성자의 재시도 설정은 여전히 기본값 3을 선택했다.
또한 botocore `Config.retries.max_attempts`는 최초 요청을 제외한 재시도 수라
정책의 총 시도 3회를 HTTP 4회로 해석했다.

이제 원장 생성에 `budget=self`를 직접 전달해 최초 생성부터 세션 정책과
계량기를 사용한다. 보관소 클라이언트는 기존처럼 활성 세션을 사용한다.
공통 설정은 `total_max_attempts`로 정책의 최초 요청 포함 횟수를 적용한다.
기본·주입 원장에 대한 명시적 본문 계량기 연결과 요청 훅은 유지해
`finish()`가 `ACTIVE`를 비운 뒤 정산 꼬리를 읽을 때도 같은 카운터를 쓴다.
정책·한도·정책 해시와 기존 원장은 변경하지 않았다. 별도로 주입하는 S3
저장소의 생성 설정은 호출자가 지정하며, 세션 정책으로 만들 때에는 동일한
`budget` 인자를 사용할 수 있다.

`tools/tests/test_r2_budget.py`의 실제 botocore·루프백 S3 시험:

- 정책 총 1·2·4회 각각에서 원장 GET의 마지막 허용 시도 성공과 전 시도
  503 실패를 검사한다. 서버 로그의 횟수·Class A/B·PUT 바이트, 재시도 수,
  실제 GET 본문 바이트가 계량기와 일치한다. 소진 시 입장은 남고 예약 없이
  중단하며 보관소 접근은 비활성이고 로컬 잠금은 해제된다.
- 같은 정책에서 활성 세션의 보관소 GET과 `ACTIVE` 해제 뒤 정산 PUT이
  마지막 허용 시도에 성공한다. 서버 로그와 요약·정산의 다운로드 바이트 및
  재시도 수를 대조하고, 정산 쓰기 최악값이 정책 횟수를 사용하는지 확인한다.
- 기존 기본·주입 원장과 체크포인트의 입장·정산 바이트 한도 초과, 정확한
  바이트 합계, 미정산 예약 전액 보존 회귀를 함께 실행한다.

실행 명령·결과·로그는 [증거 디렉터리](../../../tools/evidence/audit5-r2-budget-ledger-metering/README.md)에 기록한다.
모든 검증은 임시 원장·합성 데이터·루프백으로 수행하며 실제 R2·실제 자격
증명을 사용하지 않는다. GET 계측은 본문 스트림이 반환한 바이트이며 LIST·오류
본문·소켓 수신량은 포함하지 않는 기존 범위를 유지한다. 이 수정은 원본 보관
도구의 비용 통제 finding에 한정하며 실제 공시 확보율·R2 관측 대조·소비자
화면·첫 출시 완료 증거를 대체하지 않는다. P02·P03은 계속 미완료다.
