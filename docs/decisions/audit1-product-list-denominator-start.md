# Decision: `data/registry/README.md:134` shows `product_list_status = unqueried` for all 53 insurers and only 8

Decided by Claude Sonnet 5.5 xhigh (ONJEON autoloop, 2026-10-26 10:55 KST); reversible.

**Decision:** Do not provision a domestic-IP collection environment from the autoloop now, and do not add a new denominator task ahead of T-DT-04. Record the environment as an operator-owned precondition for real-data enumeration instead. (1) Product and document denominators already have an owner. 09 P01 maps them to T-DT-04, and T-DT-04's done_criteria plus the `acquisition-reason-not-counted` test require per-insurer progress tables and per-doc-role acquired/unacquired(reason) records. T-DT-04 can build and test its adapters against fixtures and the 8 reachable entry points without a domestic IP. (2) Register the domestic-IP collection environment as the open gate O19 (DECISIONS.md §3, BLUEPRINT §12) and add it to T-DT-04 `decision_gates.real_data` next to D-04 (real R2 storage), with `blocked_by`/notes, and to DEC-O17's 'one designated execution environment'. The P01/P02 denominator evidence then can't be claimed from the foreign sandbox. (3) Ask 준태님 to provision one domestic-IP environment (KR-region VM or domestic proxy, concurrency 1, manual runs, fixed-key jobs, per the O17 default) before T-DT-04 is switched to real data. That is a cost/hardware item, which the 2026-10-15 delegation excludes. (4) Close this finding with evidence in the paths this node may touch. a: a new `product_list_reason_codes` column (computed by `tools/registry_normalize.py`) and `data/registry/README.md` gap #7 say why the rows are unqueried: `awaiting_T-DT-04`, `awaiting_domestic_env`, `disclosure_entry_missing`, `foreign_sandbox_geo_blocked`. b: a registry test checks that every `product_list_status=unqueried` row has a non-empty reason and the right codes. It also checks that every non-archived `disclosure_status` row has a `disclosure_gap_reason` and is never `not_disclosed`, and that the counts (53 insurers, 8 archived entry points, 45 not archived) match the CSV. (5) No-cost work that can go ahead without a domestic IP: XHR/SPA analysis of the reachable sites, and a check of whether 보호금융상품등록부 and the KLIA/KNIA 상품비교공시 lists can be fetched as cross-check sources.

**Why:** README §이 환경의 한계 and gap #7 already say the 45 failures come from geo-blocking, SPAs and refused connections in a foreign-IP sandbox, and that production crawling probably needs a domestic IP too. So the environment is a real requirement for P01/P02, not something to work around. The tasks don't schedule it before T-DT-04, but that is not a sequencing bug: T-DT-04 is the S3 denominator task, and 09 P01/P02 name it as the place that evidence comes from. What is actually missing is that nothing ties the domestic environment to T-DT-04's real-data run, so a fixture-only T-DT-04 could look like a finished denominator. Provisioning is a recurring cost and a hardware decision, which the 2026-10-15 delegation excludes. DEC-O17 already limits collection to one designated environment, which should be that domestic environment. Recording it as a precondition and asking the operator costs nothing and can be undone. Provisioning it ourselves would need money we aren't allowed to commit. The registry test turns the 'unqueried / blocked is not acquired' rule into something the CI checks.

**Options:** ["A: Provision a domestic-IP environment now from the autoloop (rejected: it costs money and hardware, which the delegation excludes, and the agent can't sign up or pay for it; T-DT-04 isn't blocked on it for adapter work and tests)", "B: Add a new task before T-DT-04 to enumerate product and document denominators now (rejected: it duplicates T-DT-04's scope and would run from the same foreign sandbox where 45/53 entry points failed, so it would only produce more 'blocked' rows)", 'C: Accept the README text as is and close the finding (rejected: nothing would require a domestic environment before real-data enumeration, and P01 evidence could be produced from blocked-only records)', 'D: Keep T-DT-04 as the denominator owner, make the domestic-IP environment an explicit operator precondition for its real-data run next to D-04 and O17, add the README reason codes and a registry consistency test as evidence, and send the provisioning request to 준태님 (chosen)']

**Revisit if:** 준태님 provisions or refuses a domestic-IP environment; T-DT-04 reaches its real-data step (D-04 recorded) while no domestic environment exists; a no-cost route (association 상품비교공시 lists, 보호금융상품등록부, FISIS/파인 after the service is restored, or XHR endpoints) turns out to be reachable from the sandbox and covers product denominators for most insurers; O17 is revisited for more environments or scheduled runs; or the domestic environment also fails for the same hosts, which would mean an access issue beyond geo-blocking (robots, login walls).
