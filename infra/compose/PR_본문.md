- 작성 참여 모델 역할·실행 경로: 빌더 역할 하나(작성·시험 실행). 실행 경로는 감독 프로세스가 연 코딩 에이전트 CLI 세션이고 이 작업 트리 안에서만 일했다(임시 시험 도구와 Docker는 `/tmp`). 모델 식별자 원문은 적지 않는다.

  - 변이 확인(`evidence/mutations.log`): 개인 DB의 `log_min_messages=log`를 뺀 복사본으로 smoke를 돌리면 로그 시험 두 항목이 FAIL, `LIVE: FAILED`, 종료 코드 1. 신원 파일을 600으로 바꾸면 uid 65534 컨테이너 사용자는 `Permission denied`(644면 읽힘). 부정 검사 도우미(`denied`·`unreachable`)는 정적 시험이 가짜 명령으로 돌려 다른 오류·성공·명령 없음을 모두 FAIL로 세는지 확인한다
  - Docker 없는 환경: `bash infra/compose/smoke.sh` → `LIVE: FAILED`, 종료 코드 1(정적 시험이 검증). `ONJEON_SMOKE_STATIC_ONLY=1`이면 `LIVE: SKIPPED`, 종료 코드 0이며 완료 근거가 아니다
