# Audit 6 — R2 정산 경합과 커밋 확인

노드: `audit6-r2-budget-settle-robustness`.
제품 연결: A1·A2·A4 / Q7 / L1 / I1 / M1, 제품 목적 대응표 P02·P03의 원본 보관 비용 통제 기반.

`Session.settle()`은 꼬리를 읽은 뒤 다른 실행이 다음 순번을 선점하면
재시도 없이 실패했다. 또한 조건부 PUT이 저장된 뒤 성공 응답을 받지 못하고
HTTP 재시도에서 412를 받으면 `Ledger.append()`가 자기 기록도 경합으로
판단했다. 마감 후 정산·요약 허용과 세션 원장 GET 계량은 이전 감리에서
이미 적용돼 있어 유지하고 경합과 결합한 회귀 시험을 추가했다.

정산은 기존 정책의 `reserve_attempts`(총 2회)를 공유해 매번 새 꼬리와
스냅샷으로 다시 쓴다. 앞선 실패 PUT·확인 GET·목록 페이지 비용이 다음
정산에 들어간다. append는 충돌한 키의 저장 바이트가 이번 기록 전체와
정확히 같을 때만 성공으로 인정한다. 같은 run_id만으로 성공을 추정하지
않으며 확인 GET 실패는 중단한다. 예약도 같은 append 경로를 사용하므로
커밋 뒤 412에서 중복 예약을 만들지 않는다.

정산 스냅샷 뒤 확인 GET의 요청·본문·재시도·시간이 빠지지 않도록 최악값을
확장했다. 총 HTTP 시도 n회에서 PUT n회·GET n회, PUT 바이트 n×4,096,
GET 본문 4,096바이트, 재시도 2×(n−1), 시간 2×n×130초를 더한 뒤 예약으로
제한한다. append는 4,096바이트보다 큰 기록을 쓰기 전에 거부한다.
작업 프로필 최소값은 경합 없는 기존 경로 기준으로 유지한다. 추가 확인·재시도가
남은 한도에 들어가지 않거나 append 상한에 도달하면 정산에 실패하고 입장·예약
전액을 유지한다. 정책·프로필 한도·정책 해시·기존 원장 형식은 바꾸지 않았다.

genesis 미고정 초기화 CLI에서 요청 훅만 연결하고 본문 계량기는 전달하지
않던 경로도 발견해 생성 시 정책·계량기를 전달했다. 배포 정책은 genesis를
고정하고 있어 이 초기화 경로를 네트워크 요청 전에 계속 거부한다.

`tools/tests/test_r2_budget_settlement.py`의 합성 데이터·루프백 S3·Stubber 시험:

- 순번 경합 후 성공, 시도 소진, 같은 run_id의 다른 기록 거부, 확인 읽기 오류,
  마지막 append 자리의 경합, 요청 예산 소진 시 쓰기 중단과 예약 전액 유지.
- 저장 후 503 → 실제 botocore HTTP 재시도 412에서 예약·정산 성공과 중복 없음,
  확인 GET 자체의 503 재시도 비용도 정산이 포함하는지 서버 로그와 대조.
- 가상 시계로 마감 이후 경합 정산·최종 요약, 원래 작업 오류 보존·알람·잠금 해제.
- `IsTruncated`·`NextContinuationToken`을 사용한 입장·원장 목록의 다음 페이지
  인자를 Stubber로 검사. 페이지 크기 1의 실제 HTTP 시험에서 예약·첫 정산·재시도
  꼬리의 모든 LIST 페이지 및 GET 본문을 계량값·저장 정산과 대조.
- 미고정 초기화의 원장 GET 본문 계량·정책별 HTTP 시도 설정과 배포 프로필 호환성.

실행 명령·결과는 [검증 증거](../../../tools/evidence/audit6-r2-budget-settle-robustness/README.md)에 기록한다.
신규 14개·R2 160개, 전체 Python 1,630개 실행(기존 건너뜀 6개),
Rust 작업 공간 532개(기존 무시 1개)·별도 실행기 4개와 정적 검사를 통과했다.
원본 리비전에 대한 검증에서는 핵심 회귀 5개가 모두 기존 결함을 검출한다.
비용 문서 §2·3 변경에 맞춰 D-04 회귀 픽스처의 문서 해시만 갱신했으며,
§4~6과 다른 관문·정책 해시는 그대로 대조했다.
실제 R2·외부 자격 증명·GitHub·커밋·푸시는 사용하지 않았다.
GET 계량은 스트림이 반환한 본문 바이트이며 LIST·오류 본문·소켓 수신량은
기존 계량 범위 밖이다. 지정 환경 하나·동시 1개·수동 운영 범위의 로컬 도구
finding 증거이며 실제 공시 확보율·R2 관측 대조·상품/계약 트윈·소비자 화면·
P02/P03 전체·첫 출시 완료 증거를 대체하지 않는다.
