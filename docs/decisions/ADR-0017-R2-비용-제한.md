# ADR-0017 R2 비용 제한: 실행별 제한과 누적 사용량을 이용한 폭주 완화 장치

상태: 확정(사용자 요청, 2026-10-09) | 근거: 결정 원장 D17, `infra/r2/BUDGET.md`, `tools/r2_budget.py`

## 맥락

R2에는 하드 지출 상한이 없다. Cloudflare 예산 알림은 예상 지출이 기준을 넘으면 이메일을 보낼 뿐 과금을 막지 않는다. 대량 수집 전에, 이 저장소 도구로 하는 실행이 폭주해 비용이 커지는 것을 줄이는 장치가 필요하다.

## 결정 (사용자)

1. 대량 수집 전에 비용 제한을 구현한다. 최초 작업은 고정된 119키(원본 58, 파생 v2 61)의 업로드·대조만 허용한다.
2. 총 바이트, API 요청, 재시도, 실행 시간을 사전에 제한한다.
3. 한도가 소진되거나 한도 기록을 조회하지 못하면 중단한다.
4. 재실행·병렬 실행으로 한도를 우회하지 못하게 한다.
5. 예산 알림을 과금 차단으로 표현하지 않는다.

## 범위와 운영 (사용자 결정, 2026-10-09 후속)

1. 이 기능은 **실행별 제한과 누적 사용량을 이용한 폭주 완화 장치**로 명시한다. 전체 계정의 과금 상한이나 모든 실행의 요청 상한을 보장한다고 표현하지 않는다. 원장에 남지 않는 요청이 있다는 점은 이 도구 내부의 한계로 적는다(`infra/r2/BUDGET.md` §5).
2. 초기 운영은 지정 실행 환경 하나, 동시 실행 1개, 수동 실행으로 제한한다. 대량 자동 수집은 별도 관문으로 둔다(결정 원장 O17, BUDGET.md §6).
3. 이번 PR에서는 비용 제어 기능을 더 확장하지 않고 문서 정합성을 고친다.

위 결정 4번(재실행·병렬 실행 우회 방지)은 이 도구의 원장 기준으로 구현했다. 그 범위 밖의 요청은 BUDGET.md §5에 적었다.

## 구현 (구현자)

- 정책 `infra/r2/budget_policy.json`(전체 한도, Git 고정), 작업 `infra/r2/jobs/initial-119.json`(허용 버킷·연산·키와 해시, 작업 한도, 실행 종류별 예약량).
- 원장: 별도 버킷 `onjeon-budget-ledger`의 `ledger/v1/<순번>.json`. 한 번만 쓰는 기록, 앞 기록 해시 연결, 정책 해시, 첫 기록(genesis) 해시를 정책에 고정. 실행은 예약을 먼저 쓰고, 끝나면 측정값으로 정산한다. 정산되지 않은 예약은 전부 사용한 것으로 센다.
- 계량: botocore 이벤트로 모든 HTTP 시도를 요청 전에 검사하고 센다(연산·버킷·키·바이트·저장 등급·Class A/B·재시도·시간).
- R2·AWS 대상은 작업 파일 없이는 요청을 보내지 않는다. 에뮬레이터만 예외(시험용).

## 재검토 반영 (2026-10-09)

검토에서 두 누락을 확인했다.

1. 예약 전에 원장을 읽고 한도 부족으로 끝난 실행은 그 읽기 비용을 원장에 남기지 않았다. 거부된 실행을 반복하면 비용이 쌓여도 한도에 들어가지 않았다(옛 코드에서 거부 5회 = 요청 10건, 기록 0건 재현). → 실행 통제를 앞에 둔다: 로컬 통제(요청 없음), 마감 확인 HEAD 2회, **읽기 전 입장 기록**, 예약 전 입장 한도 적용, 정산 안 된 입장을 한도에 포함, 월 입장 횟수 소진 시 마감 기록, 예약은 남은 입장 몫을 비워 둔다.
2. 정산 PUT은 Class A 1건만 더했다. 재시도되면 정산값이 실제보다 작았다(옛 코드에서 실제 Class A 5건·재시도 1건, 정산 4건·0건 재현). → 정산 쓰기의 최악값(최대 시도 수만큼 Class A·바이트·재시도·시간 제한)을 더한다. 정산은 원장 전체가 아니라 꼬리만 읽는다.

회귀 시험: `tools/tests/test_r2_budget.py` `EndToEnd`(요청을 모두 기록하는 S3 스텁 `tools/tests/s3_stub.py`와 비교), `LocalGateChecks`.

## 결과

- 2026-10-09 원장을 만들고 순번 1에 원장 이전 사용량(측정 아님, 상한 추정)을 기록했다. 이후 R2 대조는 예약·정산을 거쳐 실행했다(`docs/blueprint/validation/source_checks/2026-10-09_r2_*`).
- 이 기능의 범위 밖: 토큰을 가진 다른 프로그램의 직접 호출, 대시보드 작업, 같은 계정의 다른 R2 사용. 이 도구 내부의 한계: 마감된 달의 마감 확인 HEAD 2회와 실패한 입장 쓰기는 원장에 남지 않고, 원장 끝 기록 삭제는 감지하지 못한다. 토큰 범위·만료·폐기, 초기 운영 범위, 원장 버킷 잠금(O14)이 보완한다.
- 대량 자동 수집은 별도 관문(O17)이다. 관문에서 원장 체크포인트(기록 수에 비례하는 읽기 비용, 100건 상한) 등을 정한다.
