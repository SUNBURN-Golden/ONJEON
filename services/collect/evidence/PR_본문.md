## 변경 내용

1. HTML 목록에 선택된 링크나 명시적인 빈 상태 증거가 없으면 파싱 실패로 기록한다. 총건수 표시가 없는 KLIA·KNIA 계획에도 같은 조건을 적용한다. 200 점검 페이지·JS 셸·일반 탐색 링크가 빈 목록 성공이 되지 않는다. 시험의 빈 목록도 `fixture_only` 빈 상태 표시를 명시한다.
2. 포함 기관마다 상품 목록과 여섯 문서 종류의 전체 기관 분모를 처음부터 미확인으로 둔다. 한 기관의 성공으로 다른 미조회 기관이 합산에서 사라지지 않는다. 축·판매상태·채널·기간·역할이 일치하는 완료만 해당 공백을 해제하며, 좁은 범위의 성공은 전체 기관 미확인을 지우지 않는다. 미확인 기관이 남으면 확보율은 숫자로 제공하지 않는다.
3. 상품 ID는 별도 집합에 보존하고 문서 분모는 실제 발견 문서 ID와 역할로 구성한다. 상품당 역할 하나의 가상 문서 슬롯을 만들지 않는다. 상품 전에 발견된 문서, 여러 특약, 공유 문서, 재발견을 처리한다. 문서 ID만 있는 manifest는 역할 하나를 명시해야 하며 다중 역할에 ID를 복제하지 않는다. 재열거는 개별 문서의 확보 증거나 미확보 사유를 덮어쓰지 않는다.
4. 성공 불가능한 범용 `EntryProbe`를 제거했다. C_life §2·§3.5에서 GET과 전량 내장 JSON이 관측된 라이프플래닛 판매·판매중지 두 목록에 상품·약관·요약서·사업방법서의 8개 구체 계획을 연결했다. JSON은 데이터로 파싱하며 JavaScript를 실행하지 않는다. 상품 후보는 전체 관측 행의 해시이며 판매본 확정을 주장하지 않는다. 문서 참조 누락은 실패로 남긴다. 검증된 파서가 없는 다른 기관은 미탐색을 유지한다.
5. robots 확인 불가 보류, 로그인 HTML 차단, 공제 제외·사유 보존, 원본+추출+판 연결 모두 있어야 확보라는 규칙을 유지한다.

공유 스키마·가격 계산·소비자 화면·규칙 결과·개인정보 경로는 이번 변경 대상이 아니다.

## 실제 검증과 한계

- 재실행 명령: `python3 -B services/collect/tests/verify.py`. 명령별 출력과 종료 코드는 `verification-00.log`~`verification-12.log`, 소스 SHA-256은 `verification.json`에 기록한다. 이 문서는 이번 회차 증거이며 이전 `verification-fix*` 파일은 과거 실행 기록이다.
- 어댑터 시험 56개(라이브러리 회귀 12 + 통합 44), workspace 시험, fmt, clippy, Python 상호운용·도구 시험, 누출 검사와 자체시험, 스켈레톤 정적 비노출 검사와 자체시험, `git diff --check`를 실행했다. 실제 결과는 `verification.json`을 기준으로 한다. `acquisition-reason-not-counted`는 `adapters::acquisition_reason_not_counted`이며, 쓰기 보존 시험 `manifest_is_stored_write_once`도 다시 실행했다.
- 의존 경계는 **실패(exit 1), 병합 차단 유지**: `python3 -B -I tools/ci/check_deps.py`에서 `packages/ontology/Cargo.toml`, `packages/ontology/tests/common/mod.rs`, `packages/ontology/tests/fixture_origin/main.rs`의 위반 3건. 이 경로·검사기·규칙은 입력 SHA와 동일하다(`dependency-boundary.json`, `verification-07.log`). 허용 범위 밖이므로 감독자가 해당 경로 수정 권한이 있는 과제에 배정해 고친 뒤 원래 검사 전체를 통과시켜야 한다. 예외·우회는 추가하지 않았다.
- 네트워크 열거는 수행하지 않았다. 모든 응답은 `fixture_only` transport이며 원문 발췌를 사용하지 않았다. 라이프플래닛 구조는 저장소 조사 기록에 근거한 구현으로 현재 실서버 검증 완료를 뜻하지 않는다. 실제 수집은 기존 D-04·O17 관문을 따른다.
- 라이프플래닛 외 보험사의 구체 요청·목록 파서와 특약·별표·가격 열거는 아직 지원하지 않는다. 좁은 계획을 모두 성공시켜도 전체 기관 미확인을 자동 해제하지 않는다. 실제 기관·판매본 전수 확보, /coverage 렌더링, 데이터·제품 출시 완료를 주장하지 않는다.
- 스켈레톤 검사는 정적 검사와 검사기 자체시험이며 실행 중인 서비스의 HTTP 경로를 검사한 결과는 아니다.

## 작성·리뷰·대상 고정

- 작성 역할: 구현 및 자체 검증. 실행 경로: CLI → 현재 worktree → Rust cargo / Python unittest. 모델 식별자 원문은 기록하지 않는다.
- 입력·리뷰 대상 SHA: `be571a90b8cc64c506e0f06b0b751617e95ea947`. 제공 리뷰 역할 `st_re_review`의 판정은 BLOCK이다.
- 실제 시험 대상: 위 SHA와 미커밋 수정본. 수정 소스 바이트는 `verification.json`의 파일별 SHA-256으로 고정한다. 이 SHA를 수정 완료 커밋으로 주장하지 않는다.
- 커밋·푸시·GitHub 호출을 하지 않았다. 감독자가 최종 커밋을 만든 뒤 최종 SHA로 검증·리뷰 대상을 다시 고정해야 한다.
- 수정본 독립 리뷰는 미실시다. 작성 계열과 다른 리뷰어가 감독자 생성 최종 SHA에 고정해 리뷰해야 한다. 자체 검증은 독립 리뷰를 대신하지 않는다.
- 변경은 `services/collect/**` 안에 한정한다. 금지 경로와 레지스트리 CSV는 수정하지 않는다.
