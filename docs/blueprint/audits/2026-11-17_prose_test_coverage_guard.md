# Audit 6: 제품 과제의 필수 ID 실행 누락 차단

2026-11-17 · 노드 `audit6-prose-test-coverage-guard` · BLUEPRINT §13 / ADR-0019

지적은 제품 과제의 `시험 …` 설명이 실행되지 않아 `required_test_ids` 선언만으로
시험 누락을 숨길 수 있다는 것이다. 현재 트리에서는 제품 62과제의 설명이 64개다.
이 중 53개 고유 ID가 과제별로 총 64번 요구된다. 같은 ID를 여러 담당 과제가
검증하는 경우를 합치지 않는다.

모든 제품 과제(T-OP-00·T-OP-09 제외)의 `tests`와 개별 `done_criteria`에
`python3 -I tools/task_test_coverage.py --task <과제 ID>`를 추가했다.
시험 등록·어댑터를 쓸 과제별 `tools/task_tests/<과제 ID>/**`만 허용·충돌 경로에
추가했다. G12c는 이 명령·완료 기준·경로가 빠지면 실패한다. 설명의 ID와
필수 ID도 과제별로 정확히 일치해야 하므로 다른 과제에 같은 ID가 남아 있어도
누락을 감출 수 없다. `common_done_criteria`의 채택 상태는 변경하지 않는다.

ID가 없던 수동 증거 설명 5개에 명시적 ID를 부여했다. T-KN-06의 실제 제공자
실행, T-OP-03의 실측, T-OP-06의 보안 점검, T-UX-01의 사용자 시험,
T-OP-07의 운영 기록은 증거 내용 검증 시험도 작성해야 한다. 이 시험은 실제 수행과
기존 결정 관문·승인·사전 고정 수락 수치를 대신하지 않는다. T-CT-08의 기존
`amount-evidence-axes-required` 설명도 필수 목록에서 누락되어 있어 등록했다.
03 작업명세의 필수 ID·완료 기준을 JSON과 동기화했다.

과제 완료 명령은 `coverage.py`의 리터럴 `TEST_IDS`와 필수 목록을 양방향으로
대조하고, 각 ID의 로컬 unittest 메서드를 실제 실행한다. 누락·미등록·중복 ID,
하나의 메서드를 여러 ID에 재사용, 등록 파일·함수 부재, 실패·오류·skip·예상 실패,
실행 개수 불일치와 assertion 없는 빈 시험은 종료 코드 1이다. assertion은 등록된
시험 메서드 실행 중에만 집계하므로 `setUp`·`tearDown`·cleanup 픽스처의
assertion이 빈 메서드를 통과시키지 않는다. 모듈·클래스 준비 단계의 skip도
통과하지 않는다. 필수 목록이 빈 과제는 빈 목록임을 명시하며,
남은 등록 파일을 무시하거나 ID 없는 설명을 통과시키지 않는다.

[등록 작성법](../../../tools/task_tests/README.md)은 Rust·Flutter·웹 네이티브 시험을
unittest 어댑터에서 호출할 때 실제 시험 개수·상태·결과와 변이를 검사하도록 요구한다.
ID 일치와 assertion 호출이 제품 요구의 의미 정확성까지 보증하지는 않는다.
네이티브 필터가 0개 시험을 실행하지 않는지, 실제 결과·증거를 검증하는지는
과제별 구현·리뷰의 책임이다.

[검증 증거](../../../tools/evidence/audit6-prose-test-coverage-guard/README.md)에 회귀·전체 시험과
현재 제품 과제 완료 검사의 결과를 기록했다. 이 노드는 미구현 제품 시험을
성공 대역으로 작성하지 않는다. 필수 ID가 있는 27과제는 현재 등록 파일 부재로
종료 코드 1이며, 나머지 35과제는 필수 목록이 비어 있음을 명시한다.
G12c·저장소 회귀 시험의 통과는 검사 장치와 작업 계약 정합성의 증거다.
제품 과제 27개, 09의 P01~P19, 실제 데이터·트윈·소비자 UX 또는 첫 출시의 완료
증거가 아니다. 출시 완료는 계속 09의 실제 완료 증거로 판정한다.

## Fix round 2: 픽스처 assertion의 빈 시험 통과 차단

리뷰는 공유 `setUp()`의 assertion 하나가 `pass` 본문인 필수 ID 시험을 통과시키는
재현을 보고했다(22380d2에서 종료 코드 0 확인). 실행기는 이제 등록된 시험 메서드
실행 중에만 assertion을 집계하고, `setUp`·`tearDown`·cleanup의 assertion은
집계하지 않는다. 회귀 시험 3개가 추가됐다: 픽스처만 assertion을 가진 빈 메서드
거부(리뷰의 단일 ID 재현 포함), 두 메서드 중 하나만 비어도 거부, 픽스처
assertion과 실제 메서드 assertion의 병존·도우미·subTest는 통과. 이 거부 회귀
2개가 수정 전 실행기에서 실패함도 확인했다. 재실행 증거는
[검증 증거 fix-round2](../../../tools/evidence/audit6-prose-test-coverage-guard/README.md)에
있다. 이 수정은 검사 장치의 결함 수정이며 제품 시험 구현이나 출시 완료를
주장하지 않는다.
