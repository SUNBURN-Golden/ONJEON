# Audit 6 — 로컬 보관 키 제한과 표본 SHA-256 검증

노드: `audit6-archive-localstore-key-confinement`.
연결: BLUEPRINT A1·A2, Q7, L1, I6의 근거 관리 기반, V1·M2,
[09 제품 목적 대응표](../proposals/설계검토_결과/09_제품목적_대응표.md)의 P02·P03.

기준 코드에는 이미 [Audit 3 경로 제한](2026-10-28_local_store_path_traversal.md)과
[Audit 5 SHA-256 재검증](2026-11-10_samples_sha256_format_check.md)의 수정이 있다.
`LocalStore`는 절대 루트에 고정하고 모든 읽기·쓰기·존재·목록 조회에서 상대 키의
구성 요소와 심볼릭 링크를 해석한 경로의 루트 포함 여부를 검사한다.
`validation_check.check`는 표본의 `sha256`을 각 행마다 검사하며,
`object_key`도 공통 검사로 정확히 64자리 ASCII 16진수만 허용한다.
대소문자 보존 동작을 유지한다.

이번 변경은 문자열이 아닌 키도 `UnsafeStoreKey`로 명시적으로 거부한다.
목록의 빈 접두어 처리 전에 검사하므로 네 저장소 연산이 같은 오류 계약을 따른다.
기존 경로·해시 방어는 유지하면서 다음 회귀 증거를 보강했다.

- 잘못된 키 타입 7종 × 네 연산을 검사하고, 보관소에 파일이 생기지 않는지 확인한다.
- 루트 `archive`와 접두어가 같은 외부 형제 `archive-other`를 가리키는 심볼릭 링크도
  읽기·쓰기·존재·목록 조회에서 거부하며 외부 파일을 보존한다.
- 정확히 64자인 경로 이탈 해시를 실제 임시 CSV로 만든다. 과거 키 조합이 실제로
  루트 밖 센티널 파일을 가리킴을 먼저 확인한 뒤, 정상 해시 검사와 그 검사를 우회한
  두 경우 모두 실제 `LocalStore` 복원이 바이트 읽기 전에 실패하는지 검사한다.
  기존 복원본·외부 파일·빈 보관소를 보존하고 종료 코드 1을 반환한다.
- 키 타입·상대 경로 형식·해석된 경로 경계 검사를 각각 제거한 변이를 검출한다.
  표본 행 검사 제거와 길이만 검사하는 해시 변이도 기존 도구로 재실행했다.

명령·실행 결과·소스 해시는 [실행 증거](../../../tools/evidence/audit6-archive-localstore-key-confinement/README.md)에 기록한다.
합성 바이트·임시 디렉터리·로컬 회귀 시험이며 실제 R2 접근·공시 확보·소비자 화면·
P02/P03 전체 또는 첫 출시 완료 증거를 대신하지 않는다.
로컬 파일시스템을 다른 프로세스가 검사와 I/O 사이에 악의적으로 교체하는 공격의
격리는 기존 도구와 같이 범위 밖이다. 신뢰하는 로컬 작업 디렉터리에서 사용한다.
