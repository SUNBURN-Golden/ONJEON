# UX/UI 구현 기준 — 담보를 이해하는 앱

상태: 구현용 초안 | 2026-10-09 | 연결: 제3부 §44·§46·§60, ADR-0009

> 2026-10-09 갱신: 주 기준은 사용자가 재지정한 `assets/selected-my-plan.png`와 [소비자 경험 설계](CONSUMER_FLOW_SPEC.md)다. 이전 네 화면 보드는 참고안이다. 월 예산·현재 유지/보완안과 공개 가격 비교를 복원한다. 충돌 시 새 명세 우선.

## 0. 화면이 전달할 핵심

“무엇을 보장하나 / 언제 못 받나 / 다른 상품과 무엇이 다른가”가 먼저다. 데이터 상태는 보조 정보다. 계약·가족력 없이도 관심 담보의 확인된 설명과 원문을 탐색할 수 있어야 한다.

최신 사용자 강조에 따라, 네 화면 이미지의 홈에 있는 상태 위주 행은 구현 시 보장·제한 한 줄로 보완한다. 예: 합성 픽스처에 근거한 “가입 첫 1년에는 진단금 50%”. 상태 칩만 보이는 이미지를 완성 사양으로 복제하지 않는다. 이 문장이 이미지보다 우선한다.

## 1. 유지할 시각 방향

사용자가 선택한 세 번째 구성과 Claude를 연상시키는 따뜻한 색감을 따른다. 승인된 원본은 `assets/approved-warm-direction.png`, 이번 네 화면 견본은 `assets/coverage-flow-reference.png`다. 화면을 카드로 빽빽하게 채우지 않는다. 큰 제목, 얇은 구분선, 담보 행, 넓은 여백, 하단의 테라코타 버튼으로 흐름을 만든다.

| 토큰 | 구현 시작값 | 역할 |
|---|---|---|
| background | #F7F4EE | 따뜻한 아이보리 |
| surface | #FFFDFA | 시트·입력 영역 |
| ink | #292723 | 본문·제목 |
| secondary | #716A62 | 보조 설명 |
| accent | #C67557 | 핵심 행동·선택 |
| line | #E4DDD3 | 경계 |
| spacing | 4, 8, 12, 16, 24, 32 | 간격 체계 |
| mobile gutter | 24 logical px | 본문 좌우 |
| typography | 제목 30–34, 본문 16, 보조 13–14 | Flutter logical px, 한글 줄바꿈 확인 |
| corner | 12–16 logical px | 버튼·입력, 과도한 둥근 카드 금지 |

값은 구현 시작값이며 화면 실측·사용성 검증으로 조정한다. 실제 폰트는 라이선스를 확인해 고른다. 색상만으로 상태를 전달하지 않는다.

## 2. 네 화면과 데이터 계약

| 화면 | 첫 질문 / 행동 | 필수 데이터 | 없는 경우 |
|---|---|---|---|
| 홈·내 보장 | 무엇을 확인할까? / 담보 조건 비교 | 담보 분류, 계약 유무 상태, 필드별 이용 등급 | 관심 담보 탐색 제공, 계약 없음으로 추정 금지 |
| 담보 비교 | 같은 이름인데 무엇이 다를까? / 차이의 근거 | 상품 버전·채널·담보 발생본·동일 비교축·증거 | 해당 셀에 자료 필요, 우열·순위 생성 금지 |
| 만약에 | 이 상황을 가정하면? / 가정 적용 | 기간·본인 입력 비용·검증된 실행 규칙·계약 조건 | 입력 안내 또는 조건부 부분 결과. 임의 필요액·0원 금지 |
| 증거 | 왜 이렇게 표시했을까? / 원문 보기 | 문서 해시·버전·페이지·좌표·정확 인용·참조 조항 | 증거 오류로 신고·hold, 다른 버전 원문 대체 금지 |

선택 이유→조건 차이→원문은 각각 한 번의 탭으로 이어진다. 뒤로 가면 선택·스크롤·가정을 유지한다. 홈의 가족력은 선택 입력이고 광고·상담 유도가 아니다. 가족력을 입력하지 않아도 비교 기능을 이용한다.

## 3. 이미지와 구현의 차이

- 네 화면 이미지의 첫 화면은 홈이다. 이미지에 강조된 '내 설계' 탭은 생성 이미지의 오류이며 구현에서는 **홈**을 활성화한다.
- 예시 A/B, 감액기간 1년/2년, 50%, 합성 약관 12쪽은 모두 가상 픽스처다. 실제 보험사 약관처럼 인용·사용하지 않는다. 이미지 속 긴 약관 문구도 법적 원문이 아니다.
- 견본의 상태 칩은 §44.3의 정확한 문구로 구현한다. '비교 가능'은 데이터의 비교 가능성이며 가입 적합성이나 지급 보증이 아니다.
- 3개월은 화면 시연용 선택값이다. 실제 앱이 개인 치료 기간을 자동 예측하거나 공통 기본값으로 강제하지 않는다.
- 선택된 이미지의 월 예산 슬라이더는 유지한다. 공개 가격을 조건과 함께 표시하며 개인 실견적과 구분한다.
- DNA는 장기 설계에 남지만 첫 출시 메뉴에 빈 버튼으로 노출하지 않는다.

## 4. 반드시 그려야 할 상태

| 상태 | 표시 | 다음 행동 |
|---|---|---|
| 첫 방문 | 내 계약/관심 담보 선택 | 예시·관심 담보·PDF 중 선택 |
| PDF 미제출 / 모름 | 아직 계약을 확인하지 않았어요 | 선택 업로드 또는 계속 탐색 |
| 보험 없음 직접 선택 | 등록한 계약 없음 | 관심 담보 탐색 |
| 수집 또는 추출 실패 | 자료 확인이 지연돼요 | 재시도·오류 상세 |
| 비교축 일부 누락 | 해당 셀 자료 필요 | 근거 확인, 다른 필드 비교 |
| 검증 보류 | 해당 조건 판단 보류 | 원문·이유·오류 신고 |
| 오래된 데이터 | 마지막 성공일과 갱신 지연 | 최신 원문 확인 |
| 계산 중 | 이전 결과에 갱신 중 표시 | 중복 요청 취소·최신 입력 우선 |
| 삭제·동의 철회 | 영향 설명 후 처리 상태 | 완료 확인, 가족력 없는 탐색 유지 |

## 5. UI 검증 시나리오

1. PDF 없는 사용자가 관심 담보 비교까지 가며 0원·무보험·보장 부족으로 오인하지 않는다.
2. 같은 담보명의 서로 다른 감액기간이 첫 화면에 보이고 한 번 탭해 정확한 증거로 이동한다.
3. 정액 담보 두 개가 같은 사고를 보장한다는 이유만으로 축소 권유를 받지 않는다.
4. 슬라이더를 빠르게 바꿔도 과거 응답이 최신 가정의 결과를 덮지 않는다.
5. 가족력을 건너뛰거나 지워도 일반 비교가 가능하고 분석 이벤트에 질환명이 남지 않는다.
6. 만약에 입력이 불완전하면 충족률 대신 필요한 입력을 보여준다.

사용성 목표는 5초 내 화면 목적, 30초 내 핵심 조건 차이를 설명하는 것이다. 대상자·표본·실패 원인을 기록한다. 이 문서는 목표와 검증 계획이며 실제 사용자 시험 결과가 아니다.
