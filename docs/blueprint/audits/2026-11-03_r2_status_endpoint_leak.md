# Audit 4 — R2 status 오류의 계정 엔드포인트 노출 차단

대상 노드: `audit4-r2-status-endpoint-leak`.
제품 연결: A1·A2·A4 / Q7 / L1 / I1 / M1, 제품 목적 대응표 P02·P03의 보관 도구 기반.

`tools/r2_budget.py`는 CLI 진입점에서 botocore 오류를 처리하지 않아
`status`의 세션 시작 또는 원장 조회 오류가 계정 ID를 포함한 엔드포인트와
함께 traceback으로 출력될 수 있었다.

CLI 진입점을 `main()`으로 감싸 `source_archive.py`와 같은 botocore 예외
분류·출력 규칙을 적용한다. `BotoCoreError`·`ClientError`는 예외 유형과
메시지·엔드포인트 생략 안내만 stderr에 출력하고 종료 코드 5를 반환한다.
이 진입점을 사용하는 다른 하위 명령에도 같은 처리가 적용된다.
예산 거부(`BudgetError`, 종료 코드 4)와 일반 프로그래밍 오류의 전파는 유지한다.
기존 예산·정산 로직은 변경하지 않는다.

회귀 시험은 합성 계정 주소를 가진 `EndpointConnectionError`·`ClientError`를
세션 시작과 원장 조회에 각각 주입한다. stdout·stderr에 계정 ID·URL·오류
본문·traceback이 없고 종료 코드가 5인지 검사한다. 정상 `status`는 임시 로컬
원장을 사용해 JSON 출력·정산 기록·활성 세션 해제를 검증한다. 별도 프로세스에서
실제 `__main__` 진입점을 실행하는 스모크 검사도 종료 코드와 출력 전체를 대조한다.

원래 진입 방식인 `_cli()` 직접 호출로는 네 가지 저장소 오류가 전파됐고,
새 진입점의 회귀 시험 4개는 통과했다. 전체 Python은 1,341개 실행·1,335개
통과·기존 건너뜀 6개·실패/오류 0이다. Rust 작업 공간은 478개 통과·기존
무시 1개, 별도 온톨로지 실행기는 3개 통과했다. 문서 정합성 검사도 통과했다.
전체 검증 명령·결과는
[검증 증거](../../../tools/evidence/audit4-r2-status-endpoint-leak/README.md)에 기록한다.

실제 R2 접근·자격 증명·과금 작업을 수행하지 않았다. 이 증거는 로컬 도구의
오류 출력 회귀 검증이며 실제 공시 확보율·R2 관측 대조·소비자 화면·첫 출시
완료 증거를 대체하지 않는다.
