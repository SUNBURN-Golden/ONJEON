## 2. 탐색 경로

### 삼성생명 (www.samsunglife.com, robots `Allow: /`)
1. 사이트맵 `GET /gw/sitemap.xml` → 상품공시 > 판매상품 `…/individual/products/disclosure/sales/PDO-PRPRI010110M`.
2. 페이지는 3.6KB 셸이다. `runtime.6e755620.js`에서 청크를 찾고 `view_pc_individual_products_disclosure_sales.2c3f877b.js`에서 API 3개를 확인했다.
   - `POST /gw/api/product/disclosure/product/prdt/{salesAllPrdtList 전체, salesPrdtList 판매, salesStopPrdtList 판매중지}`
   - 본문은 `application/x-www-form-urlencoded`여야 한다. JSON이면 `code 4200 … [pageNo]` 오류.
   - 파라미터 `mCode=+&gCode=+&sCode=+&searchYear=+&goodsName=&pageNo=1&pageRows=N`. `pageRows=7000` 한 번에 전량.
3. 문서: `https://pcms.samsunglife.com/partnerpage/CustomerPage_Unit.jsp?goodsCode=<코드>&docType=<101 요약서|401 사업방법서|301 약관>&saleDate=<fromdate>&pageGubun=prdt`(법인 `CustomerPage_Corp.jsp`). 화면 코드는 `status`가 "상품운용"·"상품수정"일 때만 문서를 연다.

### 교보생명 (www.kyobo.com, robots `Disallow:` 공란)
1. `GET /dgt/web/product-official/all-product/search`
2. 목록 `POST /dtc/product-official/find-allProductSearch`, JSON `{"dgtPdtAtrDvCd":"M","dgtPdtAtrMclCd":"99","dgtPdtAtrSmclCd":"99","saleYn":"99","currentPage":1,"pagePerSize":3000,…}` → `listCnt=1127`. 화면은 10~100개만 고를 수 있지만 3000도 받아 준다.
3. 기간별 다운로드 `POST /dtc/product-official/find-allProductSearchDetail` `{"dgtPdtPdSeqtId":"<목록의 dgtPdtAtrSeqtId>"}` → `list`(판매기간) + `list2`(같은 순서의 파일: temp01 요약서, temp02 약관, temp03 사업방법서).
4. 파일 `GET /file/ajax/download?fName=/dtc/pdf/mm/<파일명>`. Content-Length·Content-Disposition은 있고 **Last-Modified·ETag는 없다.**

## 3. 관측 사실

### 3.1 삼성생명
- **한 행 = 상품코드 × 판매기간.** 필드 `goodsCode, goodsName, fromdate, todate(현재 판매는 99999999), status, lCode(판매중/판매중지), mCode, gCode, sCode, gubun, filename1 요약서/2 사업방법서/3 약관/4, filepath*(법인), boardNum, totalRows`.
- 건수: 판매상품 296행(코드 137, 이름 127), 판매중지 6,385행(코드 4,264, 이름 3,059), 전체 탭 6,680행.
- **"판매중" 목록에 끝난 판매본이 있다.** 296행 중 168행은 todate가 과거다. 예: 삼성인터넷암보험(2404)(갱신형,무배당) `LP0286011` 8행(20240401~20240922 … 20260923~현재)이 모두 판매중.
- **같은 코드·이름의 판매본이 두 목록에 나뉜다.** 삼성인터넷암치료보험(2501) `LP0799001`: 2025년 판매본 4행은 판매중지, 2026년 3행은 판매중. 두 목록에 모두 나오는 코드 45개, 이름 63개.
- 판매중지 목록인데 `todate=99999999`인 행 4건. 예: 삼성VVIP종신보험(2601)(무배당,보증비용부과형)[무해약환급금형] `LP06740060G03` 20260101~99999999.
- 가장 오래된 판매본: 거치전환특약(노복) `01316` 19550101~19981214(추정: 자리채움 날짜), 다음은 신년금 19601202~19720731. 1990년 이전 판매본 200건 이상. 1999년 이전도 약관 파일 ID는 대부분 있다.
- **채널은 분류값(mCode)으로 드러난다**: 개인 / 온라인 / 방카슈랑스 / 제도성특약 / 법인상품 / 단체상품 / "단체" / "개인상품"(구값 6건). 방카 상품명에 `(B2601)`처럼 B 접두. 예: 삼성플래티넘행복연금보험(B2601)(거치형,무배당) `LP077000202AB11`. TM·GA 구분은 없다.
- 상품명 안 개정 연월 `(YYMM)` 1,337행. 삼성하이브리드연금보험(2211)(무배당) `LP06890015N02`는 2022-11-23~2023-12-31에 **판매본 15개**가 대부분 한 달 단위로 이어지는데 이름의 (2211)은 그대로다.
- 2026-09-23에 판매중 상품 대부분이 일제히 새 판매본을 시작했다. 하루짜리 판매본 13건. 예: 삼성밸런스종신보험(2603) `LP0758003L05` 20260319~20260922 → **20260923~20260923** → 20260924~현재.
- `status`에 결재 상태가 섞여 있다: 상품운용 6,369 / 수정검수 6 / 검수요청 6 / 신규등록 1 / 삭제결재 1 / 수정등록 1 / 상품수정 1. 시작일 > 종료일 행 3건(예: 無삼성연금보험(공시이율형) `05200` 삭제결재, 20020815~20011217).
- 파일 ID는 13자리(추정: epoch ms). ID 시각이 판매 종료보다 늦은 약관 파일 2,246건, 그중 1,321건이 2004년(일괄 등록·재등록 흔적). 예: 노후설계연금2종(거치형) 19901015~19920808의 약관 ID 시각 2004-09-01.
- 정렬: 판매중지 목록은 이름 오름차순, 전체 탭은 역순. 같은 이름 안 날짜 순서는 보장되지 않는다.

### 3.2 교보생명
- **한 행 = 상품**(1,127건; 판매중 205, 판매중지 922). 필드 `dgtPdtAtrSeqtId`(상품 ID), `dgtPdtCd`(상품코드), `dgtPdtAtrNm`, `dgtPdtAtrMclCd`(PAMS01~10), `saleYn`, `preNnnn`(1999년 이전 여부), `saleStDt/saleEdDt`, `maxSlsTerm`, `endYymmdd`, `a1/a2/a3`(최신 판매본의 요약서/약관/사업방법서), `a4/a6/a7`(계약서·운용설명서), `dgtPdtDsc`(안내문), `wrtrNm`(담당자 실명. 이 기록에는 옮기지 않는다).
- 판매기간 이력은 상세 API에만 있다. 연금저축교보연금보험(seq 248, 코드 1000649)은 판매기간 **74개**(2003-03-10 ~ 2026-06-29~현재).
- 목록 `saleStDt/saleEdDt`의 뜻이 행마다 다르다. 비너스암치료보험(seq 396)은 목록에 첫 판매기간(1995-06-09~1995-12-31)이 나오지만 상세에는 7개(~2000-02-29). `maxSlsTerm`은 직전 판매기간인 경우가 많다.
- **채널**: PAMS06 통신판매전용 225건, PAMS07 방카슈랑스전용 60, PAMS10 온라인 19. 비대면판은 `[D]`. 예: 교보K-실속종신보험 (무배당) 1000953(PAMS04) / \[D\](무배당) 1000954(PAMS06). 과거 파일명 `(FP)`, `(BA)`, `DM`. (무)교보장기주택마련저축보험Ⅱ는 1000466(FP) / 1000467(BA) / 1000474(DM) 세 행.
- **문서 공시 규칙**(화면 코드·안내문): 판매중지·1999년 이전은 약관만, 판매중지(1999년 이후)는 약관·사업방법서, 판매중은 3종. 안내문 "1999년 이전 사업방법서는 공시하지 않습니다."(163), "판매중지상품의 상품요약서는 공시하지 않습니다."(13), "이 상품의 약관을 변경대비표로 대체합니다."(8).
- 안내문의 이름 이질성: "실제 판매한 상품명칭과 기초서류상의 명칭이 다름에 유의하시기 바랍니다."(14건), "…TM,CM 등 비대면채널 상품으로 판매될 경우 상품명칭을 무배당 교보다이렉트플러스건강보험(갱신형)으로 합니다.", 여성전용 판매 시 다른 이름.
- 중도부가특약이 독립 행 91건(예: (무)교보LTC종신보험 중도부가특약).
- 가장 오래된 판매본: 종신연금보험 1979-02-19~1979-12-17. 1983년 백수보험·새로나온암보험 "인쇄약관".

### 3.3 메트라이프생명
- 주보험: 상품 58개 / 판매기간 행 689개(보장 421, 변액 179, 연금 89). 열: 구분, 주보험상품명, 판매기간, 사업방법서, 상품요약서, 약관, 상품설명서(남/여), 특약(팝업). 요약서는 현재 행 58개에만 있고, 상품설명서 열은 689행 모두 "-".
- 예: 무배당 더해주고채워주는정기보험(insProdSeq=403) 판매기간 28개(2015~). 2026.07.01~ 약관 `…_12284_20260701.pdf`, 2026.01.01~01.31 / 02.01~03.31 / 04.01~06.30 세 행은 모두 `…_12199_20260101.pdf`. 사업방법서만 `_20251031_v2` → `_202602`로 바뀌었다(**약관은 그대로인데 판매본이 새로 생김**).
- 특약 탭: 특약 270개 / 1,940행. 특약마다 자체 판매기간·약관이 있다. 무배당 재해사망특약은 2003.04.22~부터 판매기간 30개 이상. 파일명 `무배당 재해사망특약_53308_53624_53309_53625_20260701.pdf`처럼 **한 파일명에 코드 여러 개**인 행 1,172개.
- 판매중지: 상품 349개 / 1,376행. **상품요약서 열이 없다.** 1989.09.30부터. 예: "코오롱-메트 교육보험" 1989.09.30~1991.08.31, 파일 `70_YAK_200806261115.pdf`(2008년 재등록 파일명).
- 특약 팝업은 판매기간마다 다르고, **특약 판매기간이 주계약 판매기간과 다르다**(403/3991: 무배당 22대질병수술특약 2026.01.01~06.30 등).
- **공시된 주계약-특약 연결과 약관 색인이 맞지 않는다.** 403/4182(2026.07.01~) 팝업 1~2쪽은 "무배당 (간편)22대질병입원특약", "(간편)수술특약" 등 (간편) 특약뿐인데, 같은 판매기간 주계약 약관의 특약 색인 25개에는 "(간편)"이 없다.

## 5. 설계가 표현해야 할 특이 사례
1. 상품코드 재사용(교보 1000649가 1983년 상품과 2026년 상품, 코드 222개).
2. 판매중/판매중지 구분이 판매본 단위인지 상품 단위인지 회사마다 다르고 한 회사 안에서도 섞인다(삼성 LP0799001, 라이프플래닛 1000101).
3. 채널판·코드 중복판이 같은 약관을 바이트 그대로 공유한다(교보 sha256 동일, 라이프플래닛 같은 파일명).
4. 형별 약관 분리(AIA), 약관 대신 변경대비표(교보), 한 파일명에 코드 여러 개(메트라이프).
5. 특약이 독립 판매본을 가진다. 판매기간이 주계약과 다르고, 같은 본문이 두 곳에 있으며, 공시된 주계약-특약 연결이 약관 색인과 맞지 않을 수 있다.
6. 판매본 안에서 파일이 교체되거나 판매 종료 수년 뒤 재등록된다. 서버 변경 표시가 없어 내용 해시가 필요하다.
7. 결재 상태·날짜 이상 행(삭제결재·검수요청, 시작일 > 종료일, 판매중지인데 99999999, 하루짜리 판매본, 19550101).
8. 이름 변경 이력의 형태가 회사마다 다르다(AIA 문자열 안 "(구, …)", 라이프플래닛 같은 코드 다른 이름, 교보 안내문, 삼성 (YYMM)).
9. 인수·사명 변경 흔적이 상품명 접미나 옛 회사명으로만 남는다((BYC), 코오롱-메트).
10. 공시 메타데이터의 날짜 필드가 판매기간과 다르다(교보 saleStDt/maxSlsTerm, 파일명 날짜 오기, 파일 날짜 ≠ 판매본 시작일).
