# Decision: Decision gate D-02

Decided by Fable 5.1 (ONJEON autoloop, 2026-10-14 06:31 KST); reversible.

**Decision:** D-02를 다음으로 정한다(위임 결정, 사용자 확정 아님). (1) 구성: 보험 지식 검수(ReviewDecision)는 작성(추출)·승인·레드팀에 서로 다른 모델 계열을 하나씩 둔다. 하한은 2계열이며 families_count≥2는 코드가 강제한다(B3). 불일치·반례는 hold, 다수결 없음(I14). (2) 첫 배치: 작성=claude 계열(Fable·Sonnet은 한 계열, 설정안 §3.3의 엄격 해석; 유일하게 연결이 확인됨), 승인=비-claude 계열 X, 레드팀=X와 다른 비-claude 계열 Y. Y 확보 전에는 레드팀을 X의 다른 모델·프롬프트로 두되 ReviewDecision에 3계열 미달(degraded)을 기록하고 독립성을 과장하지 않는다. (3) 업체·모델 ID는 이 결정에서 고정하지 않는다(미확인 경로를 정본에 박지 않음). 비-claude 후보 조건은 API의 JSON Schema 출력, 사용자가 확인한 입력 보존·학습 조건, 제공자 측 월 한도 설정 가능, 최소 호출·모델 식별 증거를 남길 수 있을 것이다. 역할표에 이름이 있는 gpt·grok·glm 계열부터 확인하고, swe(Devin CLI)는 모델 API 확인 전까지 제외한다. 계열 라벨·모델 ID는 review_policy.json에 두며 개발 roles와 별개다(운영 규칙 7). (4) 정책 소유자는 사용자 본인 1인이다. 범위는 AI 승인 임계값 확정(O06·D-19), 모델 구성 변경, 서킷 브레이커 사고 시 중단·재개다. 중단은 자동·누구나 가능, 재개는 소유자만 한다. 임계값 수치는 정하지 않는다: T-OP-03 실측 뒤 소유자가 확정하고, 그 전엔 불일치=hold로 두며 임의 수치를 쓰지 않는다. (5) 이 결정은 지출·계약·계정 개설·키 발급을 하지도 승인하지도 않는다(사용자 조치). 제공자 측 월 한도 설정을 확인하기 전에는 production 호출을 하지 않고, 키는 빌더·데몬에 나눠주지 않고 실행 환경 비밀값으로만 둔다(D18 원칙 준용). (6) 적용 범위는 공개 약관·공시 문서의 지식 검수다. 개인 PDF의 외부 AI 처리는 D-17(O08·O09)이 따로 정한다. 풀리는 것: ai-gateway 다중 제공자 구조, review_policy.json 스키마, T-KN-06 모의 2계열(environment=test). 아직 막힌 것: environment=production ReviewDecision, T-OP-03 실측, S1 관문 (b). 비-claude 접근 확인 기록(최소 호출 성공·모델 식별 증거·계열 라벨, 05 §1a 형식 준용)이 생길 때까지다. 등록 시 주의: tasks.json이 D-02를 T-OP-03 start와 T-KN-06·T-OP-02 real_data 게이트로 쓰므로, 이 기록만으로 decisions_recorded에 D-02를 등록하면 접근 확인 없이 게이트가 열린다. 접근 확인 기록을 별도 조건으로 걸거나 게이트를 분리해야 한다(그록봇 몫). 이 결정은 기록 문서 외에 DECISIONS.md·tasks.json·review_policy.json을 바꾸지 않는다.

**Why:** 차단 요인은 구성 원칙이 아니라 비-claude 접근이다. 원칙과 소유자를 정하면 구조·모의 경로가 풀리고, 접근 확인 조건이 production 차단을 유지한다. 계열 하나로는 ReviewDecision을 만들 수 없으므로(B3) 같은 계열 가짜 독립을 막아야 'AI 합의만으로 정확도 보증 금지'가 지켜진다. 3계열을 필수로 올리면 비-claude 둘을 확보하기 전까지 production이 멈추므로 하한은 2로 두고 미달을 기록으로 드러낸다. 이 결정은 지출·계약·키 발급을 하지 않고 production 호출을 접근 확인과 월 한도 확인 뒤로 미루며 구성은 설정이라 되돌릴 수 있다. 그래서 실제 돈·비밀값·배포에 직접 닿지 않아 critical이 아니다. 다만 이후 계정 개설·한도 설정·키 발급은 비용·자격 증명이 걸린 사용자 조치이며 이 결정이 승인하지 않는다.
