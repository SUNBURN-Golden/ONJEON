# 동시성 통제

O17 기본값(DEC-O17, BUDGET.md §6): **지정 실행 환경 하나, 동시 실행 1개, 수동 실행.** 예약 실행·환경 추가·동시 2개 이상은 허용하지 않았다. 이 문서는 그 기본값이 어디서 어떻게 강제되는지, 체크포인트가 무엇을 더하는지 적는다.

| 경우 | 통제 | 강제 위치 | 한계 |
|---|---|---|---|
| 같은 컴퓨터의 동시 실행 | 파일 잠금. 두 번째는 요청 없이 거부 | 로컬 상태 파일(`$ONJEON_GATE_DIR`) | 그 컴퓨터만 |
| 같은 컴퓨터의 시작 폭주 | 시간당 시작 30회 | 로컬 | 그 컴퓨터만 |
| 다른 컴퓨터의 동시 실행 | 원장 순번 쓰기 경쟁: `If-None-Match`로 한쪽만 성공(412), 진 쪽은 새 기록을 읽고 다시 판단 | 원장(R2) | 입장 횟수는 동시에 들어오면 한도를 넘을 수 있다(남겨 둔 입장 몫으로 흡수, BUDGET.md §5) |
| 체크포인트 쓰기 경쟁 | 같은 순번 키는 한 번만 쓸 수 있다. 진 쪽은 내용이 같을 때만 성공으로 본다 | 원장(R2) | 서로 다른 내용을 쓰려 하면 중단하고 audit 필요 |
| 체크포인트 중 다른 실행의 정산 | 체크포인트는 자신이 읽은 순번까지만 덮는다. 그 뒤 기록은 다음 읽기에서 이어 붙인다 | 설계 | — |
| 예약 실행(cron·루틴·워크플로) | 쓰지 않는다 | 운영 규칙 | 도구는 막지 못한다 |
| 환경 수 | 하나 | 토큰 배치(TOKENS.md) | 토큰을 둔 곳이 곧 환경 |

## 체크포인트 운영 규칙

- 체크포인트는 수동으로, 다른 실행이 없을 때 한 번에 하나만 쓴다(`checkpoint` 명령도 입장·예약을 거친다).
- 체크포인트 이후 기록이 100건에 도달하면 일반 실행을 거부하지만, `checkpoint` 명령 세션은 읽기 상한을 넘어 검증할 수 있다(`over_limit_ok`). 쓰기 상한은 모든 세션에 적용한다. 체크포인트를 입장 한도 안에서 먼저 저장·확인한 뒤 예약·정산을 쓴다. 100건에서는 체크포인트 100 → 예약 101 → 정산 102이며, 실패한 체크포인트는 입장만 남겨 뒤받침을 늘리지 않는다. 따라서 실패를 반복해도 다음 체크포인트의 예약 전 읽기 여유가 줄지 않는다. 100건의 복구는 예약까지 Class A 7·Class B 103(기존 체크포인트가 있으면 B 104)으로 입장 한도 A 8·B 110 안이다. `audit`는 상한을 지킨다. 모든 실패의 입장은 계속 계상되므로 월별 입장·비용 한도를 소진하면 별도로 거부된다. 여전히 **한도에 닿기 전에** 쓴다(기록이 80건을 넘으면 쓰는 것을 권한다 — 운영 규칙이며 도구가 강제하지 않는다).
- 환경을 늘리거나 동시 실행을 허용하려면 O17을 다시 열어 정한다. 이 과제는 그 값을 정하지 않았다.
