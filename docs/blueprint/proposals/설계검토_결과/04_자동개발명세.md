## 2. 상태 기계

### 2.1 상태

| 상태 | 뜻 |
|---|---|
| `blocked` | 선행 과제가 `post_merge_states`에 없거나 `decision_gates.start` 미결 |
| `queued` | 실행 가능 |
| `leased` | 임대(lease_id, **fencing_token**, TTL). 쓰기 전 |
| `building` | 격리 작업 트리에서 쓰는 중. 하트비트 필요 |
| `handoff` | 전환 신호 감지. `handoff_sequence`(S02): stop → isolate(빌더 쓰기 차단·자격 회수, 보존과 무관하게 먼저) → confirm_quiescent(`preserve_manifest.function` = git_write_tree_oid 2회 일치) → preserve(로컬 커밋 → 원격 푸시, 데몬 보존 전용 자격). `handoff_record`에 phase와 `preservation_state ∈ {none, local_committed, remote_pushed}`를 별도로 기록(T03). 실패 사건은 `handoff_failure_policy.max_attempts` 안에서 재시도, 넘으면 `handoff_blocked`. preserve_succeeded(remote_pushed) 뒤에만 revoke_token·`issue_lease` |
| `handoff_blocked` | 보존 실패로 복구 가능한 상태에서 정지(T03). 작업 트리 쓰기 금지 유지, `always_revoke`(빌더 자격·토큰·preserve_credential) 회수됨, 사유·단계·시도 이력 기록. 다음 임대 없음. `recovery_decision`(사람 또는 설계 담당)으로만 handoff 재개, `recovery_decision(action=abandon)`면 returned(R-14) |
| `paused_no_builder` | 모든 빌더 불가. 작업 보존 후 대기 |
| `pr_open` → `ci_failed` / `review_pending` | PR 열림 → CI 결과 |
| `review_in_progress` → `changes_requested` / `review_approved` | 리뷰(대상 SHA 고정) |
| `audit_pending` | 즉시 감리 대상, 병합 전 감리 대기 |
| `merge_wait` | 사람 병합 대기. `reason ∈ {ready, reviewer_unavailable, auditor_unavailable, decision_pending}` |
| `merged` → `audit_queued` → `done` | 사람이 병합 → 정기 감리 묶음 → 종료 |
| `merged_invalid_approval` | 유효한 승인(SHA 일치 리뷰·필요 시 감리·merge 관문) 없이 병합이 관측됨. 기록만(R-12). `post_merge_states`가 아니며 done으로 가지 않는다. 담당자가 되돌리기·재리뷰 조치를 기록하면 review_pending |
| `returned` | 반송(return_code). **담당자가 해소를 기록하면(`owner_resolved`) queued로 재개** |
| `cancelled` | 담당자 취소 |

**병합 뒤 상태(병합 뒤 상태와 선행 조건 대응):** `post_merge_states = [merged, audit_queued, done]`. 선행 과제 충족은 `state in post_merge_states`로 판정한다. 이미 완료된(done) 선행도 충족이다.

### 2.2 사건과 전이

모든 전이는 `event`를 갖는다(`events` 52개, `noop_events` 16개, 전이 90개, 상태 21개. 이전 판 문구의 '전이 79개'는 틀렸고 기준 판의 실제 수는 80개였다. G29~G50 해소로 10개가 늘었다: G30·G37·G39의 행 나누기와 G38·G50 새 전이 5개, G48의 `envelope_invalid` 행 5개). **no-op 사건**(`noop_events`: 중복 알림·CI 대기·하트비트 등)은 상태를 바꾸지 않고 수신 기록만 남긴다. 순서가 뒤바뀐 사건은 보류 큐에 두었다가 조건이 맞을 때 적용하고 SHA가 맞지 않으면 무효(R-04)로 기록한다. 전이표 밖 조건만 반송한다. 기록은 네 가지로 분리한다(`record_separation`): 작업 생명주기 / 불변 완료 사실 / 리뷰·감리 유효성(SHA에 묶임) / 병합 관측. 핵심 전이:

| * → returned | `unmapped_condition` | 표에 없는 모든 조건. 활성 임대가 있으면 임대를 끝내고 반송한다(전이 두 개, G37) |

### 2.3 결정 관문(원본 F10 대응)

과제마다 `decision_gates{start[], real_data[], merge[], release[]}` 네 키가 있다(`gate_semantics`). **시작 전이(blocked → queued)는 `start`만 본다.** `real_data`는 지시 봉투의 `real_data_allowed`로 전달되어 실제 제공자 검수·R2 쓰기·실제 민감자료·대량 조회 단계만 건너뛰게 하고 상태 전이를 막지 않는다(D-02 미정에서 모의 제공자 작업 가능, D-04 미정에서 로컬 작업 가능). **병합 대기 전이(→ merge_wait)는 `merge`만 본다.** `release`는 데몬 밖(릴리스 빌더·기능 플래그·criteria_application)이 검사한다. **정본 변경 권한(재검토 R05)**: 지시 봉투 필수 필드 `canon_change_approval`(null 또는 `{decision_ref, scope_paths[]}`)로 전달한다. `task.canon_change.required=true`면 null일 수 없고 `decision_ref`가 결정 기록에 있어야 하며 `scope_paths ⊆ allowed_paths`이고 정본 경로만 담는다. 누락·잘못된 참조면 봉투를 보내지 않고 returned(R-13). 허용 경로에 정본 파일이 있다는 사실은 승인이 아니다. `real_data_allowed=false`는 모의·로컬 작업을 막지 않는다. `merge` 미결이면 `merge_wait(decision_pending)`에서 기다리고, 결정 기록이 오면(`decision_recorded`) `ready`로 바뀐다. README 차단 범위표는 tasks.json의 `decision_gates`에서 생성한다. 검증 상태: 명세됨 → T-OP-00 시험 `decision-gate-merge-only` → T-OP-09.

## 3. 빌더 순서와 전환 조건 (원본 F09 대응)

전환은 **사용량 제한·서비스 가용성** 문제일 때만 한다(운영 규칙 1). 신호는 **빌더 CLI 자신의 모델 호출 상태 채널**만 본다. 자식 프로세스 출력, 시험 로그, 수집 대상 사이트 응답, 저장소 API 응답은 보지 않는다. 각 신호의 `detect`는 `{source, match, scope}` 구조다.

| 신호 | source | match | scope |
|---|---|---|---|
| `usage_limit` | `provider_http_response` | 429, 또는 제공자가 문서화한 할당량 오류 유형 | `model_provider` |
| | `runner_exit_code` | CLI별 확인표(05 §1b)에 기록된 한도 종료 코드만 | `runner_self` |
| `auth_failure` | `provider_http_response` | 401/403 | `model_provider` |
| | `runner_auth_probe` | 인증 상태 명령이 미인증·만료 보고 | `runner_self` |
| `service_unavailable` | `provider_http_response` | ≥500 또는 연결 오류 3회 연속 | `model_provider` |
| | `runner_exit_code` | CLI별 확인표의 불가 종료 코드만 | `runner_self` |
| `runner_missing` | `runner_version_probe` | 명령 없음 또는 버전 프로브 비정상 종료 | `runner_self` |

전환 신호 봉투는 `{source, attempt, call_id, lease_id, fencing_token, runner, status, observed_at}`을 갖고 데몬은 `signal_validation`(출처·attempt·호출 ID·임대·토큰·실행기)으로 검증한다. 실행기 어댑터가 **자기 모델 호출(call_id)에서 관측한 구조화 오류**만 발행한다. 허용 출처는 네 가지뿐이다: `provider_http_response`(scope는 반드시 `model_provider`), `runner_exit_code`, `runner_auth_probe`, `runner_version_probe`. CLI별 종료 코드·구조화 오류의 확인 방법은 05 §1b에 두고, **미확인이면 그 CLI의 `runner_profile`은 비어 있어** HTTP 응답·인증 프로브·버전 프로브로만 전환한다. 금지 사유: 시험 실패, CI 실패, 리뷰·감리 지적, 품질 불만, 느린 진행, 자식 프로세스 stderr 문자열, 수집 대상 사이트 HTTP 오류, 저장소 API 오류. 검증 상태: 명세됨 → T-OP-00 `provider-scoped-switch` → T-OP-09(실제 CLI의 상태 채널 확인).

전환 절차(`handoff_sequence`, 재검토 S02로 개정, T02·T03으로 보강. 이전 R04③의 '보존 → 중단'은 빌더가 아직 쓰는 중에 데몬이 커밋·푸시해 반쯤 쓰인 상태를 보존할 수 있어 폐기했다): **stop**(정상 중단 요청: stop 봉투 + SIGTERM, 기한 grace_s. 빌더의 stopped·wip_preserved 봉투는 자기 보고일 뿐 보존이 아니다) → **isolate**(기한 안에 중단이 확인되지 않으면 프로세스 그룹 강제 종료 또는 작업 트리 쓰기 금지 격리. 확인됐더라도 빌더의 임대별 쓰기 자격·토큰 회수. 보존 성공 여부와 무관하게 여기서 끝난다) → **confirm_quiescent**(기계 조건 전부 참: 프로세스 그룹 생존 0, 작업 트리 최대 mtime이 `quiescence.window_s` 동안 불변, 열린 쓰기 핸들 0, `preserve_manifest.function`(git_write_tree_oid)이 2회 연속 같은 tree OID → quiescent_tree_oid. 거짓이면 quiescence_failed → `handoff_failure_policy`) → **preserve, 로컬**(**데몬이 보존 전용 자격 preserve_credential**(임대별·단기, 데몬만 보유)으로 `preserve_manifest`의 includes/excludes대로 임시 인덱스를 만들어 WIP 커밋. `commit.tree_oid == quiescent_tree_oid`(같은 함수로 계산한 OID끼리만 비교, T02). 성공 시 preservation_state=local_committed) → **preserve, 원격**(같은 자격으로 푸시, remote ref == wip_commit_sha. 성공 시 remote_pushed = preserve_succeeded) → **finally**(성공·실패 모두 `always_revoke`: 빌더 쓰기 자격·빌더 토큰·preserve_credential 회수. 실패하면 `handoff_blocked`에서 복구 가능 상태로 정지: 쓰기 금지 유지, 사유·단계·시도 이력 기록, 다음 임대 없음) → **revoke_token**(토큰·세대 폐기. 이후 옛 세대의 봉투·푸시는 `late_envelope_rejected`) → 인계 기록(phase, preservation_state, wip_commit_sha, quiescent_tree_oid, 정상/강제 여부, 실패·시도 이력) → **issue_next_lease**(전제: preserve_succeeded 또는 recovery_decision 뒤의 preserve_succeeded. `lease_guards` 통과 뒤 `issue_lease` 호출만 한다. 세대·임대 기록·outbox는 그 함수가 한 트랜잭션으로 쓴다(T04)) → `authors_families` 갱신.

## 4. 독립 리뷰 배정

```text
candidates = builders 순서
for c in candidates:
    if c.family in pr.authors_families: continue   # 작성 참여 계열 제외(운영 규칙 2)
    if c.available: assign(c); break
else: state = merge_wait(reviewer_unavailable)      # 복귀 시 reviewer_available 사건으로 review_pending
```

리뷰 결과는 `sha`를 가진다. `pr.head_sha`와 다르면 무효(R-04 기록, `head_sha_changed`). 계열표는 daemon_rules.json `roles.families`. Fable·Sonnet 같은 계열 해석은 사용자 확인 전까지 더 엄격한 쪽을 쓴다. 그 결과 이 환경에서 확인된 경로(claude 계열)만으로는 Sonnet 작성 PR의 리뷰어가 없고 모든 PR이 `merge_wait(reviewer_unavailable)`에 머문다. 병합만 막고 작성·시험·설계는 막지 않는다.

## 11. PR #2 AIOPS 인계안과 다른 점

중앙 AIOPS를 재가동하지 않는다. 데몬은 판단 주체가 아니라 전령이다. 자동 병합 권한이 없다. 역할·전환 정책은 U-04가 정했고 이 문서는 그것을 기계 규칙으로 옮겼을 뿐이다.
