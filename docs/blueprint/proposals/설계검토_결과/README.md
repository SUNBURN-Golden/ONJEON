# 설계 검토 결과 묶음 (검토용, 수정판)

## 인계 기준: 제품 목적 (사용자 진행 지시 2026-10-13, 최상위 기준)

- 만드는 것은 **세 부분이 끝까지 연결된 완성품**이다: **철저한 데이터 수집·관리·레이블링 → 수준 높은 디지털 트윈 → 소비자가 쉽게 이해하는 직관적 UX/UI.** 목적은 보험 소비자와 공급자 사이의 **정보비대칭을 줄이는 것**이다. 소비자가 설계사의 설명을 검증하고, 불필요하거나 불리한 선택을 스스로 구별할 수 있어야 한다.
- 이 목적은 소개 문장이 아니라 실제 작업과 완료 기준에 연결된다: **[09_제품목적_대응표.md](09_제품목적_대응표.md)**(제품 목적 → 소비자 기능 → 데이터·레이블 → 트윈 → 화면 → 구현 작업 → 완료 증거, P01~P19)와 tasks.json의 done_criteria·required_test_ids. 미확보 사유 기록은 확보 완료가 아니다. 결과를 바꾸는 조건은 숨기지 않는다. 종합점수로 정답을 대신 정하지 않는다.
- **일부 상품 시연이나 자동 개발 데몬 완성을 첫 출시 완성품으로 바꾸지 않는다.** 데몬 과제(T-OP-00·T-OP-09, daemon_rules.json)는 개발 도구이며 출시 완성품의 일부가 아니다. 최종 관문 T-OP-08은 09의 모든 행(근거 있는 축소·후속 제외)이 등록부 증거로 닫혀야 통과한다(`purpose-rows-all-closed`).
- 범위를 줄이거나 후속으로 옮긴 것은 09의 "축소·후속" 칸에 근거(사용자 결정 ID·정본)와 함께만 적는다. 근거 없는 축소는 없다.

## 0. 작성 주체와 실행 경로

- 작성: 사용자가 2026-10-12에 지정한 **설계 담당(아키텍트·감리) 역할 Fable**로 호출된 하위 에이전트. 실행 경로는 이 클라우드 세션의 claude CLI(2.1.296) 하위 에이전트. **자기 보고 모델명은 증명이 아니다.**
- 독립 리뷰·감리 없음. 커밋 고정과 독립 재검토 제출은 구현자가 한다. 작성 계열(claude) 밖 리뷰어는 현재 확인된 경로가 없다. 그것은 **이 묶음의 정본 반영 병합만** 막고, 사용자 검토와 다음 설계 작업은 막지 않는다.
- 금지 사항 준수: 정본·토의 자료·`검증/spec_check.py`·`검증/재현_ffbcaf6.txt`·`온톨로지/**`·`.github/workflows/**`를 고치지 않았다. 이 폴더의 README, 01~09, tasks.json, daemon_rules.json만 고쳤다. 커밋·푸시·CLI 설치·외부 수집·배포·가동·발송 없음. 비밀값·모델 식별자 원문·원문 발췌 없음. 생성기 중간 산출물은 저장소에 두지 않았다(세션 스크래치패드).

## 4. 핵심 판단 요약 — [설계 담당 결정(감리 대상)]

1. 구역은 정본 D15 다섯 개 그대로. knowledge 안에 **책임 영역 C(판단 기준 관리)**를 모듈로 둔다([사용자 결정 2026-10-12]). 설계 승인은 특정 기준의 서비스 적용 승인이 아니며, 적용은 별도 관문(criteria_application, D-08)으로만.
2. Assertion과 FieldAssertion 통합 저장. 문서는 원본(관측) → 구획(판단, 지문) → 본문 판(판단, ReviewDecision으로만 accepted) → 계열. 본문 같아도 참조 별표·정의·범위가 다르면 다른 판(K16).
3. 릴리스는 구성원 목록(주장·노드·조항·구획·판·공백·가격·기준 릴리스 참조) + 규칙 파일 해시 + 내용 해시로 고정(K15). 재현(view)과 사용 제한(ReleaseNotice, 영향 담보 단위)은 다른 장치.
4. 결론별 의존 기록. 미확인과 겹치는 결론만 보류, 독립 계약 결과 유지, 합산은 포함하지 못한 계약을 밝힘(토의 9차).
5. 온톨로지 사례는 시험 전용 고정(origin=fixture, decision.by=fixture_assumption, fixture_only). 지름길은 B1~B9에서 막힘(설계).
6. 트윈 축을 S0~S1에 고정. 범위 관계는 공식 CodeSystem 있을 때만 accepted.
7. 데몬은 전령. 전이표 밖 조건은 반송. 시작 전이는 decision_gates.start만, 병합 대기는 merge만. 선행 충족은 post_merge_states. 전환 신호는 모델 제공자 응답·실행기 종료 코드·프로브만.
8. 늦은 쓰기 차단은 펜싱 토큰·격리 작업 트리·데몬 전용 푸시·자격 회수로 **명세**했다. 모의 검증(T-OP-00)과 실제 실행기 검증(T-OP-09)은 분리된 과제이며 둘 다 아직 없다. "차단된다"는 증명되지 않았다.
9. 수치(임대 TTL·동시 임대·grace_s·window_s·max_attempts)는 정하지 않았다(JSON에는 보수 기본값 숫자 + `decided: false`). 비용 상한은 사용자 결정 U-05(2026-10-13)로 두지 않는다.

## 7. 구현됨 / 설계 구분 (보고 정확성)

02 §10의 표가 기준이다. 요약: **구현됨**은 규칙 엔진(I1~I5·I18), 어휘 검사기, 원본 보관·R2 원장 도구, 그리고 토의 자료 수준의 검증기 둘(ontology_check.py, spec_check.py)뿐이다. DB 제약·적재 거부·릴리스 빌더·API·개인정보 강제·판단 기준·의존 기록·데몬은 **전부 설계(구현 예정, 과제 ID)**다. 이전 판 보고의 "기존 엔진 검사 통과"는 이 묶음의 설계가 구현되었다는 뜻이 아니다.

## 8. 이 묶음에 들어 있지 않은 것

자동 개발 가동, 자동 병합, 병합, 커밋·푸시, 배포, 외부 문의 발송, CLI 설치, 외부 사이트 수집, 정본·토의 자료·검증기·워크플로 변경, 규제 검토(해당 항목은 "규제 검토 대상, 이 문서는 판단하지 않음"), 보험 지식 검수, 현재 클라우드 환경의 데몬 생성, 수정 완료 판정.

## 9. 스스로 확인하지 못한 것

- VM의 CLI·인증·모델·한도·종료 코드(05 §1b 전부 미확인). GPT Astra·Grok·SWE2·GLM 경로.
- 사용자 상세 검토서 밖의 추가 요구(있다면). 검토서 F01~F12·본문·다음 작업 1~3은 07에 대응시켰다.
- 데몬 안전장치의 실제 동작(T-OP-00·T-OP-09 없음). "이전 CLI의 쓰기가 차단된다"는 미증명.
- 과제 크기·순서·수치의 적정성. 크레이트·스크립트 이름의 최종 확정.
- 판단 기준·부분 보류·릴리스 공지의 제품 의미 적절성(사람 검토 대상).
- G10(CI 단계)은 구현자 커밋에 달려 있다.

## 10. 다음 검토자에게

구현자가 커밋을 고정하고 독립 재검토를 제출한다. 작성 계열(claude) 밖 리뷰어가 대상 SHA에 고정해 검토해야 하며 현재 확인된 경로가 없으므로 정본 반영 병합만 기다린다. "수정 완료"는 독립 재검토의 판정이다. 자동 개발 가동은 그 검토 뒤이며 이 묶음은 가동을 포함하지 않는다.
