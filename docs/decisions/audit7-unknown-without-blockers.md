# Audit 7의 0 분모 계산 보류와 사건 목록 입력

2026-11-18, ONJEON 자동 개발 루프의 가역 결정. BLUEPRINT §8 I1과 DEC-O12를 적용한다.

## 0 분모

`pro_rata`의 `whole=0`과 `divide_count`의 `count=0`이 금액 계산을 막으면 엔진은 금액을 `unknown`으로 두고 `EvaluationResult.amount_issues`에 `{"code":"zero_denominator","path":"amount.…"}`를 담는다. 경로는 해당 연산의 trace 경로이며 지급 요건 판정은 기존 규칙을 따른다. 이 선택 필드는 기존 결과에도 적용되는 폐쇄 스키마에 추가했다. 사유 코드는 공통 어휘에 등록했다. 배포용 계약 버전 상향에는 루트 Cargo 잠금 파일 변경이 필요하므로 이번 작업 트리 변경에는 포함하지 않았다.

시나리오 계산 어댑터는 위 사유가 있으면 `display_status=hold`와 설명 ‘나눌 기준이 0이라 금액을 계산할 수 없어요’를 반환한다. 분모가 누락되거나 `null`이면 실제 입력 이름을 `missing_inputs`에 담고, 금액 보류 사유가 없는 누락 결과는 `input_missing`으로 표시한다. 일부 입력도 누락된 보류 결과에는 사유와 입력 이름이 함께 있을 수 있다. 분기를 선택하지 않았거나 아직 선택할 수 있고 가능한 다른 분기에서 계산할 수 있으면 그 분기의 0 사유는 결과에 싣지 않는다. `blocked_by`는 엔진 호출 전에 연결이 막혔을 때 사용한다.

## 사건 목록 입력

`services/scenario-api`의 입력 준비 단계가 `class_money_list`의 빈 목록 출처를 판별한다. 명시 가정(`assumptions`), 개인 시나리오의 명시적 사용자 확인(`confirmed_facts`), 또는 호출자가 이 담보와 사건 기간을 모두 확인한 서버 측 `verified_facts`에서 온 `[]`만 확인된 사건 없음으로 사용한다. 확인되지 않은 빈 배열은 `null`로 전달한다. 목록의 개별 `krw: null`은 유지한다.

이 노드의 편집 범위에는 `packages/twin-runtime`이 포함되지 않는다. 시나리오 어댑터가 `input_stage::fill` 호출 전에 확인된 빈 목록을 내부 표지 `{"confirmed_empty":true}`로 바꾼다. 어댑터가 받은 내부 표지 모양의 입력은 `null`로 처리한다. 엔진의 타입 변환은 표지에만 빈 목록을 만들고, 런타임을 직접 호출한 경로의 원시 `[]`도 `null`과 같은 미확인 값으로 처리한다. 서버 측 확인 자료의 출처와 범위 확인은 어댑터 호출자의 책임이다.

## 검증 범위

엔진, 입력 준비부터 트윈 실행까지의 공개·개인 API 계산, 폐쇄 스키마의 직렬화를 합성 사례로 검증했다. [실행 증거](../../tools/evidence/audit7-unknown-without-blockers/README.md)를 참조한다. 이 저장소의 HTTP 전송 및 소비자 화면에는 계산 호출이 연결되지 않았다. 09의 P08·P16 완료 판정에는 실제 릴리스 응답과 소비자 화면 증거가 필요하다.

검수된 약관에서 0 분모에 별도의 계산 결과를 정하거나 사건 없음의 확인 범위를 현재 출처로 표현할 수 없을 때 이 결정을 다시 검토한다.
