## 3. 개발 구역과 병렬 작업

| 구역 | 소유 책임 | 외부로 내보내는 것 | 경계 |
|---|---|---|---|
| data | 분모, 목록, 수집, 원본 보관, 문서 구조 복원 | 원본·관측·추출 명세와 근거 위치 | 공시 자료 전용, 개인 계약·DNA 금지 |
| knowledge | 온톨로지, 필드·관계·가격 의미, 검수 | 버전 고정 지식 릴리스와 실행 규칙 | 약관 해석 책임, 미검수를 승인으로 승격 금지 |
| twin | DSL, 컴파일러, 계산과 계약 시뮬레이션 | 입력·규칙·근거·릴리스가 연결된 결과 | 약관을 다시 자유 해석하지 않음 |
| app | Flutter 화면, API, 인증·동의, 비공개 계약 처리 | 근거와 미확인을 구별하는 소비자 경험 | knowledge 직접 조회 가능, 최소 개인 입력만 twin 전달 |
| contracts | 공통 ID·상태·스키마·API·호환성 | 같은 레포에서 배포하는 버전 패키지 | 별도 다섯 번째 레포를 만들지 않음 |

contracts 합의 후 각 구역은 독립 픽스처로 병렬 구현한다. 한 작업에는 작성자 한 명만 둔다. 공통 파일은 담당 작업 하나가 수정하고, 다른 작업은 계약 변경 요청으로 연결한다. 담당 빌더·모델은 현재 호스트의 적격 레인으로 정하며 이 계획에서 임의 배정하지 않는다.

레포 분리는 개발 착수 조건이 아니다. 독립 빌드·배포, 버전 고정, 호환성 검사, 통합 재현이 갖춰지면 data부터 분리한다.

N11은 계산을 지원하지 않는 상품도 확인된 설명과 가격을 제공한다. N12의 개인 영역이 늦어져도 N11 개발을 계속한다. 첫 대외 출시의 범위는 기존 단일 출시 결정을 유지하며 이 표가 별도 조기 출시를 허가하지 않는다.

## 5. 데이터 수집·분류의 수락 기준

### 목록과 수집

기관 → 상품 → 판매본 → 주계약/특약 → 문서 → 담보의 연결을 보존한다. 상품명만으로 합치지 않는다. 상품 ID, 코드, 회사, 적용 기간, 판매 채널 등 확보한 구별 근거를 사용하고 불명확한 연결은 보류한다. 주계약과 특약은 다대다 관계 및 의무 부가·동시 소멸을 표현한다.

각 기관의 모든 공시 탐색 경로, 페이지네이션 종료 근거, 접근 실패와 재개 지점을 기록한다. 공시에서 사라졌다는 이유로 기존 상품을 삭제하거나 판매 종료로 단정하지 않는다. 판매 종료와 문서 조회 불가를 따로 기록한다. 전 대상의 진행표를 먼저 만들고, 작업량에 맞춰 묶음 실행한다.

원본은 수집 직후 해시와 관측 기록으로 보존한다. 바이트 변경과 의미 변경을 구분하고 정규화 규칙 버전을 남긴다. 접근 실패는 변경 없음으로 처리하지 않는다. detect의 종료 코드·표본별 실패 사유·요약을 N08 수락 시험에 넣는다.

현재 고정 119키 작업은 새 목록 근거를 저장할 권한이 아니다. N03은 기존 근거 분석과 목록 형식 개발을 먼저 할 수 있다. 새 원격 자료 수집·보존에는 작업 범위와 한도를 명시적으로 추가한다. 임시 사본을 영속 보존 완료로 보고하지 않는다.

목표는 전 소스의 일일 확인과 변경분 신속 반영이다. 실제 주기·호스트별 요청 제한·재시도·최신성 임계값은 O02·O06·O17에서 측정 후 고정한다. AIOPS 개발 작업의 상태 폴링과 제품 크롤링 일정은 별개 운영이다.

### 문서 복원과 온톨로지

PDF 텍스트, 스캔 OCR, HTML 표를 별도 추출기로 처리한다. 페이지·좌표·표 행/열·병합 셀·표 제목·각주와 외부 참조를 보존한다. 두 추출기가 같은 값을 냈다는 사실만으로 원문 정확성을 승인하지 않는다.

라벨 사전에는 정의, 포함/제외 사례, 원문 근거, 판/유효기간, 상하위 관계를 둔다. 암·뇌·심장 같은 소비자 분류와 실제 질병 정의·분류코드의 판을 분리한다. 같은 담보 이름이어도 지급사유와 제외 조건이 다르면 서로 다른 담보 발생 항목으로 유지한다.

필드마다 값, 단위, 적용 대상, 기간의 기산점, 예외, 근거 위치, 추출 도구/모델판, 검수 결과를 갖는다. 부정문, 예외의 예외, 감액, 면책, 한도, 횟수, 갱신·부활, 종료, 특약 종속을 검증 세트에 포함한다. 외부 문서의 명령문은 데이터로만 취급한다.

### AI 검수와 릴리스

추출 모델과 다른 계열 모델이 원문 근거를 보고 독립 검수한다. 불일치는 근거와 함께 보류하고, 코드 검사는 숫자·단위·참조·논리 모순을 확인한다. 모델 일치율과 실제 정답률을 분리해서 보고한다.

문서 유형·상품군별 정답 평가 세트를 분리하고, 평가에 쓴 자료와 모델 설정을 고정한다. 승인 기준과 정책 소유자는 M2 관문 전에 확정한다. 기준이 미정인 동안 서비스 승인을 만들지 않는다. 오류 사례는 회귀 세트로 추가한다.

릴리스는 원본·추출·온톨로지·규칙·검수의 버전을 고정한다. 변경 영향에 따라 관련 필드와 트윈만 재생성하고, 치명적 오류가 발견되면 해당 기능을 보류하거나 이전 릴리스로 되돌린다. 과거 사용자 결과가 적용한 릴리스를 재현할 수 있어야 한다.

### 가격

보험료표, 요율·산식, 상품 공시 예시를 각각 확보한다. 나이/보험나이, 성별, 직업·위험등급, 채널, 가입금액, 주계약·특약 구성, 납입기간·주기, 보험기간, 갱신, 할인, 기준일의 출처를 연결한다. 표 밖 소제목·각주·팝업의 조건도 포함한다.

공개 예시 한 점과 검증된 산식 재현을 구별한다. 미확인 조건을 일치로 바꾸지 않고, 나이 보간·가입금액 비례 환산은 허용하지 않는다. 같은 조건임을 확인한 값만 예산 필터와 합계에 사용한다. 가격을 확보하지 못한 상품도 조건 설명에서 숨기지 않는다.

| 마이보험·계약 상세 | 실제 계약의 상품 판매본·담보·기간 |
| 내 설계 | 예산 입력, 현재/보완안, 가격 조건과 적용 가능 여부 |
| 담보 상세 | 무엇을 보장하고 언제 못 받는지 |
| 같은 담보 비교 | 질병 정의·면책·한도·가격 조건 차이 |
| 두 안 비교 | 추가·감소·유지·새 면책·가격 미확인 |
| 증거 보기 | 바로 해당 원문 페이지와 강조 구간 |
| 내 정보 | 동의·입력 출처·외부 처리·삭제 |

S1은 행동 제안과 데이터 확인 상태를 별도 축으로 표현해 모든 행이 “조건 확인”으로 뭉개지지 않게 푼다. S6은 예산 입력을 유지하되 적용 가능한 공개 가격이 없는 경우 그 한계를 먼저 알리고 비교 가능한 조건을 제시한다. 미확인 상품을 싼 상품이나 0원으로 처리하지 않는다.

금액·기간·비율은 구조화된 값에서 문구를 생성하고 그 경로를 시험한다. 임의 문구와 출처 숫자를 따로 유지하는 대조 방식에서 점진적으로 전환한다. 보기 좋은 시안과 실제 사용성 검증은 별도 증거다. 사용자 시험의 과제·표본·수락 기준은 O07로 정한다.

가족력은 선택 입력이다. 실제 건강정보 없이 합성 프로필로 먼저 개발한다. 개인 계약 문서는 공시 원본 버킷에 들어가지 않는다. DNA 서비스 연계 구상은 장기 항목으로 남기며 현행 구현 동결을 유지한다. DNA·건강 파생정보의 보험사·설계사 전달은 허용하지 않는다.

## 7. AIOPS 등록과 실행 계약

중앙 참고 문서:
- [engineering/AGENTS.md](https://github.com/SUNBURN-Golden/ai-ops-control-plane/blob/c8b9982da78dd56a4a1e086c7ca9fbceb5c832f8/engineering/AGENTS.md)
- [TASKS/TEMPLATE.md](https://github.com/SUNBURN-Golden/ai-ops-control-plane/blob/c8b9982da78dd56a4a1e086c7ca9fbceb5c832f8/engineering/TASKS/TEMPLATE.md)
- [프로젝트 등록](https://github.com/SUNBURN-Golden/ai-ops-control-plane/blob/c8b9982da78dd56a4a1e086c7ca9fbceb5c832f8/engineering/.github/control-plane/projects.json)

등록 PR에서는 ONJEON의 실제 repository/owner ID, 중앙 ID, 기본 브랜치, 필수 검사 이름, post-merge 검사, 권한 경계, 레인 후보와 계획 해시를 확인한다. 기존 프로젝트의 ID·잠금 파일·모델 승인·예외를 복사하지 않는다. 현재 ONJEON CI job 이름은 `rules-engine`이며 실제 체크 컨텍스트는 등록 시 조회해 고정한다.

이 문서는 런타임 plan JSON이 아니다. 중앙의 현행 스키마로 검증되는 실행 계획을 별도로 만들고, 위 N 번호·선행 조건·명세 해시와 연결한다. 승인 포인터와 레인 설정이 없는 초안은 배포·실행 비활성 상태로 둔다. 최초 인계 전에 설치된 Mac/다른 호스트, 기존 세션 소유권, 정상화되지 않은 UNKNOWN, 실제 모델과 과금 경로를 확인한다.

각 작업은 TASK_ENVELOPE v4의 필수 필드, 정본 포인터, 허용 파일 범위, 선행 증거, 완료 시험, 독립 리뷰와 해당 감사 요구를 갖는다. 작성자가 자기 변경을 독립 감사하지 않는다. CI 실패와 리뷰 수정은 같은 작성자에게 돌아간다. 새 HEAD에는 그 HEAD의 검증 증거를 요구한다.

정규화한 이벤트 하나로 짧은 작업 하나만 디스패치한다. 반복 상태 조회와 중복 작업을 만들지 않는다. 중앙에서 채택한 heartbeat 예외가 있더라도 온전용 감시를 추가하지 않는다. 기존 KIX·Film 등 작업의 소유권을 빼앗거나 중단시키지 않는다.

계약·권한·비용·개인정보 경계 변경과 출시 노드는 해당 중앙 규칙의 감사와 사용자 결정을 유지한다. 다른 제품에 한정된 GLM 감사 승인이나 자동 병합 권한을 온전에 확대하지 않는다. 사용자 최종 승인 전 자동 출시하지 않는다.

## 8. 운영 권한과 비용

코드 개발 자동화와 R2 대량 수집 활성화는 별도다. AIOPS 개발자는 기본적으로 합성 픽스처와 로컬 시험을 사용한다. R2 자격 증명을 모든 빌더에게 나눠주지 않는다. 원격 작업은 인계 기록이 있는 실행 환경 하나, 동시 실행 하나로 제한한다.

현행 D18의 Claude 환경 지정은 그대로 유지한다. 다른 환경으로 옮길 때 기존 실행 종료·소유권·자격 증명 범위와 인계를 확인하고 결정 원장에 변경을 기록한다. 다른 환경에 키가 없다는 사실은 검사 없이 주장하지 않는다.

O13·O14·O17은 원격 수집 관문에 묶는다. 토큰 교체, 잠금 대상/기간, 원장 체크포인트, 새 키 허용 범위, 요청·바이트·실행시간·월 누적 정책, 실제 R2 시험과 청구 대조를 준비한다. 계정 전체 과금 상한을 보장한다고 표시하지 않는다. 원격 시험은 사전에 제한된 작업으로 실행하고 무한 재시도를 하지 않는다.

AI API 비용과 R2 비용은 별도 한도로 관리한다. 모델별 호출·입력/출력 토큰·재시도·OCR 페이지·동시성의 작업 상한을 정의한다. 추가 과금이나 다른 제공자로의 자동 우회는 별도 승인 없이 하지 않는다. 청구 지연과 도구 밖 사용량은 측정 한계로 보고한다.

각 노드 완료 시 코드 병합, 데이터 승인, 운영 적격, 사용자 출시를 따로 판정한다. 숫자만 있는 PASS 보고를 받지 않는다. PR·HEAD·CI·독립 리뷰·원문 검증과 미실행 항목을 연결한다.

출시는 원문 추적, 가격 비교 조건, 개인정보 격리·삭제, 오류 신고·수정·릴리스 철회, 사용자 이해도와 운영 장애 시험 및 O10 판단을 완료한 뒤 사용자에게 요청한다. 전 대상 중 확인하지 못한 구간은 공개하고 “모든 상품 구축 완료”라고 포장하지 않는다.

## 10. 바로 다음 실행 묶음

이 계획을 검토한 뒤 N01(계약), N02(파생 재생성), N05(화면 설계 초안), N06(등록 초안)을 준비한다. N05의 구현은 N01 계약에 맞춘다. 중앙 등록 자체가 막혀도 수동으로 허용된 로컬 작업까지 멈추지 않는다.

첫 AIOPS 작업 후보는 범위가 분명하고 원격 비밀값 없이 시험할 수 있는 N01이다. N02는 실제 보관본 접근이 필요한 부분을 별도 제한 작업으로 분리한다. 담당 모델과 감사 주체는 등록 과정에서 현행 적격 상태로 확정한다.

계획 채택 뒤 BLUEPRINT에는 이 문서 링크와 실행 상태만 연결하고, 기존 상세 계약을 복제하지 않는다. AIOPS 등록 PR과 제품 실행 계획의 승인·호환성 검사가 끝난 다음 최초 한 작업을 디스패치한다. 그 성공 증거를 확인한 뒤 허용된 독립 노드를 병렬화한다.
