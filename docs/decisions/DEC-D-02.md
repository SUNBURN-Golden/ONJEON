# Decision: Decision gate D-02

Decided by Fable 5.1 (ONJEON autoloop, 2026-10-14 06:31 KST); reversible.

**Decision:** D-02를 다음으로 정한다(위임 결정, 사용자 확정 아님). (1) 구성: 보험 지식 검수(ReviewDecision)는 작성(추출)·승인·레드팀에 서로 다른 모델 계열을 하나씩 둔다. 하한은 2계열이다. 하한(families_count≥2)과 '불일치·반례는 hold, 다수결 없음'(I14)은 설계 계약이다(02_구현계약 B3, BLUEPRINT I14). 둘 다 아직 구현되지 않았다: services/ai-review가 없고 I14는 미구현 표기다. 지금 이를 강제하는 코드는 없다. 강제는 T-KN-06 완료 기준(계열이 하나뿐이면 ReviewDecision을 만들지 않고 pending 유지, 다수결 코드 경로 없음)을 구현·시험할 때 생긴다. (2) 첫 배치: 작성=claude 계열(Fable·Sonnet은 한 계열, 설정안 §3.3의 엄격 해석; 유일하게 연결이 확인됨), 승인=비-claude 계열 X, 레드팀=X와 다른 비-claude 계열 Y. Y 확보 전에는 레드팀을 X의 다른 모델·프롬프트로 두되 ReviewDecision에 3계열 미달(degraded)을 기록하고 독립성을 과장하지 않는다. (3) 업체·모델 ID는 이 결정에서 고정하지 않는다(미확인 경로를 정본에 박지 않음). 비-claude 후보 조건은 API의 JSON Schema 출력, 사용자가 확인한 입력 보존·학습 조건, 제공자 측 월 한도 설정 가능, 최소 호출·모델 식별 증거를 남길 수 있을 것이다. 역할표에 이름이 있는 gpt·grok·glm 계열부터 확인하고, swe(Devin CLI)는 모델 API 확인 전까지 제외한다. 계열 라벨·모델 ID는 review_policy.json에 두며 개발 roles와 별개다(운영 규칙 7). (4) 정책 소유자는 사용자 본인 1인이다. 범위는 AI 승인 임계값 확정(O06·D-19), 모델 구성 변경, 서킷 브레이커 사고 시 중단·재개다. 중단은 자동·누구나 가능, 재개는 소유자만 한다. 임계값 수치는 정하지 않는다: T-OP-03 실측 뒤 소유자가 확정하고, 그 전엔 불일치=hold로 두며 임의 수치를 쓰지 않는다. (5) 이 결정은 지출·계약·계정 개설·키 발급을 하지도 승인하지도 않는다(사용자 조치). production 호출 전에 제공자 측 월 한도 설정을 확인하고, 키는 빌더·데몬에 나눠주지 않고 실행 환경 비밀값으로만 둔다(D18의 지정 환경 하나 방식 준용). 이 둘은 운영 절차 조건이며 강제하는 코드는 아직 없다. 월 한도는 지식 검수 운영 호출의 폭주 완화용이고, 자동 개발 비용 정책 U-05와는 별개다. (6) 적용 범위는 공개 약관·공시 문서의 지식 검수다. 개인 PDF의 외부 AI 처리는 D-17(O08·O09)이 따로 정한다. (7) 이 결정이 막는 것과 막지 않는 것: 계약상 D-02가 막는 것은 environment=production의 ReviewDecision 생성(P4)뿐이다(02_구현계약 C-19·C-25). tasks.json에서 D-02를 쓰는 게이트는 T-OP-03 start([D-02]), T-KN-06 real_data([D-02]), T-OP-02 real_data([D-02, D-04], S1 관문 (b))이다. 반대로 ai-gateway 구조와 단일 계열 호출, review_policy.json 스키마, 추출(T-KN-05), T-KN-06의 모의 2계열(environment=test) 시험·병합은 D-02와 무관하게 이미 진행 가능하고(03_작업명세 §5 표, T-KN-06 start=[]), 이 결정이 푸는 것이 아니다. 이 결정이 새로 정하는 것은 production 검수의 계열 구성 원칙과 정책 소유자, 그리고 사용자가 확보할 접근 대상과 조건이다. (8) 등록 조건: 데몬은 결정 ID가 decisions_recorded에 있는지만 보고, 게이트 집합 전체가 들어 있을 때만 연다(decision_gates.<gate> ⊆ decisions_recorded, tools/daemon/core/envelope_validator.py). 이 기록은 접근 증거를 담지 않으므로 production 차단을 스스로 유지하지 못한다. 이 기록만으로 D-02를 decisions_recorded에 등록하면 접근 확인 없이 T-OP-03 시작과 T-KN-06의 real_data_allowed=true(R2 쓰기 허용 포함)가 열린다. T-OP-02의 real_data 게이트는 [D-02, D-04]이므로 D-02 등록만으로는 열리지 않고 D-04까지 등록되어야 열린다. 다만 D-04가 이미 등록되어 있거나 나중에 등록되면 같은 문제가 T-OP-02에도 생긴다. 따라서 비-claude 접근 확인 기록(최소 호출 성공·모델 식별 증거·계열 라벨, 05 §1a 형식 준용)이 생긴 뒤에 D-02를 등록하거나, 접근 확인을 별도 게이트로 분리해 start·real_data에 추가한다. 어느 쪽을 쓸지와 등록은 그록봇 몫이다. 등록 전에는 production ReviewDecision, T-OP-03 실측, S1 관문 (b)가 열리지 않고 S1의 AI 검수 칸은 비어 있다. 이 결정은 기록 문서 외에 DECISIONS.md·tasks.json·review_policy.json을 바꾸지 않는다.

**Why:** 차단 요인은 구성 원칙이 아니라 비-claude 접근이다. D-02는 production ReviewDecision 생성만 막고 구조·모의 경로는 이미 막혀 있지 않으므로(C-19, 03 §5 표, T-KN-06 blocked_by), 원칙과 소유자를 정한다고 구조가 새로 풀리지는 않는다. 정해지는 것은 무엇을 확보할지다: 비-claude 계열 하나 이상(가능하면 둘)과 그 조건을 사용자가 알고 접근 확보를 시작할 수 있다. 계열 하나만으로는 ReviewDecision을 만들 수 없다는 B3(설계 계약)와 '모델 일치는 독립 증거가 아니다'(ADR-0006 2)에 따라 같은 계열 가짜 독립을 막아야 'AI 합의만으로 정확도 보증 금지'가 지켜진다. 다만 지금 이를 막는 코드는 없어서 T-KN-06이 구현되기 전까지는 이 기록과 계약 문서가 근거다. 3계열을 필수로 올리면 비-claude 둘을 확보하기 전까지 production이 멈추므로 하한은 2로 두고 미달을 기록으로 드러낸다. production을 접근 확인 전에 여는 길은 이 기록이 아니라 등록 시점 조건(결정 8)으로 막는다. 이 결정은 지출·계약·키 발급을 하지 않고 production 호출을 접근 확인과 월 한도 확인 뒤로 미루며 구성은 설정이라 되돌릴 수 있다. 그래서 실제 돈·비밀값·배포에 직접 닿지 않아 critical이 아니다. 다만 이후 계정 개설·한도 설정·키 발급은 비용·자격 증명이 걸린 사용자 조치이며 이 결정이 승인하지 않는다.

**Options:** ['A. 계열별 1역할(하한 2), 작성=claude·승인/레드팀=비-claude, 소유자=사용자, 업체 미고정, 접근 확인 뒤 등록 또는 게이트 분리 (채택)', 'B. 업체·모델 ID까지 지금 고정 (기각: 연결·가격·약관 미확인. 운영 규칙 8과 같은 취지로 미확인 경로를 지정하지 않음)', 'C. claude 계열 안의 서로 다른 모델로 승인·레드팀 구성 (기각: 같은 계열이라 ADR-0006 1·2와 설계 계약 families_count≥2에 어긋나고 R14 위험을 줄이지 못함)', 'D. 정책 소유자를 AI나 다른 역할에 위임 (기각: ADR-0006 5·BLUEPRINT §12가 사람 1인으로 둠. AI가 자기 임계값을 정하면 통제가 아님)', 'E. 개발 역할표의 계열을 검수 구성으로 그대로 승인 (기각: 운영 규칙 7, 코드 리뷰와 지식 검수는 별개)', 'F. 비-claude 접근이 생길 때까지 결정 보류 (기각: 구조·모의 경로는 D-02 없이도 진행되지만, 원칙과 소유자를 정하지 않으면 접근 확보 대상과 조건이 정해지지 않아 확보가 시작되지 않는다)', 'G. 접근 확인 없이 이 기록만으로 D-02를 decisions_recorded에 등록 (기각: 데몬이 ID만 보므로 T-OP-03 시작과 T-KN-06 real_data가 접근 증거 없이 열리고, D-04도 등록되면 T-OP-02 real_data까지 열림)']

**Revisit if:** 비-claude 계열을 하나도 연결하지 못하거나 조건(구조화 출력·보존·월 한도)을 맞추는 제공자가 없을 때; T-OP-03 실측에서 계열 간 불일치로 거의 모든 후보가 hold가 되거나 비용·지연이 운영 불가일 때(수치 기준은 실측 뒤 소유자가 정함, O06); 사용자가 정책 소유자를 맡지 않거나 넘길 때; 사용자가 계열 해석(Fable·Sonnet=claude 한 계열)을 달리 확인할 때; 사용 가능한 계열이 늘어 3계열이 채워질 때(degraded 해제); 제공자의 보존·학습·지역 조건이 바뀌거나 공개 문서 밖 입력(개인 자료)이 검수에 들어올 때(D-17 경로); ReviewDecision·families_count·review_policy.json 계약이 바뀔 때; T-KN-06이 구현되어 families_count 하한과 I14가 코드로 강제될 때(이 기록의 '미구현' 서술을 갱신); D-02 등록 방식(접근 확인 뒤 등록 또는 게이트 분리)이 정해질 때
