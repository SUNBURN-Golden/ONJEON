# Decision: Decision gate O12

Decided by Fable 5.1 (ONJEON autoloop, 2026-10-15 07:35 KST); reversible.

**Decision:** Settle the O12 semantics as follows. Common rule: the clause-based rule defines meaning and the engine never fills gaps with defaults. Unsupported semantics are rejected when the rule loads or fail explicitly when evaluated (capability blocked); in their place the screen shows only the original text, never a computed value or generated wording that looks like one. S1 실손 (indemnity): the order is covered cost → deductible (clause wording as written) → floor at 0 → coinsurance → per-event cap → remaining cumulative cap → pro-rata across policies. The rule's expression tree states this order and the engine never reorders it. Covered/uncovered classification and 실손 generation are inputs from outside the DSL. Amounts are integer KRW; rounding and unit are required, and if missing the result is a range. Pro-rata is computed only when every other policy's liability is a confirmed engine result; otherwise unknown plus missing_inputs (never 0, never estimated); a zero denominator gives unknown. Summing or double-payment judgements not confirmed by a relation rule are rejected. Results are called '조건부 계산액' (conditional amount), never a confirmed payout. S2 이력 (claim history): history and cumulative usage come from the contract twin's usage_counters (with as_of, period_basis backed by the clause, and evidence); the rule only computes max(0, cap − used). No history means unknown, never 'zero used'. Resets on renewal apply only when the clause says so. Sequential scenarios run by event date, and same-day events only in the order the input states; otherwise the result is unknown. S3 범위 비교 (range comparison): between requires both endpoint inclusivity flags and has no default. Comparing against a {min,max} value gives true or false only if every value in the range agrees, otherwise unknown. Interval arithmetic is allowed only for monotone operations. Ranges are never collapsed to a single representative value. In plan_diff, a difference whose sign spans the range is classified '달라질 수 있음' (may change), not as an increase or decrease. Dates outside 1900–2199 fail explicitly. S4 시각 (time of day): date and offset-bearing timestamp are separate types with no implicit conversion; Asia/Seoul calendar, day boundary 00:00. If the clause specifies a time and the input lacks one, the result is unknown (no 00:00 assumption). Sub-day day-counting is done in the time_stage input step. Accident, confirmation and claim dates are separate inputs. S5: G11 (split by beneficiary), G24 (in-kind payment) and W6 (disclosed interest/return models) are out of scope and fail explicitly. S6 release condition per operation: allow-list entry and schema-rejection test, boundary/unknown/range synthetic tests, mutation tests, at least one real sample case (T-KN-08), byte-identical determinism, and an unbroken trace evidence_ref chain. Operations that fall short are merged but kept capability-blocked. Registering DEC-O12 in decisions_recorded lifts the O12 release gate on T-TW-04 and T-TW-05.

**Why:** The biggest risk to the product goal is the engine presenting what it doesn't know as known. This decision adds no new principles: it applies existing ones (ADR-0014 §4, §49.3–49.5, §44.5, I9) to 실손, history, ranges and time of day, so the result is always 'unknown, or explicit failure plus the original text'. O12 only blocks release, but building without these semantics would mean rework. It is a design document, reversible with Git, and touches no money, legal matters, secrets or deployment.

**Options:** ["A. Settle the semantics now and tie each operation's release to S6 (chosen)", 'B. Postpone until T-KN-08 real samples exist (rejected: O12 must be decided before the calculation is built; real-case checks already sit in S6(d))', 'C. Put cumulative history, time-of-day judgement and coverage classification inside the DSL (rejected: conflicts with ADR-0014 §4, G05, G09 and C-08)', 'D. Replace unsupported calculations with AI-generated explanations or estimates (rejected: this is exactly what O12 blocks; also violates §44.5)', 'E. Collapse ranges or missing history into a single value (rejected: §49.5 forbids arbitrary defaults)']

**Revisit if:** Real samples include a 실손 generation whose order or deductible can't be expressed as an expression tree; a regulatory pro-rata method that doesn't need the other policies' results is confirmed; history that usage_counters can't hold is needed (e.g. limits shared across insurers); non-monotone range arithmetic is needed; dates outside 1900–2199 or non-KST contracts come into scope; G11, G24 or W6 move into first-release calculations; the owner decides O12 directly or withdraws this; or C-08, C-26 or the decision_record rules change
