# ADR-0012 통합 설계도와 구현 추적

상태: 이번 문서 정리에 적용한 설계 기준 | 날짜: 2026-10-09

사용자는 정보비대칭 해소라는 구상에서 구현이 벗어나지 않도록 설계도를 먼저 탄탄히 작성하라고 요청했다. 기존 문서가 누적되면서 범위·우선순위·가격·분모 검증 문구가 충돌하고 있어 공통 진입점과 추적 기준을 둔다.

1. 원격에서 추가된 `docs/BLUEPRINT.md`를 유일한 진입점으로 유지하고 `docs/blueprint/SYSTEM_CONTRACT.md`를 하위 실행 계약으로 둔다. 사용자 최신 결정과 불변 원칙을 우선하며, 과거 문서와 충돌하는 부분은 DECISIONS의 해소표를 따른다.
2. 소비자 질문→요구 ID→모듈/데이터→화면→수락 사례를 REQUIREMENTS에 연결한다. 코드·문서 PR마다 영향 ID와 증거를 기록한다.
3. 설명·조건 비교·가격 비교·계산 자격을 분리한다. 계산 불가를 이유로 확보된 공개 정보를 숨기지 않는다.
4. 확정·설계 기준·미정을 구분한다. 미정 항목에는 책임 역할·결정 시점·차단 범위를 부여한다. 담당자·수치·소스가 확정됐다고 꾸미지 않는다.
5. ADR-0006의 포획 추정 문구는 현재 분모 조사 기준으로 대체한다. 조회 증거·교차 대조·미탐색 상태가 기준이며 추정으로 완전성을 입증하지 않는다.
6. 공개 가격·선택 UX·개인정보·출시 범위의 기존 사용자 결정은 유지한다. 이번 작업은 구현 확대·서비스 배포·병합 승인이 아니다.

결과: 기존 마스터플랜과 평가서는 이력 및 세부 방법론으로 보존한다. 구현자는 최신 기준을 한 곳에서 찾고 과거의 폐기된 가정을 다시 도입하지 않는다. 이번에 추가한 세부 계약은 사용자 개별 승인을 받았다고 표현하지 않는다.

원격 dc18fc5의 A·Q·L·I·M 체계와 ADR-0011을 보존했다. 병렬로 작성된 두 설계도를 별도 정본으로 두지 않고 상세 계약과 추적표를 합쳤다.
