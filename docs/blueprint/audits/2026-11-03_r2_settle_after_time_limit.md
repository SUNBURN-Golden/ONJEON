# Audit 4 — 실행 시간 초과 후 정산·최종 요약

대상 노드: `audit4-r2-settle-after-time-limit`.
제품 연결: A1·A2·A4 / Q7 / L1 / I1 / M1, 제품 목적 대응표 P02·P03의 원본 보관 비용 통제 기반.

## 원인과 수정

`tools/r2_budget.py`의 계량기는 예약 전부터 경과 시간을 재지만 SIGALRM은 예약 뒤에
시작한다. 입장·예약에 30초를 쓴 600초 실행은 총 601초에 정상 작업을 마쳐도 알람이
아직 울리지 않는다. 기존 정산은 알람만 해제하고 원장 꼬리 요청·`snapshot()`에서
실행 시간 제한을 계속 검사했다. 정산이 실패하고 `finish()`의 최종 요약도
`BudgetError`를 던져 정상 실행을 종료 코드 4로 바꾸거나 원래 시간 초과 오류를 가렸다.

정산 진입 시 계량기의 `deadline_s`를 `None`으로 바꾼다. `_check_time()`은 이 경우
시간 초과를 거부하지 않고 경과 시간을 계속 갱신한다. 정산과 최종 요약이 같은 계량기를
사용하므로 둘 다 완료할 수 있다. 실행 중 시간 검사·알람, 바이트·요청·재시도 한도,
개별 요청의 연결·읽기 시간 제한은 유지한다. 정산 기록의 사용량은 기존대로 정산 쓰기의
최악값을 더하고 예약량으로 제한한다. 실제 경과 시간은 요약에 그대로 남는다.

## 회귀 범위

- 입장·예약에 30초를 쓴 실행이 계량기 제한과 알람 사이에 정상 종료하는 상황에서,
  `finish("ok")`가 정산 순번과 요약을 반환하고 실제 botocore의 원장 LIST·GET·PUT을
  계량하는지 루프백 S3 스텁으로 확인한다.
- 실행 시간 초과는 보관소 요청을 계속 거부하며 SIGALRM의 원래 오류가 `finally` 뒤에도
  유지되고 `failed` 정산·요약·알람 해제·로컬 잠금 해제가 완료되는지 검사한다.
- 시간 초과 뒤 정산 꼬리 GET이 바이트 한도를 넘으면 정산 실패를 요약에 반환하고
  예약 전액을 유지한다. 기본 원장과 주입 원장을 모두 검사한다.
- 정산 쓰기가 `OSError`로 실패해도 경과 시간이 포함된 요약을 반환하고,
  원래 알람 핸들러·로컬 잠금·미정산 예약 전액 처리를 유지하는지 확인한다.

수정 전 같은 시험은 65개 중 실패 1개·오류 4개로 문제를 재현했다.
수정 후 R2 시험 128개가 모두 통과했고, 전체 Python은 1,326개 실행·1,320개 통과·
기존 건너뜀 6개·실패/오류 0이다. Rust 작업 공간 시험은 478개 통과·기존 무시 1개,
별도 온톨로지 실행기 시험은 3개 통과했다. 문서·설계 정합성 검사도 통과했다.
명령·수정 전후 로그와 전체 시험 결과는
[검증 증거](../../../tools/evidence/audit4-r2-settle-after-time-limit/README.md)에 기록한다.

이 검증은 로컬 원장·루프백 S3 스텁·가상 시계에 한정한다. 실제 R2 접근이나 비용 정책
변경은 없으며 전 상품 공시 확보율·R2 관측 대조·소비자 화면·첫 출시 완료 증거를
대체하지 않는다.
