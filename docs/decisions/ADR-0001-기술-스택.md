# ADR-0001 기술 스택

상태: 부분 확정 | 날짜: 2026-10-08 | 근거: 제3부 §48

## 맥락

문서 복원·AI 추출이 데이터 트랙의 중심이고, 소비자 앱·공개 웹·관제 콘솔을 한 팀이 만든다. 시각 완성도가 최우선이다. 클라우드 공급자는 미정이다.

## 결정

| 계층 | 선택 | 상태 |
|---|---|---|
| 백엔드 API | Rust(Axum) | 확정(사용자 결정) |
| 규칙 엔진 | Rust 크레이트, 정수·유리수 연산 | 확정(백엔드 결정의 결과) |
| 수집·검증·재계산 워커 | Rust | 확정 |
| 문서 복원·OCR 워커 | Python(Docling 등), 격리 컨테이너 | 제안 |
| 모바일 | Flutter(Dart) | 확정(사용자 결정) |
| 공개 웹·관제 콘솔 | Next.js + TypeScript | 제안 |
| DB | PostgreSQL (+pgvector) | 제안 |
| 객체 저장소 | S3 호환(로컬 MinIO) | 제안 |
| 작업 큐 | PostgreSQL 기반. 복잡해지면 Temporal | 제안 |
| 인프라 | Docker, Terraform. 클라우드 미확정 | 제안 |

## 이유

- Rust는 규칙 엔진에 맞는다. 정수 연산, 소유권에 의한 불변성, 컴파일 시점의 열거형 검사(상태 enum, 3값 논리)로 불변 원칙 3·7을 타입으로 강제하기 쉽다.
- 한국어 보험 문서의 복원·OCR 도구는 Python 쪽이 성숙하다. 그 부분만 분리하고 큐와 파일로만 통신한다.
- Flutter는 화면을 자체 렌더링하므로 슬라이더·전환 같은 맞춤 시각 표현의 자유도가 높다. Flutter와 React Native는 모두 현재 활발히 유지되는 프레임워크이며 어느 쪽이 더 새롭다고 말하기는 어렵다. 이 프로젝트에서 Flutter를 택한 이유는 최신성이 아니라 시각 표현이다.
- 공개 웹은 검색 노출이, 관제 콘솔은 표와 PDF 대조 화면이 필요해 Flutter web 대신 Next.js를 쓴다.
- AI 검수(ADR-0006)는 서로 다른 모델 계열 2개 이상을 호출해야 하므로 AI 게이트웨이는 다중 제공자를 지원한다.

## 결과와 위험

- Rust, Dart, Python, TypeScript 네 언어를 운영한다. 공통 계약은 `packages/schemas`(JSON Schema, OpenAPI)에서 각 언어로 생성한다.
- Rust 개발자 채용과 개발 속도가 위험이다. 첫 2주 안에 API·엔진 골격을 만들어 팀 속도를 측정한다.
- Flutter의 자체 렌더링은 시스템 접근성 기능과 연동이 약할 수 있다. 접근성이 목표에서 빠졌으므로(제3부 §51.4) 수용한다.
