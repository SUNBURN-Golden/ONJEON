## 2. 모든 과제에 공통인 완료 기준

1. PR 템플릿의 A·Q·L·I·M과 R 요구 ID를 적는다.
2. 과제 ID, 작성에 참여한 모델 역할과 실행 경로, 대상 SHA를 적는다. 모델 식별자 원문은 적지 않는다.
3. `tests`의 명령을 실행하고 로그를 남긴다. "시험 추가 예정"은 통과가 아니다.
4. 시안 숫자·임시 데이터·미연결 경로가 제품 코드에 없다. 시험 전용 자료는 `fixture_only` 또는 `origin=fixture`다.
5. 스켈레톤 비노출 시험과 누출 정적 검사(T-CT-06)가 통과한다.
6. 독립 리뷰가 대상 SHA에 고정되어 있고 리뷰어는 작성 계열이 아니다. 리뷰어가 없으면 병합을 기다린다.
7. 비밀값·원문 발췌를 포함하지 않는다(저장소는 public, O16).
8. `allowed_paths` 밖을 수정하지 않았다.

**완성으로 세지 않는 것(구현계획 §1 그대로):** 시안·예시 모드·HTML 시안, 미연결 버튼, 픽스처로만 동작하는 기능, CI 통과 자체, 미확보 사유만 기록된 상품, 모델끼리 일치, 구현자 읽기 점검. S1(T-OP-02)과 S2는 **내부 검증**이며 축 1에 넣지 않는다. T-OP-00·T-OP-09의 완료는 가동 승인이 아니다.

## 8. 이 명세가 보증하지 않는 것

- 과제 수·순서는 설계 추정이다. 실측(S2 파일럿) 뒤 바뀔 수 있다.
- 시험 명령의 크레이트·스크립트 이름은 제안이다. 실제 이름은 첫 과제에서 고정하고 tasks.json을 갱신한다.
- 어떤 과제의 완료도 축 1(기능 완성)의 통과가 아니다. T-OP-00·T-OP-09의 완료는 가동 승인이 아니다.
- spec_check 통과는 그래프·경로·필드의 정합성만 뜻한다. 과제 내용의 적절성은 사람 검토 대상이다.
