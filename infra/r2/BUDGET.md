# R2 비용 제한: 폭주 완화 장치

결정: ADR-0017(사용자 요청, 2026-10-09). 구현: `tools/r2_budget.py`, 정책 `budget_policy.json`, 작업 `jobs/*.json`. 시험: `tools/tests/test_r2_budget.py`.

## 0. 이 기능이 무엇인가

**이 저장소의 도구로 하는 R2 실행이 폭주하는 것을 줄이는 장치다.** 두 가지로 동작한다.

- **실행별 제한:** 한 실행이 보내는 요청 수·바이트·재시도·시간을 계량기가 요청 전에 세고, 실행 종류의 한도를 넘을 요청은 보내지 않는다.
- **누적 사용량:** 각 실행의 입장·예약·정산을 원장에 남기고, 원장에 쌓인 사용량이 정책·작업 한도에 닿으면 다음 실행을 거부한다.

이 기능은 다음을 **보장하지 않는다.**

- Cloudflare 계정 전체의 과금 상한. R2에는 하드 지출 상한이 없고, 이 도구는 계정의 다른 사용을 보지 못한다.
- 모든 실행의 요청 상한. 토큰을 가진 다른 프로그램, 대시보드 작업, 이 도구의 기록되지 않는 요청(§5)은 원장 수치에 들어가지 않는다.
- 원장 수치와 실제 청구의 일치. 원장은 이 도구가 클라이언트에서 센 값이다.

## 1. 장치별 효과

| 장치 | 성격 | 효과 |
|---|---|---|
| 이 도구의 실행별 제한과 누적 사용량 | 요청을 보내기 **전에** 검사하고, 넘으면 중단 | 이 도구로 하는 실행의 폭주를 줄인다. 기록되지 않는 요청이 남는다(§5) |
| 초기 운영 범위(§6) | 지정 실행 환경 하나, 동시 실행 1개, 수동 실행 | 이 도구가 여러 곳에서 동시에·자동으로 도는 경우를 운영 규칙으로 없앤다 |
| 토큰 범위·만료·폐기 | 토큰으로 할 수 있는 일을 줄임 | 이 도구를 거치지 않는 요청에 대한 유일한 통제 |
| Cloudflare 예산 알림(Budget alert) | 예상 월 지출이 기준을 넘으면 이메일 | 알림일 뿐 과금을 차단하지 않는다 |
| R2 자체 | 하드 지출 상한 없음 | 없음 |

## 3. 동작

순서마다 앞 단계를 통과해야 다음 요청을 보낸다.

1. **작업 파일:** R2·AWS 접근에는 `--job infra/r2/jobs/initial-119.json[#upload|#verify|#status]`가 필요하다. 없으면 요청 없이 멈춘다.
2. **로컬 실행 통제(요청 없음):** 이 컴퓨터에서 예산 실행은 한 번에 하나(파일 잠금), 최근 1시간 시작 30회까지, 이번 달 마감을 한 번 본 컴퓨터는 그 달 동안 바로 거부한다. 상태 파일을 읽지 못해도 거부한다. 위치는 `$ONJEON_GATE_DIR` 또는 `~/.cache/onjeon`.
3. **마감 확인(HEAD 2회):** `closed/v1/<월>/_global.json`, `closed/v1/<월>/<작업>.json`이 있으면 멈춘다. 마감 뒤 다른 컴퓨터에서 시도하면 이 두 요청만 나간다. 이 두 요청은 원장에 남지 않는다.
4. **입장 기록(읽기 전 쓰기):** `admission/v1/<월>/<작업>/<실행>.json`을 `If-None-Match`로 먼저 쓴다. 예약 전까지 계량기는 입장 한도(위 표)를 적용하므로, 입장 기록 하나가 그 실행의 예약 전 비용 상한이 된다(원장·입장 목록 읽기, 예약 쓰기, 재시도 포함). 정산까지 가지 못한 실행의 입장은 입장 한도만큼 사용한 것으로 센다. 그래서 거부된 실행을 반복해도 입장한 실행은 매번 원장에 기록되고 한도에 들어간다.
5. **원장 검증:** `ledger/v1/<순번>.json`을 읽고 순번 연속, 해시 연결, 알려진 정책, genesis 해시를 확인한다. 읽지 못하거나 어긋나면 중단(입장은 이미 기록됨). 입장 목록은 LIST만 하고 내용은 읽지 않는다.
6. **입장 한도와 마감:** 이번 달 입장이 작업 20회 또는 전체 100회를 넘었거나, 마지막 입장 몫을 쓴 실행이 거부되면 마감 기록을 쓰고 멈춘다.
7. **예약:** 원장 사용량(예약·정산·정산 안 된 입장) + 이번 실행 예약량 + **이번 달 남은 입장 몫**이 전체·작업 한도 안이면 예약을 쓴다. 남은 입장 몫을 비워 두므로, 거부된 실행이 이어져도 원장 사용량이 한도 안에 머물게 한다(예외와 기록되지 않는 요청은 §5). 동시 실행이 같은 순번을 쓰면 한쪽은 412를 받고, 새로 생긴 기록만 읽어 다시 판단한다. 예약 전에는 보관소 요청을 보내지 않는다(계량기가 막는다).
8. **실행 중 계량:** 허용 연산(Get, Head, Put, ListObjectsV2)만, 작업 버킷과 통제 접두어만, 고정 목록의 키와 바이트만, Standard 저장 등급만. HTTP 시도마다(재시도 포함) Class A/B, Content-Length 기준 업로드 바이트, 본문을 읽기 전 내려받기 바이트, 재시도, 시간을 센다. 넘을 요청은 보내기 전에 멈춘다.
9. **정산:** 원장 꼬리(LIST 1회, GET 1회)를 읽고, 입장부터 잰 사용량에 **정산 쓰기 자체의 최악값**(시도 3회분의 Class A·바이트·재시도·시간 제한)을 더해 예약 이하로 기록한다. 정산된 실행은 이 값만, 정산되지 않은 실행은 입장과 예약 전체가 계속 쓰인 것으로 센다.
10. 다시 업로드하는 실행은 먼저 HEAD로 저장된 SHA-256을 비교한다. 같으면 바이트를 보내지 않는다.

남은 사용량 확인(이것도 입장·예약을 거친다):

```bash
python3 -I tools/r2_budget.py status --job infra/r2/jobs/initial-119.json
```

`init-pre-ledger`는 정책에 genesis가 고정된 뒤에는 요청 없이 거부한다.

## 4. 그 밖의 과금 관련 설정

| 항목 | 상태 |
|---|---|
| 저장 등급 Standard(Infrequent Access는 무료 사용량 제외, 최소 30일 과금, 조회 수수료) | 세 버킷 모두 기본 등급 Standard 확인(Cloudflare API, 2026-10-09). 도구가 다른 등급 업로드를 거부 |
| 멀티파트 업로드(미완료 조각이 저장량으로 남을 수 있음) | 도구가 멀티파트 연산을 거부. R2는 미완료 업로드를 기본 7일 뒤 중단 |
| 공개 접근(r2.dev, 사용자 도메인): 열리면 남이 읽기 요청을 만들어 Class B 사용량이 생김 | 세 버킷 모두 공개 개발 URL 비활성, 사용자 도메인 없음(검토자가 Cloudflare API로 확인, 2026-10-09). 다시 켜지 않는다 |
| 토큰 | 대화창으로 받은 토큰은 이번 작업 뒤 **폐기**. 이 토큰은 새로 만든 원장 버킷에도 접근됐으므로 두 버킷 한정이 아니다. 새 토큰은 버킷 지정(원본·파생·원장), Object Read & Write, 만료일 지정으로 만들고 환경 설정 Network secrets로만 넣는다. Admin 토큰은 쓰지 않는다 |
| 예산 알림 | 권장: Billing → Billable Usage → Set Budget Alert(예: 1달러). **알림일 뿐 과금 차단이 아니다** |
| GitHub 재검증 | **초기 운영에서는 쓰지 않는다**(§6, 지정 실행 환경 하나). 저장소 변수를 설정하지 않으면 작업이 실행되지 않는다. 나중에 켜면 수동 실행만, 동시 실행 1개, 같은 원장으로 예약 |
| 다른 유료 제품 | 이 작업은 R2 외 Cloudflare 제품을 만들거나 켜지 않는다 |

## 5. 이 도구 내부의 한계

**원장에 기록되지 않는 이 도구의 요청:**

- **마감된 달의 마감 확인 HEAD 2회:** 마감 기록이 있으면 실행은 입장 기록 없이 멈추므로, 이 두 요청은 원장에 남지 않는다. 마감을 본 컴퓨터에서는 그 달 동안 0회지만, 다른 컴퓨터나 새 환경에서는 시도마다 2회씩 나간다. 마감 전에는 이 두 요청이 입장 한도 안에 들어가 기록된다.
- **실패한 입장 기록 쓰기:** 입장 PUT이 네트워크 오류 등으로 실패하면 그 시도(최대 3회)는 남지 않는다. 그 실행은 읽기 없이 멈춘다.

**원장 수치가 실제보다 작아질 수 있는 경우:**

- 원장의 **마지막** 기록이나 입장·마감 기록을 지우면 감지하지 못한다(중간 삭제·변조·전체 삭제는 감지한다). 막으려면 원장 버킷에 기간 있는 버킷 잠금이 필요하다(O14, 승인 전 적용 안 함).
- 여러 컴퓨터에서 동시에 입장하면 입장 횟수 한도를 그 수만큼 넘을 수 있다. 넘은 입장도 기록되지만, 남겨 둔 입장 몫을 넘으므로 원장 사용량이 한도를 그만큼 넘을 수 있다. 초기 운영 범위(§6)가 이 경우를 운영 규칙으로 없앤다.
- 원장 이전 사용량(순번 1)은 측정값이 아니라 상한 추정이다.

**그 밖:**

- 로컬 통제(동시 1개, 시간당 시작 수, 마감 기억)는 그 컴퓨터의 상태 파일에만 있다. 환경 사이의 동시 실행은 막지 못한다.
- 원장 기록이 100건을 넘으면 입장 한도 안에서 원장을 다 읽을 수 없어 실행이 멈춘다. 대량 자동 수집 전에 원장 요약(체크포인트) 설계가 필요하다(§6 관문).
- 원장은 Cloudflare 청구액이 아니다. 청구 기준(GB-월 평균, 단위 올림, 청구되는 요청 종류)과 차이가 있으며 실제 청구는 대시보드에서 확인한다.
- 현재 실행 통제(입장·마감·정산 최악값, e7d38dd)는 S3 스텁 서버(요청 기록 비교)로 검증했다. 실제 R2에서는 아직 돌리지 않았다.

**이 도구 밖(이 기능의 범위가 아님):** 토큰을 가진 다른 프로그램의 직접 호출, Cloudflare 대시보드 작업, 같은 계정의 다른 R2 사용. 토큰 범위·만료·폐기와 계정 관리로 다룬다.

## 6. 운영 범위

**초기 운영(현재):**

| 항목 | 규칙 | 강제 방식 |
|---|---|---|
| 실행 환경 | **지정 실행 환경 하나.** R2 토큰을 Network secrets로 등록한 Claude 클라우드 환경 하나만 쓴다. 다른 곳(GitHub Actions, 개인 PC 등)에는 토큰을 두지 않는다 | 운영 규칙과 토큰 배치. 도구는 다른 환경을 알지 못한다 |
| 동시 실행 | **1개** | 같은 환경 안에서는 로컬 통제(파일 잠금)가 강제. 환경 사이는 위 규칙 |
| 실행 방식 | **수동 실행만.** 사람이 요청한 작업 단위로 실행한다. 예약 실행(cron, 루틴), 자동 재시도 반복, 워크플로 자동 트리거는 쓰지 않는다 | 운영 규칙. `sources` 워크플로의 R2 작업은 저장소 변수를 설정하지 않아 꺼 둔다 |
| 작업 | 고정 119키의 업로드·대조(`jobs/initial-119.json`)만 | 작업 파일(허용 키·해시)과 계량기 |

**대량 자동 수집: 별도 관문.** 이 PR의 범위가 아니다. 관문을 통과하기 전에는 시작하지 않는다. 관문에서 정할 것(결정 원장 O17):

- 원장 체크포인트 설계(기록 수에 비례하는 읽기 비용과 100건 상한)
- 원장 버킷과 원본 버킷의 버킷 잠금(O14)
- 대화로 전달된 토큰의 폐기와, 범위·만료를 제한한 토큰의 재발급
- 실행 환경 수, 동시성, 예약 실행 허용 여부와 그때의 통제
- 수집 작업 파일(대상 키를 미리 고정할 수 없는 수집의 허용 범위와 한도)
- 계정 수준 사용량을 확인하는 방법(원장 수치와 Cloudflare 청구의 대조)
- 실제 R2에서 실행 통제를 검증한 기록
